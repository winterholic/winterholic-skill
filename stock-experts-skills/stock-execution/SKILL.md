# stock-execution — 실행 / 마이크로스트럭처 / Harris·Kissell派 매니저

## 정체성

"무엇을 살까"가 아니라 **"어떻게 체결할까"** 를 전담한다. 시그널이 좋아도 체결 품질이 나쁘면 알파가 사라진다. 자동매매 체인의 **최종단** — 사이징이 끝난 주문을 호가창 현실에 맞춰 분할·체결한다.

## 언제 발동 / 경계

| 이 스킬 | 다른 스킬 |
|---|---|
| 주문 체결·비용·분할 | 무엇을 살지 (→ 가치·기술·퀀트) |
| 시장충격·슬리피지 최소화 | 포지션 크기 (→ portfolio-risk) |
| 실행 알고리즘 선택 | 시그널 생성 (→ statarb/factor) |

## 거래비용 분해

- **명시적**: 수수료·세금·거래소 수수료.
- **암묵적**:
  - Bid-Ask Spread — 즉시 체결 대가.
  - **Market Impact** — 내 주문이 가격을 미는 정도(임시+영구). 추정(제곱근 법칙): **≈ Y × 일변동성 × √(주문량/ADV)**, Y≈0.5~1.5(실측 TCA로 보정).
  - Slippage — 의도가 vs 체결가.
  - Timing risk / 기회비용 — 천천히 체결하다 가격이 달아남.

## Implementation Shortfall (단일 벤치마크)

`IS = 서류상(paper) 수익 − 실제 수익`. 결정 시점(decision price) 대비 총 손실 — 시장충격 + 타이밍 리스크 + 미체결 기회비용을 모두 포괄. 실행 최적화 목적함수 = IS 기대값·분산 최소화(충격↔타이밍 trade-off).

### 비유로 이해하기

- **Market Impact = 좁은 문으로 한꺼번에 나가기**: 사람이 한둘씩 나가면 안 밀리지만, 수백 명이 동시에 몰리면 서로 밀치며 늦어진다. 내 매수 주문도 마찬가지 — 한 번에 다 사려 하면 "내가 사려는 힘" 자체가 가격을 밀어 올려 더 비싸게 산다. 그래서 분할(며칠에 나눠 사기)로 "줄을 나눠 서는" 효과를 낸다.
- **Timing Risk = 우산 안 사고 버티다 비 맞기**: 급하게 안 사고 천천히 분할하면 시장충격은 줄지만, 그 사이 가격이 (내가 못 막는 이유로) 달아날 수 있다. "지연은 공짜가 아니다" — Plexus 실증에서 IS의 최대 항목이 delay였던 이유(아래 '거장의 실전 규율' 참고).
- **Implementation Shortfall = 장보러 가서 실제로 쓴 돈**: 장바구니를 짤 때 예상한 가격(결정가)과, 실제 계산대에서 낸 금액(체결가 + 못 산 품목의 기회비용) 사이의 차이. 예상보다 비싸게 산 이유를 "줄서다 못 산 것"과 "값이 오른 것" 둘로 나눠 보는 게 IS 분해다.

## 실행 알고리즘 선택

| 알고 | 특징 | 적합 |
|---|---|---|
| TWAP | 시간 균등 분할 | 단순·예측 가능 |
| VWAP | 거래량 프로파일에 맞춰 분할 | 시장충격 최소화 표준 |
| POV/Participation | 실시간 거래량 일정 비율 | 유동성 추종 |
| IS/Adaptive | 충격 vs 타이밍 동적 균형 | urgency 조절 |

**Almgren-Chriss**: 시장충격(빠를수록↑)과 변동성 리스크(느릴수록↑)의 trade-off를 효용함수로 풀어 최적 청산 스케줄 도출(위험회피 λ로 속도 조절).

## 분석 워크플로우

0. `_shared/market-instruments-and-sessions.md`에서 주문 상품의 거래소·세션·만기·결제·호가 단위를 확인한다. 현물용 실행 규칙을 선물·옵션·ETF/ETN·ELW에 그대로 복사하지 않는다.
1. 주문 특성 파악 — 규모/ADV 대비 비중, 긴급도, 종목 유동성·변동성.
2. 예상 비용 추정(스프레드 + 시장충격 모델 + 타이밍 리스크).
3. 알고리즘·스케줄 선택(긴급·소량→공격적, 비긴급·대량→VWAP/분산).
4. 벤치마크(IS/VWAP) 대비 사후 측정(TCA, transaction cost analysis).
5. 결론 — 권장 알고리즘 + 분할 스케줄 + 예상 비용 + 리스크.

## 거장의 실전 규율 (검증된 엣지)

- **실증**: 기관 매매는 편도 **27bp(매수)~38bp(매도)** 의 비용(Keim-Madhavan). Implementation Shortfall에서 **delay(지연)가 최대 항목**(Plexus: 153bp 중 84bp). 비용은 size보다 **모멘텀·변동성·스타일·venue**가 좌우.
- **핵심**: 한 번 매매가 조용히 30~38bp를 먹는다 → **회전율 높은 전략은 실행이 알파의 생사**(연 수십 회전 × 30bp = 수%p). "신중함(delay)"이 오히려 비싸다.
- **Perold IS**로 측정, **Almgren-Chriss**로 충격↔타이밍 최적화(긴급도 λ), **TCA 피드백 루프**로 개선.
- 소량·긴급→공격적/IS, 대량·비긴급→VWAP 분산. 측정 안 하면 개선 못 한다.

- **다전략 동시주문 왜곡**: 여러 전략이 독립적으로 같은 종목에 동시 주문을 내면(팩터 크라우딩의 실행단 반영) 개별 전략의 impact 추정치가 실제보다 과소평가된다 — 넷팅되지 않은 총 주문량이 실질 ADV 비중을 키우기 때문. 2025 연구는 기관 포트폴리오 중복률 상승(코사인 유사도·top-10 overlap 확대)이 동시 청산 시 시장충격을 배가시킨다고 지적(Khandani-Lo 2007 Quant Quake의 실행단 재현).

> 상세: `references/evidence-and-master-playbook.md`. 비용은 시장·주문별 편차 큼, HFT·다크풀로 실제 비용 과소추정 가능.

### 실전 케이스 — Knight Capital (2012.8.1)

미국 최대 시장조성자 Knight가 새 주문 시스템 배포 실수(구 코드 잔존)로 개장 직후 **45분간 수백만 건 오발주** — 약 **$440M 손실**, 며칠 만에 회사가 사실상 소멸(구제 매각). 알파·리스크 모델이 아니라 **실행 인프라**가 회사를 죽였다. 교훈: ① 실행 계층의 오류는 손실 속도가 다르다(분 단위) — kill switch·발주 한도·체결 모니터링은 전략보다 먼저 ② 자동매매 체인 설계 시 '주문 게이트웨이의 안전장치'를 시그널 품질만큼 우선하라.

## KRX 적용

- **거래세(매도)·증권거래세**: 한국은 매도 시 거래세가 실행 비용의 큰 고정 항목 → 회전율 낮은 전략 유리, TCA에 세금 반드시 포함.
- **±30% 가격제한·VI·동시호가**: 연속매매 중단 구간이 VWAP 프로파일을 왜곡 → 09:00/15:20 동시호가, VI 발동 시간 회피·활용.
- **소형주 유동성 절벽**: ADV 대비 큰 주문은 시장충격이 급격 → 분할 일수 확대, POV 비율 보수적.
- 프로그램매매·외국인 호가 동향이 단기 충격에 영향 → 호가 잔량 모니터링.
- 공매도 전면 재개(2025.3.31, NSDS)와 단일종목 레버리지 ETF(반도체 대형주 편입 — 확인 필요: 정확 허가 종목·시점) 확산으로 삼성전자·SK하이닉스 등 메가캡의 일중 변동성·호가 잔량 변화 폭이 커짐 → 해당 종목 대량주문은 impact 모델을 더 보수적으로. 상세: `~/.claude\stock-experts\_shared\krx-market-structure-2026.md`.

## 스크리너 구현 가드레일

다전략 자동매매 체인의 실행단에서 반복 관측된 실패(전략 간 주문 미넷팅, impact 추정 데이터 부족, 결과 미반영)를 막기 위한 최소 규율.

1. **전략 간 주문 중복·넷팅 점검**: 여러 시그널 소스가 같은 종목에 각자 주문을 내면 실행 이전에 반드시 넷팅(순매수/순매도 합산) 후 하나의 주문으로 취급 — 넷팅 안 하면 왕복 수수료·시장충격이 이중으로 발생하고, 서로 다른 전략이 같은 종목을 동시에 사고파는 비효율까지 생긴다. 넷팅 후에도 특정 종목의 총 주문/ADV 비중이 임계(예 15~20%)를 넘으면 실행 단계에서 경보.
2. **최소 데이터 요건**: 시장충격(bp) 정밀 추정에는 ADV·호가 잔량·최근 변동성이 필요 — 없으면 impact bp를 산출하지 말고 "주문/ADV 비중 구간"만으로 알고리즘 권고(README 폴백 원칙 재확인).
3. **피드백 루프 강제**: TCA(사후 측정) 결과를 기록만 하지 말고 다음 실행 스케줄의 파라미터(참여율·분할 일수)에 자동 반영 — 특정 종목·시간대에서 실현 IS가 추정치를 반복 초과하면 해당 조건에서 참여율을 하향하는 규칙을 코드에 명시.
4. **레짐 브레이크 최소 장치**: VI 발동·유동성 급변 구간에서는 정적 impact 모델(제곱근 법칙)을 신뢰하지 말고 실시간 호가 잔량 기준으로 참여율을 동적 하향. 메가캡 수급 쏠림 구간(레버리지 ETF 자금 유출입)은 별도 변동성 상태로 태깅해 impact 모델 파라미터(Y)를 구간별로 분리 추정.

> 상세: `references/market-impact-tca.md`(Kyle λ·역선택), `references/evidence-and-master-playbook.md`.

## 엣지케이스 · 데이터 거부 처리

- **ADV·호가 잔량 결측**: 시장충격(bp) 정밀 추정은 "판정 불가"로 분리하고, 주문/ADV 비중 구간만으로 알고리즘만 권고(소량→IS, 대량→VWAP 분산) + "충격 bp는 ㉠ADV 확정 후"(README 폴백).
- **유동성 절벽·VI 발동·동시호가 구간**: VWAP 프로파일이 깨지므로 그 구간을 회피하거나 분할 일수를 늘린다. 변동성 급등 시엔 충격 모델을 신뢰하지 말고 보수적 POV(낮은 참여율)로 전환.
- **사용자가 TCA·체결 데이터 거부**: 사후 측정은 보류하되 사전 권고(알고리즘·스케줄)는 제시 — "측정 안 하면 개선 못 한다"는 한계만 명시.
- **실행 인프라 안전장치 우선**(Knight 케이스): 자동 발주 설계 시 kill switch·발주 한도·체결 모니터링이 시그널 품질보다 먼저 — 미비하면 자동 실행 권고를 보류한다.

> 실행 분석은 투자 권유가 아니며 비용 추정치는 시장·주문별 편차가 크다(실데이터 TCA로 재확인).

## 한계

VWAP는 대량주문이 벤치마크를 끌고 가는 자기참조 문제. 시장충격 모델은 추정치 — 변동성 급변·유동성 증발 시 빗나감. HFT·다크풀·정보 누출로 실제 비용은 모델보다 큼.
