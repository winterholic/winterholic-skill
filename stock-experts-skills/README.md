# stock-experts — 주식 분석 전문가 스킬군

Claude Code용 주식 분석 스킬을 **학파 × 시간축 × 기능** 3축으로 세분화한 23개 스킬 모음(전문가 20 + 라우터 1 + 사후채점 메타 1 + 개인 전략 오버레이 1).
단일 범용 스킬 대신, 각자 공신력 있는 레퍼런스(고전·논문·유명 애널리스트 이론)를 갖춘 숙련 매니저를 다수 둔다.

> **설계 근거**: vault `wiki/stock-investing/주식 전문가 스킬 설계.md` 및 `sources/stock-investing/*`.
> 각 스킬 `references/`의 내용은 그 vault 소스를 스킬 실행용으로 가공한 것이다.

## 이 폴더의 성격

- **자동 로드되지 않는 전용 프로젝트 폴더**다. 글로벌 `.claude/skills/`에 두지 않은 이유: 20개 description이 매 세션 컨텍스트를 상시 점유하는 것을 피하기 위함.
- 사용하려면: ① 라우터 `stock-chief-strategist/SKILL.md`를 먼저 Read해 어떤 전문가를 부를지 정하고 ② 해당 전문가 `SKILL.md`를 Read해 그 매뉴얼대로 분석한다.
- **전역 디스패처**: `~/.claude/skills/stock-experts/SKILL.md`가 설치되어 있어, 일반 세션에서 주식 분석 질문이 나오면 이 폴더로 자동 라우팅된다.
- 본문·레퍼런스의 `[[이름]]` 표기는 이 스킬군 내 다른 SKILL/레퍼런스 파일을 가리킨다(같은 이름의 `.md`를 검색해 Read). `(→ stock-x)`는 해당 전문가 스킬로의 위임 표시다.
- 개별 스킬을 자주 쓰게 되면 그 폴더만 글로벌 `skills/`로 승격한다.

## 공통 면책 (모든 스킬에 적용)

- 이 스킬군은 **교육·분석 프레임워크**다. 투자 자문이 아니며 매수·매도 권유가 아니다.
- 숫자·재무데이터는 **반드시 최신 실데이터로 재확인**한다. 스킬·레퍼런스에 적힌 임계값은 출발점일 뿐이다.
- 확신 없는 수치·기준은 "확인 필요"로 표기하고 추측으로 메우지 않는다.

## 공통: 데이터 부재·판단 불가 처리 (모든 스킬 적용)

핵심 입력(재무·가격·거래량·국면 지표 등)이 없거나 신뢰할 수 없으면 **멈추거나 추측하지 않고** 아래 4단계로 처리한다. 각 SKILL.md 출력의 "확인 필요" 항목은 이 형식으로 쓴다:

1. **무엇이 막혔나** — 결측·불신 입력을 한 줄로 명시.
2. **누가·어디서 채우나** — 사용자에게 *어떤 값을*(예: 최근 분기 총부채) *어디서*(DART 공시·증권사 HTS·데이터 벤더) 가져오면 되는지 요청.
3. **기대 결과** — 그 값이 오면 *어떤 판정*이 가능해지는지.
4. **부분 결론(partial)** — 가용 데이터로 가능한 잠정 결론 + "판정 불가" 항목을 분리 표기한다. 전체를 보류하지 않는다.

사용자가 값을 못 주거나(거부·무응답) 데이터 자체가 없으면 **대용 지표 사다리**로 폴백한다:

1. **1차 데이터**(공시·HTS·데이터 벤더) — 기본.
2. **대용 지표** — 각 SKILL.md 'KRX 적용' 섹션의 대체값(예: IBD RS Rating → 시장 대비 수익률 순위, 기관 보유 → 외국인·기관 순매수 추이, scuttlebutt → 채용·리뷰·IR 데이터). 대용 사용 시 해당 판정의 신뢰도를 한 단계 낮춰 표기한다.
3. **그래도 없으면** — 그 항목만 "판정 불가"로 분리하고, 가용 항목만으로 부분 결론 + **결론 신뢰도 등급(상/중/하)** 을 부착한다. 전체를 보류하지 않는다.

> 리스크/심리 스킬(portfolio-risk·tail-risk·behavioral)의 경고는 시그널이 좋아도 거부권(veto)에 가깝게 가중한다.

## 공통: 증거·출처 계약 (모든 스킬·직접 호출 적용)

현재 가격·재무·공시·정책·시장상품 데이터를 근거로 쓸 때는 `_shared/evidence-source-contract.md`를 적용한다. `source_id`, 원문, 공개·수집·검증 시각, 판단 `as_of`를 분리하고, 판단 시각보다 늦게 공개된 미래 정보는 사용하지 않는다. 가상 평가 자료는 `synthetic`으로 명시하며 실전 판단에 섞지 않는다. 출처 충돌이나 관측 시각 미확인은 숨기지 말고 `counterevidence`와 `data_gaps`에 남긴다.

## 공통: 빠른 사용 (Quick Start)

급할 때 3단계로 쓴다:
1. **라우터부터** — `stock-chief-strategist/SKILL.md`를 읽어 질문의 시간축·목적으로 전문가 1~3명을 고른다. (학파가 이미 명확하면 해당 전문가 SKILL.md 직행)
2. **그 전문가 SKILL.md의 "분석 워크플로우 + 출력 템플릿"** 만 따라 바로 결론을 낸다. 심화는 `references/`로 미룬다.
3. **데이터가 없으면** 멈추지 말고 아래 "데이터 부재 처리" 4단계로 부분 결론 + 확인 필요만 표기.

> 5~10분 내 1차 판단이 목표. 정밀 검증·다중 전문가 종합은 그 다음 단계.

## 공통: 상품 연결 점검 (모든 스킬·직접 호출 적용)

종목·시장 분석을 시작할 때 `_shared/market-instruments-and-sessions.md`에서 대상과 연결된 현물·ETF/ETN·선물·옵션·통화·금리·원자재 상품 및 현재 거래세션을 확인한다. CIO 라우터를 거치지 않고 전문가를 직접 호출한 경우에도 적용한다.

- 펀더멘털 분석은 상품 신호로 기업가치를 대체하지 않되, 환율·금리·원자재·헤지상품이 실적과 수급에 전달되는 경로를 확인한다.
- 기술·단기 분석은 현물 가격을 지수선물·관련 ETP·옵션·프로그램 수급과 분리해 오인 가능성을 점검한다.
- 시장 상품을 근거로 쓰면 가격뿐 아니라 거래량, 미결제약정, 베이시스·NAV 괴리, 만기·롤오버, 세션 중 가용 항목을 교차확인한다.
- 필요한 상품 데이터가 없으면 `영향 없음`이 아니라 `미관측`으로 표시한다.

## 공통: 시스템 구현 자문 규칙 (스킬 철학 → 코드 전환 시)

사용자가 이 스킬군의 조언을 **자동매매/스크리너 코드**로 옮길 때, 다음 가드레일을 스킬 전반에 공통 적용한다. 배경: 여러 '전략'이 유니버스를 공유해 같은 종목으로 수렴하는데도 아무도 감지하지 못하고, 리스크 게이트를 프롬프트 권고로만 남겨 코드가 실제로 지키지 않으며, 채점 원장(ledger)처럼 설계만 하고 한 번도 가동하지 않는 실패가 실제로 있었다(sample-service 프로젝트 사례).

1. **리스크 게이트는 코드로 강제한다, 프롬프트로 권고하지 않는다** — "분산 확인해라"는 문구는 매 실행마다 누락될 수 있다. 편입/사이징 함수 자체가 조건을 검사하고 실패 시 값을 반환하지 않는 구조로 만든다. (상세: `stock-portfolio-risk` '스크리너 구현 가드레일')
2. **다전략 시스템은 종목별 중복보유·유니버스 중복을 상시 계측한다** — effective N·HHI를 로깅하고, 임계 초과 시 자동 경보(→ `stock-portfolio-risk`, `stock-chief-strategist` 체크리스트).
3. **피드백 루프는 가동 여부를 스스로 확인한다** — "기록해라"는 지시만으로는 루프가 돌지 않는다. 원장 파일 존재·최근 갱신 여부를 세션 진입 시 점검하는 절차 자체를 코드/스킬에 넣는다(→ `stock-scorecard` '가동 강제').
4. **설계자 자신의 편향을 의심한다** — 반복 추천을 신호 확증으로 오인하는 자동화 편향, 파라미터 튜닝에 스며드는 확증편향을 시스템 설계 검토 항목에 포함한다(→ `stock-behavioral` '시스템 설계자의 편향').
5. **시장구조 전제를 문서로 고정한다** — KRX 특유의 쏠림·수급 구조(메가캡 주도, 외국인 동반매매, 공매도 제약 등)에 대한 공통 전제는 `_shared/krx-market-structure-2026.md`(별도 작성 중인 시장구조 문서)를 참조한다. 각 스킬의 'KRX 적용' 섹션과 배치되지 않게 그 문서를 1차 참조로 삼는다.

## 공통: 분석 결과 저장 규칙 (모든 스킬 적용)

분석을 파일로 남길 때:
- **경로·파일명**: `~/.claude\stock-experts\analyses\{YYYY-MM-DD}-{종목코드}-{스킬명}.md` (예: `~/.claude\stock-experts\analyses\2026-06-09-005930-quality.md`). 디렉토리가 없으면 생성한다.
- **덮어쓰기 금지(append 아님)**: 같은 종목을 재분석하면 **날짜를 바꾼 새 파일**을 만든다(판단 이력 보존). 기존 분석을 수정하지 않는다.
- **종합 분석**(라우터)은 `analyses/{날짜}-{종목}-cio.md`로, 호출한 전문가별 결론을 함께 기록.
- **스코어카드 블록 의무**: 모든 분석 말미에 stock-scorecard가 정의한 5요소 블록(판정·시간축/점검일·확신도·무효화 조건·성공 기준)을 붙인다 — 없으면 사후 채점 불가. 채점 결과는 `analyses/ledger.md`(append-only)에 누적.
- 시각화·리포트가 필요하면 `/html-report` 스킬로 내보낸다(스킬 자체는 인라인 분석이 기본).

## 상태

**평가 기반 고도화 진행 중(2026-07-30~)**. 기존 문서·계산기·역사 사례는 학습 자료로 보존하지만 이를 운영 품질 완료의 근거로 보지 않는다.

- 최신 구조 기준선: `_eval/baselines/2026-08-01-core-hardening.json`
- 레퍼런스 출처 감사: `_eval/scripts/reference_audit.py` — 현재 87개 중 URL·검증일을 모두 갖춘 문서는 0개다. 이 수치를 근거 품질이 확보됐다는 뜻으로 과장하지 않는다.
- 평가 계약·검증기: `_eval/scripts/`
- 공개 회귀 사례: `_eval/cases/public/`
- 현재 완결된 첫 실패공간: 가치 실현(value realization)의 정상·실패·판단보류·경계 사례
- 운영 리포트·추천 이력과 ledger 채점이 확보되지 않은 상태에서는 전체 스킬군을 “검증 완료”로 부르지 않는다.

다음 개선은 문서 분량이나 전문가 수가 아니라, 고정된 as-of 사례·숨은 홀드아웃·단순 기준선·사후결과에서 성능이 나아졌을 때만 승격한다.
