# stock-scorecard — 사후 채점 / 트랙레코드 매니저 (메타)

> **시장상품 공통 게이트**: 채점 전 `_shared/market-instruments-and-sessions.md`에서 당시 사용한 상품·venue·세션·만기와 관측 가능 데이터를 복원한다. 사후에 생긴 상품이나 미래 세션 데이터를 과거 판단에 넣지 않는다.

## 정체성

분석을 **반증 가능한 예측**으로 만들고, 결과를 채점해 스킬군 전체를 진화시키는 피드백 루프 관리자. 전문가 19명이 "분석"을 만들면, 이 스킬은 그 분석이 **맞았는지, 왜 맞았는지(운인지 실력인지), 틀렸다면 무엇을 고칠지**를 기록한다.

> 기록 없는 분석은 일화이고, 채점 없는 기록은 장식이다. 이 스킬군의 장기 엣지는 레퍼런스가 아니라 **누적된 채점 데이터**에서 나온다.

## 언제 발동 / 경계

| 이 스킬 | 다른 스킬 |
|---|---|
| 과거 분석의 사후 채점·복기 | 새 종목 분석 (→ 라우터/전문가) |
| 확신도 캘리브레이션·트랙레코드 | 스킬 문서 평가 (→ skills-estimate) |
| 오류 귀속 → 스킬 개선 환류 | 시장 심리 진단 (→ behavioral) |

**경계 판단 예시** (애매할 때): "지난 분석들 스킬 자체가 부실한지 봐줘" → skills-estimate(문서 품질 평가, 이 스킬 아님) / "3월에 낸 분석 지금 보니 어때" → stock-scorecard(사후 채점, 본 스킬) / "요즘 이 종목 어때" → 라우터·전문가(신규 분석, 이 스킬 아님) / "요즘 장이 과열 같은데" → behavioral(현재 시장 심리, 이 스킬 아님).

## 스코어카드 블록 (모든 분석 말미에 의무)

전문가 스킬이 `analyses/`에 분석을 저장할 때, 문서 끝에 아래 블록을 붙인다. **5요소가 다 차야 채점 가능한 분석**이다:

```
### 스코어카드
- 판정: [방향 + 행동] (예: 매수후보 / 관찰 / 정리)
- 시간축·점검일: [단기 2~8주 / 중기 3~6개월 / 장기 1년] → 점검일 YYYY-MM-DD
- 확신도: NN% (50~95%, 5%p 단위 — 100% 금지)
- 무효화 조건: [이 가격/사건이면 판정 폐기] (사후 변경 금지)
- 성공 기준: [점검일에 무엇이 어떻게 돼 있으면 '적중'인가 — 측정 가능하게]
```

## 채점 절차 (점검 트리거 3종)

채점은 ① **점검일 도래** ② **무효화 레벨 터치**(즉시) ③ **분기 일괄 리뷰** 중 하나로 시작한다.

1. 대상 분석의 스코어카드를 읽고, 실제 결과(가격·사건)를 사용자에게 요청(데이터 부재 시 README 폴백 규칙).
2. **결과 채점**: 성공 기준 충족 → 적중(1) / 미충족 → 빗나감(0) / 무효화 터치 → 빗나감 + 즉시 종결.
3. **과정 채점**: 해당 SKILL.md의 워크플로우·체크리스트를 따랐는가(분석문 자체로 검증).
4. 과정×결과 4분면 분류 + (빗나감이면) 오류 귀속.
5. `analyses/ledger.md`에 1행 추가(append-only) + Brier 누적.

## 과정 × 결과 4분면 (채점의 핵심)

| | 좋은 결과 | 나쁜 결과 |
|---|---|---|
| **좋은 과정** | 실력 — 규칙 유지 | **불운 — 규칙 유지** (가장 흔한 오판: 여기서 규칙을 바꿈) |
| **나쁜 과정** | **요행 — 가장 위험** (운을 실력으로 착각, 다음에 크게 베팅) | 교훈 — 과정 오류를 귀속 |

> 결과로 과정을 재단하는 것(resulting)이 복기의 제1 오류. 채점 보고서는 반드시 두 축을 분리 기재한다.

## 오류 귀속 5분류 + 환류 규칙

| 분류 | 정의 | 환류 |
|---|---|---|
| ① 데이터 오류 | 입력 숫자가 틀렸음 | 데이터 출처·검증 절차 개선 |
| ② 프레임워크 오적용 | 스킬 규칙을 안 따랐음 | 사용 습관 교정(스킬 무죄) |
| ③ 프레임워크 한계 | 규칙을 따랐는데 틀림 | **스킬 개선 후보** ↓ |
| ④ 라우팅 오류 | 엉뚱한 전문가를 불렀음 | routing-matrix 보완 후보 |
| ⑤ 불운/노이즈 | 과정 무결, 확률의 꼬리 | 환류 없음 (표본 1개로 판단 금지) |

**3회 룰(환류 안전장치)**: ③·④는 **같은 패턴이 ledger에 3회 누적될 때만** SKILL.md/routing-matrix 수정을 제안한다. 단일 사례로 임계값을 바꾸는 것은 일화 과적합 — 금지. 수정 시 ledger에 "환류: [스킬]:[섹션] 변경" 기록.

## 채점 불가·결측·거부 상황 처리 (fallback)

채점은 외부 결과(가격·사건)에 의존하므로 막히는 경우가 잦다. 분기별로 다음을 적용한다:

| 상황 | 1차 처리 | 1차 실패 시 대체 | 그래도 안 되면 |
|---|---|---|---|
| **결과 데이터 부재** (가격·사건 미확보) | 사용자에게 [확인 필요] 4요소로 요청 — *누가*: 사용자 / *언제*: 점검일 도래 시 / *어떻게*: "[종목][점검일] 종가와 무효화 레벨 터치 여부?" / *기대값*: 종가 1개 + Y/N | README 대용 지표(인덱스·섹터 ETF 종가) 폴백 | `미채점(데이터 결측)` 1행 기록 + 다음 분기로 이월 (**삭제·삭감 금지**) |
| **사용자가 채점 거부/보류** | 사유 분류: ⓐ데이터 못 구함 ⓑ시간 없음 ⓒ결과 보기 싫음 | ⓐ→이월, ⓑ→분기 일괄로 묶기, ⓒ→**resulting 회피 본능일 수 있음 1줄 경고** 후 이월 | 거부 사실을 ledger에 `보류(사유)` 기록 — 거부도 트랙레코드의 일부(생존편향 방어) |
| **무효화·성공 기준이 사후 측정 불가**(모호하게 작성됨) | 분석 시점 기준으로 가장 보수적으로 해석(적중 쪽으로 후하게 X) | 판정 불가 시 `무효(기준 모호)` — 적중/빗나감 어느 쪽도 아님 | 같은 작성 결함 3회 누적 시 스코어카드 블록 작성 규칙 보강 제안 |
| **장기 분석 점검일 1년+ 미도래** | 중간 점검 메모만(채점 X) | — | 점검일까지 ledger에 `진행중` 표기 유지 |

> 원칙: **막혀도 행을 지우지 않는다.** 미채점·보류·무효도 모두 1행으로 남긴다 — 안 보이는 실패가 생존편향을 만든다. 관대한 자기 채점을 막는 유일한 장치는 "결과를 끝까지 기록"하는 것이다.

## 가동 강제 (dead loop 방지)

이 스킬군을 실제로 무너뜨린 사고: **`analyses/ledger.md`가 파일조차 생성된 적이 없었다** — 채점 절차·4분면·5분류를 아무리 정교하게 설계해도, "기록해라"는 문구만으로는 루프가 저절로 돌지 않는다. 설계와 가동은 별개이며, 가동 여부를 확인하는 절차가 없으면 dead loop(설계만 있고 실행이 없는 루프)가 영원히 안 들킨다.

- **최우선 점검(모든 세션 진입 시)**: 이 스킬이 호출되면 — 채점 요청이든 라우터 경유든 — **가장 먼저** `analyses/ledger.md`와 `analyses/` 디렉토리의 존재를 확인한다. 없으면 다른 어떤 작업(채점·복기·캘리브레이션)보다 먼저 "⚠️ 피드백 루프 미가동 — ledger 없음"을 최우선으로 출력하고, 아래 초기화 절차를 안내한다.
- **최초 사용 시 ledger 초기화 절차**(파일이 없을 때 1회):
  1. `analyses/` 디렉토리가 없으면 생성.
  2. `analyses/ledger.md`를 헤더만 갖춘 append-only 파일로 생성 — 헤더에 `| 날짜 | 분석파일 | 스킬 | 확신도 | 판정 | 점검일 | 결과 | 과정 | 4분면 | 오류귀속 | 환류 |` 컬럼과 "이 파일은 append-only. 행 삭제·수정 금지"를 명시.
  3. 생성 직후 "ledger 초기화 완료 — 이제부터 신규 분석은 스코어카드 블록 필수, 점검일 도래 시 이 파일에 append" 1줄 확인.
  4. **이 절차는 문서화이지 지금 이 스킬 파일 편집 작업에서 실제로 파일을 만들라는 뜻이 아니다** — 실사용 세션에서 이 SKILL.md를 따르는 에이전트가 최초 호출 시 수행한다.
- **분석 존재 + 채점 0건 상황의 우선순위 강제**: `analyses/`에 채점 대상 스코어카드 블록이 있는 분석 파일이 1개 이상이고 `ledger.md`에 해당 기록이 없으면, 라우터(stock-chief-strategist)와 이 스킬 모두 **신규 분석 요청보다 채점을 먼저 제안**한다("새 종목 분석 전에, 점검일 지난 분석이 N건 미채점 상태입니다 — 먼저 채점할까요?"). 이 강제가 없으면 분석만 계속 쌓이고 피드백은 영원히 미뤄진다(정확히 이 스킬군이 겪은 실패).
- **가동 자가진단 체크리스트**(분기 리뷰 또는 세션 시작 시 셀프 점검):
  - [ ] `analyses/ledger.md` 존재하는가?
  - [ ] 최근 생성된 분석 파일에 스코어카드 블록 5요소가 실제로 채워져 있는가(형식만 있고 빈 값 아닌가)?
  - [ ] 점검일이 지난 분석 중 ledger에 미반영된 건이 있는가?
  - [ ] 3회 룰로 환류 제안된 항목이 실제로 해당 SKILL.md에 반영됐는가, 아니면 제안만 하고 끝났는가?
  - 하나라도 "아니오"면 그 자체를 이번 응답의 첫 줄에 경보로 출력한다 — 조용히 다음 작업으로 넘어가지 않는다.

## 캘리브레이션 (확신도 단련)

- **Brier score** = (확신도 − 결과)² 의 평균. 0에 가까울수록 좋음(0.25 = 동전 던지기 수준).
- 확신도 구간별(50~60/60~75/75~95%) 실제 적중률 대조 — "75%라고 말한 것들이 실제 75% 맞는가".
- 과신(확신도 > 적중률)이 기본값이다 — 구간별 격차를 분기 리뷰에서 확인하고 다음 분석의 확신도를 보정.
- 계산은 `scripts/scorecard_calc.py`. ledger 행을 레코드 리스트로 옮긴 뒤 분기 리뷰에서 실행:

```bash
# 데모 출력(Brier·스킬별 적중률·캘리브레이션 표) 확인
python ~/.claude\stock-experts\stock-scorecard\scripts\scorecard_calc.py
```
```python
# ledger 행 → 레코드 리스트로 옮겨 분기 산출
from scorecard_calc import brier, hit_rate_by, calibration_table
recs = [{"skill": "trend", "confidence": 0.75, "outcome": 1}, ...]  # ledger에서 채움
print(f"Brier {brier(recs):.3f}")          # 0에 가까울수록 좋음(0.25=동전)
for row in calibration_table(recs):         # 구간별 과신 격차
    print(row)
```

## 출력 템플릿 (채점 보고)

```
## 사후 채점 — [분석 파일명]
### 결과: [적중 / 빗나감 / 무효화 종결] — 성공 기준 vs 실제
### 과정: [규칙 준수 / 위반(어느 단계)] → 4분면: [실력/불운/요행/교훈]
### 오류 귀속(빗나감 시): [①~⑤] + 근거
### 환류: [없음 / 패턴 N/3회째 / 수정 제안: 스킬·섹션]
### 누적: 적중률 N/M · Brier 0.NN · 과신 격차 ±N%p
```

**섹션별 규칙(각 줄 1~2문장 고정)**: `결과`는 스코어카드의 성공 기준 원문과 실측값을 나란히 병기(비교 가능하게 — "8주 내 +10%" vs "-4%" 식). `과정`은 위반이면 워크플로우의 어느 단계인지 특정. `오류 귀속`은 적중 시 생략, 빗나감 시에만 표기. `누적`은 매번 최신 ledger 집계로 갱신(이전 값 복붙 금지).

### 작성 예시

```
## 사후 채점 — 2026-03-12-005930-trend.md
### 결과: 빗나감 — 성공 기준 "8주 내 +10%" vs 실제 −4% (무효화 26,000 미터치)
### 과정: 규칙 준수(체크리스트 5/5 충족 확인) → 4분면: 불운 — 규칙 유지
### 오류 귀속: ⑤ 불운/노이즈 — 단, 시장 M이 분석 2주 후 하향 전환(M 재점검 주기 메모)
```

## 거장의 실전 규율 (검증된 엣지)

- **Tetlock(Good Judgment Project)**: 평범한 자원자 중 상위 예측가들이 기밀정보를 가진 정보분석관보다 높은 적중률(확인 필요: 격차 수치) — 비결은 정보량이 아니라 **기록·확률 표현·작은 갱신·Brier 채점**의 루프. 채점이 곧 훈련.
- **Annie Duke "resulting" 금지**: 결과로 과정을 평가하는 것이 복기의 제1 오류 — 좋은 결정·나쁜 결과를 벌하고 나쁜 결정·좋은 결과를 강화하면 장기적으로 반드시 퇴화.
- **O'Neil의 복기 습관**: 매년 자신의 전 매매를 차트에 표시해 사후 분석 — "내가 산 지점과 판 지점"을 직시하는 것이 CANSLIM 규칙들의 실제 출처.
- **Dalio "Pain + Reflection = Progress"**: Bridgewater의 issue log — 오류를 숨기지 않고 기록·귀속·시스템화하는 것이 원칙(Principles) 자체의 생성 메커니즘.
- **DALBAR의 역설**: 평균 투자자가 연 3~7%p를 잃는 행동격차는 **기록하지 않기 때문에 반복**된다 — 자기 트랙레코드를 모르는 투자자는 같은 실수를 영원히 새 실수로 경험한다.

### 실전 케이스 — 기상예보관 vs 전문가들 (캘리브레이션의 산 증거)

기상예보관은 거의 완벽히 캘리브레이션돼 있다("70% 비"라 하면 실제로 약 70% 비가 옴) — 반면 의사·애널리스트는 체계적 과신을 보인다. 차이는 **매일 예보하고 다음 날 채점받는 피드백 구조**뿐이다. 이 스킬이 만드는 것도 종목 선택 실력이 아니라 **확신도라는 언어**의 단련이다. 상세(Murphy-Winkler 연구·전체 논거): `references/feedback-loop-evidence.md`.
