# 서비스 블루프린트 표기법 & 저니맵 실무 (실전)

> 근거: Bitner·Ostrom·Morgan, *California Management Review* 50(3), 2008 · NN/g Service Blueprints. 표기법은 현대 실무 표준.

## 1. 블루프린트 5개 스윔레인 (위→아래 순서 고정)

블루프린트는 위에서 아래로 **5개 가로 레인(swimlane)**을 세로 라인으로 구분한다. 순서를 바꾸지 말 것 — 위가 고객, 아래로 갈수록 무대 뒤.

| # | 레인 | 담는 것 | 예 |
|---|------|---------|-----|
| 1 | **물리적 증거 (Physical Evidence)** | 각 단계에서 고객이 접하는 유형물 | 앱 화면, 이메일, 매장, 영수증, 포장 |
| 2 | **고객 행동 (Customer Actions)** | 고객이 실제 하는 행위(주어=고객) | 검색, 가입, 결제, 문의 |
| 3 | **프론트스테이지 (Onstage/Frontstage)** | 고객에게 **보이는** 직원·시스템 접점 | 상담원 응대, 챗봇, 셀프 키오스크 |
| 4 | **백스테이지 (Backstage)** | 고객에게 **안 보이는** 직원 활동 | 주방 조리, 창고 피킹, 심사 담당자 |
| 5 | **지원 프로세스 (Support Processes)** | 접점을 떠받치는 내부 시스템·서드파티 | 결제 게이트웨이, CRM, 배송사 API |

## 2. 4개 구분선 (레인 사이의 라인 — 표기 핵심)

Zeithaml·Bitner 정립. 이 4개 라인이 블루프린트를 저니맵과 구별짓는 핵심.

- **① 상호작용선 (Line of Interaction)**: 고객 행동 ↔ 프론트스테이지 사이. 고객과 서비스 조직이 직접 접촉하는 지점.
- **② 가시선 (Line of Visibility)** ⭐: 프론트스테이지 ↔ 백스테이지 사이. **이 선 위=고객이 봄, 아래=안 봄.** Shostack의 원 기여.
- **③ 내부 상호작용선 (Line of Internal Interaction)**: 백스테이지 ↔ 지원 프로세스 사이. 접점 직원 ↔ 이들을 지원하는 내부 부서/시스템.
- **④ 실행선 (Line of Implementation, 선택)**: 지원 프로세스 안에서 관리 영역 ↔ 실무 지원 영역 구분(고급).

## 3. 화살표(arrow) 표기
- **세로 화살표**가 라인을 가로지르면 = 상호작용(고객↔프론트, 프론트↔백스테이지 지원 요청).
- **가로 화살표** = 시간 순 흐름(왼→오른쪽 단계 진행).
- 실선=직접 상호작용, 점선=간접/시스템 트리거로 구분하면 가독성↑(관행).

## 4. 저니맵 확장 템플릿 (블루프린트로 승격하기)

저니맵(고객 시선)에서 시작해, 각 접점 아래에 가시선·백스테이지를 덧붙이면 블루프린트가 된다.

```markdown
| 단계 | 인지 | 가입 | 첫사용 | 지원 | 이탈 |
|------|------|------|--------|------|------|
| 물리적 증거 | 인스타 광고 | 가입폼 | 대시보드 | CS 이메일 | 해지 화면 |
| 고객 행동 | 클릭 | 정보 입력 | 첫 가치 도달 | 문의 작성 | 해지 시도 |
| 감정 | 호기심 😐 | 좌절 😣 | 안도 🙂 | 불안 😟 | 분노 😠 |
| 고통점 | 로딩 느림 | 필수항목 과다 | 빈 화면(0데이터) | 응답 지연·재설명 | 동선 숨김 |
| ── 상호작용선 ── |
| 프론트스테이지 | 광고 크리에이티브 | 폼 검증 UI | 온보딩 툴팁 | 챗봇 1차 | 해지 확인 모달 |
| ── 가시선 ── |
| 백스테이지 | 광고 운영팀 | 회원 DB 생성 | 초기데이터 시드잡 | CS 상담원 배정 | 리텐션 담당 알림 |
| ── 내부 상호작용선 ── |
| 지원 프로세스 | 광고 API | 인증 서버 | 배치 스케줄러 | CRM 티켓팅 | 정산·환불 시스템 |
```

## 5. 실무 워크숍 순서 (as-is 블루프린트 1회 세션)
1. 스코프 확정: **하나의 고객 시나리오**(예: "신규 가입→첫 결제")만. 전 여정을 한 판에 담으려다 실패하는 게 최빈 실수.
2. 고객 행동 레인부터 왼→오른 채우기(고객 관점 앵커).
3. 각 행동에 대응하는 프론트/백스테이지/지원을 세로로 채우기.
4. **"이 접점이 실패하면?"** 질문으로 취약점(fail point) 표시 — 빨간 스티커.
5. 대기시간·중복입력·핸드오프 지점을 표시(운영 비효율 = 고통점의 뒷단 원인).

## 6. 흔한 실수 (교정)
- ❌ 고객 행동 레인에 시스템 동작을 씀("DB에 저장됨") → ✅ 고객 행동은 **주어가 고객**인 것만.
- ❌ 가시선을 안 그림 → 저니맵과 구별 안 됨. 가시선이 블루프린트의 정체성.
- ❌ 한 판에 5개 시나리오 → 읽기 불가. 시나리오당 1판.
- ❌ 감정 곡선을 프론트/백에만 붙임 → 감정은 **고객 행동 레인**에 붙어야(고객이 느끼는 것).
