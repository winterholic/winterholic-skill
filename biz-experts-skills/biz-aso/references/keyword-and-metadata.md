## 1. Apple vs Google 인덱싱 차이 (공식 확인)

| 필드 | Apple App Store | Google Play |
|---|---|---|
| 앱명(제목) | ✅ 인덱싱·30자 | ✅ 인덱싱·30자 |
| 부제(Subtitle) | ✅ 인덱싱·30자 | N/A(짧은 설명이 유사 역할) |
| 짧은 설명 | N/A | ✅ 인덱싱·80자 |
| 키워드 필드 | ✅ **100자·비공개·핵심 무기** | ❌ 없음 |
| 전체 설명 | ❌ **비인덱싱**(공식 확인 2026-07) | ✅ 인덱싱·4000자 |
| 프로모텍스트 | ❌ **비인덱싱**(공식 확인 2026-07) | N/A |
| 카테고리 | ✅ 인덱싱(1·2차) | ✅ 인덱싱 |

**공식 출처(Apple)**: "Don't add unnecessary keywords to your description in an attempt to improve search results." / "promotional text doesn't affect your app's search ranking" — https://developer.apple.com/app-store/product-page/

**함의**: Apple은 키워드 필드가 발견의 핵심 무기. Google은 설명 전체가 키워드 소스 — 자연어·밀도 게임.

## 2. Apple 키워드 필드 100자 최적화 실무

### 기본 원칙
- **100자 한도**: 쉼표로 구분, 쉼표 사이 공백 없음(`yoga,meditation,sleep` ← 공백 없음).
- **공백 금지**: `"yoga meditation"` → 2자 낭비, `yoga,meditation`이 맞음.
- **앱명·부제 중복 회피**: 이미 인덱싱된 단어를 키워드 필드에 반복하면 해당 자릿수 낭비(Apple 공식·벤더 컨센서스 일치).

### 중복·낭비 패턴 피하기
| 낭비 패턴 | 이유 | 대안 |
|---|---|---|
| 앱명 단어 반복 | 이미 인덱싱됨 | 다른 키워드로 교체 |
| 공백 포함 | 문자수 낭비 | 쉼표만 구분자 |
| 단수·복수 동시 입력 | Apple이 양쪽 인식(벤더 컨센서스, 확인 필요) | 단수만 — 복수는 생략 |
| 관사(a, the, an) | 불용어 처리 가능성(확인 필요) | 제거 |
| 경쟁사 앱명·브랜드 | App Review 정책 위반 리스크 | 카테고리 일반 용어로 |

### 단수·복수 주의
"Apple이 단수 입력 시 복수도 인식한다"는 벤더 컨센서스가 있으나 **Apple 공식 확인 없음**. 보수적으로 테스트하며 운용 권장. ⚠️ 확인 필요.

### 키워드 선정 우선순위
1. **관련성 최우선** — 앱과 무관한 고볼륨 키워드는 관련성 신호 약화(랭킹에 역효과 가능).
2. **검색량(Volume) vs 난이도(Difficulty) 균형** — 초기 앱은 난이도 낮은 키워드로 랭킹 확보 후 고볼륨 경쟁.
3. **틈새 키워드 조합** — 볼륨 낮아도 전환율 높은 쿼리가 실설치에 기여.

### 키워드 리서치 소스
- **Apple 자동완성(Suggest)**: 검색창 타이핑 → 연관어 수집 (무료·직관적).
- **ASO 도구**: AppTweak, AppFollow, MobileAction, Sensor Tower, AppAnnie(data.ai) — 볼륨·난이도·경쟁 추정. ⚠️ 추정치이며 도구마다 상이.
- **경쟁사 메타데이터 역분석**: 상위 앱 앱명·부제에서 공통 키워드 추출.
- **App Store Connect 검색 용어 보고서**: 실제 유입 쿼리 확인(정책상 일부만 공개).

## 3. Apple 메타데이터 필드별 배치 우선순위

| 우선순위 | 필드 | 제한 | 전략 |
|---|---|---|---|
| 1순위 | **앱명** | 30자 | 브랜드명 + 핵심 키워드 1개 자연스럽게. 검색 랭킹+첫인상 동시 |
| 2순위 | **키워드 필드** | 100자 | 앱명·부제 미포함 단어만. 쉼표·공백없이 빡빡하게 |
| 3순위 | **부제** | 30자 | 보조 키워드 2~3개 + 가치 제안. 앱명 중복 회피 |
| 4순위 | **프로모텍스트** | 170자 | 비인덱싱 → 전환용(할인·이벤트·신기능 알림). 키워드 무의미 |
| 5순위 | **설명** | 4000자 | 비인덱싱 → 전환 서술. 첫 3줄이 핵심(더보기 클릭 전) |

**핵심 원칙**: 키워드 인덱싱 가치는 `앱명 ≥ 부제 ≥ 키워드필드`(정확 가중치 미공개). 앱명이 가장 강하므로 핵심 키워드는 앱명에 넣는 게 이상적(브랜드 손상 없는 범위 내).

## 4. Google Play 메타데이터 필드별 배치 우선순위

| 우선순위 | 필드 | 제한 | 전략 |
|---|---|---|---|
| 1순위 | **제목** | 30자 | 핵심 키워드 1개. 브랜드+카테고리 키워드 |
| 2순위 | **짧은 설명** | 80자 | 주요 키워드 2~3개 자연스럽게. 검색결과에 노출 → 전환도 영향 |
| 3순위 | **전체 설명** | 4000자 | 주 키워드 2~3%(벤더 권장), 보조 1~2%. 첫·마지막 180자 강조. NLP 친화적 자연어 |

**Google 특이점**: 키워드 스터핑(같은 단어 반복) 역효과 가능 — NLP가 의미적 관련성 평가. 동의어·변형어 분산이 더 효과적(벤더 컨센서스). 밀도 수치(2~3%)는 벤더 권장, Google 공식 아님. ⚠️ 확인 필요.

## 5. Apple 크로스-로컬라이제이션 (지역화 스필오버) — 심화

### 원리
Apple은 스토어프론트(지역별 App Store)마다 **primary + secondary 로컬라이제이션**을 지원. 각 로컬라이제이션의 키워드 필드가 모두 인덱싱되어 실효 키워드 공간 확대.

예시:
- US 스토어(en-US): 키워드 100자
- US 스토어에 es-MX 추가: 키워드 100자 더 인덱싱
- → 실효 공간 ~200자 활용 가능

### 핵심 제약 (반드시 숙지)
1. **반복 단어 가중 안 됨**: 동일 단어가 여러 로컬에 있어도 1회 취급.
2. **로컬라이제이션 간 조합 없음**: en-US의 "blocks" + es-MX의 "kids"로 "kids blocks" 쿼리 불가. 각 로컬이 의미적으로 독립적이어야 효과.
3. **콘텐츠 일치 필요**: 실제 앱이 해당 언어·지역 사용자에게 서비스하는 게 아니라면 App Review 이슈 가능.

⚠️ **전체 트릭은 벤더 컨센서스** — Apple 공식 문서는 로컬라이제이션 구조만 기술, 이 전략을 명시하지 않음. 확인 필요.
출처(벤더): https://www.mobileaction.co/blog/app-store-cross-localization/ · https://www.apptweak.com/en/aso-blog/how-to-benefit-from-cross-localization-on-the-app-store

### 스토어프론트 선택 팁
- en-US 스토어에 es-MX(스페인어): 라틴 미주 키워드 확보
- en-GB 스토어에 fr-FR: 영어권+불어권 동시 커버
- 우선순위: 실제 트래픽이 오는 지역 언어 로컬라이제이션부터 추가.
