# biz-customer-success — 실무 플레이북

> 일류 CSM의 실전 절차·계산식·플레이북. 출처·검증사실은 `evidence.md` 참조.
> 원칙: 헬스스코어에 **표준 공식 없음**(자사 가치 동인 기반 설계·반복 검증). NRR≠GRR(둘 다 본다).

---

## 1. NRR / GRR 계산식과 사용법

### 계산식(월 또는 연 코호트 기준, 금액=MRR/ARR)
```
기간 시작 코호트 매출 = Starting
+ 확장(업셀·크로스셀·단가인상) = Expansion
- 다운그레이드(축소)          = Contraction
- 이탈(해지)                  = Churn

GRR = (Starting − Contraction − Churn) / Starting × 100      # 확장 제외, ≤100%
NRR = (Starting + Expansion − Contraction − Churn) / Starting × 100   # 확장 포함, >100% 가능
```
- **신규 고객은 분자·분모 모두 제외** — 기존 코호트의 유지·확장만 측정(신규 매출을 섞으면 리텐션이 아니라 성장률이 됨. 최빈 실수).
- **GRR과 NRR을 나란히 본다**: NRR 120%인데 GRR 80%면 = 소수 대형 고객 확장이 대량 logo churn을 가리는 중(위험). NRR만 보면 못 봄(불변 규칙).

### 벤치마크(방향성 — 정확 수치는 evidence.md, "확인 필요")
| 세그먼트 | NRR 경향 | 메모 |
|---|---|---|
| Enterprise(ACV>$100K) | 가장 높음(확장 여지 큼) | ~118% 흔히 인용(1차 출처 확인 필요) |
| Mid-market | 중간 | ~108% |
| SMB(<$25K) | 낮음, 100% 미만 흔함 | 구조적으로 축소 경향 |
- 사기업 B2B SaaS 중앙값: NRR ~101%, GRR ~88%(ChartMogul 1차, 2024). Stripe 중앙값 NRR ~102%/GRR ~91%.
- ⚠️ "좋은 NRR = 몇 %"는 **세그·단계·리포트판별로 다름** — 자사 세그먼트 비교군을 명시하고 절대치 단정 금지.

## 2. 헬스스코어 설계 (표준 공식 없음 — 가설→검증→반복)

### 설계 절차
1. **가치 동인 정의**: "이 고객이 우리 제품으로 얻어야 하는 결과(desired outcome)"에서 역산 → 그걸 예고하는 관측 신호를 고른다.
2. **신호 4~6개 선정**(과다 금지). 흔한 축:
   - **사용(Usage)**: 폭(핵심기능 채택 수)·깊이·빈도(WAU/MAU), 추세(증감).
   - **성과(Outcome)**: 약속한 결과 지표 달성 여부(예: "야근 제거" → 자동화 실행 횟수).
   - **관계(Relationship)**: 챔피언 존재·멀티스레딩(의사결정자 수), 임원 참여.
   - **지원(Support)**: 심각 티켓 수·추세, 에스컬레이션.
   - **결제(Commercial)**: 연체, 계약 규모 변화.
   - (선택) **감정(Sentiment)**: NPS/CSAT, CSM 정성 평가.
3. **가중치 배정** — 예시(Gainsight 블로그): 사용 40 / 지원 25 / 감정 20 / 임원참여 15. ⚠️ **예시일 뿐**. 자사에선 "무엇이 실제로 갱신·이탈을 예측했는지"로 조정.
4. **구간(threshold)**: R/Y/G 또는 0–100. 각 신호별 임계값을 명시(왜 그 점수인지 재현 가능하게 — 감점 사유 추적).
5. **검증·반복**: 첫 스코어는 **가설**. 3~6개월 후 "🔴로 찍힌 계정이 실제로 이탈했나 / 🟢가 갱신했나"로 예측력 측정 → 신호·가중치 재조정.

### 헬스스코어 안티패턴
- ❌ 로그인 여부 하나로 헬스(단일 신호) → 사용 깊이·성과·관계를 놓침.
- ❌ 남의 공식 복사 → 자사 가치 동인과 무관.
- ❌ 만든 뒤 검증 안 함 → 예측력 없는 장식.
- ❌ 정성(CSM 감) 완전 배제 → 데이터가 못 잡는 조기 신호(챔피언 이직 소문 등) 누락.

## 3. 온보딩 · 도입(Time-to-Value) 단계

목표: **가장 빠른 첫 가치(TTV)** → 도입 정착 → 확장 기반.
1. **킥오프**: desired outcome 문서화(측정 가능한 형태로), 성공 기준·챔피언·타임라인 합의.
2. **초기 설정·통합**: 가치를 막는 기술 장벽 제거(데이터 연동·SSO 등)를 최우선.
3. **첫 가치(First Value)**: 작지만 확실한 win 1개를 빠르게 — TTV 단축이 갱신의 선행지표.
4. **핵심 기능 채택**: desired outcome에 직결된 기능부터 교육·정착(전체 기능 나열 금지).
5. **정착·확산**: 사용을 팀·부서로 넓혀 스티키니스 확보 → 확장의 토대.
- 지표: TTV(첫 가치까지 일수), 온보딩 완료율, 핵심기능 채택률, 초기 30/60/90일 활성.

## 4. 이탈(Churn) 리스크 플레이북 — 경보→진단→개입→에스컬레이션

### 경보(Trigger)
헬스 🔴 전환, WAU 급락(예: 3개월 -30%↑), 핵심기능 사용 0, 챔피언 이직, 심각 티켓 급증, 결제 연체, QBR 노쇼, 갱신 D-120 진입.

### 진단(사유 분류 — 플레이가 갈린다)
1. **가치 미실현**(안 씀/성과 미달) — 가장 흔함.
2. **관계 공백**(챔피언 이직·단일 스레드 의존).
3. **외부 요인**(예산 삭감·조직 변화·인수).
4. **경쟁 이탈**(대체재로 이동).

### 개입(사유별)
- 가치 미실현 → desired outcome 원점 재확인 → 미사용 핵심기능 원인 진단(설정? 교육? 워크플로 불일치?) → **가치 재실현 30일 플랜 + 빠른 win 1개**.
- 관계 공백 → 후임 의사결정자 즉시 식별·재온보딩, **멀티스레딩**(챔피언 3명 이상 목표).
- 외부 요인 → 달성 성과를 정량화한 **비용 정당화 자료**, 다운그레이드라도 관계 유지(미래 재확장 여지).
- 경쟁 이탈 → 차별화 가치·전환 비용 재확인, 이탈 원인 정직 수집(회복 불가여도 학습).

### 에스컬레이션
고가치·고위험이면 CSM 단독 아님 → 경영진 스폰서 매칭(exec-to-exec), 제품팀(기능 갭)·영업(상업 조건) 협업. **막판 할인은 원인 미해결이면 다음 해 재이탈** — 진단 먼저.

## 5. 확장(Upsell / Cross-sell) 트리거

**전제: 가치 입증 후에만.** 가치 전 업셀은 반발·평판 손상(안티패턴).
- **사용 한도 근접**: 시트·사용량·스토리지 소진 → 상향(자연스러운 확장).
- **높은 도입·성과 달성**: desired outcome 달성 + 사용 확산 → 인접 팀·부서 확장.
- **새 use case 발견**: QBR에서 미충족 니즈 포착 → 크로스셀(추가 모듈).
- **조직 성장**: 고객사 인원·매출 증가 → 자연 확장.
- 규칙: 헬스 🟢 + 성과 입증이 확장의 게이트. 🔴/🟡 계정엔 확장 대신 구하기·가치 재실현.

## 6. CS 세그멘테이션 (자원 배분)

| 모델 | 대상 | 방식 |
|---|---|---|
| **하이터치(High-touch)** | 고 ACV·전략·고위험 | CSM 1:소수, 직접 QBR·계정 플랜·구하기 플레이 |
| **테크터치(Tech-touch/Low-touch)** | 중간 규모·다수 | 1:다수, 트리거 기반 자동 개입 + 선택적 접촉 |
| **디지털(Digital/Pooled)** | 소액·롱테일 | 1:대량, 인앱 가이드·이메일·KB·자동화, CSM 풀(pooled) 큐 |
- 원칙: **CSM 시간은 유한** → 위험×가치로 우선순위. "전부 하이터치"는 확장 불가.
- 세그 이동: 소액이 성장하면 상위 세그로 승격, 저활성 대형은 위험 큐로.

## 7. 흔한 실수 (요약)
1. NRR만 보고 GRR 무시 → 대형 확장이 logo churn 은폐(불변).
2. 신규 매출을 리텐션 계산에 섞음 → 성장률과 혼동.
3. 헬스스코어를 남의 공식 복사·검증 없이 사용 → 예측력 0.
4. 만족(CSAT) = 성공으로 착각 → 친절한데 가치 못 얻어 이탈.
5. 갱신 D-30에야 첫 헬스 체크 → 이미 결정된 이탈.
6. 가치 입증 전 업셀 → 반발.
7. 전 계정 동일 대우(전부 하이터치 or 전부 방치) → 자원 낭비 / 위험 방치.
8. 이탈 사유 진단 없이 할인으로 봉합 → 다음 해 재이탈.
