## 1. 지표 트리 (Metric Tree)

**목적**: "무엇을 움직이면 노스스타가 움직이나"를 인과적으로 분해해, 팀이 직접 손댈 수 있는 선행지표(input)까지 내려가는 것.

### 구조
```
노스스타(NSM, 후행/lagging)      ← 고객 가치의 대리지표, 팀이 직접 못 움직임
  ├─ 입력 동인 A (leading)       ← 팀이 직접 움직일 수 있음
  │    ├─ 서브지표 A1
  │    └─ 서브지표 A2
  ├─ 입력 동인 B
  └─ 입력 동인 C
```

### 분해 원칙
- **곱/합 관계로 명시**: NSM = 사용자 수 × 사용자당 활동 빈도 × 활동당 가치 처럼 **수식으로** 쪼갠다. "느낌상 관련"이 아니라 산술적으로 노스스타에 합쳐져야 한다.
- **각 입력은 (a) 노스스타를 실제로 움직이고 (b) 팀이 영향을 줄 수 있어야** 한다. 둘 중 하나라도 아니면 트리에서 뺀다.
- **후행 vs 선행**: 노스스타(매출·리텐션 등)는 늦게 반응한다. OKR·주간 트래킹은 **선행 입력지표**로 잡아야 조기 조향이 된다.
- **MECE 지향**: 입력 동인들이 겹치지 않고(상호배타) 빠짐없이(전체포괄) 노스스타를 설명하도록.

### 노스스타 선정 체크
- 고객이 얻는 **핵심 가치**를 반영하는가? (매출 그 자체는 회사 가치이지 고객 가치가 아님 → 대개 나쁜 NSM)
- 예: Airbnb=예약된 숙박 밤 수, Spotify=청취 시간, Slack=메시지를 주고받은 팀 수. (예시는 통념·확인 필요)
- ⚠️ **단일 지표 맹신 금지**: NSM 하나가 가드레일 없이 최적화되면 부작용(예: "체류시간"만 올리려다 UX 악화). 반드시 **가드레일 지표**(품질·이탈·CS)와 병행.

## 2. 퍼널 분석 (Funnel)

### 단계 정의 (뼈대: AARRR)
Acquisition(유입) → Activation(첫 가치 경험, "aha moment") → Retention(재방문) → Referral(추천) → Revenue(수익). 자사 제품 흐름에 맞게 커스텀 단계로 재정의.

### 분석 절차
1. **단계 정의를 먼저 명문화** — 각 단계의 "진입 이벤트"를 정확히(예: Activation = 가입 후 첫 프로젝트 생성). 정의 없으면 전환율이 무의미.
2. **단계별 전환율 + 드롭오프** — 각 단계→다음 단계 %와, 어디서 가장 많이 이탈하는지.
3. **가장 큰 드롭오프 = 최우선 개선 후보** (제약이론적 사고: 병목 한 곳이 전체 산출을 결정).
4. **세그먼트 분해** — 전체 퍼널은 심슨의 역설을 숨긴다(evidence §3). 채널·기기·신규/기존·지역별로 쪼개 진짜 원인 찾기.
5. **코호트로 시간축 통제** — 6월 가입자와 7월 가입자를 섞으면 안 됨. 가입 시점 코호트별로 퍼널을 봐야 개선의 효과가 보인다.

### 흔한 함정
- **시간창(window) 미정의**: "전환율"이 1일 내인지 30일 내인지 안 정하면 비교 불가.
- **분모 오염**: 봇·내부 트래픽·테스트 계정 포함 → 상단 이탈이 과장됨.
- **생존 단계만 보기**: 이미 통과한 유저만 분석하면 왜 떨어졌는지 못 봄(생존편향, §7).

## 3. 리텐션 곡선 (Retention)

### 세 가지 정의 (혼용 절대 금지 — Amplitude Docs 기준)
| 유형 | 정의 | 언제 쓰나 |
|---|---|---|
| **N-day retention** | N일째에 **정확히** 활동한 사용자 % | 매일 쓰는 제품(게임·SNS). 엄격. |
| **Unbounded(rolling) retention** | N일째 **또는 그 이후** 언젠가 돌아온 % | 사용 주기가 불규칙한 제품. 관대. |
| **Bracket(range) retention** | 기간 구간(예: 1~7일)으로 묶어 측정 | 노이즈 감소, 큰 추세 파악. |
> 출처: https://amplitude.com/docs/analytics/charts/retention-analysis/retention-analysis-interpret

같은 제품도 어떤 정의를 쓰냐에 따라 리텐션이 2~3배 차이 난다. **정의를 먼저 고정**하고 항상 같은 정의로 비교.

### 곡선 읽기
- **가파른 초기 하락 → 평탄화(flattening/plateau)** 가 건강한 모양. **곡선이 평평해지는 것 = 제품이 가질 수 있는 가장 강한 신호** — 일부 사용자군이 습관을 형성해 지속적으로 가치를 얻는다는 뜻(Amplitude).
- **평탄화 없이 0으로 수렴** = 반복 가치를 못 주는 제품. 신규 유입으로 메우는 "밑빠진 독"(leaky bucket).
- **미소 곡선(smile/upward)**: 후반부가 다시 올라가면 리인게이지먼트/코호트 성숙 신호(드묾).
- **평탄화 높이(=asymptote)**가 장기 사업성을 좌우. 곡선 초반 기울기보다 **어디서 멈추는가**가 더 중요.

### 실무 팁
- **코호트 크기 표기**: 후반 데이터는 표본이 작아 튄다 — n을 항상 병기, 소표본 구간은 해석 자제.
- **적정 이벤트 선택**: "로그인"이 아니라 "핵심 가치 이벤트"(예: 결제, 콘텐츠 소비) 기준 리텐션이 더 유의미.

## 4. 대시보드 기획

**제1원칙: 대시보드는 결정을 위한 도구다.** "이 숫자가 바뀌면 우리가 무엇을 다르게 할까"에 답 못 하는 위젯은 뺀다.

### 청중별 계층
| 청중 | 목적 | 지표 |
|---|---|---|
| 경영진 | 전략 조향 | 노스스타 + 소수 후행 KPI, 목표·추세 대비 |
| 팀 리드 | 주간 운영 | 담당 입력 동인, 이상 알림 |
| 실무자 | 진단·드릴다운 | 세부 세그먼트, 원인 분석 |

### 설계 규칙
- **위계**: 상단=노스스타/핵심, 하단=드릴다운. 눈이 위→아래로 읽는 순서 = 중요도 순.
- **맥락 필수**: 모든 숫자에 (a) 추세 (b) 목표/벤치마크 (c) 세그먼트 중 최소 하나. 맥락 없는 단일 숫자 금지(SKILL 안티패턴 5).
- **차트 더미 금지**: "가능한 모든 차트"가 아니라 "이 결정에 필요한 차트"만. 위젯 하나마다 "어떤 결정을 돕는가"를 답할 수 있어야.
- **이상 알림 > 상시 응시**: 사람이 대시보드를 매일 쳐다볼 순 없다. 임계 이탈 시 알림(anomaly detection)이 실제 행동을 만든다.
- **정의 툴팁**: 각 지표 옆에 정의 링크(SSOT). "활성 사용자"가 뭔지 hover로 확인 가능하게.

## 5. 데이터 스토리텔링 (Knaflic)

### 절차
1. **맥락**: 청중이 누구고, 무슨 결정을 하며, 그들이 이미 아는 것은? "So what?"(그래서 뭐)을 한 문장으로.
2. **적절한 시각 선택**: 시계열=선, 구성=막대, 상관=산점도. **파이/3D/이중축은 대개 안티패턴**.
3. **clutter 제거**: 테두리·격자선·불필요 눈금·범례 삭제 → 데이터 라벨 직접 부착. Gestalt 원리(근접·유사·둘러싸기 등)로 정리(evidence §1).
4. **주의 집중**: preattentive attribute(색·굵기·크기)로 **핵심 하나만** 강조. 나머지는 회색으로 후경화.
5. **서사 구조**: 배경 → 긴장(문제) → 해결(권고). 결론(권고)을 먼저 던지고 근거로 뒷받침(BLUF, Bottom Line Up Front).

### 출력 순서 (의사결정자용)
```
핵심 메시지(So what / 권고) → 근거(핵심 차트 1~2개) → 한계·확인 필요
```
raw 표·차트만 던지지 말 것 — "그래서 뭘 하라는 건데?"에 답이 나와야 행동이 생긴다.

## 6. 상관 ≠ 인과 판별

### 상관만 봤을 때 의심할 것
1. **교란변수(confounder)**: A와 B 둘 다에 영향 주는 제3변수 C. (심슨의 역설, evidence §3)
2. **역인과**: B가 A를 일으키는데 A→B로 착각.
3. **우연/허위상관**: 표본이 작거나 다중검정으로 우연히 상관(Vigen 반례집).
4. **선택편향**: 특정 그룹만 데이터에 들어와 상관이 조작됨.

### 인과 주장에 필요한 증거 (사다리 오름차순)
- **A/B 테스트(RCT)** — 가장 강함. 무작위 배정으로 교란 제거. 가능하면 1순위.
- **자연실험 / 준실험** — 정책 변경·시점 차이 등 외생 충격 활용(DiD, RDD, IV).
- **메커니즘 + 통제** — 실험 불가 시, 인과 경로를 논증하고 관찰 가능한 교란을 통제. **한계를 반드시 명시**.
- ⚠️ 그래도 관찰 데이터의 인과 추론은 항상 "확인 필요" 꼬리표. 강한 권고엔 강한 증거를.

### 실무 규칙
- 상관을 버리지 말 것 — **가설 생성기**로 쓴다. "A와 B가 같이 움직인다 → 왜인지 실험으로 검증하자."
- 인과를 단정하지 말 것 — 보고서에 "상관 관찰됨, 인과는 미검증"을 명시.

## 7. 지표 정의 문서화 (SSOT)

각 핵심 지표에 대해 명문화:
- **이름·한 줄 정의**: "월간 활성 사용자(MAU) = 해당 월 1회 이상 핵심 이벤트를 발생시킨 고유 사용자."
- **포함/제외**: 봇·내부 계정·환불·테스트 제외 여부.
- **시간창·타임존**: 월 경계 기준, UTC/KST.
- **소스 테이블·계산 로직**: 어느 데이터에서, 어떻게.
- **소유자**: 정의 분쟁 시 최종 권위자.
> "단일 진실 원천(SSOT)"은 **물리적 단일 DB가 아니라 지표별 단일 권위 정의**(거버넌스). 정의가 갈리면 같은 대시보드로 다른 결론이 난다.

## 8. 흔한 실수 카탈로그

| 실수 | 무엇 | 방어 |
|---|---|---|
| **Vanity metric** | 늘 우상향, 결정 못 바꿈(누적 가입자) | "이 숫자로 뭘 다르게 하나?" 물어라. 비율·코호트로 대체 |
| **심슨의 역설** | 집계 방향 ≠ 세그먼트 방향(Berkeley 1973) | 항상 세그먼트 분해로 교차검증 |
| **생존편향** | 살아남은 표본만 봄(이탈자 누락) | 이탈·실패 코호트도 분석 대상에 |
| **p-hacking / 다중검정** | 여러 지표·세그먼트를 뒤져 우연한 유의성 발견 | 가설 사전 등록, 다중검정 보정, 효과크기 병기 |
| **평균의 함정** | 평균이 분포를 숨김(소수 고래가 평균 견인) | 중앙값·분위수·분포 함께 |
| **체리피킹 기간** | 유리한 시작·끝점 선택 | 기간을 결정과 무관하게 고정, 전체 추세 공개 |
| **잘린 축·왜곡 비율** | 시각적으로 차이 과장 | 0 기준선, 정직한 축(무결성 게이트) |
| **분모 미고정** | 전환율 시간창·모수 불일치 | 정의 문서화(§7) |
