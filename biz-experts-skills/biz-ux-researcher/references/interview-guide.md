# 인터뷰·사용성 테스트 실전 가이드 — 스크리너·스크립트·중립질문·동의

> 복사·편집해 쓰는 템플릿. 원칙: 유도 차단·행동 우선·동의·프라이버시(→ `evidence.md` §4·§6).

---

## 1. 스크리너 설계 (타깃을 정확히 거른다)

목적: 연구 대상이 아닌 사람을 걸러 데이터 품질↑·편향↓. **정답이 드러나지 않게** 설계(참가비 노리는 거짓응답 방지).

원칙:
- 자격 조건을 질문에 노출하지 말 것. ❌ "주 3회 이상 쓰시죠? (예/아니오)" → ✅ "지난 한 달간 [작업]을 몇 번 하셨나요? [0 / 1–2 / 3–5 / 6+]"
- 행동·빈도로 거른다(자기규정 X). "스스로를 얼리어답터라 생각하나요?" 같은 자기규정 항목은 신뢰 낮음.
- **쿼터**: 세그먼트별 인원 배분(신규/기존/이탈), 인구통계 다양성.
- **경쟁사·업계 종사자·직전 참여자 제외** 문항 포함.

예시 스크리너:
```
Q1. 지난 30일간 [제품/유사 서비스]를 사용한 적 있나요? [매일/주 몇 회/월 1–2회/없음]
    → "없음"=비대상 제외(신규 연구면 반대로 "있음"=제외)
Q2. 지난 3개월간 [핵심 과업]을 직접 해보셨나요? [예/아니오]  → 아니오=제외
Q3. 본인 또는 가족이 UX/마케팅/[경쟁사] 업계 종사자인가요? [예/아니오] → 예=제외
Q4. (쿼터) 연령대 / 사용 기간 → 세그먼트 균형 맞춤
```

## 2. 인터뷰 스크립트 구조

1. **오프닝(라포·고지)**: 목적·소요시간·녹화 동의·"정답 없음, 솔직히"·철회권. → §4 동의.
2. **워밍업(맥락)**: 배경·최근 관련 경험(개방형). "최근에 [과업]을 했던 때 얘기해 주세요."
3. **본론(과거 행동 중심)**: 실제 있었던 일 → 그때 무엇을·왜. 가상·미래·의견은 후순위. 5 Whys로 표면 답 아래 동기 탐색.
4. **딥다이브(구체 사례)**: "가장 최근/가장 불편했던 그 사건을 처음부터 끝까지" — 일반론 대신 구체.
5. **랩업**: "제가 안 물어봤는데 중요한 게 있을까요?"·감사·인센티브 안내.

프로빙(중립 심화): "조금 더 말씀해 주세요" / "그때 어떤 생각이 드셨어요?" / "왜 그렇게 하셨어요?" / (침묵을 견딘다).

## 3. 사용성 테스트 진행 스크립트

원칙: **시키고 관찰(말하게 하지 않는다)**. 진행자는 답·힌트·반응을 주지 않는다.

```
[고지] "제품을 테스트하는 거지 당신을 테스트하는 게 아니에요. 정답·오답 없습니다.
        생각을 소리 내어 말해 주세요(thinking-aloud). 제가 도와드리지 못해도
        평소처럼 하시면 됩니다."
[과업] "이 서비스에 가입해보세요."  (❌ "이 편리한 가입을 해보세요")
[막힐 때] "지금 무슨 생각을 하고 계세요?" / "다음에 뭘 하려고 하세요?"
          (❌ "여기 버튼 눌러보세요" / "이거 편하죠?")
[요청 회피] 참가자가 "이거 맞아요?" → "당신이라면 어떻게 하실 것 같아요?"
[사후] "방금 그 단계 어땠나요?" (❌ "방금 단계 편리하지 않았나요?")
```
과업·문항은 **무작위 순서(rotation)** 로 앵커링·순서 편향 차단.

## 4. 중립 질문뱅크 (유도 → 중립 치환)

| 유도(❌) | 중립(✅) |
|---|---|
| "이 새 기능 편리하지 않나요?" | "이 기능을 써본 경험은 어땠나요?" |
| "디자인과 속도에 만족하세요?"(이중) | "디자인은 어땠나요?" + "속도는 어땠나요?"(분리) |
| "이거 쓰실 건가요?"(미래) | "최근에 비슷한 걸 마지막으로 쓴 게 언제인가요?"(과거 행동) |
| "얼마면 사시겠어요?"(지불의사) | "지금 이걸 위해 무엇을(돈·시간·도구) 쓰고 계세요?" |
| "왜 이 나쁜 디자인이 싫으세요?"(전제) | "이 화면에서 무엇이 눈에 들어오나요?" |
| "대부분 이걸 좋아하던데 어떠세요?"(사회적) | "솔직히 불편했던 점이 있다면요?" |

빈도 척도(정량, 열린 회상 대신 선택): "이 작업을 얼마나 자주 하나요? [매일/주1–2/월1/거의안함]".

## 5. 동의(consent) 템플릿

```
[연구 동의 고지]
- 목적: [무엇을 알아보려는 연구인지 1줄]
- 소요: 약 [X]분
- 녹화: 화면/음성/영상을 [분석 목적으로만] 녹화합니다. [보관기한] 후 파기.
- 데이터: 개인 식별정보는 분리·익명 처리되며 보고서에 실명 노출 없음.
- 자발성: 언제든 중단·특정 질문 거부 가능하며 불이익 없습니다.
- 인센티브: [금액/방식]
□ 위 내용을 이해했고 참여·녹화에 동의합니다.   서명/구두확인: ______  일자: ______
(미성년·취약군: 보호자 동의 별도)
```

## 6. 진행 전 체크리스트

- [ ] 리서치 질문 1문장 + "이걸 알면 어떤 결정이 바뀌나" 적음
- [ ] 방법이 질문 축(태도/행동·정성/정량)과 맞나(→ `methods-map.md`)
- [ ] 표본·쿼터·스크리너 완성, 편의표본 아님(이탈·신규·비사용자 포함)
- [ ] 질문에 유도·이중·미래가정 없음(§4로 점검), 순서 rotation
- [ ] 동의·녹화·PII 처리 계획, 취약군 보호
- [ ] 파일럿 1명으로 스크립트·과업 리허설
- [ ] 합성 계획: 코딩→테마→인사이트, 반증 탐색 의무, (다인이면) 교차 코딩

## 7. 합성·리포팅 체크리스트

- [ ] 원자료 태깅 → 어피니티로 테마화 → 인사이트(패턴+이유) → 권고(행동)
- [ ] 각 인사이트에 근거(관찰 n/로그/설문)·신뢰수준·한계 병기
- [ ] 정성은 "패턴", 정량은 "%±마진" — 정성 %일반화 금지
- [ ] 반증 프롬프트: "가설과 어긋나는 발언이 있었나? 없으면 확증편향 의심"
- [ ] 심각도(빈도×영향×지속)×수정비용으로 우선순위
- [ ] 경영진용은 결정·권고·리스크 먼저(역피라미드)
