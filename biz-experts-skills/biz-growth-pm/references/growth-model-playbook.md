# growth-model-playbook — 성장 모델·PLG·North Star·실험 우선순위 실무판

> 그로스 PM이 실제로 손을 움직이는 순서대로 정리한 실무 플레이북. evidence.md가 "무엇이 검증된 사실인가"라면, 이 파일은 "그래서 어떻게 만드나"이다. 수치·벤치마크는 회사별이며 절대 기준 아님("확인 필요").

## 1. 성장 모델 만들기 (Growth Model)

성장 모델 = **우리 성장을 입력 변수의 수식으로 표현한 것**. 목적은 예측이 아니라 **레버 우선순위 결정**이다. "이 변수를 X% 올리면 상단 지표가 얼마 움직이나"를 시뮬레이션해 가장 큰 레버부터 실험한다.

### 1-1. 비즈니스 모델별 기본 방정식

| 모델 | 성장 방정식(예) | 지배 레버 |
|---|---|---|
| **SaaS(구독)** | 기말 MRR = 기초 MRR + 신규(방문×가입전환×활성화×유료전환×ARPA) + 확장(업셀·시트↑) − 이탈(로고×ARPA) | 활성화·확장·이탈 |
| **마켓플레이스** | GMV = 활성 구매자 × 구매 빈도 × 평균 주문액 (공급 측: 활성 공급자 × 리스팅 × 전환) | 유동성(공급↔수요 매칭) |
| **광고형(콘텐츠)** | 매출 = MAU × 세션/유저 × 페이지/세션 × RPM(1000뷰당 매출) | 참여 깊이·빈도 |
| **트랜잭션/이커머스** | 매출 = 방문 × 구매전환 × AOV × 재구매율 | 전환·재구매 |
| **PLG(프리미엄)** | 유료 = 가입 × 활성화 × 습관형성 × PQL도달 × PQL→유료전환 | 활성화·PQL 전환 |

> 원리(Balfour/Reforge): 성장은 **신규 + 기존(유지·확장) − 이탈**의 합. 세 항 모두 곱셈 사슬이라 어느 한 마디가 낮으면 전체가 깎인다(예: 활성화 20%면 그 앞 획득을 아무리 부어도 80%가 샌다).

### 1-2. 모델 세우는 6단계
1. **상단 지표(NSM 후보) 고정** — 가치 교환을 대표하는 단일 출력(§3).
2. **입력 변수로 분해** — 위 방정식처럼 곱/합으로. 각 변수는 측정 가능해야.
3. **현재 baseline 채우기** — 각 변수의 실제 값(추정이면 표기).
4. **민감도 분석** — 변수마다 "±10% 시 상단 영향"을 계산 → 지배 레버 식별.
5. **병목 판정** — 보통 활성화·리텐션이 가장 큰 레버(밑 빠진 독이면 상단 획득은 무의미).
6. **실험 큐로 연결** — 지배 레버에 실험 가설을 매핑(§4).

### 1-3. 흔한 실수
- 변수를 너무 잘게 쪼개 손댈 수 없게 만든다 → 3~7개 레버로.
- baseline 없이 모델만 예쁘게 → 숫자 없는 모델은 우선순위를 못 정함.
- 매출을 상단에 두고 역산 → 매출은 후행. 선행 가치 행동을 상단에.

## 2. PLG · PQL · 활성화

### 2-1. PLG 성립 조건 (아무 제품이나 PLG 안 됨)
- **셀프서브로 가치 도달 가능**(영업 없이 첫 아하 경험) · **짧은 TTV(time-to-value)** · **개인/팀 단위 진입 후 조직 확산** · **사용량이 늘수록 가치·전환 압력↑**. 이 조건이 안 되면 sales-led가 맞다(억지 PLG 금지).

### 2-2. 활성화(Activation) 정의법
활성화 = **첫 가치 경험(aha)에 도달한 상태**. "가입"이 아니다.
1. **후보 이벤트 나열** — 온보딩 중 사용자가 할 수 있는 행동들.
2. **리텐션 상관 분석** — 각 이벤트를 한/안 한 코호트의 N일 리텐션 차이 비교(가장 크게 벌어지는 행동이 aha 후보).
3. **"마법의 수" 탐색** — 그 행동을 **얼마나(횟수)·언제까지(기간)** 하면 잔존하는가. 
   - 예: Slack "팀 누적 2,000 메시지 → 93% 잔존"(evidence §5, First Round 1차). Facebook "10일 내 7친구"는 **널리 인용되나 회사 공식 1차 확인 어려움 → 패턴 예시로만, 베끼기 금지**.
4. **상관 ≠ 인과 주의** — 헤비유저라서 그 행동도 한 것일 수 있음. 온보딩을 그 행동으로 유도해보고 리텐션이 실제로 오르는지 A/B로 검증(→ biz-product-analytics 안티패턴 4).

### 2-3. PQL(Product-Qualified Lead)
- **정의**: 제품을 써서 가치를 이미 경험한 계정/사용자 — MQL(마케팅 반응)·SQL(영업 판단)과 달리 **실제 사용 신호** 기반.
- **PQL 신호 예**: 핵심 기능 N회 사용, 팀원 초대, 사용량 한도(free) 근접, 협업 문서 생성 등.
- **PQA(Product-Qualified Account)**: B2B에서 개인이 아닌 **계정 단위** 신호(한 조직 내 여러 활성 사용자) — 확장·영업 인입 판단에 사용.
- **운영**: PQL 점수 모델(신호별 가중) → 임계 도달 시 (a) 인앱 업셀 트리거 또는 (b) 영업 인입(hand-raise). 다크패턴(허위 한도 경고 등)으로 PQL 조작 금지 — 단기 전환↑, 신뢰↓.

## 3. North Star Metric 설계

### 3-1. 좋은 NSM의 3요건
1. **가치를 대표** — 사용자가 실제 얻는 가치(nights booked, messages sent)를 담는다.
2. **선행성** — 매출보다 앞서 움직인다(후행 매출은 NSM 부적합).
3. **분해 가능** — 입력 지표 3~5개로 쪼개진다(§3-2).

### 3-2. 입력 지표 4축 (Amplitude, 검증)
NSM을 못 움직이니 그 밑 **입력 레버 3~5개**를 당긴다:
- **Breadth(폭)**: 몇 명이 — 신규 획득 + 재활성.
- **Depth(깊이)**: 얼마나 깊이 — 사용자당 세션·행동 수.
- **Frequency(빈도)**: 얼마나 자주 — 재방문 주기, DAU/MAU stickiness.
- **Efficiency(효율)**: 얼마나 빨리 — TTV, 마찰 감소, 활성화율.
> 검증 예: Airbnb=nights booked, Facebook=DAU. (evidence §6)

### 3-3. 안티패턴
- 여러 개의 NSM(초점 분산) → 하나. 부서별은 입력 지표로 배분.
- NSM=매출·MAU 같은 후행/허영 지표 → 가치 선행 행동으로 교체.
- NSM만 보고 입력 지표 없이 → 팀이 뭘 당길지 모름.

## 4. 성장 루프 & 실험 우선순위

### 4-1. 루프 3종 (Balfour: "Loops are the new funnels")
- **바이럴/추천 루프**: 사용 → 초대/공유 → 신규 → 다시 사용. (예: Dropbox 양면 추천, evidence §5)
- **콘텐츠 루프**: 사용자 생성 콘텐츠 → SEO/공유 유입 → 가입 → 더 많은 콘텐츠.
- **페이드/유료 루프**: 매출 → 광고 재투자 → 획득(단위경제가 받쳐야 지속).
> 루프는 **출력이 입력으로 재투입**돼 복리로 는다. 깔때기는 한 번 흐르고 샌다. 단, **루프도 리텐션이 받쳐야** 돈다.

### 4-2. 실험 우선순위 (ICE / RICE, 검증)
| | 공식 | 창안 | 언제 |
|---|---|---|---|
| **ICE** | (Impact+Confidence+Ease)/3, 각 1~10 | Sean Ellis (LogMeIn·Dropbox) | 초기·고속(주 다건), 단순 |
| **RICE** | (Reach×Impact×Confidence)/Effort | Sean McBride (Intercom) | 도달 인원이 중요, 세그먼트 상이, 스프린트당 20+ |

- Impact/Reach는 **성장 모델의 민감도 분석**에서 나온다(§1-2) — 지배 레버를 건드리는 실험이 Impact 높음.
- Confidence 낮음 = "먼저 싸게 검증(정성 인터뷰·페인티드도어)"하라는 신호이지 배제 사유 아님.
- 점수는 상대 순위 도구 — 절대값 맹신 금지.

### 4-3. 실험 실행 규율
- 가설·성공지표·표본 크기·기간을 **사전 등록**(peeking·중간 종료 금지 → 거짓 양성).
- 성장 모델 변수로 결과 해석: "전환 +3%"가 상단 NSM에 얼마 기여했나까지.
- 실패 실험도 학습으로 기록(왜 안 됐나 → 다음 가설).
> 실험 통계 함정(SRM·다중비교·peeking)은 (→ biz-product-analytics), 권위 앵커 Kohavi et al. *Trustworthy Online Controlled Experiments*(2020).

## 5. 그로스 PM 30-60-90 (신규 착수 시)
- **0~30일**: 성장 모델 초안 + baseline 수집 + NSM 후보 합의 + 활성화 정의 데이터 분석.
- **30~60일**: 지배 레버 확정 → 실험 큐(ICE/RICE) → 첫 A/B 2~3건 사전등록·실행.
- **60~90일**: 결과 복기 → 모델 갱신 → 지속 루프 1개 제품화 착수(콘텐츠/추천/네트워크).
