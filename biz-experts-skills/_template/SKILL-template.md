## 작성 원칙 (dev-experts에서 흡수)

1. **Claude는 이미 똑똑하다** — LLM이 아는 일반론은 쓰지 않는다. "그 거장이 실제 가르치는 기준·함정"과 정량/프레임 기준만.
2. **본문 500줄 미만** — 넘으면 references/로 분리. 참조는 1단계만.
3. **description은 3인칭** + what + when(트리거 한·영 10+) + SKIP. 1024자 이내.
4. **기본값 1개 + escape hatch** — "A도 되고 B도 되고" 금지. 권장 1개 + 벗어날 조건.
5. **시한성 정보 금지** — 버전 라벨 + "플랫폼 정책은 공식 문서 우선".
6. **eval 먼저** — 본문 전에 "이 스킬이 없으면 Claude가 틀리는 시나리오 3개"를 적고 그 갭만 메운다.
7. **biz 특수 4종**: ① 거장 앵커 명시 ② 산출물에 "가설·성공지표·언제 확인"(사후 채점) ③ 윤리 게이트 해당 직무(마케팅·HR·가격·투자유치·리서치)는 "하지 말 것" 1줄+ ④ 프레임워크 = 정량 기준의 자리(RICE·AARRR·HEART·JTBD 등) + 가능시 벤치마크 수치.
8. **scripts는 계산 가능한 곳만** (python 3.10 표준 라이브러리, 인자 없이 데모, 출력 ASCII만, 작성 즉시 실행 검증). RICE/ICE 스코어, CAC·LTV, 번레이트, A/B 표본 크기 등.
