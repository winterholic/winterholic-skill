# search-intent-and-content — 검색 의도·토픽 클러스터·E-E-A-T 신뢰 체크리스트

> 출처: Broder(2002) ACM SIGIR Forum · Google QRG · HubSpot pillar-cluster(벤더 방법론) · 2026-07-01 검증.
> ⚠️ **이 문서의 어떤 항목도 "공식 Google 랭킹 팩터"가 아니다.** E-E-A-T는 rater 평가 프레임(랭킹 점수 아님), 토픽 클러스터는 벤더(HubSpot) 방법론, 의도 4구분 중 commercial은 업계 추가다. "검색이 보상하려는 목표에 부합하는 콘텐츠를 만드는 실무 규율"이지 알고리즘 우회법이 아니다.
> 기술 SEO 항목은 `technical-seo-checklist.md`. 근거·지위 확인은 `evidence.md`.

## 1. 검색 의도 3종 원전 + 업계 4구분

**원전**: Broder(2002), "A Taxonomy of Web Search," ACM SIGIR Forum 36(2):3–10.
공식 3종: **Navigational / Informational / Transactional**
https://sigir.org/files/forum/F2002/broder.pdf

⚠️ **"Commercial Investigation(상업조사형)"** 은 Broder·Google 공식이 아닌 SEO 업계 추가 개념이다. 실무에서 이 4구분을 쓸 때는 항상 "업계 분류, 공식 아님"을 명시해야 한다.

## 2. 의도 → 콘텐츠 포맷 매핑표

| 의도 유형 | 지위 | 사용자 상태·질문 예시 | 권장 콘텐츠 포맷 | 흔한 안티패턴 |
|---|---|---|---|---|
| **Informational** (정보형) | Broder 공식 | "X란?", "어떻게 하나요", "Y의 원인" | 심층 가이드·정의·튜토리얼·FAQ·비교 분석 | 정보 검색에 판매 페이지 노출 → 의도 불일치·이탈 |
| **Commercial** (상업조사형) | **업계 추가, 공식 아님** | "best X", "A vs B", "X 추천", 리뷰 | 비교·리뷰·베스트 리스트(경험·기준 명시) | 근거 없는 어필리에이트 도배 → 스팸 리스크 |
| **Transactional** (거래형) | Broder 공식 | "X 구매", "X 가입", "X 다운로드" | 제품·카테고리·가격·CTA·데모 페이지 | 정보 글로 클릭만 받고 전환 못 함 |
| **Navigational** (내비형) | Broder 공식 | 브랜드명·특정 사이트 URL 의도 | 해당 브랜드/제품 페이지(자사면 홈·제품) | 브랜드 키워드에 엉뚱한 페이지 노출 |

**의도 판별 원칙 — SERP가 정답지다**:
이론으로 의도를 정하지 말고, **현재 SERP를 관찰**해 판별한다. 상위에 무엇이 랭크됐는지가 Google이 판단한 의도의 실증이다.
- SERP 상위가 가이드/블로그 → 정보형
- 제품·카테고리 페이지 → 거래형
- "best X" 비교 → 상업조사형
- 특정 브랜드 페이지 → 내비형
- AI Overview/피처드 스니펫 다수 → 직답 수요 강한 정보형
- 상위 10개 포맷이 동일 → 의도 강하게 굳음 — 다른 포맷으로 역공은 위험

## 3. E-E-A-T 신뢰 체크리스트 (rater 관점 — 랭킹 팩터 아님)

⚠️ **E-E-A-T는 랭킹 팩터도 점수도 아니다.** 품질 평가자(human rater)가 페이지를 평가하는 프레임이다. "EEAT 점수를 올린다"는 표현은 틀렸다. 평가자 평점은 알고리즘 변경을 보정하는 데 쓰이며 개별 페이지 순위를 직접 움직이지 않는다.
출처: evidence.md §2 · https://developers.google.com/search/blog/2022/12/google-raters-guidelines-e-e-a-t

**목표**: "E-E-A-T 최적화"가 아니라 **평가자·사용자가 신뢰를 판단할 근거를 콘텐츠에 실재시키는 것**.

### 3-1. Experience (경험) — 2022-12 추가된 첫 번째 E
- [ ] 저자의 직접 경험 증거가 있는가? (실사용 사진·1인칭 데이터·구체 사례)
- [ ] AI 요약이 흉내 낼 수 없는 1차 경험이 있는가? (AI Overviews 시대 핵심 차별점)
- [ ] 제3자가 대신 쓴 것처럼 보이지 않는가?

### 3-2. Expertise (전문성)
- [ ] 실제 저자가 명시되어 있는가? (익명·"편집팀" 대신 실명)
- [ ] 저자 바이오/저자 페이지에 이력·자격·경험이 기재되어 있는가?
- [ ] 전문가 검수가 있다면 검수자 실명·자격이 표기되어 있는가? (가짜 검수 금지)
- [ ] 콘텐츠 내 주장이 1차 출처·근거로 뒷받침되는가?

### 3-3. Authoritativeness (권위)
- [ ] 해당 주제에서 외부에서 인용·언급되는가? (자연 링크·디지털 PR)
- [ ] 동종 업계·미디어에서 참고 출처로 쓰이는가?
- [ ] 권위는 *구매*하는 게 아니라 좋은 콘텐츠로 *획득*하는 것 — 구매 링크로 대체 불가.

### 3-4. Trustworthiness (신뢰 — Google이 "가장 중요한 E" 강조)
- [ ] 발행일·최종 수정일이 표기되어 있는가?
- [ ] 명확한 회사·연락처 정보가 있는가?
- [ ] 광고·어필리에이트 관계가 투명하게 고지되어 있는가?
- [ ] HTTPS, 개인정보처리방침, 오류 수정 정책이 갖춰져 있는가?
- [ ] 의도적 오정보·날조가 없는가?

**YMYL(Your Money or Your Life) 주의**:
YMYL은 페널티가 아니라 **주제 범주**(건강·금융·안전·법률·시민 정보 등). 이 주제에서는 신뢰 기준이 훨씬 엄격하게 적용된다. 신뢰 근거 없이 상위 노출 자체가 어렵다.

⚠️ "저자 schema 넣으면 E-E-A-T 오른다" 같은 벤더 인과 주장 인용 금지 — 신호는 *신뢰의 증거*이지 켜는 스위치가 아니다.

## 4. 토픽 클러스터 / 필러-클러스터 IA

**원전**: HubSpot Pillar-Cluster 모델 (2017년 정식화, 벤더 방법론).
⚠️ **Google 공식 IA(정보 아키텍처) 방식이 아니다.** 효과 메커니즘의 검증된 부분(내부 링크·주제 응집)과 벤더 마케팅이 섞여 있다.

### 구조

```
필러 페이지 (Pillar)
├── 클러스터 서브 1 ──────→ (필러로 내부링크)
├── 클러스터 서브 2 ──────→ (필러로 내부링크)
├── 클러스터 서브 3 ──────→ (필러로 내부링크)
└── ...서브끼리도 관련성 있으면 상호 링크
```

- **필러(Pillar)**: 넓은 주제를 포괄하는 허브 페이지. 광의 키워드 타깃. 각 클러스터 서브로 링크.
- **클러스터(서브)**: 세부 키워드·하위 질문을 각각 깊게 다루는 페이지. 모두 필러로 내부 링크(주제 키워드 앵커). 관련 서브끼리도 링크.

### 실무 포인트

| 항목 | 기준 |
|---|---|
| 키워드 중복 방지 | 1페이지 = 1의도(카니발라이제이션 방지 — 같은 의도에 여러 페이지가 잠식하지 않도록) |
| 의도 확인 | 새 클러스터 페이지 전에 SERP 관찰 — "이건 별도 페이지가 맞나, 기존에 합칠까" 판단 |
| 내부 링크 앵커 | 설명적 앵커텍스트(주제 키워드), "여기 클릭" 금지 |
| 깊이 우선 | 얕은 클러스터 많이 보다 깊은 클러스터 적게가 낫다 |

**효과 메커니즘(검증된 부분)**: 내부 링크 → 크롤·문맥 전달. 주제 응집 → 사용자가 관련 답을 한 사이트에서 완결 → 체류·재방문. HubSpot 사내 실험(Hussain·Davies, ~2015): 내부 링크 늘릴수록 SERP 순위·노출 상승 관찰.

⚠️ "N개 이상 서브를 걸면 권위가 생긴다" 같은 수치 규칙은 벤더 2차 — 공식 근거 없음. "토픽 권위 점수" 없음, John Mueller "신경 쓰지 마라"(2023).

## 5. AI Overviews 시대 콘텐츠 전략 (부패 빠름 — 상당수 확인 필요)

AI Overviews GA: 2024-05-14. 순위 ≠ 트래픽(무클릭 증가). 출처: evidence.md §9.

| 전략 방향 | 구체 행동 |
|---|---|
| 인용 가능 구조 | 질문을 소제목으로, 첫 문단에 직답 요약, 리스트·표로 스캔 가능하게 |
| 요약 불가 가치 | 1차 경험·독자 데이터·심층 분석 — AI가 대체 못 하는 콘텐츠 |
| 실체 신호 | 브랜드·저자 실체가 인용 시 신뢰 증거 |
| 클릭 유인 | 요약 후 더 알고 싶게 만드는 심층 정보·독자 자료 |

⚠️ "GEO(Generative Engine Optimization)/AEO로 AI 인용 보장" 류 벤더 주장은 검증 미비 — 확인 필요, 날조 금지.

## 6. 화이트햇 링크 실무

출처: developers.google.com/search/docs/essentials/spam-policies

| 구분 | 내용 |
|---|---|
| 화이트햇 | 콘텐츠 품질로 자연 획득, 디지털 PR, 편집 링크 |
| 금지(스팸) | 링크 매매·PBN·자동 생성·과도한 교환·앵커 조작 |
| rel 속성 필수 | 후원: `rel="sponsored"` / UGC: `rel="ugc"` / 비편집: `rel="nofollow"` |
| Disavow | Search Console 거부 파일 — 비자연 링크 누적 시 최후 수단 |
| 품질 > 양 | 관련성·신뢰 높은 사이트의 링크 1개 > 스팸 사이트 링크 100개 |

앵커 텍스트 과최적화(정확 매치 앵커 도배)는 비자연 신호 → 자연스러운 다양성 유지.
