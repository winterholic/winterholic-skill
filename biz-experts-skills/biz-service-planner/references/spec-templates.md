# spec-templates — 화면설계서·정책정의서·IA·예외처리 양식 실무판

> 한국형 서비스 기획자가 바로 복붙해 채울 수 있는 산출물 템플릿 모음. evidence.md의 검증 사실(산출물 체인은 국내 관행·영어 원전 없음·Garrett 5 Planes 백본·정책정의서=business-rules doc 최약 앵커) 위에 실제 양식을 얹는다.

---

## 0. 산출물 순서 (왜 이 순서인가)
IA → 기능정의서 → 정책정의서 → 플로우차트 → 화면설계서(스토리보드).
- **IA가 먼저**: 늦게 바뀌면 그린 화면 전부 재작업(기초공사).
- **정책이 화면보다 먼저**: 화면은 정책 번호를 참조만 함(SSOT 1곳). 구두 정책 금지.
> 이 체인은 **국내 실무 관행**이지 정전 프레임워크 아님. 학술 백본은 Garrett 5 Planes(Strategy→Scope→Structure→Skeleton→Surface).

---

## 1. IA(정보구조도) 템플릿

```
# IA — <서비스명>
## 뎁스 구조 (Depth)
- 1뎁스: 홈
  - 2뎁스: 상품 > 카테고리 > 상품상세
  - 2뎁스: 마이 > 주문내역 / 장바구니 / 설정
- 1뎁스: (비로그인 시 접근 가능 범위 표기)

## 페이지 목록 (화면 ID 부여)
| 화면 ID | 화면명    | 뎁스 경로        | 접근 권한        | 비고 |
|---------|-----------|------------------|------------------|------|
| SCR-001 | 홈        | 홈               | 전체             |      |
| SCR-010 | 상품상세  | 홈>상품>상세     | 전체             |      |
| SCR-020 | 장바구니  | 마이>장바구니    | 로그인(비로그인=로컬) | |
```
> 확정 전 카드소팅(사용자가 분류)·트리테스팅(구조 탐색성 검증)으로 IA 검증(NN/g). https://www.nngroup.com/articles/card-sorting-tree-testing-differences/

## 2. 기능정의서 템플릿

```
# 기능정의서 — <화면/모듈>
| 기능 ID | 기능명       | 설명(무엇을)              | 화면 ID | 우선순위 | 연관 정책     |
|---------|--------------|---------------------------|---------|----------|---------------|
| F-CART-01 | 수량 변경  | 담은 상품 수량 +/- 조절   | SCR-020 | High     | P-CART-02,03  |
| F-CART-02 | 품절 처리  | 품절 상품 표기·자동 제외  | SCR-020 | High     | P-CART-04     |
```

## 3. 정책정의서 템플릿 (SSOT — 규칙은 여기만)

```
# 정책정의서 — <도메인>
## 규칙 번호 체계: P-<도메인>-<일련>  (미정=TBD-P-XXX-NN)

| 정책 번호 | 유형   | 규칙 내용                                          | 근거/비고 |
|-----------|--------|----------------------------------------------------|-----------|
| P-CART-01 | 제한   | 장바구니 최대 담기 100종, 종당 최대 수량 99         |           |
| P-CART-02 | 유효성 | 수량은 1 이상 정수, 재고 초과 입력 시 재고량으로 조정 |           |
| P-CART-03 | 금액   | 합계 = Σ(단가×수량), 원단위 절사, 표시통화 KRW      |           |
| P-CART-04 | 상태   | 품절 상품은 회색 표기 + 결제 시 자동 제외(안내 노출) |           |
| P-CART-05 | 권한   | 비로그인은 로컬 저장, 로그인 시 서버 병합            |           |
| TBD-P-CART-06 | 시간 | (미정) 장바구니 상품 보관 기간 — 확인 필요           | 기본값=무기한 보관, 차단 없음 |
```
> 화면설계서는 규칙을 **다시 쓰지 않고 번호만 참조**. 정책 변경 시 이 문서만 갱신.

---

## 4. 플로우차트 규칙
- **정상 + 예외 분기를 함께**. 각 분기 끝에 도달 화면 ID.
- 결정 노드(마름모)에서 조건별 갈래를 모두 표기(누락 = 임의 처리).
- 상태 갖는 객체는 별도 **상태 전이표**(§6) 첨부.

## 5. 화면설계서(스토리보드) 템플릿 — 핵심 산출물

```
# 화면설계서 — [SCR-020 장바구니]
## 화면 메타
- 화면 ID: SCR-020 / IA 경로: 마이>장바구니
- 진입: 상품상세 담기, GNB 장바구니 아이콘 / 이탈: 결제(SCR-030), 계속쇼핑

## 레이아웃/영역 (요소 번호)
① 헤더  ② 상품 목록(썸네일·상품명·옵션·수량스텝퍼·금액·삭제)
③ 금액 요약(상품합계·배송비·총결제금액)  ④ 결제 버튼

## 디스크립션 (요소별 — 구체적으로)
- ②-수량스텝퍼: - 버튼은 수량 1에서 비활성. + 는 재고까지. 재고 초과 시 재고량으로 조정하고 "재고 N개까지 가능" 토스트. [P-CART-02]
- ④-결제버튼: 선택 상품 0개면 비활성. 품절 상품 포함 시 "품절 상품은 제외되고 결제됩니다" 확인 모달. [P-CART-04]

## 상태 정의 (4상태 의무)
- 빈(empty): "담은 상품이 없어요" + [추천 상품 보기] CTA
- 로딩: 상품 목록 스켈레톤 3줄
- 에러: "장바구니를 불러오지 못했어요" + [다시 시도]
- 정상: 위 레이아웃

## 예외·분기 (조건 → 결과)
- 결제 진행 중 재고 소진: 결제 단계에서 "품절되었습니다" + 해당 상품 제외 후 재계산
- 가격 변동: 진입 시 최신가 재조회, 변동 시 "가격이 변경되었습니다" 배지
- 세션 만료: 로그인 화면으로, 복귀 시 장바구니 유지

## 권한 매트릭스
| 역할     | 목록 보기 | 수량 변경 | 결제 | 비고 |
|----------|-----------|-----------|------|------|
| 비로그인 | O(로컬)   | O         | 로그인 유도 | [P-CART-05] |
| 일반     | O         | O         | O    |      |
| 관리자   | O         | O         | O    |      |

## 데이터
| 항목     | 출처(API/필드)          | 정렬     | 페이징 | 갱신     |
|----------|-------------------------|----------|--------|----------|
| 상품 목록| GET /cart / items[]     | 담은순   | 없음   | 진입 시  |
| 재고     | items[].stock           | -        | -      | 진입·결제 시 |

## 정책 참조: P-CART-01 ~ 05
## 확인 필요: TBD-P-CART-06(보관 기간)
```

## 6. 상태 전이표 템플릿 (정합성 사고 예방)

```
# 상태 전이 — 주문
| 현재 상태   | 액션      | 조건            | 다음 상태   | 실패 처리                     |
|-------------|-----------|-----------------|-------------|-------------------------------|
| 결제대기    | 결제      | 재고>0, 결제승인 | 결제완료    | 결제성공+주문실패 시 자동 환불(보상) |
| 결제완료    | 취소      | 배송 전         | 취소완료    | 이미 배송 시 취소 불가 안내    |
| 배송중      | 취소      | -               | (불가)      | "배송중 취소 불가, 반품 안내"  |
```
> 정합성 사고(결제됨+주문실패·재고 음수·쿠폰 중복)는 **여기서 예외를 정의**하면 개발이 그대로 구현. 기획 단계 미정의 = 버그.

## 7. 예외·엣지케이스 카탈로그 (화면마다 훑기)
- **입력**: 빈값·최대초과·특수문자·중복·형식오류
- **상태/시점**: 세션만료·중복제출(더블클릭)·뒤로가기·새로고침
- **데이터**: 0건·삭제됨·권한없음·연동실패·타임아웃
- **동시성**: 재고0·가격변동 중 결제·동시 수정
- **결제 정합성**: 결제성공+주문실패·중복쿠폰·부분환불
- **권한**: 역할별 노출/액션 경계(타인 데이터 노출 = 보안·법적 리스크)
- **기기/환경**: 오프라인·저사양·접근성·다국어 길이

## 8. 완성도 셀프체크 (핸드오프 전)
- [ ] IA 확정 후 화면을 매달았나 (역순 아님)
- [ ] 모든 목록/상세에 4상태(빈·로딩·에러·정상)
- [ ] 정책은 번호로 정책정의서에(구두·주석 아님), 화면은 번호 참조
- [ ] 권한 매트릭스(역할×보임/액션)
- [ ] 데이터 출처(API·필드)·정렬·페이징·갱신
- [ ] 디스크립션에 "적절히/알아서" 없음(구체 문구·조건)
- [ ] 상태 갖는 객체는 상태 전이표
- [ ] 미정은 TBD-번호 + 안전 기본값, 빈칸 없음
> `scripts/spec_lint.py`로 누락 자동 점검.
