# 한국어 화면 조판 — 실사용 함정 모음

> 기준: 실사용 회고 (2026-07 ~ 2026-09) · 부패 등급: 느림
> *Refactoring UI* 를 비롯한 원전은 전부 라틴 문자 기준이다. 한글은 **어절·받침·조사** 때문에 규칙이 다르고, 그 차이에서 같은 사고가 반복됐다.

| # | 함정 | 한 줄 |
|---|---|---|
| 1 | 어절 중간 줄바꿈 | `word-break: keep-all` 은 전역 기본값으로 깔 것 |
| 2 | 일본어에 keep-all | 그대로 쓰면 문장이 통째로 한 단어가 된다 |
| 3 | 라틴 기준 line-height | 1.0 미만은 받침이 깨진다 |
| 4 | 폭 제한이 만드는 줄바꿈 | `max-width` 가 원인인 어색한 줄바꿈 |
| 5 | 본문 가운데 정렬 | 여러 줄 한글을 가운데 두지 않는다 |
| 6 | 글자 크기 하한 | 8~10px 이 방치되면 71%가 13px 이하가 된다 |
| 7 | 두 글자 링크 | 폭이 24px 에 1px 모자란다 |

---

## 1. `word-break: keep-all` 을 전역 기본값으로 깐다

한글은 브라우저 기본값이 음절 단위로 끊어서 **"오 / 늘의 카드는"**, **"등급은 여행지 / 의 점수가"** 처럼 어절 중간에서 갈라진다.

```css
:where(body) {
  word-break: keep-all;      /* 어절 단위 줄바꿈 */
  overflow-wrap: break-word; /* 긴 영문·URL 방어 (동반 필수) */
}
```

- **`:where()` 로 감싸 특이도를 0 으로 만든다.** 기존 컴포넌트 규칙이 항상 이기게 하려는 것이다.
- `overflow-wrap: break-word` 를 같이 준다. keep-all 만 주면 긴 URL·영문 단어가 컨테이너를 뚫는다.
- **제목만 고치고 끝내지 않는다.** `h1` 에만 넣었다가 리드 문단에서 `3,884 / 개 세션` 으로 수사와 단위가 갈라진 적이 있다. 숫자+단위, 고유명사+조사가 특히 잘 깨진다.

> 이 규칙은 실사용 로그에서 **일곱 번 따로 발견됐다**(2026-07-29 표지 h1 → 07-29 리드 → 07-30 About → 07-31 태그라인 → 08-04 홈 → 08-10 상세 → 08-22 전역화). 매번 "이번 화면의 버그"로 취급됐다. 화면 단위로 고치지 말고 전역에 깔 것.

## 2. 일본어에는 keep-all 을 쓰지 않는다

일본어는 띄어쓰기가 없다. `keep-all` 을 주면 **문장 전체가 한 단어**가 되어 줄이 컨테이너를 뚫는다.

- 다국어 화면이면 `:lang(ko)` 로 한정하거나, 일본어 페이지에서 `word-break: normal` 로 되돌린다.
- 실제로 일본어판 이력서·랜딩에서 6곳을 `normal` 로 교체해야 했다.

## 3. `line-height` 는 라틴 기준으로 정하지 않는다

- **1.0 미만은 한글에서 깨진다.** 받침 때문에 글자 높이가 라틴보다 크다. `line-height: .92` 로 조판했다가 표지 h1 두 행이 겹쳤다(31pt / 1.06 으로 조정).
- 반대로 **본문 행간을 전역으로 올리는 것도 위험하다.** A4 같은 고정 지면에서 `body { line-height: 1.68 }` 을 걸었다가 여러 페이지가 동시에 넘쳤다(2p 46px · 4p 5px 넘침 + 카드 18px 잘림).
- 제목에 `line-height` 를 지정하지 않으면 본문값(예: 1.6)을 상속해 **줄상자가 글자보다 훨씬 커진다.** 17px 글자가 27px 줄상자를 만들어 "이중 여백"의 원인이 된 사례가 있다. 제목·버튼·힌트는 `1.3` 안팎을 명시한다.

## 4. 어색한 줄바꿈의 원인이 `max-width` 인 경우

문장 중간에서 끊기고 오른쪽이 비어 보이면 폰트가 아니라 **폭 제한**을 먼저 본다. `max-width: 32em` 같은 값이 걸린 텍스트 블록에서 반복적으로 나왔다(같은 패턴을 두 번 연속 고쳤다).

- 처방: `max-width` 제거 또는 완화 + `keep-all`.
- 다만 데스크톱 초광폭에서는 한 줄 45~75자 규칙이 여전히 유효하다. **"오른쪽이 이유 없이 비는 것"과 "읽기 좋은 줄길이"는 다른 문제**이므로 실제 렌더를 보고 판단한다.

## 5. 여러 줄 한글 본문을 가운데 정렬하지 않는다

가운데 정렬은 줄마다 시작점이 달라져 **눈이 매 줄 앞을 다시 찾아야 한다.** 안내 모달의 여섯 줄 덩어리를 가운데로 흘렸다가 지적받았다. 한 줄짜리 문구·버튼 라벨만 가운데를 쓴다.

## 6. 글자 크기 하한과 타입 스케일

크기 토큰이 없으면 선언이 난립한다 — 실측 예: `font-size` 선언 515개 중 **13px 이하가 365개(71%), 10px 이하가 74개**, 종류는 8~56px 24가지.

- **하한 11px** 을 먼저 올리는 것이 회귀 위험이 가장 낮다. 그 이상(12·13px)은 레이아웃이 잡혀 있으므로 건드리지 않는다.
- 근본 해결은 `--fs-*` 토큰을 만들어 5~7단계로 수렴시키는 것. 범위가 크므로 **별건으로 잡고 승인을 받는다**(→ `../../existing-screen-edit.md` 규율 7).
- 크기를 올릴 때 제약은 대개 **가장 긴 라벨**이다. 그 라벨이 한 칸에 들어가는지로 상한을 정한다.

## 7. 두 글자 링크는 24px 에 걸린다

`경력`·`소개` 같은 두 글자 내비 링크는 실측 폭이 23px 로 나와 **WCAG 2.5.8(24px) 에 1px 미달**한다. `min-width: 24px` 를 준다.

- 다만 **인라인 텍스트 링크는 2.5.8 예외**다. 본문 안 링크에 억지 패딩을 주면 줄 높이가 벌어져 "이중 여백"이 된다 — 히트 영역만 키우고 레이아웃 박스는 유지하는 방식(`padding` + 상쇄 `margin`)을 쓴다.
- 모바일 관례 44px 은 WCAG 최소와 다른 기준이다. 둘을 섞어 근거로 대지 않는다.

```
줄바꿈: keep-all 전역? · overflow-wrap 동반? · 숫자+단위 / 고유명사+조사 렌더 확인
행간:   제목 line-height 명시? · 1.0 미만 없음? · 고정 지면에 전역 행간 변경 없음?
정렬:   여러 줄 본문 가운데 정렬 없음?

타깃:   두 글자 링크 min-width 24px · 인라인 링크는 예외 처리
```
