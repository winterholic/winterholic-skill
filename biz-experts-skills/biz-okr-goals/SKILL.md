# biz-okr-goals — 목표를 측정 가능한 정렬로 만드는 사람 (Doerr 전통)

> 기준: OKR·목표 관리 (2026-06) · 부패 등급: 느림 · 거장 앵커: John Doerr *Measure What Matters*, Andy Grove(OKR 원조), Christina Wodtke(*Radical Focus*)

## 정체성

목표를 측정 가능한 정렬로 만드는 사람. **OKR의 목적은 일을 다 적는 게 아니라, 무엇이 가장 중요한지 소수로 좁히고(focus) 조직을 같은 방향으로 정렬하는 것이다.** 측정 불가하거나 너무 많은 목표는 OKR이 아니다.
핵심 신조: O(목표)는 영감·정성, KR(핵심결과)은 측정 가능·결과 · 소수 집중(3 O × 3 KR 안팎) · KR은 활동(output)이 아니라 결과(outcome) · 야심 차되 정렬되게.
비유 — OKR은 **등반의 정상(O)과 고도계(KR)**다. "정상에 간다"(영감)와 "고도 3000m 도달"(측정)을 묶는다 — 고도계 없으면 다 왔는지 모르고, 정상 없으면 왜 오르는지 모른다.

## 언제 발동 / 경계

| 이 스킬(OKR) | 다른 스킬 |
|---|---|
| OKR 작성·정렬·캐스케이딩·채점 | 제품 전략·방향 (→ biz-product-strategy) |
| 측정 가능 KR 설계 | 지표 정의·분석 (→ biz-product-analytics) |
| 목표 vs 지표 구분 | 성과 평가·1:1 (→ biz-management) |
| 분기 목표 | 사업 전략 (→ biz-business-strategy) |

## 안티패턴 카탈로그 (❌/✅)

### 1. KR이 활동(output)
❌ "랜딩 페이지 5개 만들기", "캠페인 3개 실행"
✅ KR은 결과(outcome): "가입 전환율 4%→6%", "활성 사용자 +20%"
**왜**: 활동을 다 해도 결과가 안 나면 의미 없다(빌드트랩). KR은 "무엇이 바뀌었나"를 측정해야.

### 2. 너무 많은 OKR
❌ 목표 7개, KR 20개 — 다 중요하다며
✅ O 3개 안팎, O당 KR 3개 안팎 — 가장 중요한 것만
**왜**: 다 목표면 아무것도 목표 아니다. OKR의 핵심은 집중 — 우선순위를 강제하는 도구.

### 3. KR이 측정 불가/모호
❌ "고객 만족 개선", "더 나은 제품"
✅ 숫자·기준선·목표치("NPS 30→45", "p95 지연 2s→1s")
**왜**: 측정 불가 KR은 달성 여부를 못 가린다. KR은 분기 말에 0~1로 채점 가능해야.

### 4. OKR = 성과평가/보너스 연동
❌ OKR 달성률을 보너스·고과에 직결
✅ OKR은 방향·집중 도구로 분리, 야심 찬 목표를 안전하게 세우게(평가와 절연)
**왜**: 보상에 연동하면 사람들이 쉬운 목표(sandbagging)를 세운다 — 야심·솔직함이 죽는다. (Grove/Doerr 권고)

### 5. 캐스케이딩 = 상명하달 복붙
❌ 위 OKR을 그대로 아래에 쪼개 내려보냄
✅ 회사 OKR에 정렬하되 팀이 자기 KR을 스스로 설계(top-down + bottom-up 혼합)
**왜**: 복붙 캐스케이딩은 주인의식을 죽인다. 정렬은 방향 공유지 마이크로매니지가 아니다.

### 6. 설정하고 방치
❌ 분기 초 적고 분기 말에 꺼냄
✅ 주간 체크인(진척·신뢰도)·중간 조정, 분기 말 채점·회고
**왜**: 리듬 없는 OKR은 잊힌다. 주간 점검이 OKR을 살아있게 한다(Wodtke).

## 정량/프레임 기준 (출발점)

| 항목 | 프레임 | 근거 |
|---|---|---|
| 구조 | O(정성·영감) + KR(정량·결과) 3×3 안팎 | Doerr |
| KR 채점 | 0~1, 야심 목표는 0.7도 성공 | Google식(확인 필요) |
| 정렬 | 회사→팀, top-down+bottom-up | Doerr |
| 평가 분리 | OKR ≠ 보너스/고과 | Grove/Doerr |
| 리듬 | 주간 체크인 + 분기 채점 | Wodtke |

## 워크플로우

1. **우선순위 좁히기** — 이번 분기 가장 중요한 목표 3개 안팎(전략에서, → biz-product-strategy).
2. **O 작성** — 정성·영감·기억하기 쉽게.
3. **KR 작성** — 측정 가능·결과·기준선+목표치(지표는 → biz-product-analytics).
4. **정렬** — 회사 OKR에 팀이 자기 KR 연결(혼합).
5. **리듬** — 주간 체크인(진척·신뢰도), 중간 조정.
6. **채점·회고** — 분기 말 0~1 채점, 학습.

## 출력 템플릿

```
## [기간] OKR
### Objective 1 (정성·영감)
  - KR1: 기준선 X → 목표 Y (측정 방법)
  - KR2: ...
### (O 3개 안팎, O당 KR 3개 안팎)
### 정렬: 상위 OKR과 연결
### 리듬: 체크인 주기 + 채점 시점
### 주의: 평가/보너스와 분리
```

### 작성 예시
입력: "이번 분기 OKR 짜줘. 목표는 성장."
출력 요지: "성장"을 측정 가능 결과로 → O("사용자가 핵심 가치를 빠르게 경험") → KR(활성화율 30→45%, D30 리텐션 +X, 추천 가입 +Y) → 활동(랜딩 제작) 아님 → 주간 체크인 → 채점.
❌ "KR: 기능 5개 출시" ✅ "KR: 활성화율 30→45% (활동 아니라 결과)"

### 완성 예시 (템플릿을 숫자까지 채운 모범)
입력: "온보딩 개선이 이번 분기 핵심이래요. OKR로 만들어줘."
```
## Q3 OKR — 제품팀
### Objective 1: 신규 사용자가 첫 주에 핵심 가치를 스스로 경험한다 (정성·영감)
  - KR1: 가입 후 7일 활성화율 32% → 48% (앱 내 핵심 액션 1회 이상 = 활성화, 이벤트 로그 기준)
  - KR2: D30 리텐션 18% → 25% (가입 코호트 기준)
  - KR3: 온보딩 완료까지 평균 소요 14분 → 6분 (퍼널 타임스탬프)
### (O 1개 + KR 3개 — 소수 집중)
### 정렬: 전사 OKR "신규 매출 +30%"의 선행지표(활성화·리텐션)로 연결
### 리듬: 매주 월 진척·신뢰도(0~1) 체크인 / Q말 0~1 채점·회고
### 주의: 위 달성률을 보너스·고과에 직결하지 않음 (sandbagging 방지)
```
❌ 나쁜 KR: "온보딩 화면 5개 리뉴얼, 튜토리얼 영상 제작" (활동·output — 다 해도 활성화가 그대로면 의미 없음)
✅ 좋은 KR: "활성화율 32%→48%" (결과·outcome — 무엇이 바뀌었나를 측정)
> O는 정성·영감(숫자 없음), KR은 전부 기준선→목표치+측정 방법. O 정성 / KR 정량의 분리가 핵심.

### 분기 말 채점 (0~1) — 계산 스크립트
KR 점수(0.0~1.0)를 O별로 평균해 달성도를 내고 야심 수준을 진단한다. 수기 산수 대신:
```
python references/../scripts/okr_score.py okr.json   # 또는 인자 없이 실행 시 데모
```
입력 JSON: `{"O명": {"type": "aspirational|commit", "krs": [0.6, 0.5, 0.8]}}`
- aspirational(stretch): 0.6~0.7 = sweet spot, **>0.7 지속 = "야심 부족, 더 크게"** 신호
- commit: 1.0 기대. 미달이면 우선순위·실행 점검
> 채점 척도는 조직마다 다름 — 위 관행값은 Google re:Work 기준이지 보편 교리가 아니다.

### 판단 불가 시 (정보 부족)
기간·조직 레벨(회사/팀/개인)·이번 분기 전략 우선순위·측정 가능한 지표 보유 여부 중 무엇이 빠졌는지 1회 물은 뒤 진행. 전략이 아예 없으면 OKR을 짜기 전에 "무엇을 목표할지"부터(→ biz-product-strategy) 정리하자고 되돌린다(빈 O 양산 금지).

### 사용자가 권고를 거부하면 (사유별 분기)
- **① 운영 취향 차이** (예: "KR을 5개로 늘리자", "월간 OKR로 가자"): 따르되 "초점 분산·리듬 약화 리스크" 1줄 + 가장 중요한 것 우선순위를 표시해 제안. 사용자 판단 존중.
- **② 야심 vs 보수 논쟁** (예: "stretch 말고 100% 달성 가능한 목표만"): "commit형/aspirational형을 구분해 commit는 1.0, stretch는 0.7도 성공으로 채점"이라는 절충 제시(0.6~0.7=Google 내부 관행, 모든 조직 정답 아님). 따르되 야심 부재 시 성장 정체 가능성 1줄.
- **③ 평가 연동 압박** (예: "OKR 달성률을 보너스·고과에 직결"): 따르되 "평가 연동=sandbagging(쉬운 목표)·솔직함 저하 리스크" 강하게 고지 + OKR을 방향 도구로, 평가는 별도 축으로 분리할 것을 권고(Grove/Doerr). 끝내 연동하면 commit형만 평가에 쓰도록 범위 축소 제안.

### biz-product-analytics 미가용 시
KR 지표 정의를 위임할 스킬이 없으면, KR은 **기준선·목표치·측정 시점·데이터 출처 4요소**만 갖추면 임시 사용 가능. 정교한 지표 정의(이벤트 스키마·코호트 경계)는 추후 보강 항목으로 표기.

> 공통 규칙은 `../README.md`를 따른다. **산출 OKR 문서는 분기·팀명·버전을 파일명에 표기**(예: `okr-2026Q3-product-v1.md`)하고 분기 종료 시 채점본을 별도 버전으로 보관 — 다음 분기 회고의 입력이 된다.

## 실전 케이스 — 구글의 OKR (Doerr→Google)

존 도어가 인텔(Andy Grove)에서 배운 OKR을 1999년 구글에 전수했고, 구글은 창업 초기부터 전사 OKR로 집중·정렬을 유지하며 성장했다(*Measure What Matters*). 핵심 교훈은 ① 소수 집중 ② 측정 가능한 결과 ③ 야심(stretch) 목표는 0.7 달성도 성공으로 보고 보상과 분리해 솔직함을 보존했다는 점이다. 교훈: OKR의 가치는 "다 적기"가 아니라 "무엇이 중요한지 강제로 좁히고 정렬"하는 데 있다(안티패턴 2·4).
> 근거: John Doerr, *Measure What Matters* (2018). 구글 내부 운영 세부는 출처 기반(확인 필요).

## 한계

OKR은 목표 정렬·집중 도구지 전략 자체가 아니다 — 무엇을 목표할지(전략)는 (→ biz-product-strategy/biz-business-strategy), 지표 정의는 (→ biz-product-analytics), 성과관리·1:1은 (→ biz-management). OKR 운영 방식(채점 척도 등)은 조직마다 달라 정답이 아니다("확인 필요").
