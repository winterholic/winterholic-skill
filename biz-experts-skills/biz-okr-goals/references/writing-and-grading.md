# OKR 작성 & 채점 실무

> evidence.md 보강. O/KR 작성 문법 · 2티어 · 0~1 채점 절차 · 안티패턴 심화. 검증 사실은 evidence.md §2·§5 참조(2티어=Rick Klau/GV, 0.6~0.7=Google 관행이지 교리 아님).

## 1. Objective 작성 문법 — 정성·영감·기억 가능

O는 "무엇을·왜"의 질적 선언이다. 숫자를 넣지 않는다(숫자는 KR의 몫).

**좋은 O의 4요소**
1. **결과·상태 지향** — "무엇을 하겠다"(활동)가 아니라 "어떤 상태가 되겠다".
2. **영감·기억 가능** — 팀이 외워서 말할 수 있는 짧은 문장. 슬로건성 OK.
3. **기간 한정** — 대개 분기. "언젠가"는 O가 아니라 미션.
4. **가치·의미 내포** — "왜 중요한가"가 읽혀야.

| ❌ 약한 O | ✅ 강한 O |
|---|---|
| "매출 30% 성장" (숫자=KR 자리, O가 지표가 됨) | "우리 제품이 시장의 기본 선택지가 된다" |
| "온보딩 개선" (모호·활동) | "신규 사용자가 첫 주에 핵심 가치를 스스로 경험한다" |
| "여러 기능 출시" (활동 나열) | "결제 경험이 업계에서 가장 매끄럽다" |

## 2. Key Result 작성 문법 — 정량·결과·검증 가능

KR은 O 달성을 **증명**하는 측정 가능한 결과다. 활동(output)이 아니라 변화(outcome).

**KR 4요소(필수)**: ① 지표 ② 기준선(baseline) ③ 목표치(target) ④ 측정 방법·데이터 출처.
- 형식: `<지표> <기준선> → <목표치> (<측정 방법>)`
- 예: `가입 후 7일 활성화율 32% → 48% (앱 내 핵심 액션 1회 = 활성화, 이벤트 로그)`

**output vs outcome 판별법** — "이 KR을 100% 했는데 O가 그대로일 수 있는가?"
- 그렇다 → output(활동). 잘못된 KR. (예: "튜토리얼 영상 5개 제작")
- 아니다 → outcome(결과). 좋은 KR. (예: "활성화율 32%→48%")

**KR에 활동을 꼭 넣어야 할 때**: 초기 탐색·연구 과제라 결과 지표가 없으면 "learning KR"로 명시(예: "3개 세그먼트 인터뷰로 이탈 원인 가설 3개 검증"). 단 임시임을 표기하고 다음 분기 결과 지표로 전환.

## 3. 2티어 — committed vs aspirational

작성 시 각 O(또는 KR)에 유형을 명시한다. 채점 기준이 다르기 때문.

| | Committed(약속형) | Aspirational(야심/stretch) |
|---|---|---|
| 성격 | 반드시 해야 하는 것(출시·마감·SLA·채용) | 크게 걸어보는 것(성장·혁신·신시장) |
| 기대 달성 | **1.0(100%)** | **0.6~0.7** |
| 미달 의미 | 문제 신호 — 우선순위·자원 재점검 | 정상. 0.7 넘으면 오히려 "너무 안전" |
| 리스크 | 미달 시 다른 일 밀어내서라도 채움 | 미달해도 처벌 금지(학습 데이터) |

> 두 유형을 섞어 쓰되, 한 분기에 committed로 안전판을 깔고 aspirational로 야심을 건다. 전부 committed면 성장 정체, 전부 aspirational면 실행 신뢰 붕괴.

## 4. 0~1 채점 절차 (분기 말)

1. **KR별 채점(0.0~1.0)** — 기준선→목표치 대비 실제 진척의 선형 비율이 기본.
   - 예: 32%→48%(목표 +16%p) 목표에서 실제 32%→40%(+8%p) → 8/16 = **0.5**.
   - 이진(binary) KR("출시 완료")은 1.0 또는 0.0.
2. **O 점수 = KR 점수 평균**(re:Work 방식, 단순 평균). 가중치 필요 시 명시.
3. **유형별 해석**:
   - committed: 1.0 기대. 미달이면 회고에서 원인(과대설정 vs 실행격차) 분리.
   - aspirational: 0.6~0.7=sweet spot. >0.7 지속이면 "더 크게". <0.4면 목표 과대 or 실행 격차.
4. **채점은 처벌이 아니라 데이터** — 낮은 점수 = 다음 분기 학습 입력(Klau). 보너스·고과에 직결 금지(sandbagging 유발).
5. 계산은 `scripts/okr_score.py`로 자동화(유형별 코멘트 포함).

**채점 흔한 실수**
- 사후에 목표치를 몰래 낮춰 점수 부풀리기 → 금지. 목표는 분기 초 고정.
- "노력했으니 0.8" → 활동이 아니라 결과 수치로만 채점.
- 0/1 아닌 KR을 이진으로 채점 → 부분 진척 반영 못 함.

## 5. 안티패턴 심화 (SKILL.md 6종의 확장)

**7. Sandbagging(쉬운 목표 깔기)** — 평가·보상 연동 우려로 달성 확실한 목표만 세움. → 원인은 대개 "OKR=고과" 연결. CFR로 평가 분리를 문화적으로 보장해야 야심이 산다.

**8. KPI를 KR로 위장** — "매출 유지", "가동률 99% 유지" 같은 상시 운영 지표를 KR로. → KR은 **변화**를 목표하는 것. 유지·건강 지표는 별도 "health metric"으로 트래킹(Wodtke의 4사분면 중 하나)하고 KR에서 분리.

**9. Set-and-forget(설정 후 방치)** — 체크인 리듬 부재. → cadence-and-cfr.md 참조. 주간 신뢰도 트래킹이 없으면 분기 말에야 실패를 안다.

**10. 캐스케이딩 = 상명하달 복붙** — 상위 KR을 그대로 하위 O로 붙임. → 정렬(alignment)은 방향 공유지 복제가 아님. 하위 팀이 상위 O에 기여하는 **자기 KR을 스스로 설계**(bottom-up 혼합)해야 주인의식.

## 6. 완성 예시 — committed + aspirational 혼합 (제품팀 Q3)

```
## Q3 OKR — 제품팀
### O1 (aspirational): 신규 사용자가 첫 주에 핵심 가치를 스스로 경험한다
  - KR1: 7일 활성화율 32% → 48% (핵심 액션 1회=활성화, 이벤트 로그)   [stretch]
  - KR2: D30 리텐션 18% → 25% (가입 코호트)                          [stretch]
  - KR3: 온보딩 완료 소요 14분 → 6분 (퍼널 타임스탬프)               [stretch]
  → 기대 채점 0.6~0.7. 0.7 초과 지속이면 목표 상향.
### O2 (committed): 결제 인프라가 안정적으로 동작한다
  - KR1: 결제 성공률 97.5% → 99.3% (게이트웨이 로그)                 [commit=1.0 기대]
  - KR2: 결제 p95 지연 2.1s → 1.0s (APM)                            [commit]
  → 기대 채점 1.0. 미달 시 최우선 자원 투입.
### 정렬: 전사 "신규 매출 +30%"의 선행지표(활성화·리텐션)로 O1 연결
### 리듬: 주간 신뢰도 체크인 / Q말 0~1 채점·회고
### 주의: 위 달성률을 보너스·고과에 직결하지 않음(sandbagging 방지)
```
