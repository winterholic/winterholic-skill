# biz-product-marketing — 실전 운용집 (Playbook)

> 일류 PMM의 실무 절차·템플릿·판정 기준. 근거는 `evidence.md`. 산출은 기본 채팅, 파일은 요청 시.

## A. Dunford 10단계 포지셔닝 워크숍 진행법

포지셔닝은 혼자 쓰는 문서가 아니라 **크로스펑셔널 워크숍**으로 도출한다(영업·CS·제품이 다르게 인식하면 시장에서 깨진다).

**준비 (Step 1~3, 워크숍 전)**
- 1️⃣ 제품을 *가장 사랑하는* 고객 10~20곳 리스트업 → 공통점 추출(회사 규모/역할/트리거 이벤트). "왜 우리를 골랐나, 대신 뭘 썼었나"를 1차 인터뷰.
- 2️⃣ 포지셔닝 팀: PMM + 영업 리더 + 제품 + CS 1명씩(현장 언어 확보).
- 3️⃣ **Baggage 버리기**: "우리가 원래 이런 회사였으니까"를 괄호 치고 시작. 창업 스토리·기존 카테고리 집착이 최대 방해물.

**도출 (Step 4~8, 워크숍 본체 — 2~3시간)**
| 단계 | 진행 질문 | 산출 |
|---|---|---|
| 4. 경쟁 대안 | "우리가 사라지면 고객은 뭘 쓰나?" (SaaS만 적지 말 것 — "엑셀/수작업/아무것도 안 함"까지) | 진짜 대안 리스트 |
| 5. 고유 속성 | "그 대안엔 없고 우리엔 있는 기능·역량은?" | 속성 목록 |
| 6. 가치 테마 | 속성 → "그래서 고객이 얻는 것" 그룹핑 (3~4개 테마) | 가치 테마 3~4 |
| 7. Who cares a lot | "어떤 고객이 이 가치에 *돈을 더 낼 만큼* 절박한가?" | 베스트핏 세그 |
| 8. 시장 프레임 | "우리 강점이 자명해지는 카테고리는? 기존 카테고리 내 차별 vs 새 카테고리 창출?" | 시장 카테고리 결정 |

**마무리 (Step 9~10)**
- 9️⃣ 트렌드 얹기(선택·주의): 관련 메가트렌드가 있으면 "왜 지금"에 힘. 억지로 얹으면 신뢰 하락.
- 🔟 캡처: 아래 **메시징 하우스**(C)와 **Moore 포지셔닝 문장**으로 문서화 → 전사 공유.

> 새 카테고리 창출은 교육 비용이 크다. 기존 카테고리 안에서 차별이 가능하면 그쪽이 저비용. "카테고리 디자인"은 자원·시간이 충분할 때만.

## B. 런칭 티어 판정 기준표 + 티어별 체크리스트

**판정 (2축 스코어)** — 각 0~3점, 합산으로 티어 결정
| 축 | 0점 | 3점 |
|---|---|---|
| 비즈니스 임팩트 | 지표 변화 미미 | 신규 획득·신시장·GTM 조정급 |
| 고객 임팩트 | 워크플로 변화 없음 | 목소리 컸던 문제 해결·입소문 유발·워크플로 재편 |

- 합 5~6 → **Tier 1 (Scream)** · 합 3~4 → **Tier 2 (Shout)** · 합 0~2 → **Tier 3 (Cheer)**

**티어별 실행 체크리스트**
| | Tier 1 Scream | Tier 2 Shout | Tier 3 Cheer |
|---|---|---|---|
| **사전** | 포지셔닝·메시징 하우스 갱신, 베타/디자인파트너, 세일즈 인에이블먼트 킷, 애널리스트/프레스 브리핑, 랜딩·데모, 리더십 승인 | 세일즈 교육, 블로그·이메일 초안, 데모 업데이트 | 릴리스노트 초안 |
| **당일** | 프레스릴리스, 프로덕트헌트/이벤트, 전 채널 동시, 고객사례, 임원 소셜 | 블로그 발행, 타깃 이메일, 인앱 공지 | 인앱 공지·체인지로그 |
| **사후 (2~6주)** | 세그먼트별 콘텐츠 확장, 파이프라인 추적, 애널리스트 팔로업, 메시지 인식 측정(E) | 사용 지표 추적, 세일즈 피드백 | 채택률 확인 |
| **채널 규모** | 전사 총동원 | 마케팅 집중 협업 | 최소 |

> 런칭은 *이벤트가 아니라 과정*이다. 티어와 무관하게 사전-당일-사후 3단계로 계획. 단발 발송은 하루 스파이크 후 소멸.

## C. 메시징 하우스 템플릿 + 작성 예시

```
                    ┌─────────────────────────────┐
   [지붕] 포지셔닝    │  한 문장: "[타깃]을 위한       │
   한 문장 (핵심)     │  [카테고리]. [대안]과 달리 [차별]." │
                    └─────────────────────────────┘
   [기둥] 핵심 가치   │ 가치①      │ 가치②      │ 가치③      │
   3~4개             │            │            │            │
   [토대] 증거 (proof)│ 데모/수치/고객사례/기능으로 각 기둥 지지  │
```

**작성 규칙**: 기둥은 *기능*이 아니라 *고객이 얻는 결과*. 각 기둥 아래 반드시 증거(입증 가능한 것만). 지붕 문장이 25자 넘게 길어지면 카테고리가 2개 뒤섞인 신호.

**예시 (팀 의사결정 추적 SaaS "DecideHub")**
- 지붕: "의사결정이 잦은 팀을 위한 결정 추적 도구. 채팅 앱과 달리 결정과 근거가 사라지지 않습니다."
- 기둥①: 결정이 안 휘발 ← *증거*: 타임라인에 결정·근거 고정(데모)
- 기둥②: 책임 명확 ← *증거*: 결정마다 담당·기한 자동 기록
- 기둥③: 회의 절반 ← *증거*: 고객사 △△ 회의 40%↓(실제 데이터만, 일반화 금지)

## D. 세일즈 인에이블먼트 킷 구성

마케팅 포지셔닝이 영업 현장에서 깨지면 시장 인식이 분열된다. Tier 1/2 런칭엔 필수.

**① One-pager (한 장 요약)**
- 포지셔닝 문장 · 타깃(누구에게 팔고 누구엔 안 파나) · 핵심 가치 3 + 증거 · 가격 요약 · "이럴 때 쓴다" 유스케이스 3.

**② Battlecard (경쟁 비교표)**
- 경쟁 대안별(SaaS + "엑셀·아무것도 안 함") 1장씩: 그들 강점(인정) / 우리 우위 / "이 고객이 그들에게 끌릴 때 되받는 한 문장(trap-setting)".
- ⚠️ 경쟁사 허위 비방 금지 — 사실·입증 가능한 비교만.

**③ Objection handling (반론 대응)**
- Top 5~7 이의(가격·전환비용·기능부족·리스크·타이밍)마다: 이의 → 재프레이밍 → 증거 → 다음 액션.
- 형식: "고객: '너무 비싸다' → '무엇 대비 비싼가요?(대안 재프레이밍)' → 현상유지 비용 수치 → 파일럿 제안."

**④ Discovery 질문 세트** — Dunford Sales Pitch의 Setup(insight/alternatives/perfect world)을 대화로: "지금 이 문제를 어떻게 풀고 계신가요? 이상적으로는 어떤 모습이면 좋겠어요?"

## E. 포지셔닝 검증 (고객이 우리를 어떻게 부르나)

포지셔닝은 *가설*이다. 시장이 의도대로 인식하는지 측정해야 다음 수가 보인다.

| 신호원 | 무엇을 본다 | 재포지셔닝 트리거 |
|---|---|---|
| 영업 통화 녹취(Gong 등) | 고객이 우리를 어떤 카테고리로 부르나 | 의도한 카테고리와 다른 단어를 반복 |
| G2/리뷰·SNS 언급 | "이건 결국 ○○ 같은 거" 비유 | 엉뚱한 경쟁군에 묶임 |
| Win/Loss 인터뷰 | 산 이유·안 산 이유의 언어 | 우리 차별을 인지 못함 |
| 데모 이탈 지점 | 어디서 "그래서 뭐가 다른데?"가 나오나 | 가치 전달 실패 |

- **측정 문항 예**: "우리를 한 문장으로 지인에게 설명한다면?" — 답이 우리 지붕 문장과 다르면 메시징·카테고리 재검토.
- 검증 없이 정한 포지셔닝은 관성으로 굳는다. Tier 1 런칭 후 4~6주 시점에 반드시 1회.

## F. 빠른 판정 룰

- 경쟁 대안이 "엑셀·아무것도 안 함" → SaaS 기능 비교 금지, *카테고리 교육·문제 인식*부터.
- "모두를 위한" 요구 → 베스트핏 1개로 좁혔다가 확장(볼링앨리). 좁고 강한 가치가 레퍼런스를 만든다.
- 차별 속성·증거 부재 → 포지셔닝 전에 증거(고객사례·수치) 확보부터. 없으면 가설로 명시.
- 없는 기능·미검증 우월성 요구 → 1회 경고 후 입증 가능 표현/로드맵 표기로 대체(그 문장만 교체, 나머지는 진행).
