## (a) 위기 유형 진단표 — SCCT 클러스터 판정 → 권장 대응

### 1단계 · 귀속 책임 판정 (예/아니오 3문항)
1. 조직이 **의도적으로/알면서** 저질렀거나 명백한 위법·비위인가? → 예: **Preventable**
2. 조직의 **과실·인적 오류·통제 실패**로 벌어졌는가? → 예: **Accidental**
3. 위 둘 다 아니고 조직도 **외부 요인의 피해자**(재해·루머·외부자의 제품 변조·직장 폭력)인가? → 예: **Victim**

> 애매하면 **한 단계 무겁게** 잡는다(대중은 귀속을 실제보다 무겁게 인식하는 경향). 위기 이력이 있거나 평소 평판이 나쁘면 여기서 한 단계 더 올린다(SCCT: 이력·평판이 귀속을 가중).

### 2단계 · 클러스터 → 권장 대응 (evidence.md §1-1 원전 매칭 기준)

| 클러스터 | 대표 예시 | 귀속 책임 | 권장 자세 | 핵심 전술 |
|---|---|---|---|---|
| **Victim** | 자연재해, 루머, 외부자의 제품 변조, 직장 폭력 | 약함 | **Inform + (필요시) Diminish** | instructing/adjusting information 먼저. 루머·부당공격엔 Deny(단, 근거 확실할 때만) |
| **Accidental** | 기술 결함 사고, 기술 결함 제품 위해, 이의제기 | 최소 | **Diminish** | excuse(의도 없음)·justification(피해 경미) + 시정 |
| **Preventable** | 인적 오류 사고, 위법·경영진 비위, 기만 | 강함 | **Rebuild** | apology(전면 책임 인정) + compensation. 상황 불문 |

**보조(Bolstering)** — 위 자세에 덧대는 2차 전략: Reminder(과거 선행)·Ingratiation(감사)·Victimage(조직도 피해). 단독 사용 금지, 재건·축소를 대체하지 못한다.

**가중 규칙**:
- 같은 위기라도 **위기 이력 있음 / 평소 평판 나쁨** → 한 단계 강한 자세로(예: Accidental이라도 Rebuild).
- **Deny는 최후의 카드** — 사실이 확실히 조직 편일 때만. 나중에 뒤집히면 2차 위기(은폐·거짓)로 최악.
- **모든 클러스터 공통 1순위**: ① **instructing information**(피해 차단 지침 — "해당 제품을 사용하지 마세요") ② **adjusting information**(피해자 심리 대처 지원 — 공감·시정). 자세 결정보다 이게 먼저다.

### 판정 → 문구 톤 매핑 (즉시 참고)
| 자세 | 열면 안 되는 말 | 열어야 하는 말 |
|---|---|---|
| Rebuild | "유감입니다만…", "오해가…" | "저희 잘못입니다. 책임지고 ~하겠습니다." |
| Diminish | "큰 문제 아닙니다"(무시조) | "의도치 않은 ~로 인해 발생했고, 영향은 ~로 한정, 조치 중입니다." |
| Inform | (침묵) | "현재까지 확인된 사실은 ~, 다음 업데이트는 ~시입니다." |

## (b) 위기 메시지 하우스 템플릿 + 작성 예시

Message House = **지붕(핵심 메시지 1) + 기둥(지지 메시지 3~4) + 토대(proof point)**. 위기엔 모든 스포크스퍼슨이 이 한 장으로 정렬(한목소리).

### 빈 템플릿
```
┌──────────────────────────────────────────┐
│ [지붕] 핵심 메시지 (한 문장, 우리가 가장       │
│         기억되길 바라는 것 — 대개 "책임/안전")  │
├──────────┬──────────┬──────────┬──────────┤
│ [기둥1]   │ [기둥2]   │ [기둥3]   │ [기둥4]   │
│ 무슨 일이  │ 지금 무엇을│ 재발 방지 │ (선택)     │
│ / 사실     │ 하고 있나  │ 를 위해   │ 이해관계자 │
│           │           │          │ 지원      │
├──────────┴──────────┴──────────┴──────────┤
│ [토대] 각 기둥을 뒷받침하는 사실·수치·조치     │
│   (검증된 것만. 미확인은 "조사 중"으로 명시)   │
└──────────────────────────────────────────┘
```

### 작성 규칙
- **지붕은 하나.** 두 개면 메시지가 쪼개진다. "고객 안전이 최우선" 같은 가치 문장.
- **기둥은 사실→행동→예방 순.** 각 기둥 = 한 문장 + 뒷받침 proof 1~2개.
- **미확인 정보는 기둥에 넣지 않는다.** 추측은 나중에 뒤집혀 2차 위기가 된다.
- **모든 답변은 기둥 중 하나로 회귀(bridging).** Q&A·인터뷰에서 어떤 질문이 와도 세 기둥으로 되돌아온다.

### 채운 예시 — 데이터 유출 의심 (Preventable에 가까움 → Rebuild 톤)
```
[지붕] "고객의 데이터 안전이 무엇보다 우선입니다. 인지 즉시 조치에 착수했습니다."

[기둥1 · 사실]      [기둥2 · 조치]        [기둥3 · 예방]
○월○일 ○시 비정상   영향 가능 고객에     외부 보안기관
접근 인지·즉시 차단. 24h 내 개별 통지 +   전면 감사 착수,
현재 확인된 노출은   비밀번호 재설정      결과 투명 공개 +
이메일·연락처, 결제  안내 발송.           재발방지책 ○일 내
·비밀번호는 미포함.                        공표.

[토대]
- 인지 시각 ○시 / 차단 완료 ○시 / 최초 공지 ○시 (타임라인 명시)
- 노출 범위: ○○건으로 한정(현재까지 확인)
- 감사 기관: (제3자 기관명) / 규제기관 신고: ○월○일 완료
```

## (c) 홀딩 스테이트먼트(1차 성명) 템플릿 + 골든아워 체크리스트

**홀딩 스테이트먼트 = "인지함 + 진지하게 다루는 중 + 다음 업데이트 시점"** 세 요소의 짧은 사실 확인문. 추측·책임 판정·상세 원인은 담지 않는다. 정보 공백을 루머가 채우기 전에 "노 코멘트도 침묵도 아닌 길"을 내는 것이 목적(Stealing Thunder 원리 — 남이 터뜨리기 전에 우리가 먼저).

### 빈 템플릿
```
[회사명]은 [○월○일 ○시경 발생한 / 제기된] [사안]을 인지하고 있습니다.
저희는 이 문제를 매우 심각하게 받아들이며, [즉시 취한 조치 1개]에 착수했습니다.
현재 [사실관계를 확인 / 관계기관과 협력]하고 있으며, 확인되는 대로 투명하게
공유하겠습니다. [영향받으신 분들께 / 고객께] 깊은 유감을 표합니다.
추가 업데이트는 [○시 / ○시간 내]에 드리겠습니다.

문의: [스포크스퍼슨/창구] [연락처]
```

### 작성 규칙 (holding statement)
- **확인된 사실만.** 원인·책임·피해 규모가 미확정이면 "확인 중"으로 명시 — 숫자를 지어내지 않는다.
- **반드시 "다음 업데이트 시점"을 약속하고 지킨다.** 이게 통제권 신호. 어기면 신뢰 붕괴.
- **"노 코멘트" 금지.** 대중은 "숨긴다"로 읽는다. 할 말이 없으면 "현재 확인 중이며 ○시에 업데이트"라고 말한다.
- **조건부 사과 금지.** "불편을 드렸다면"이 아니라 "유감을 표합니다"(사실 판정 전이라도 공감은 무조건 가능).
- 채널: 영향 당사자 개별 통지 + 공개 채널(홈/뉴스룸/SNS) **동시**. 언론엔 단일 창구.

### 골든아워 체크리스트 (첫 60분 ~ 첫 몇 시간)
> IPR·PRSA 실무 권장 — "발명자 없는" 관습. 위기 인지 즉시 순서대로.

- [ ] **팩트 확보**: 무엇이/언제/어디서/누구에게. 확인된 것 vs 미확인을 분리한 1장 팩트시트.
- [ ] **위기팀 소집**: 의사결정자·법무·PR·운영·(필요시)보안. 단일 지휘 체계.
- [ ] **스포크스퍼슨 1인 지정** + 백업 1인. 승인 라인 확정("이 말은 누가 OK하나").
- [ ] **법적·규제 통지 의무 확인**: 개인정보 유출 신고 등 → 법무/컴플라이언스 즉시 확인(→ dev-privacy-compliance / life-legal).
- [ ] **이해관계자 우선순위**: 피해 당사자 > 직원 > 규제기관 > 언론 > 일반. **직원이 언론보다 먼저 알게** 한다(내부가 뒤늦으면 유출·엇박).
- [ ] **instructing information**: 추가 피해를 막을 즉시 지침이 있으면 최우선 공지("사용 중지하세요").
- [ ] **홀딩 스테이트먼트 발행**: 위 템플릿. "인지+조치+업데이트 시점".
- [ ] **모니터링 시작**: 언론·SNS·검색 실시간 추적, 루머·오보 목록화.
- [ ] **다크사이트/공지 페이지** 준비: 상세 업데이트를 올릴 단일 진실 소스(single source of truth).
- [ ] **내부 정렬**: 전 직원에 "대외 문의는 창구로" + 승인된 핵심 메시지 공유.

## (d) 보도자료 구조 템플릿 (역피라미드 · 구성요소)

**역피라미드**: 가장 중요·뉴스가치 높은 정보가 맨 위, 아래로 갈수록 세부. 기자가 어디서 잘라도 핵심이 살아남게. 1페이지·300~500단어 권장.

### 구성요소 (위→아래)
| 요소 | 내용 | 규칙 |
|---|---|---|
| **릴리스 표기** | `배포 즉시(FOR IMMEDIATE RELEASE)` 또는 `엠바고: ○월○일 ○시까지` | 최상단 |
| **헤드라인** | 핵심을 능동태로, 뉴스가치 강조 | 짧게(10단어/100자 내), 제목형 |
| **서브헤드(선택)** | 헤드라인 보완 한 줄 | |
| **데이트라인** | `도시(대문자), 날짜 —` 로 리드 시작 | 국내는 `서울, 2026년 7월 1일 —` |
| **리드(첫 문단)** | **5W1H**(누가·무엇을·언제·어디서·왜·어떻게)를 50~75단어에 | 가장 중요한 사실 |
| **본문** | 리드 부연 + **인용문 2개 이상**(자사 1 + 제3자/전문가 1) + 근거·수치 | 짧은 문단(2~3문장) |
| **보일러플레이트** | 회사 소개 "About [회사명]" 표준 단락 | 매 릴리스 동일하게 재사용 |
| **연락처** | 미디어 담당자 이름·이메일·전화 | 하단 |
| **종료 표기** | `###` 또는 `-끝-` | 본문 끝 |

### 빈 템플릿
```
배포 즉시

[헤드라인 — 능동태·핵심·10단어 내]
[서브헤드 — 보완 한 줄 (선택)]

서울, 2026년 7월 1일 — [리드: 누가 무엇을 언제 어디서 왜/어떻게. 50~75단어로
가장 중요한 사실 하나를 완결.]

[본문 1문단: 리드 부연 — 배경·규모·의미.]

"[자사 인용문 — 대표/책임자 코멘트, 왜 중요한지]," [직책 이름]이 말했다.

[본문 2문단: 근거·수치·세부.]

"[제3자/고객/전문가 인용문 — 객관성 부여]," [직책 이름]이 덧붙였다.

[본문 3문단: 다음 단계·가용성·추가 정보 링크.]

About [회사명]
[보일러플레이트: 회사 소개 3~4문장. 설립·사업·규모·비전. 매 릴리스 동일.]

미디어 문의: [이름] / [이메일] / [전화]

###
```

### 보일러플레이트 예시
```
About 코르누코피아
코르누코피아는 2024년 설립된 AI 솔루션 기업으로, [핵심 사업 한 줄]을 제공합니다.
[대표 제품/서비스]를 통해 [고객군]이 [핵심 가치]를 달성하도록 돕습니다.
자세한 정보는 [웹사이트]에서 확인할 수 있습니다.
```

> 위기 상황의 대언론 자료는 보도자료가 아니라 (c)의 **홀딩 스테이트먼트/입장문** 형식을 쓴다. 보도자료는 런칭·발표 등 능동적 뉴스에.

## (e) 스포크스퍼슨 · 미디어 대응 Do / Don't

**용어(사전에 기자와 합의해야 성립)**
- **On the record**: 이름·직책 인용 가능(기본값). 명시적으로 바꾸지 않으면 모든 발언은 on record.
- **On background**: 인용 가능하나 소속만 표기("회사 관계자"). 사전 합의 필요.
- **Off the record**: 보도 불가·배경 이해용. **기자가 동의해야 성립** — 말한 뒤 "이건 오프"는 무효. 신뢰 없는 기자에겐 쓰지 말 것.

### 스포크스퍼슨 Do
- **핵심 메시지(메시지 하우스 3기둥)를 미리 정하고 연습.** 어떤 질문이 와도 되돌아올 세 지점.
- **정직·투명.** 신뢰가 최우선 자산. 모르면 "지금은 모른다, 확인해 회신하겠다".
- **브리징(bridging)**: 곤란한 질문 → "그 부분은 ~, 중요한 것은 [핵심 메시지]입니다"로 자연스럽게 전환.
- **공감 먼저, 사실 다음.** 피해자가 있으면 사람 이야기부터.
- **인터뷰 전 준비**: 매체·기자·독자·포맷·시간 파악, 장비 점검, 일찍 도착.
- **간결하게, 한 번에 하나씩.** 짧은 문장이 정확히 인용된다.
- **어려운 질문 리허설**(적대적 Q 포함) — 예상 Q&A를 소리 내어.

### 스포크스퍼슨 Don't
- **"노 코멘트" 금지.** 숨긴다는 신호. 대신 "현재 확인 중, ○시 업데이트".
- **가정형 질문에 답 금지**("만약 ~라면?"). "가정에는 답하지 않겠다, 확인된 것은 ~".
- **스핀(억지 포장) 금지.** 나중에 풀리면 더 큰 역풍.
- **공표 원치 않는 말은 입 밖에 내지 말 것.** 오프더레코드는 지켜지지 않을 수 있다고 가정.
- **필요 이상 세부 금지.** 말이 많을수록 실수·새 헤드라인 생성.
- **화·방어·논쟁 금지.** 침착·전문. 기자와 싸우지 않는다.
- **추측·미확인 수치 금지.** 틀리면 2차 위기.

### 미디어 관계 실무 (do/don't)
| Do | Don't |
|---|---|
| 기자의 영역·담당·독자를 알고 맞춤 피칭 | 무차별 대량 배포·스팸 피칭 |
| 평소에 가치 있는 정보·관계를 장기 구축 | 위기·필요할 때만 연락 |
| 마감·리듬 존중, 신속 회신 | 마감 임박에 압박·재촉 |
| 오보엔 정중한 정정 요청 + 팩트시트 | 공개 비난·기자 공격 |
| 단일 창구·일관 메시지 | 부서·임원마다 다른 말(엇박) |
| 배타적 소재는 적합한 한 곳에 | 같은 "독점"을 여러 곳에 |

### 사과문 구성요소 (Rebuild 상황)
`유감 표명 → 무엇이 잘못됐는지 설명 → 책임 인정 → 시정·재발방지 → (필요시) 보상 → 재발방지 약속`.
❌ 조건부("불편을 드렸다면")·수동태·희생양 돌리기 → 진정성 훼손, 분노 증폭.
✅ "저희가 ~를 잘못했습니다. 영향받으신 ~께 사과드리며, ~를 즉시 시행하고 ~로 재발을 막겠습니다."
