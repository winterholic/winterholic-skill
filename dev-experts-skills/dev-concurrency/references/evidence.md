# dev-concurrency evidence — 장애·실증 사례

## 1. Therac-25 (1985~87) — 소프트웨어 공학 전체의 경고비 (Leveson 공식 조사)

- **무슨 일**: 방사선 치료기 과조사 6건(사망 3+). Nancy Leveson의 조사 보고가 표준 문헌. 동시성 관련 핵심: 조작자가 화면에서 모드를 빠르게 수정하면(8초 내) 입력 처리 태스크와 장비 셋업 태스크의 비동기 실행이 어긋나 — UI는 전자빔 모드, 장비는 고출력 X선 모드로 불일치. 공유 변수에 동기화 없음.
- **구조적 교훈**:
  1. **발현 조건이 '숙련'**: 빠른 입력 = 좁은 타이밍 창 진입 — 테스트(천천히 조작)는 통과, 베테랑 조작자가 트리거. 동시성 버그의 발현 분포는 사용 숙련도와 함께 이동한다.
  2. **단일 방어층**: 이전 모델의 하드웨어 인터락 제거로 소프트웨어 버그가 곧 사고 — 안전 불변식은 독립 층 이중화.
  3. **"재현 불가" 종결의 죄**: 간헐 보고를 일축한 대응이 사고를 누적시켰다 — 간헐+부하/타이밍 의존은 동시성 수사 개시 신호다.

## 2. 이중 처리 사고 — check-then-act의 돈 버전 (운영 표준 패턴)

- **무슨 일**: 결제·포인트·재고에서 반복되는 표준 사고 — "잔액 확인 → 차감" 두 쿼리 사이에 동시 요청이 끼어 이중 사용. 사용자가 버튼 연타·새로고침만 해도 발생(악의 불필요). 커뮤니티·감사 보고에 무수히 반복.
- **방어 서열**: ① DB 원자 연산으로 합치기(`UPDATE balance SET v = v - ? WHERE id = ? AND v >= ?` — 영향 행 0이면 거부) ② 유니크 제약 기반 멱등 키(같은 요청 ID 재진입 차단 — dev-payments·dev-event-driven 연결) ③ 행 잠금(`SELECT FOR UPDATE`)은 정합 요구 높고 경합 낮을 때.
- **검증**: 동시 50발 테스트가 유일한 그물 — "잔액 10,000원 계좌에 6,000원 출금 50발 동시 → 성공은 정확히 1건" 단언.

## 3. Python GIL 오해 — "스레드 늘렸는데 더 느려요" (도구 미스매치 실증)

- **무슨 일**: CPU 작업(파싱·계산)을 ThreadPoolExecutor로 병렬화 → 속도 동일 또는 악화. GIL이 바이트코드 실행을 한 번에 한 스레드로 제한하므로 CPU 작업은 병렬이 아니라 교대 실행 + 스위칭 비용. 반대로 IO 작업은 GIL이 대기 중 해제되므로 스레드가 유효 — 같은 도구가 부류 따라 정반대 결과.
- **판정표**: CPU 바운드 → multiprocessing/네이티브 확장(numpy 내부는 GIL 밖) / IO 바운드 → async 또는 스레드. (참고: free-threaded 빌드가 GIL 제거를 진행 중이나 기본 빌드 기준은 여전히 유효 — 버전별 확인 필요.)
- **이 스킬과의 연결**: 안티패턴 4. "병렬화했는데 안 빨라짐"의 진단 1순위는 코드가 아니라 부류 판정이다 — 측정(CPU 사용률)이 답을 즉시 준다.

> 출처(전부 2026-06 재확인):
> - Leveson & Turner, "An Investigation of the Therac-25 Accidents", *IEEE Computer* 26(7), 1993, pp.18-41 (DOI 10.1109/MC.1993.274940) — 사고 조사의 표준 1차 문헌. 8초 자석 셋업 창·`Datent`/`Magnet`/`Ptime` 공유 변수 경쟁·Therac-20 하드웨어 인터락 비교가 여기서 나온다. 공개 PDF: users.csc.calpoly.edu/~csturner/courses/508/Therac-25.pdf
> - 이중 처리(check-then-act) 사고 패턴 — 결제/재고 도메인의 표준 사고로 감사·커뮤니티에 반복 집적(스킬 본체가 근거).
> - Python GIL·free-threading: docs.python.org/3/howto/free-threading-python.html — 공식 문서. free-threaded 빌드는 3.13 실험적 → 3.14에서 PEP 779로 "공식 지원이나 여전히 선택적(기본 빌드는 GIL 유지)". 따라서 본문의 GIL 전제는 기본 빌드 기준이며, free-threaded 빌드에서는 달라진다.
