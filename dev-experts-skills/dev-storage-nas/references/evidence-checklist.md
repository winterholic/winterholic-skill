# evidence + 출고 전 체크리스트

> 장애·실증 사례 본문은 같은 폴더 `evidence.md`(WD Red SMR 침묵 혼입 · RAID5 리빌드 수학/URE · Backblaze 통계 활용). 이 파일은 출처 색인 + 출고 체크 + 점검 주기.

## 실증·출처

- **OpenZFS 2.3.0 릴리스** (openzfs.github.io, 2025-01) — RAIDZ 확장(기존 vdev에 디스크 단건 추가)·fast dedup·Direct I/O. 버전 라벨 + 확장 경로(SKILL 한계 절·작성 예시) 갱신의 1차 출처. 확인 필요: 풀이 2.3 기능 플래그로 생성/업그레이드됐는지.
- **Backblaze Drive Stats 2025** (backblaze.com/blog/backblaze-drive-stats-for-2025, 2026 초 공개, 13년 누적) — 모델별 연간 고장률(AFR)의 가장 큰 공개 표본. "연 ~1-2% 사망" 전제(정량 기준 표)·로트 분산(안티패턴 5)·SMART 재할당 섹터 예고력(안티패턴 6)의 실증 근거. 절대값보다 모델 간 상대 비교로 사용.
- **WD Red SMR 침묵 혼입 사태** (2020 공개 조사·집단소송, 2020~2021 합의) — NAS 라벨 디스크에 SMR 무표기 혼입 → ZFS 리실버/RAID 리빌드 탈락. 안티패턴 4(SMR 회피)·실전 케이스의 1차 출처. 이후 제조사 CMR/SMR 명시화의 계기. `evidence.md` §1.
- **RAID 신뢰성 문헌 (URE·리빌드 수학)** — 대용량 단일 패리티(RAID5/RAIDZ1) 리빌드 중 2차 고장·읽기 에러(URE) 확률. 안티패턴 2·정량 기준(8TB+ 미러/Z2)의 근거. `evidence.md` §2. (확인 필요: URE 수치는 제조사 스펙시트별 — 인용 시 해당 모델 데이터시트.)
- **OpenZFS 공식 문서 (scrub·ARC·SMART 연동)** — 월 1회 scrub·자가 치유·체크섬 의미(안티패턴 3). smartd/smartctl는 smartmontools 공식 문서.
- 오픈소스 차용 표기: 스토리지 가이드류 다수(색인 인지, 본문 비복사). **역흡수**: "RAID≠백업" 역할 분리 선언의 강제화·로트 분산을 안티패턴으로 명문화·`[확인 필요]` 4요소(잘못된 디스크 분리 방지) 절차 — 본 스킬 차별점.

## 출고 전 체크리스트 (스토리지 설계/구성 시)

- [ ] RAID 가용성 설계와 백업 경로(dev-backup-dr)를 같은 문서에 별도 선언 — "RAID 있으니 백업됐다" 없음
- [ ] 8TB+ 디스크는 미러/RAIDZ2 기본 — RAIDZ1은 근거(소용량·백업 충실) 명시
- [ ] 구매 전 CMR 스펙시트 확인 (SMR은 RAID 풀 배제, 아카이브 단독만)
- [ ] 디스크 로트 분산 (구매 시점/판매처/모델) + 어차피 죽는다 전제의 조달 계획
- [ ] scrub 월 1회 스케줄 + 결과 알림(dead man's switch)
- [ ] SMART 일 단위 점검(재할당/펜딩 섹터 추세 0) + 풀 사용률 80% 경보 + 온도
- [ ] 디스크 분리 전 시리얼 대조(smartctl -i / LED) — 엉뚱한 디스크 탈락 방지
- [ ] 사망 리허설(디스크 1개 분리→리실버) 평시에 1회 수행
- [ ] 풀 구성 명령 기록 보존 (재구축 가능성)

## 점검 주기 (부패 느림 — 연 1회)

- OpenZFS 메이저/마이너 추적(현 2.3.x) — RAIDZ 확장·dedup 같은 운용 옵션 변화만 라벨 갱신
- Backblaze 최신 연간/분기 Drive Stats로 후보 모델 AFR 재확인(매 구매 전 + 연 1회)
- 디스크 용량 인플레이션(리빌드 창 확대)에 따른 단일 패리티 임계(현 ~8TB) 재검토 — 용량이 커질수록 Z1 안전 마진은 매년 감소
- 제조사 CMR/SMR 표기 정책·신규 침묵 혼입 보도 모니터링(2020 사태의 재발 감시)
