# TDD 리듬 각론 — 구현 3전략·보폭 조절·TODO 운용 (SKILL.md 비중복)

## green을 만드는 3전략 (벡 원전)

| 전략 | 언제 | 형태 |
|---|---|---|
| **가짜 구현 (Fake It)** | 불안하거나 막혔을 때 (기본값) | `return 150` 하드코딩 — 일단 green |
| **삼각측량 (Triangulation)** | 일반화가 맞는지 확신 없을 때 | 두 번째 예시 테스트 추가 → 하드코딩 2개가 모순 → 공식 도출 |
| **명백한 구현 (Obvious)** | 확신할 때 | 바로 진짜 구현 — 단 red가 뜨면 즉시 보폭 축소로 후퇴 |

리듬의 본질은 **전략 전환**이다: 명백한 구현으로 달리다 → 예상 밖 red → 가짜 구현으로 후퇴 → 삼각측량으로 재일반화. 항상 같은 보폭으로 걷는 게 아니라 노면에 따라 기어를 바꾼다.

## 보폭 신호 (언제 좁히고 언제 넓히나)

- **좁혀라**: red가 5분+ 지속 · 실패 원인 후보가 2개 이상 · "아마 되겠지"로 구현 중 · 디버거를 열고 싶어짐.
- **넓혀라**: 사이클이 기계적 반복으로 느껴짐 · 같은 패턴 3번째 — 명백한 구현으로 전환 + parametrize로 묶기(dev-testing).
- 막힌 상태에서 코드를 늘리는 것이 최악 — 마지막 green 커밋으로 되돌리고(`git checkout .` 전에 stash 고려) 더 작은 스텝으로 재진입. **사이클당 커밋**이 이 후퇴를 싸게 만든다.

## TODO 리스트 운용

- 형식: 행동 한 줄("빈 주문 합계 0", "naive 타임스탬프 거부"). 구현 항목("DB 연결 만들기")이 아니라 **관찰 가능한 행동**으로 적는다.
- 작업 중 떠오른 것은 즉시 리스트에 추가하고 현재 사이클로 복귀 — 머릿속 스택을 리스트로 비우는 것이 리듬 유지의 핵심.
- 고르는 순서: ① 가장 배우는 게 많은 것 ② 가장 쉬운 것 — 막혔으면 무조건 ②.
- 리스트가 한 세션에 안 끝나면 그대로 핸드오프 재료가 된다(WIP 상태가 자동 문서화).

## 첫 테스트 고르기 (스타터 패턴)

1. **퇴화 케이스(degenerate)**: 빈 것·0·요소 1개 — "빈 포트폴리오의 평가액은 0". 구현이 한 줄로 green.
2. 그 다음 **대표 정상 1개** → 삼각측량.
3. 예외·검증 케이스는 정상 경로가 선 다음에 — 처음부터 에러 처리로 시작하면 인터페이스가 방어 코드로 굳는다.

## 테스트 목록과 커밋 리듬 예시

```
git log --oneline (이상적 보폭의 흔적):
  a3f1 test: empty portfolio totals zero
  b7c2 test: single tick portfolio
  c9d4 refactor: extract Money value object
  d2e8 test: reject naive timestamp
```

- 커밋 메시지에 사이클이 보이면 리뷰어가 설계 의도를 재생할 수 있다.
- refactor 커밋은 행동 변화 0이어야 한다 — 테스트 수정이 같이 들어가면 그건 리팩터가 아니라 행동 변경.

## async·I/O 코드의 TDD

- 코어 로직을 순수 함수로 뽑아내는 것 자체가 TDD의 압력이다 — "await 없이 테스트 가능한가?"가 설계 질문.
- 외부 I/O 경계는 스파이크로 형태 파악 → 경계 인터페이스 확정 → 그 인터페이스의 Fake(dev-testing 더블 분류)로 코어를 TDD → 경계 자체는 통합 테스트.
