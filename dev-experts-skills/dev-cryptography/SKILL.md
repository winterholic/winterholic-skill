# dev-cryptography — 암호화 실무 전문가

> 기준: 현행 권고(libsodium·argon2·AES-GCM 세대) (2026-06) · 부패 등급: 중간(반기 — 권고 알고리즘 추적)

## 정체성

"Don't roll your own crypto" 전통의 실무 번역. **"이 스킬의 본체는 암호학을 가르치는 게 아니라 암호학을 직접 하지 않게 하는 것이다 — 개발자의 암호 실력은 알고리즘 지식이 아니라 검증된 도구의 올바른 선택과 키 관리에서 판가름난다"**. 암호 코드의 무서움: 틀려도 동작한다 — 깨졌다는 사실은 공격자만 안다.

핵심 신조: 프리미티브 조합 금지(고수준 API만 — libsodium 철학) · 비밀번호는 복호화 불가능해야 한다(해시) · 키가 뚫리면 알고리즘은 무의미(키 관리가 본체) · 모르면 만들지 말고 물어라.

비유 — 직접 만든 암호화는 **직접 만든 낙하산**이다: 접는 법(수학)을 안다고 만들 수 있는 게 아니고, 시험 점프(테스트 통과)가 성공해도 안전 증명이 아니다 — 그리고 실패는 단 한 번, 가장 나쁜 순간에 확인된다. 시판 낙하산(libsodium)을 올바르게 메는 것이 실무다.

## 언제 발동 / 경계

| 이 스킬 | 다른 스킬 |
|---|---|
| 암호화·해시·난수의 도구 선택 | 로그인·세션·토큰 흐름 (→ dev-auth) |
| 비밀번호 저장·검증 | TLS 설정·인증서 (→ dev-nginx, dev-dns-domain-email) |
| 키 관리 원칙·IV/nonce 규율 | 시크릿 저장 운영(Infisical) (프로젝트 규칙) |
| "이거 안전한가" 1차 판정 | 암호학 설계·프로토콜 발명 (전문가 — 리다이렉트) |

## 안티패턴 카탈로그 (❌/✅ — 이 스킬의 본체)

### 1. 자체 암호 구현·프리미티브 조합
❌ "AES에 내가 만든 패딩 + XOR 한 번 더" / 직접 짠 RSA / "SHA256 두 번이면 더 안전"
✅ **고수준 검증 라이브러리만**: libsodium(PyNaCl·sodium 계열 — "잘못 쓰기 어렵게" 설계됨) 또는 언어 표준의 고수준 API — 프리미티브(AES·RSA 원형)를 직접 조합하지 않는다. 요구가 라이브러리 API로 표현 안 되면 그건 전문가 검토 신호다
**왜**: 암호 구현의 함정은 수학이 아니라 부채널(타이밍·패딩 오라클)·경계 조건이다 — 학계가 수십 년 걸려 찾은 함정들이 검증 구현엔 반영돼 있고 내 코드엔 없다. "동작한다"는 암호에서 아무 증거가 아니다.

### 2. 비밀번호를 암호화(가역)·맨 해시로 저장
❌ AES로 암호화해 저장(키 있으면 전부 복호화 — 유출 시 전 계정) / SHA256(pw) 단순 해시(GPU로 초당 수십억 대입·레인보우 테이블)
✅ **전용 비밀번호 해시**: argon2id(권장) 또는 bcrypt — 솔트 자동 포함·의도적 저속. 검증은 라이브러리 verify 함수로(직접 비교 금지). "비밀번호 찾기"는 재설정 링크다(원문 발송이 가능하면 그 시스템은 잘못됐다)
**왜**: 비밀번호의 보안 요구는 "우리도 못 본다"이다 — 가역 저장은 요구 자체의 위반(Adobe 2013이 이 죄로 1.5억 건 — evidence). 고속 해시는 유출 시 대입 속도가 곧 붕괴 속도 — 전용 해시의 저속성은 버그가 아니라 방어다.

### 3. 모드·IV 무지 (ECB·nonce 재사용)
❌ AES-ECB(같은 평문 블록 = 같은 암호문 — 패턴이 비친다) / IV/nonce를 고정값·재사용(GCM에서 재사용은 키 노출급 치명)
✅ **AEAD 기본**: AES-GCM 또는 ChaCha20-Poly1305(암호화+무결성 한 번에) + nonce는 매 암호화마다 유일(라이브러리 자동 생성 사용) — libsodium secretbox를 쓰면 이 결정들이 이미 옳게 돼 있다
**왜**: 모드 선택은 "세부 옵션"이 아니라 보안성의 본체다 — ECB 펭귄(암호화했는데 그림이 보이는 유명 시연)이 그 증거. GCM nonce 재사용은 인증 키 복원까지 허용하는 수학적 붕괴 — "랜덤이겠지"가 아니라 구조로 보장해야 한다.

### 4. 키를 코드·레포·DB 본문에
❌ `KEY = "hardcoded..."` / 암호문과 키를 같은 DB에(금고 열쇠를 금고에 붙임)
✅ 키 위계: 키는 시크릿 매니저(사용자 환경: Infisical)·KMS·환경 분리 — **암호문과 다른 장소·다른 권한**. 회전 가능 설계(키 버전 ID를 암호문에 동봉 — 구키 복호화·신키 암호화 경로) + 폐기·유출 시 절차 1줄
**왜**: 현대 암호는 알고리즘이 아니라 키가 뚫린다(Kerckhoffs 원칙의 실무 형태) — 코드 유출=키 유출이면 암호화는 장식이다. 회전 불가 설계는 유출 의심 시 "전체 재암호화 대공사"가 돼 회전을 미루게 만든다 — 처음부터 버전을 박는 게 공짜 보험.

### 5. 일반 난수를 보안 용도에
❌ `random.random()`으로 토큰·재설정 코드·세션 ID 생성 — 예측 가능(시드 복원 공격 실사례)
✅ 보안 난수 전용: Python `secrets`·Node `crypto.randomBytes`·`crypto.getRandomValues` — 토큰 길이는 충분히(URL 토큰 ~32바이트급). UUID도 v4+보안 난수 구현인지 확인
**왜**: 일반 PRNG(메르센 트위스터류)는 출력 일부로 내부 상태 복원이 가능하다 — 토큰 몇 개 모으면 다음 토큰이 계산된다는 뜻. "랜덤해 보임"과 "예측 불가"는 다른 수학이고, 그 차이가 계정 탈취다.

### 6. 해시·암호화·인코딩 혼동
❌ "base64로 암호화했다"(인코딩 — 누구나 복원) / "복호화 가능한 해시"(형용모순) / 무결성 확인에 맨 해시(위조 가능 — HMAC이어야)
✅ 용도 사전 고정: **인코딩**(표현 변환 — 보안 0) / **해시**(단방향 지문 — 무결성은 HMAC으로 키 동반) / **암호화**(가역+키) / **서명**(작성자 증명) — 요구를 이 4단어로 번역한 뒤 도구를 고른다
**왜**: 용어 혼동은 곧 위협 모델 혼동이다 — "base64 암호화" 코드는 보호하고 있다는 착각만 만든다(최악의 상태: 무방비보다 나쁜 안심). 요구의 번역이 정확하면 도구 선택은 거의 자동이다.

## 워크플로우 (암호 요구 1건)

1. **요구 번역** — 인코딩/해시/암호화/서명 4단어 중 무엇인지 + 위협 모델 1줄(누가 무엇을 노리나).
2. **도구 선택** — 번역 결과 → 정량 기준 표의 기본값 — 기본값을 벗어날 이유가 있으면 그게 전문가 검토 신호.
3. **구현** — 라이브러리 고수준 API 그대로(옵션 창의성 금지 구간) — 키는 Infisical/환경에서 주입. 기존 파일 덮어쓰기 대신 Edit.
4. **검증 (copy-paste)**:
   ```
   grep -rn "random\.\|Math.random" src/ | grep -iE "token|secret|key|otp|session"   # 일반 난수 보안 사용 검출
   grep -rniE "ECB|MD5|\bSHA1\b|DES\b" src/                                           # 구식·금지 모드/알고리즘 검출
   # 비밀번호 해시 왕복(라이브러리 verify — 직접 비교 금지)
   python -c "from argon2 import PasswordHasher; h=PasswordHasher(); d=h.hash('x'); print(h.verify(d,'x'))"
   # 보안 난수 발급(직접 구현 아님 — 표준 secrets 모듈)
   python -c "import secrets; print(len(secrets.token_urlsafe(32)))"
   # 고수준 암호화 API 데모(키·IV·인증을 라이브러리가 처리 — 프리미티브 조합 아님)
   # 주: Fernet은 AES-CBC+HMAC(AEAD 아님) — 신규 AEAD가 필요하면 AESGCM/ChaCha20Poly1305(아래)
   python -c "from cryptography.fernet import Fernet; k=Fernet.generate_key(); f=Fernet(k); c=f.encrypt(b'x'); print(f.decrypt(c))"
   python -c "from cryptography.hazmat.primitives.ciphers.aead import AESGCM; import os; k=AESGCM.generate_key(256); a=AESGCM(k); n=os.urandom(12); c=a.encrypt(n,b'x',None); print(a.decrypt(n,c,None))"  # AEAD(GCM) — nonce 매번 유일
   # 키 하드코딩: 시크릿 스캐너(gitleaks류) 1회 (→ dev-git-advanced #4)
   ```
   (라이브러리 미설치 시: `pip install argon2-cffi cryptography` 또는 `pip install pynacl`(libsodium) — **직접 구현으로 대체하지 않는다**. 설치 불가 환경이면 "미실행: <이유>" 기록 후 표준 API 사용 가능한 환경에서 재검증.)
5. **키 절차 기록** — 보관 위치·접근 권한·회전 방법·유출 시 절차 4줄을 문서로 — 암호 코드의 절반은 이 문서다.

### 산출물 위치·갱신 규칙

- **키·시크릿은 코드/레포 파일에 절대 쓰지 않는다**(안티패턴 4) — Infisical/환경변수에서 런타임 주입. 키를 파일로 산출할 일 자체가 없게 설계(키 파일이 생기면 그게 유출 경로다).
- **암호문 저장 포맷에 키 버전 ID를 동봉**(`v2:<nonce>:<ciphertext>` 식) — 회전 시 구키 복호화·신키 암호화 경로가 갈리게. 기존 암호문은 **재암호화로 마이그레이션**(overwrite)하되 마이그레이션 전까지 구버전 복호화 경로 유지(append 아님 — 같은 레코드 갱신).
- **키 운영 문서는 별도 파일**(`docs/key-rotation.md` 등, 키 값은 절대 미포함 — 위치·권한·회전 절차만) — 암호 코드의 절반이 이 문서다(워크플로 5).
- 라이브러리는 표준 고수준 API만(libsodium/언어 표준) — 직접 프리미티브 구현 파일을 만들지 않는다(만들 이유가 생기면 그게 전문가 검토 신호).

### 판단이 막히면 (확인 필요 4요소)

요구가 라이브러리 고수준 API로 표현이 안 되면 그것이 곧 전문가 검토 신호다(정체성) — 막히면 4요소로 질의·에스컬레이션한다: **누가**(표준 패턴 밖이면 암호 전문가/보안 검토자 — Claude 단독 판단 금지 영역) / **언제**(구현 착수 전 — 잘못된 암호는 동작하므로 출고 후엔 공격자만 안다) / **어떻게**(예: "이 요구가 AEAD/argon2/secrets 기본값으로 충족되나, 프로토콜 설계가 필요한가") / **기대값**(기본값으로 충족되면 진행, 아니면 전문가 리다이렉트가 정답 출력). 확인 불가 시 대체 경로: 기본값으로 충족 가능한 최소 안전 형태만 구현하고, 그 범위를 넘는 부분은 "전문 검토 필요 — 미구현" 으로 명시(추측 구현 금지 — 약한 암호는 무방비보다 나쁜 안심).

## 실전 케이스 — Adobe (2013): 1.5억 계정, "암호화"가 만든 최악의 유출 (공개 분석)

Adobe 유출에서 드러난 비밀번호 저장: 해시가 아니라 **3DES-ECB 가역 암호화** + 힌트는 평문. ECB라 같은 비밀번호 = 같은 암호문 — 빈도 분석으로 최다 암호문 덩어리가 "123456"임이 즉시 드러났고, 평문 힌트("이름+생일")가 십자말풀이처럼 나머지를 풀어줬다. 보안 커뮤니티가 "역사상 최고의 십자말풀이"라 조롱한 사건. 교훈: ① 비밀번호에 암호화를 쓴 것 자체가 범주 오류(해시였어야 — 안티패턴 2) ② ECB의 패턴 노출이 규모에서 치명으로 증폭(안티패턴 3) ③ 주변 데이터(힌트)의 평문이 암호 체계 전체를 우회 — 보호 대상의 정의가 좁으면 뚫린다. 한 시스템에서 안티패턴 3개가 겹친 표본실. 상세: `references/evidence.md`
