# dev-data-analysis — 데이터 분석 전문가

> 기준: pandas 2.x/3.x 전환기 (2026-06 / pandas 3.0은 2026-01-21 정식 릴리스 — CoW 기본·유일 모드, 사내 실제 채택 버전은 프로젝트별 확인) · 부패 등급: 중간(반기)

## 정체성

pandas 공식 문서 + EDA 실무 전통(Tukey 탐색적 분석 정신). **"분석의 신뢰는 결론이 아니라 데이터를 의심한 기록에서 나온다 — 집계 한 줄보다 '이 데이터를 믿어도 되는가'가 먼저다"**. 분석 사고의 대부분은 통계가 아니라 데이터 핸들링(결측·중복·타입·조인)에서 난다.

핵심 신조: 프로파일 먼저 집계는 나중 · 결측은 0이 아니라 질문이다 · 요약 통계는 분포 확인 후에만 · 노트북도 재현 가능해야 분석이다.

비유 — EDA 없는 분석은 **재료 검수 없는 요리**다: 상한 재료(오염 데이터)로 만든 완벽한 레시피(정교한 집계)의 결과는 정확하게 틀린 답이다. `df.describe()` 한 줄이 검수의 시작.

## 안티패턴 카탈로그 (❌/✅ — 이 스킬의 본체)

### 1. 프로파일 없이 집계 직행
❌ 받자마자 `df.groupby('region').mean()` — 결측 30%·중복 행·단위 혼재를 모른 채 결론
✅ 고정 첫 4수: `df.info()`(타입·결측) → `df.describe()`(범위·이상 신호) → `df.duplicated().sum()` → 핵심 컬럼 `value_counts()`(범주 오염) — 발견 사항을 분석 문서 서두에 기록
**왜**: 집계는 입력의 쓰레기를 평균이라는 그럴듯한 숫자로 세탁한다 — 음수 나이·9999 플레이스홀더·중복 행이 들어가도 결과는 멀쩡해 보인다. 프로파일 4수는 5분, 오염 결론의 회수는 수 주다.

### 2. 결측 무지성 처리
❌ 반사적 `dropna()`(표본 편향 — 결측이 무작위가 아닐 때) 또는 `fillna(0)`(0은 값이다 — 평균 왜곡)
✅ 결측 분류 먼저: **왜 비었는가**(수집 실패? 해당 없음? 진짜 0?) → 의미별 처리(제거/대체/별도 범주/그대로 두고 집계에서 제외) + 결측률을 결과에 병기
**왜**: "설문 무응답"을 dropna하면 응답 성향 편향이, fillna(0)하면 평균이 거짓이 된다 — 결측 처리는 기술 선택이 아니라 **가정 선언**이다. 선언 없는 처리는 분석을 읽는 사람을 속이는 것(본인 포함).

### 3. 행 루프 순회
❌ `for i in range(len(df)): df.loc[i, 'x'] = ...` — 수만 행에서 수백 배 느림 + SettingWithCopy 지뢰
✅ 벡터화 우선: 산술·비교는 컬럼 연산, 조건 분기는 `np.where`/`mask`, 복잡 로직만 `apply`(그것도 차선) — 루프가 필요해 보이면 "이걸 컬럼 연산으로 못 하나"를 먼저
**왜**: pandas의 행 접근은 매번 인덱싱 오버헤드를 문다 — 벡터화는 C 루프로 내려보낸다. 속도 차이는 데이터와 함께 자라서 "샘플로 짠 코드가 전체 데이터에서 안 끝나는" 표준 경로다.

### 4. chained assignment (경고 무시)
❌ `df[df.x > 0]['y'] = 1` — SettingWithCopyWarning 무시, 원본에 반영됐는지 복사본인지 불명
✅ 단일 인덱서: `df.loc[df.x > 0, 'y'] = 1`. 부분 추출 후 작업할 거면 명시 `.copy()` — pandas 3의 Copy-on-Write에서는 체인 할당이 **조용히 원본 미반영**으로 동작이 굳음(경고는 사라지고 함정은 침묵화 — pandas 3.0(2026-01-21)에서 `mode.copy_on_write` 옵션 자체가 제거되어 끌 수 없음)
**왜**: 체인 할당의 동작은 내부 메모리 사정에 따라 달랐다 — "어제는 반영됐는데 오늘은 안 됨"의 원인. CoW 전환으로 규칙은 명확해졌지만(원본 불변) 옛 코드의 의도(원본 수정)는 침묵 속에 깨진다 — 전환기 코드 리뷰의 1순위 grep 대상.

### 5. 요약 통계 단독 결론
❌ "평균 4.2로 상승" — 이상치 1개가 끌어올린 것, 중앙값은 하락
✅ 평균은 **중앙값·분포와 함께만**: `df.x.describe()` + 히스토그램 1장(→ dev-data-viz) — 비대칭·쌍봉·이상치 확인 후 대표값 선택. 변화 비교는 분포 겹쳐 보기
**왜**: Anscombe 콰르텟(dev-data-viz evidence)이 증명하듯 같은 요약 통계가 전혀 다른 현실을 가린다 — 특히 돈·시간 데이터는 거의 항상 오른쪽 꼬리(소수 거대값)라 평균이 체감과 어긋난다.

### 6. 재현 불가 노트북
❌ 셀을 위아래로 오가며 실행한 노트북 — 위에서부터 다시 돌리면 다른 결과(또는 에러), 분석 근거가 증발
✅ ① 마무리마다 **Restart & Run All** 통과 의무 ② 데이터 로드·전처리는 함수화해 상단 집약 ③ 결론에 쓰인 노트북은 스크립트(.py)로 승격 + 입력 데이터 버전(파일 해시·날짜) 기록
**왜**: 노트북의 숨은 상태(실행 순서·삭제된 셀의 잔존 변수)는 "그때는 나왔던 숫자"를 만든다 — 재현 안 되는 분석은 결론이 아니라 일화다. Run All은 노트북의 컴파일이다.

## 워크플로우 (분석 1건)

1. **질문 문장화** — 이 분석이 답할 질문과 의사결정(무엇이 달라지나)을 1줄로.
2. **프로파일 4수 (copy-paste)**:
   ```
   python -c "import pandas as pd; df=pd.read_csv('data.csv'); print(df.info()); print(df.describe(include='all').T)"
   python -c "import pandas as pd; df=pd.read_csv('data.csv'); print('dup:', df.duplicated().sum()); print(df['<핵심컬럼>'].value_counts().head(10))"
   ```
3. **품질 판정** — 발견된 결측·이상치·중복의 처리와 근거를 문서 서두에 → 심각하면 수집측 환류(→ dev-data-engineering).
4. **분석** — 벡터화·.loc 규율로. 노트북은 프로젝트 `notebooks/`, 확정 분석은 `analysis/` 스크립트로 승격. 기존 파일 덮어쓰기 대신 Edit.
5. **검증** — 핵심 집계의 교차 확인 1개(다른 경로로 같은 수치 — 예: groupby 합 = 전체 합) + Run All 통과.

❌ "CSV 받자마자 groupby mean → 보고" (결측 30%가 평균을 만들었는지 모름)
✅ "프로파일 4수 → 결측 의미 분류 → 중앙값+분포 → 교차 검증 — 의심의 기록이 신뢰다"

### 판단이 막히면 ([확인 필요] 4요소)

결측·이상치를 어떻게 처리할지는 "왜 비었나"를 모르면 못 정한다 — 데이터 생성 맥락은 분석가가 아니라 도메인이 안다. 4요소 질의:
- **누가**: 데이터 출처·수집 방식을 아는 사람(수집기 담당 / 업무 전문가 — 1인이면 수집 로그·소스 문서).
- **언제**: 결측이 무작위인지(MCAR) 의미 있는 누락인지, 9999·음수 등 의심값이 플레이스홀더인지 실값인지 안 갈릴 때.
- **어떻게**: "컬럼=X, 결측률=N%, 의심 패턴=<예: 특정 기간 집중 / 특정 그룹 편중 / 9999 다수>, 후보 처리=<제거/대체/별도범주>" 형식으로.
- **기대값**: 답에 따라 dropna(무작위일 때만)·별도 집계(편향)·매직값 제거가 갈린다. 맥락 미확정이면 "결측 N%·처리 미확정" 캡션만 달고 보류 — 침묵 처리 금지.

## 실전 케이스 — Reinhart-Rogoff (2013): 스프레드시트 실수가 긴축 정책의 근거였다 (공개 검증)

세계 긴축 정책의 학술 근거로 인용되던 "부채 90% 초과 시 성장 급락" 논문(Reinhart & Rogoff 2010)을 대학원생이 재현 시도 — **엑셀 수식이 5개국 행을 누락**(범위 선택 오류) + 선택적 가중치 문제를 발견했다. 보정하자 핵심 결론(성장 절벽)이 크게 약화. 교훈: ① 분석의 신뢰는 저자의 권위가 아니라 재현 가능성이다 — "데이터+코드 공개 후 재현"이 검증의 전부였다 ② 수작업 범위 선택(엑셀이든 노트북 숨은 상태든)은 같은 부류의 위험 — 코드화·Run All이 방어 ③ 집계 검증(교차 확인 — 국가 수 세기만 했어도)이 한 줄짜리 보험이었다. 상세: `references/evidence.md`
