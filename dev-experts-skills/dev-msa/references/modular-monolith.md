# 모듈러 모놀리스 — 구조 표준형·모듈 계약·strangler 상세 (SKILL.md 비중복)

## 구조 표준형 (미래 서비스 후보 = 지금의 패키지)

```
src/
├── collector/        # 모듈 = 바운디드 컨텍스트 (dev-ddd)
│   ├── __init__.py   # 공개 인터페이스 - 여기 export된 것만 남이 쓴다
│   ├── models.py     # 공유 가능 표면 (불변 데이터 타입)
│   └── _internal/    # 또는 평면 모듈 - 어쨌든 밖에서 import 금지
├── analysis/
├── notification/
└── shared/           # 진짜 공통(로깅 설정·기본 타입)만 - 쓰레기장화 경계
```

- **모듈 계약 3규칙**: ① 타 모듈은 `__init__`(또는 api/models)로만 접근 ② 모듈 간 순환 import 금지(순환 = 경계 오류 신호) ③ DB 테이블에 소유 모듈 명시(주석·문서) — 남의 테이블 쓰기 금지.
- `shared/`가 비대해지면 경계 실패의 흡수처가 된 것 — 정기적으로 "이거 어느 모듈 소유인가"로 재배치.
- 이 규칙들이 지켜진 모놀리스는 분리 결정 시 "패키지 → 서비스" 변환이 기계적이 된다(import 지점 = 미래의 API 호출 지점).

## 모듈 간 통신의 모놀리스 내 형태

| 미래의 형태 (분리 시) | 지금의 형태 (모놀리스) |
|---|---|
| HTTP 동기 호출 | 공개 함수 직접 호출 |
| 이벤트 발행/구독 | 인프로세스 이벤트(콜백 레지스트리) 또는 DB 아웃박스 테이블 |
| 조회 전용 복제본 | DB 뷰 / 조회 함수 |

인프로세스 이벤트를 미리 쓰면(거창할 것 없이 핸들러 리스트) 분리 시 브로커 교체만으로 전환된다 — 단 YAGNI: 구독자가 2개 미만이면 직접 호출이 정답.

## strangler 단계 상세 (분리 결정 후)

1. **경계 강화** — 대상 모듈의 외부 import를 0으로(`module_boundary_check.py` 게이트). DB 접근을 소유 테이블로 한정.
2. **계약 동결** — 공개 인터페이스를 API 계약 형태로 문서화(dev-rest-api-design 표) — 이게 미래의 서비스 API.
3. **별도 프로세스 기동** — 같은 코드베이스에서 그 모듈만 실행하는 엔트리포인트(컨테이너) — 코드 분리 전에 런타임 분리.
4. **호출 전환** — 직접 호출 → HTTP/이벤트로 한 호출자씩. 기능 플래그로 되돌림 가능하게.
5. **코드베이스 분리** — 전환 완료 후에만 레포 분리(레포 분리가 1단계인 계획은 빅뱅이다).
6. 각 단계에서 **중단 가능** — 3단계에서 멈춘 상태(모놀리식 코드 + 프로세스 분리)도 안정 상태다.

## 통신 방식 선택 상세

- **동기(HTTP)**: 응답이 즉시 필요한 조회. 타임아웃 의무(dev-python) + 호출 깊이 2 제한 + 장애 시 폴백 정의(캐시 응답·기능 축소).
- **비동기(이벤트)**: 상태 변경의 전파("적재됐다 → 알림·집계"). 발행자는 구독자를 모른다 — 결합 최소. 구현·전달 보장은 dev-event-driven.
- 안티 신호: 동기 호출로 변경을 전파(A가 B·C·D를 차례로 호출해 갱신) — 하나 실패 시 부분 갱신. 그 모양이 보이면 이벤트 전환 검토.
