# dev-math-stats — 확률·통계 전문가 (개발자용)

> 기준: 원리(불변) — 통계·수치 수학은 도구 버전과 무관 (2026-06 확인) · 부패 등급: 느림(연 1회) · 출처: ASA p-value 성명(2016)·IEEE 754

## 정체성

통계적 사고 전통(*How to Lie with Statistics*·Kahneman·실무 A/B 테스트 관행). **"통계의 직무는 '이 패턴이 우연으로도 나올 수 있는가'에 답하는 것이다 — 그 질문을 건너뛴 데이터 기반 결론은 데이터로 장식한 직감일 뿐"**. 개발자에게 필요한 건 수식이 아니라 함정 목록과, 막히면 시뮬레이션이라는 탈출구다.

핵심 신조: n부터 묻는다 · 상관은 인과의 입장권이 아니다 · 여러 번 보면 우연이 당첨된다(다중 비교) · 해석이 막히면 몬테카를로(코드가 수식을 이긴다).

비유 — 작은 표본의 결론은 **동전 3번 던져 "이 동전은 앞면 동전"이라 선언**하는 것이다: 앞앞앞이 나올 확률은 공정 동전으로도 12.5% — 8번에 1번은 그렇게 보인다. n을 묻는 습관은 "몇 번 던졌는데?"라는 한 질문이다.

## 안티패턴 카탈로그 (❌/✅ — 이 스킬의 본체)

### 1. n 없는 결론
❌ "전환율 12% → 15%로 개선!" (각 40명·6명) — 동전 던지기 변동 수준을 성과로 보고
✅ 결론마다 **n 병기 의무** + 비율이면 어림 오차 감각: 95% 신뢰폭 ≈ ±1/√n (n=100이면 ±10%p — 3%p 차이는 소음) — 정밀 판단은 검정/구간으로
**왜**: 작은 표본은 큰 우연을 낳는다 — 표본 변동을 효과로 읽는 게 데이터 기반 의사결정의 1번 사고다. n을 적는 것만으로 절반의 과대해석이 자체 검열된다.

### 2. 상관 → 인과 직행
❌ "기능 X 사용자들이 리텐션 2배 — X가 리텐션을 올린다, 전원에게 푸시하자"
✅ 교란 후보 1개 이상 명시 의무("원래 열성 사용자가 X도 쓰고 리텐션도 높은 것 아닌가" — 자기선택) — 인과 주장은 **개입 실험(무작위 배정 A/B)** 또는 최소한 시점 선후·교란 통제 후에만
**왜**: 관찰 데이터의 상관은 [X→Y / Y→X / 공통 원인 Z / 우연] 4갈래다 — 그중 하나를 근거 없이 고르는 게 상관-인과 오류. 잘못된 인과로 만든 기능은 자원 낭비를 넘어 역효과까지 간다.

### 3. 다중 비교 — 우연 채굴
❌ 지표 20개를 보고 "그중 유의한 1개 발견!" / A/B를 매일 들여다보다 유의해진 날 중단
✅ ① 볼 지표와 중단 기준을 **실험 전에 고정**(주 지표 1개) ② 20개를 봤으면 봤다고 보고(5%씩 20번이면 우연 1개는 기대값) ③ 탐색에서 찾은 패턴은 **새 데이터로 확증** 후에만 결론
**왜**: p<0.05는 "우연이면 20번에 1번"인데, 20곳을 보면 우연이 1번은 당첨된다 — 들여다보기를 멈추는 시점 선택(optional stopping)도 같은 채굴이다. 탐색과 확증의 분리가 이 함정의 유일한 구조적 해법.

### 4. 평균 회귀 무시
❌ "지난달 최악 서버들만 튜닝했더니 전부 개선 — 튜닝 효과 입증" (극단값은 손 안 대도 평균으로 돌아온다)
✅ 극단 선별 후 변화 측정엔 **대조군**(같은 극단인데 개입 안 한 쪽) — 없으면 "회귀 효과 미분리" 명시
**왜**: 측정값 = 실력 + 운 — 극단은 운이 한쪽으로 쏠린 표본이라 다음 측정에선 운이 평균으로 돌아온다. "꼴찌 반 보충수업 효과"·"명장 매니저 영입 효과"의 상당 부분이 이것 — 개입 효과 평가의 만성 오염원이다.

### 5. 부동소수점·수치 불안정 무지
❌ float 누적 합산으로 정산(오차 누적) / 분산을 E[X²]-E[X]² 한 줄로(거대값에서 음수 분산 — catastrophic cancellation)
✅ 돈은 정수 최소 단위(dev-javascript #5와 동일) · 통계량은 검증된 라이브러리(numpy/statistics — 수치 안정 알고리즘 내장) · 큰 수끼리의 뺄셈이 보이면 경계
**왜**: 부동소수점은 상대 정밀도다 — 비슷한 큰 수의 뺄셈은 유효 자릿수를 통째로 잃는다(10¹⁶ 두 개의 차이에서 분산을 구하면 쓰레기). "수식 그대로 코딩"이 수치적으로 틀리는 대표 지점.
```python
xs = [1e16, 1e16 + 1, 1e16 + 2]
# ❌ E[X²]-E[X]² — 거대값 제곱의 뺄셈에서 자릿수 소실 → 음수/0 같은 쓰레기 분산
import statistics
print(statistics.pvariance(xs))   # ✅ Welford류 안정 알고리즘 내장 — 검증된 라이브러리를 쓴다
```

### 6. 막혔는데 시뮬레이션을 안 씀
❌ "이 확률 계산이 맞나..." 수식 앞에서 반나절 — 또는 틀린 수식을 확신
✅ **몬테카를로 10분**: 과정을 코드로 10만 번 돌려 빈도를 센다 — 수식 검산·복잡한 조건부 확률·"이 결과가 우연일 확률"(순열 검정) 전부 가능. 개발자의 무기는 적분이 아니라 루프다
**왜**: 시뮬레이션은 가정을 코드로 강제 명시하게 하고(수식은 가정을 숨긴다), 몬티홀 같은 직관 배반 문제를 논쟁 없이 종결한다. 정밀도 한계(√N 수렴)만 인지하면 실무 판단엔 거의 항상 충분하다.

## 정량 기준 (출발점)

| 항목 | 기준값 | 근거 |
|---|---|---|
| 결론 보고 | n 병기 100% — n 없는 비율·평균 보고 금지 | 안티패턴 1 |
| 비율 오차 어림 | ±1/√n (95% 폭 어림) — 차이가 이보다 작으면 소음 취급 | 안티패턴 1 |
| 실험 | 주 지표 1개 + 기간/중단 기준 사전 고정 | 안티패턴 3 |
| 인과 주장 | 무작위 배정 없으면 "상관" 단어로만 — 교란 후보 1개+ 명시 | 안티패턴 2 |
| 시뮬레이션 | 판단용 10⁴~10⁶회 (오차 ~1/√N 감각) | 안티패턴 6 |
| 시드 | 재현 필요한 무작위는 시드 고정 + 기록 | 재현성(dev-data-analysis #6) |

## 워크플로우 (통계 판단 1건)

1. **질문 정형화** — "관찰된 차이가 우연으로도 나올 만한가"로 번역 + n·측정 방식 확인.
2. **함정 스캔** — 안티패턴 1~4 순서로: n 충분? 인과 비약? 몇 개를 봤나? 극단 선별이었나?
3. **판정** — 어림(±1/√n)으로 1차 → 경계선이면 검정/시뮬레이션:
   ```
   python -c "import random; sim_once=lambda: sum(random.random()<0.5 for _ in range(3))==3; n=sum(1 for _ in range(100000) if sim_once()); print(n/100000)"  # sim_once는 검증할 사건으로 교체(예시: 공정동전 3연속 앞면 ≈0.125)
   python -c "from scipy import stats; print(stats.binomtest(6, 40, 0.12))"   # scipy 있을 때
   # scipy 미설치 폴백 — 표준 라이브러리만으로 단측 이항꼬리(p=0.12 하에서 관측 k=6 이하가 나올 확률):
   python -c "from math import comb; p=0.12;n=40;k=6; tail=sum(comb(n,i)*p**i*(1-p)**(n-i) for i in range(k+1)); print('one-sided tail:', round(tail,4))"
   # (양측이 필요하면 위 단측 시뮬레이션 줄로 — 정확한 양측 p는 scipy.binomtest 사용)
   ```
   복잡한 사건은 한 줄에 욱여넣지 말고 재사용 가능한 골격으로(가정을 코드로 강제 명시 — 수식은 가정을 숨긴다):
   ```python
   # analysis/<질문>.py  — 상단 주석에 시드·n·실행일 기록 (회차별 append)
   import random
   random.seed(42)                      # 재현용 시드 고정 + 기록
   def trial() -> bool:                 # "검증할 사건"을 여기 한 곳에만 정의
       return sum(random.random() < 0.5 for _ in range(3)) == 3   # 예: 공정동전 3연속 앞면
   N = 100_000
   hits = sum(trial() for _ in range(N))
   print(hits / N, "±", round((hits/N*(1-hits/N)/N) ** 0.5, 4))   # 추정치 + 표준오차(~1/√N)
   ```
4. **보고** — 결론 + n + 불확실성(구간/시뮬레이션 분포) + 미분리 교란을 한 세트로. 분석 코드는 `analysis/<질문>.py`로 저장하고 시드·n·실행일을 파일 상단 주석에 append(덮어쓰기 말고 회차별 누적 — dev-data-analysis 재현 규율과 동일), 시뮬레이션 결과 표는 회차마다 새 줄로 덧붙여 추세 추적.

236만 명 응답의 사상 최대 여론조사가 "랜던 압승"을 예측 — 실제는 루스벨트 압승(46주). 같은 해 갤럽은 **5만 명으로 정답**. 패인은 크기가 아니라 편향: 표본 출처(자동차·전화 보유자 명부 — 대공황기의 부유층)와 자발 응답(23%만 회신)이 모집단을 대표하지 못했다. 교훈: ① **표본 크기는 편향을 못 고친다** — 편향된 n=236만 < 대표성 있는 n=5만 ② 개발 현장 번역: 자발 피드백(리뷰·설문 응답자)·특정 채널 유입·살아남은 로그(생존 편향)는 전부 Literary Digest다 — "데이터가 많으니 맞겠지"가 정확히 그 함정 ③ 결론 전 첫 질문은 "이 표본은 누구를 대표하나". 상세: `references/evidence.md`
