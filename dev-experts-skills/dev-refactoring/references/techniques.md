# 핵심 기법 12종 — 단계별 절차 (Fowler 2판 발췌, 언어 중립 / SKILL.md 비중복)

각 기법: [언제 → 미세 단계 → 함정]. 모든 단계 사이에 테스트 실행이 생략돼 있다고 읽어라.

## 1. 함수 추출 (Extract Function)
- 언제: 이름 붙는 덩어리·주석으로 설명되는 블록.
- 단계: 새 함수 생성(이름=의도) → 블록 복사 → 지역변수를 인자/반환으로 → 원위치를 호출로 교체.
- 함정: 추출 후 인자가 5개+면 덩어리가 아니라 데이터 군집이 숨어 있는 것 — 매개변수 객체(#3) 선행.

## 2. 함수 인라인 (Inline Function)
- 언제: 본문이 이름만큼 명확 / 위임만 하는 함수가 늘었을 때(과추출 청소).
- 함정: 다형성으로 쓰이는 메서드는 인라인 금지.

## 3. 매개변수 객체 도입
- 언제: 같은 인자 묶음이 함수 2~3개에 반복(start/end, code/date...).
- 단계: 구조체(dataclass/타입) 생성 → 새 인자 추가 → 호출처 하나씩 이전 → 옛 인자 제거.
- 효과: 묶음에 이름이 생기면 그 객체로 **행동이 이사 올 자리**가 생긴다(기능 질투 해소의 씨앗).

## 4. 함수 이동 (Move Function)
- 언제: 함수가 자기 모듈보다 남의 데이터·함수를 더 참조(기능 질투).
- 단계: 대상 컨텍스트에 복사 → 정리 → 원본을 위임으로 → 호출처 이전 → 원본 제거.

## 5. 변수 추출 / 인라인
- 언제: 복잡한 식에 이름이 필요할 때(추출) / 이름이 식 그대로일 때(인라인).
- 함정: 추출한 이름이 거짓말하지 않는지 — 이름이 곧 주석이다.

## 6. 이름 바꾸기 (Rename)
- 단계: IDE rename → 동적 접근 grep(`getattr`, 문자열 키, 직렬화 필드) → 테스트.
- 공개 계약(API 필드·DB 컬럼)이면 rest-api-design 호환 규칙(병행+폐기)로 승격.

## 7. 질의와 변경 분리 (Separate Query from Modifier)
- 언제: 값을 반환하면서 상태도 바꾸는 함수.
- 효과: 질의는 자유 호출 가능(테스트·캐시·재시도), 변경은 명시 지점만 — dev-data-engineering 멱등 사고와 동형.

## 8. 조건문 분해 + 가드 절
- 단계: 중첩 if를 이른 return(가드)으로 평탄화 → 각 분기 본문을 함수 추출.
- 함정: 가드 절 전환은 행동 보존 확인이 미묘(else 누락) — 분기 케이스 테스트 먼저.

## 9. 조건부 로직 → 다형성 / 매핑
- 언제: 같은 switch/if-elif가 2곳+ (switch 중복 냄새).
- 파이썬 관용: 클래스 계층보다 dict 매핑(`handlers = {"buy": handle_buy, ...}`)이 먼저 — 다형성은 상태·변형이 함께 있을 때.

## 10. 값 객체 도입 (Replace Primitive)
- 언제: 검증·포맷 로직이 string/float 주위에 흩어질 때(기본형 집착).
- 연결: dev-python dataclass·dev-typescript 브랜드 타입이 구현 수단.

## 11. 죽은 코드 제거
- 단계: 참조 검색 → 커밋 메시지에 "removed dead: <이유>" → 삭제(주석 처리 보존 금지 — git이 보존한다).
- 함정: 리플렉션·설정 문자열로 불리는 코드 — grep을 문자열로도.

## 12. 단계 쪼개기 (Split Phase)
- 언제: 한 함수가 [파싱→계산→출력]을 다 할 때.
- 단계: 후반부를 함수로 추출 → 중간 자료구조 도입 → 전반부가 그것을 생산.
- 효과: 파이프라인화 — dev-data-engineering의 extract/transform/load 분리가 이 기법의 거시판.
