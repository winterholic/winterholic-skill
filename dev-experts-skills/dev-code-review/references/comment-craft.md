# 코멘트 작법·받는 자세·갈등 해소 (SKILL.md 비중복)

## 어조 변환표 (같은 지적, 다른 비용)

| ❌ 사람 겨냥 | ✅ 코드 겨냥 |
|---|---|
| "왜 이렇게 짰어요?" | "이 접근을 선택한 맥락이 있을까요? X 경우가 걱정돼서요" |
| "이거 틀렸어요" | "code=None일 때 31행이 AttributeError가 날 것 같습니다 — 재현: ..." |
| "기본인데 이걸 모르네요" | "(참고) 이 패턴은 dev-python #1에 정리돼 있어요" |
| "전에도 말했는데" | "지난 PR #12와 같은 패턴이라 컨벤션 문서에 박아두면 어떨까요" |

- 질문형이 단정형보다 정보를 더 끌어낸다 — 작성자만 아는 맥락(외부 제약·실험 결과)이 실재한다.
- 단, 블로커는 명확하게: 질문형으로 위장한 블로커("...괜찮을까요?")는 무시되면 그대로 머지된다 — 등급 라벨이 어조를 대신 든다.

## 풀어쓰기 패턴 (지식 전파 장치로서의 코멘트)

1. **원리 링크**: 지적 + 그 원리의 출처(스킬 ❌/✅·공식 문서) — 같은 지적의 재발을 끊는다.
2. **재현 시나리오**: "이 입력이면 이 줄에서 이렇게 된다" — 추상 지적을 구체 버그로.
3. **대안 코드 조각**: 5줄 이내면 코멘트에 직접 — 단 "이대로 붙여라"가 아니라 방향 표시임을 명시.

## 받는 자세 절차 (작성자)

1. 모든 코멘트에 응답 — 침묵 머지는 리뷰어의 다음 리뷰를 얕게 만든다. [수용: "고쳤습니다 (커밋 abc)"] / [반론: 근거] / [질문].
2. 반론은 검증 먼저 — 코드를 다시 읽고, 리뷰어가 본 시나리오를 재현 시도 후에. 즉답 반박은 보통 둘 다 손해.
3. 수용한 지적이 3회 반복되면 본인의 체크리스트(셀프 리뷰 항목)에 추가 — ledger 3회 룰의 개인판.
4. 큰 방향 이견은 코멘트 스레드를 떠나 대화(통화·대면)로 — 텍스트 핑퐁 5회면 매체가 틀린 것.

## 갈등 해소 사다리

```
코멘트 핑퐁 2회 초과
→ ① 기존 컨벤션·문서가 답하나? (있으면 그쪽이 이김 - 우선순위 사다리)
→ ② 둘 다 동작한다면: 작성자 선택 + nit 강등 (코드 소유권 존중)
→ ③ 정확성·보안 이견: 재현 코드/테스트로 판정 (말 대신 실행)
→ ④ 그래도 미해결: 제3자 1명 - 그 판정에 양쪽 승복 (재논쟁 금지)
```

## 셀프 리뷰 절차 (1인 개발 기본)

1. PR 만들기 전 `git diff`를 **리뷰어 모드로 통독** — 자기 에디터가 아니라 diff 뷰로(맥락이 바뀌면 눈도 바뀐다).
2. 1차 pass 질문을 자신에게: 이 변경 필요한가 / 위치 맞나 / 계약 바뀌나 / 테스트가 행동 검증하나.
3. 검출기·린트 실행 결과 첨부 (도구가 잡을 것을 눈으로 찾지 않는다).
4. 다음날 아침 5분 재독이 가능하면 최고의 보완 — 시차가 맹점을 깬다.
