# 규약 각론 — 상태코드 트리·필터·커서·하위 액션 (SKILL.md 비중복)

## 상태코드 선택 트리

```
성공인가?
├─ 생성됨 → 201 (+ Location 헤더) / 비동기 접수만 → 202
├─ 응답 본문 없음 (DELETE 성공 등) → 204
└─ 그 외 → 200

실패 — 누구 잘못인가?
├─ 클라이언트
│   ├─ 형식 자체가 깨짐(JSON 파싱 불가) → 400
│   ├─ 형식은 맞는데 값이 규칙 위반 → 422
│   ├─ 인증 없음/만료 → 401 / 인증됐는데 권한 없음 → 403
│   ├─ 리소스 없음 → 404 (권한상 존재를 숨겨야 하면 403 대신 404 - 정보 노출 판단)
│   ├─ 상태 충돌(이미 취소된 주문 취소) → 409
│   └─ 호출 한도 → 429 (+ Retry-After 헤더)
└─ 서버 → 500 (상세는 로그에, 응답엔 추적 id만 - 내부 정보 비노출)
```

- 422 vs 400: FastAPI 기본이 검증 실패 422 — 그 관례를 따르되 한 API 안에서 일관되게.
- 401의 의미는 "인증 다시 해와라"(WWW-Authenticate 헤더 동반이 원칙) — 로그인 실패에도 401.

## 필터·정렬 규약

```
GET /candles?code=005930&from=2026-01-01&to=2026-06-11&sort=-base_date&limit=50
```

- 필터는 쿼리 파라미터 평면으로(`field=value`), 범위는 `from/to` 또는 `field_gte/field_lte` — 한 API에서 한 방식만.
- 정렬: `sort=-field`(내림차순 `-` 접두) 단일 규약 추천. 다중 정렬은 콤마(`sort=-base_date,code`) — 지원 필드는 화이트리스트(임의 필드 정렬 허용은 인덱스 없는 정렬 = DoS 통로).
- 검색(전문)·복잡 조건은 GET 쿼리스트링 한계(URL 길이·인코딩)에서 `POST /candles/search`로 — 동사지만 검색 리소스로 정당화되는 관례적 예외.

## 커서 인코딩

```python
import base64, json
def encode_cursor(d: dict) -> str:
    return base64.urlsafe_b64encode(json.dumps(d).encode()).decode()
# {"d": "2026-06-10", "c": "005930"} -> "eyJkIjogIjIwMj..."
```

- 불투명성의 계약: 클라이언트는 커서를 **해석하지 않고 그대로 반납**한다 — 문서에 명시. 내부 구조(keyset 키, dev-postgres)는 자유롭게 바뀔 수 있다.
- 커서 위변조 대비: 디코드 실패·미지 필드는 422 `invalid_cursor` — 500으로 새지 않게.
- 만료 개념이 필요하면(스냅숏 일관성) 커서에 타임스탬프 포함 후 오래된 것 거부.

## 하위 액션(POST /resource/{id}/verb) 판단 기준

허용 조건 — 셋 다 만족할 때만:
1. 상태 전이다 (cancel, publish, retry) — CRUD로 자연스럽게 표현 불가
2. 그 전이에 도메인 규칙이 있다 (아무 필드 PATCH가 아니라 "취소 가능 상태에서만")
3. 같은 일을 PATCH status로 하면 검증·부수효과가 핸들러 밖으로 샌다

이 조건 없이 동사가 늘어나면 RPC로 퇴화 중인 신호 — 리소스 모델 재검토(예: `/orders/3/approve`가 3개 생기면 `approvals`라는 리소스가 숨어 있는 것).

## 요청·응답 봉투(envelope) 규약

```json
// 목록
{ "data": [...], "next_cursor": "...", "has_more": true }
// 단건 - 봉투 없이 객체 그대로 (과잉 중첩 금지)
{ "code": "005930", "name": "삼성전자", ... }
// 에러 - SKILL.md 표준 스키마
{ "error": { "code": "...", "message": "...", "details": {} } }
```

- 목록만 봉투를 쓰는 이유: 페이지네이션 메타를 나중에 추가해도 안 깨지게(처음부터 배열이면 메타 추가가 breaking — 검출기 R4).
- `data` 안 객체와 단건 응답 객체는 같은 스키마(CandleOut 하나) — 목록용/단건용 분화는 유지비.
