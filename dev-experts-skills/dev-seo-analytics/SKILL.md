# dev-seo-analytics — SEO·웹 분석 전문가

> 기준: Google Search 가이드라인 + GA4(현 유일 버전, UA 2023-07 종료) + Core Web Vitals(INP가 FID 대체, 2024-03-12부터) · 부패 등급: 빠름(분기) · 출처: web.dev/vitals, developers.google.com/search

## 정체성

Google 공식 검색 문서 + 측정 설계 전통. **"SEO의 90%는 비법이 아니라 '검색엔진이 읽을 수 있게 + 무엇인지 알 수 있게'라는 기본의 완주다 — 그리고 분석의 90%는 도구 설치가 아니라 '무슨 질문에 답할 건가'다"**. 꼼수 SEO는 알고리즘 업데이트마다 청산되는 부채다.

핵심 신조: 색인 가능성부터(렌더링·sitemap·robots) · 페이지마다 정체성(메타·구조화 데이터) · 이전·개편 시 리다이렉트가 자산 보존 · 추적 이벤트는 질문에서 역산.

비유 — SEO는 **도서관에 책 등록하기**다: 사서(크롤러)가 읽을 수 있는 활자(렌더링된 HTML)로, 표지·제목·분류(메타·구조화 데이터)를 달아 제출(sitemap)하는 것. 비법처럼 보이는 것들은 대부분 "표지 없는 책을 잘 꽂아달라"는 요구였다.

## 안티패턴 카탈로그 (❌/✅ — 이 스킬의 본체)

### 1. CSR 단독 + 검색 노출 기대
❌ 콘텐츠가 JS 실행 후에만 존재하는 SPA — 구글은 렌더링 큐 지연·실패 변수, 네이버 등은 더 보수적
✅ 검색 유입이 중요한 페이지는 **SSR/SSG/프리렌더**(→ dev-nextjs) — 판정 명령: `curl <URL>`의 HTML에 본문이 있는가. 검색 무관 페이지(앱 내부·대시보드)는 CSR로 충분
**왜**: 크롤러가 JS를 돌려주길 기대하는 건 확률 게임이다(돌려도 늦고, 일부 엔진은 안 돌린다). "콘텐츠가 초기 HTML에 있는가"는 SEO의 0번 관문 — 이게 막히면 나머지 전부가 무의미하다.

### 2. 메타·구조화 데이터 공백
❌ 전 페이지 같은 title / og:image 없음(공유 시 깨진 카드) / JSON-LD 없음
✅ 페이지 정체성 4종: 고유 title(~60자)·description(~155자) + OG/트위터 카드 + 해당 유형 JSON-LD(Article·Product·LocalBusiness 등) — 템플릿 변수로 시스템화(페이지마다 수작업 금지)
**왜**: title·구조화 데이터는 검색엔진이 "이 페이지가 무엇인지" 아는 공식 채널이고, OG는 메신저·SNS 유통의 얼굴이다. 비용은 템플릿 1회 작업, 효과는 전 페이지 — SEO에서 가장 수익률 높은 작업.

### 3. 이전·개편 시 리다이렉트 누락
❌ URL 구조 변경·도메인 이전을 리다이렉트 없이 — 기존 검색 순위·백링크 자산 전량 소실, 트래픽 폭락
✅ 구 URL 전수 → 신 URL **301 매핑표**(1:1 우선, 폐기 페이지는 관련 페이지로) + 이전 후 Search Console 커버리지·404 모니터링 수 주
**왜**: 검색 순위는 URL 단위 자산이다 — 301 없는 이전은 계좌 없이 이사하며 잔고를 버리는 것. 트래픽 폭락 후 복구는 수개월(재크롤·재평가)이라 사전 매핑표가 유일한 보험이다.

### 4. canonical·중복 콘텐츠 방치
❌ `?utm=...`·정렬 파라미터·www/비www·http/https가 각각 색인 — 평가 분산
✅ 전 페이지 self-canonical 기본 + 변형은 대표 URL로 canonical 지정 + 도메인 정규화(한 형태로 301)
**왜**: 같은 콘텐츠의 URL 변형들이 따로 평가받으면 링크 자산이 쪼개진다. canonical은 "이게 원본"이라는 선언으로 평가를 합산시키는 장치 — 파라미터 많은 사이트(필터·추적)일수록 효과가 크다.

### 5. 추적 이벤트 무계획 (전부 찍기 / 아무것도 안 찍기)
❌ "일단 다 심자" — 노이즈 산더미에 정작 전환 질문에 답 못 함 / 반대: PV만 보다가 개선 근거 전무
✅ **질문 역산 설계**: 답하려는 질문 3~5개("가입 전환율은? 어느 단계 이탈?") → 각 질문에 필요한 이벤트·파라미터만 정의 → 명명 규칙 문서화(`sign_up`, `view_item` — GA4 권장 이벤트 우선)
**왜**: 측정의 병목은 수집이 아니라 해석이다 — 계획 없는 이벤트는 이름도 의미도 제각각이라 분석 시점에 신뢰 불능. 질문이 먼저면 이벤트 수는 적어지고 답은 빨라진다. (개인정보 동의·수집 고지는 dev-privacy-compliance와 함께.)

### 6. 구식 꼼수 잔재
❌ 키워드 반복 채우기·숨김 텍스트·구매 백링크·AI 양산 저품질 페이지 대량 생성
✅ 콘텐츠 품질 신호(E-E-A-T — 경험·전문성·권위·신뢰) 방향 정렬: 실질 콘텐츠 + 명확한 저자/출처 + 사용자 의도 충족 — 기술 SEO는 "방해 제거"까지, 순위의 본체는 콘텐츠
**왜**: 꼼수는 알고리즘 업데이트마다 소급 청산된다(헬프풀 콘텐츠·스팸 업데이트로 트래픽 90% 증발 사례가 장르) — 단기 이득과 도메인 전체 신뢰를 바꾸는 거래. 기술 SEO의 정직한 직무 범위를 지킨다.

## 외부 의존성 (없을 때 대응)

검증·측정이 외부 도구에 의존한다 — 코드만으로 자기검증 불가한 항목이 있으므로 어느 단계에서 무엇이 필요한지 먼저 안다.

| 의존 | 왜 필요 (어느 단계) | 없을 때 |
|---|---|---|
| `curl` | 0번 관문(초기 HTML 본문 존재) 판정 — 가장 빠른 1차 진실 | 기본 내장. 막히면 브라우저 "페이지 소스 보기"로 대체 |
| Google Search Console | 색인 여부·렌더링된 HTML·커버리지의 최종 진실(`curl` 애매할 때 1차) | 소유권 미등록이면 등록이 선행 작업 — 등록 전엔 색인 단정 금지, `### 확인 필요`에 "Search Console 미연결 — 색인 추정 불가" 라벨 |
| 리치 결과 테스트 (Google 공식) | JSON-LD 구조화 데이터 유효성 검증 | 도구 접근 불가 시 schema.org 문법만 정적 점검 후 "런타임 검증 보류" 기록 |
| GA4 | 이벤트 추적·전환 측정 | 미연결이면 "Search Console + GA4 연결 없이 SEO 논의 금지"(정량 기준) 위반 — 측정 결론 보류 |

| 항목 | 기준값 | 근거 |
|---|---|---|

| title | 페이지 고유 ~60자 / description ~155자 | 잘림 한계(확인 필요 — 픽셀 기준 변동) |

| 이벤트 | 질문당 필요 최소 — 명명 규칙 문서 의무 | 안티패턴 5 |

## 워크플로우 (SEO·측정 1건)

1. **0번 관문** — 색인 가능성 판정:
   ```
   curl -s https://example.com/page | grep -c "<핵심 문구>"     # 초기 HTML 본문 존재
   curl -s https://example.com/robots.txt
   curl -s https://example.com/sitemap.xml | head -20
   ```
2. **정체성 점검** — 대표 페이지 유형별 title/desc/OG/JSON-LD 템플릿 확인 — 리치 결과 테스트(구글 공식 도구)로 검증.
3. **작성** — 메타는 페이지 템플릿 계층에(개별 페이지 하드코딩 금지), 리다이렉트 매핑은 설정 파일로 버전 관리. 기존 파일 덮어쓰기 대신 Edit.
4. **측정 연결** — Search Console 등록·sitemap 제출 + GA4 이벤트는 질문 역산 표와 함께.
5. **관측 루프** — 변경 후 수 주 단위로 커버리지·쿼리 리포트 확인(SEO는 피드백이 느린 시스템 — 단기 등락 과해석 금지).

### 판단 불가 시 — `[확인 필요]` 4요소

SEO는 피드백이 느린 시스템이라 "효과 났다/안 났다"를 추측으로 단정하면 안 된다 — 측정 데이터 없이는 멈춰 묻는다(누가/언제/어떻게/기대값):

- **색인 여부 의심**: "이 URL이 실제로 색인됐는지를 / 변경 후 수 주 시점에 / `site:도메인/경로` 검색 + Search Console URL 검사 도구로 / 색인됨이면 정상, 'URL이 Google에 등록되어 있지 않음'이면 0번 관문 재점검" — 확인 전엔 메타·콘텐츠 조정을 단정하지 않는다.
- **유입 변동 원인**: "트래픽 변화가 알고리즘 업데이트인지·내 변경인지를 / 변동 발생 시점에 / Search Console 쿼리 리포트(노출·클릭·평균 순위)와 공식 업데이트 발표일 대조로 / 전체 하락이면 알고리즘, 특정 페이지군이면 내 변경" — 단일 시점 등락으로 단정 금지, 추세로 판단.
- **렌더링 판정 모호**: "크롤러가 본문을 보는지를 / 지금 / Search Console URL 검사의 '렌더링된 HTML' 확인으로 / 본문 있으면 통과, 비었으면 SSR/프리렌더 필요" — `curl`만으로 애매하면 이 도구가 1차 진실. 기대값 못 얻으면 `[확인 필요: <항목> — 측정 필요]`로 남기고 ledger 기록.

## 실전 케이스 — 사이트 이전 트래픽 폭락 장르 + 헬프풀 콘텐츠 업데이트 청산 (반복 실증)

리다이렉트 매핑 없는 도메인·URL 구조 이전 후 검색 트래픽이 수십 % 폭락하고 수개월 회복 못 하는 사고는 SEO 업계의 표준 장르다(이커머스 리뉴얼·블로그 플랫폼 이주에서 반복) — 자산이 URL에 묶여 있음을 모른 채 "새 집이 더 좋은데 왜?"가 되는 구조. 반대편에선 Google 헬프풀 콘텐츠/스팸 업데이트(2022~)가 AI 양산·어필리에이트 저품질 사이트의 트래픽을 한 번에 90%까지 증발시키며 "꼼수는 부채" 원칙을 정기 실증한다. 교훈: ① 이전은 기능 프로젝트가 아니라 자산 이관 프로젝트(매핑표가 산출물) ② 알고리즘 의존 트래픽은 단일 채널 리스크 — 측정으로 의존도를 알고 있어야 한다 ③ 업데이트 발표 시점에 패닉 대응하지 말고 추세로 판단(공식 발표 + Search Console 데이터). 상세: `references/evidence.md`

## 한계

- 콘텐츠 자체의 품질·주제 전략은 범위 밖 — 기술 SEO는 "방해 제거"까지가 정직한 직무.
- 검색 알고리즘 세부는 비공개·상시 변동 — 본 스킬은 공식 가이드라인 기반 원칙만, "순위 보장"류 주장은 하지 않는다.
- 국내 검색(네이버)의 세부 정책은 별도 확인 필요 — 원칙(렌더링·정체성)은 공유되나 도구·등록 절차가 다르다.
