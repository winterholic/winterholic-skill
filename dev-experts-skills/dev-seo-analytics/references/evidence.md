# dev-seo-analytics evidence — 실증 사례

## 1. 이전 트래픽 폭락 — "새 사이트가 더 좋은데 유입이 반토막" (업계 표준 장르)

- **무슨 일**: 플랫폼 이주·URL 구조 개편·도메인 변경에서 301 매핑 누락 → 검색엔진 입장에선 기존 페이지 전부 404 + 신규 사이트 제로 베이스 → 트래픽 수십 % 폭락, 회복은 수개월(재크롤·재평가 주기). SEO 컨설팅 업계의 최다 반복 사고 유형.
- **체크리스트 도출**: ① 이전 전 전체 URL 인벤토리(크롤 + Search Console + 서버 로그) ② 1:1 매핑표(불가 시 최근접 관련 페이지 — 홈으로 일괄은 soft-404 취급) ③ 리다이렉트 체인 금지(구→신 1홉) ④ 이전 후 404 리포트·커버리지 수 주 관측 ⑤ 구 도메인은 충분 기간(1년+) 리다이렉트 유지.
- **원칙**: 검색 자산은 URL에 적립된다 — 이전 프로젝트의 산출물 1순위는 디자인이 아니라 매핑표.

## 2. 헬프풀 콘텐츠·스팸 업데이트 — 꼼수 부채의 정기 청산 (2022~ 공개 사례 다수)

- **무슨 일**: Google의 Helpful Content(2022~)·연이은 코어/스팸 업데이트가 검색용 양산 콘텐츠(AI 대량 생성·어필리에이트 짜깁기·전문성 위장) 사이트의 트래픽을 일괄 강등 — 공개된 사례 중 90%+ 증발 사이트 다수. 일부는 도메인 단위 평가 하락으로 정상 페이지까지 동반 강등.
- **교훈**: ① 페이지 단위 꼼수가 도메인 단위 부채가 된다 ② "지금 통하는 편법"의 기대수명은 다음 업데이트까지 ③ 기술 SEO(이 스킬)와 콘텐츠 품질은 곱셈 관계 — 어느 쪽이 0이면 결과도 0.
- **건전성 점검**: 트래픽의 검색 의존도(채널 비중)를 GA4로 상시 파악 — 단일 알고리즘 의존은 사업 리스크로 보고.

## 3. JS 렌더링 색인 — "구글은 JS 돌려준다"의 실제 조건 (공개 실험·공식 문서)

- **무슨 일**: Google은 2단계 색인(HTML 즉시 → 렌더링 큐 경유 JS)을 공식화했지만, 커뮤니티 실험들이 반복 확인한 현실: 렌더링 색인은 지연되고(수일+ 사례), 에러·타임아웃에 취약하며, 렌더링 예산은 사이트 신뢰도에 비례. 네이버 등 타 엔진은 더 보수적.
- **실무 번역**: "구글이 JS 돌려준다"는 참이지만 **신규·소규모 사이트가 기대기엔 약한 보장** — 검색 유입이 목표인 콘텐츠는 초기 HTML에 있는 게 유일하게 통제 가능한 전략. 판정은 추측 말고 도구로: Search Console URL 검사의 "크롤링된 페이지 보기"로 구글이 실제 본 HTML 확인.
- **이 스킬과의 연결**: 안티패턴 1. SSR 전환 비용 논의의 사실 기반 — "되긴 된다"와 "기대도 된다"의 간극.
