# evidence + 출고 전 체크리스트

> 실증 사례 본문은 같은 폴더 `evidence.md`(Stack Overflow 모놀리스 · 과잉 설계 부검 장르 · 봉투 뒷면 숫자표). 이 파일은 출처 색인 + 출고 체크 + 점검 주기.

## 실증·출처

- **Stack Overflow 아키텍처 공개 자료** (Nick Craver 블로그·발표, nickcraver.com — "How We Do" 시리즈) — 세계 최대급 트래픽을 소수 물리 서버 모놀리스 + 극단적 캐시로 처리한 공개 기록. 안티패턴 2(×10 원칙)·실전 케이스의 반례 실증. `evidence.md` §1. 성립 조건(읽기 압도·고성능 팀·캐시 친화 도메인)도 함께 명시 — 카고컬트 방지.
- **과잉 설계 스타트업 부검 장르** (창업자 회고·VC 포스트모템, CB Insights "Why Startups Fail"류) — 시드 단계 마이크로서비스·멀티리전으로 런웨이 소진 패턴. 안티패턴 2·6의 근거. `evidence.md` §2. 빈도 균형 각주(반대 실패도 실재하나 빈도 낮음) 포함.
- **봉투 뒷면 지연 수치** (Jeff Dean "Numbers Everyone Should Know" 계보, 현대화 필요) — 메모리 ~100ns · SSD 랜덤 ~수십µs · 같은 DC 왕복 ~0.5ms · 대륙 간 ~100ms. **확인 필요**: 하드웨어 세대마다 변동 — 자릿수 비교용이며 인용 시 최신 벤치 확인. `evidence.md` §3.
- **가용성 환산** (관행 — 99.9%=8.8h/년 · 99.99%=53min/년) — SLA 산수. 안티패턴 5. 수학적 항등이라 불변.
- **단일 RDB 캐파** — PostgreSQL 18(2025-09 GA, postgresql.org/docs/18) 기준, NVMe + 대용량 RAM에서 수천 QPS·수 TB는 흔히 단일 인스턴스 사정권(워크로드 의존). 안티패턴 2의 "수직 확장 잔여 거리" 근거. 실측이 항상 우선.
- *System Design Interview* (Alex Xu, Vol.1·2) — 면접 절차(요구 5분 → 봉투 뒷면 → 상위 설계 → 심화 → 트레이드오프)의 표준화 출처. 안티패턴 6·워크플로우.
- 오픈소스 차용 표기: 시스템 설계 가이드류 다수(색인 인지, 본문 비복사). **역흡수**: "첫 산출물은 숫자"의 복붙 가능한 봉투 뒷면 스크립트(stdlib)·SPOF 목록화(사람·외부 의존 포함)·규모 미상 시 4요소 질의 절차 — 본 스킬 차별점.

## 출고 전 체크리스트 (설계 산출 시)

- [ ] 봉투 뒷면 계산 먼저 — QPS(평균/피크)·저장/년·대역폭 자릿수
- [ ] 비기능 3축 수치 선언 — 지연(p95)·가용성(%)·일관성(stale 허용 범위)
- [ ] 현 규모 ×10까지만 설계 + 이행 경로 메모(×100은 그때)
- [ ] 대표 경로 2~3개(쓰기1·읽기1·실패1) 홉별 추적 — 박스 나열 아님
- [ ] SPOF 목록(컴포넌트 + 사람 + 외부 의존) + 수용/이중화 명시 결정
- [ ] 부품(큐·샤딩·캐시)은 숫자가 요구할 때만 — "혹시 몰라서" 없음
- [ ] 산출물 저장 위치 — 프로젝트면 `docs/adr/NNNN-*.md`(append, 덮어쓰기 금지) / 스킬 폴더 저장 안 함
- [ ] (면접) 요구 확인 → 봉투 뒷면 → 상위 → 심화 → 트레이드오프 순, 가정 소리 내어 명시

## 점검 주기 (부패 느림 — 연 1회)

- 지연/캐파 어림치 재확인: 하드웨어 세대(메모리·NVMe·네트워크)·RDB 메이저(현 PG18) 변화로 "단일 서버 천장"은 매년 상향 — 자릿수만 갱신
- 가용성 환산·봉투 뒷면 산수는 수학적 항등이라 불변(원칙은 버전보다 오래 감)
- 실증 사례(Stack Overflow·부검 장르)는 역사적 사실 — 출처 링크 유효성만 연 1회 확인, 새 공개 사례 있으면 보강
