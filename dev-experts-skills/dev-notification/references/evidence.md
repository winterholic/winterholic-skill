# dev-notification evidence — 실증 사례

## 1. HBO Max 인턴 메일 (2021-06) — 구조 결함의 미담 포장 (공개 사건)

- **무슨 일**: 전체 구독자에게 빈 테스트 메일 발송 → 회사가 "인턴 실수" 공지 → #DearIntern 연대 트윗 물결. 따뜻한 결말과 별개로, 테스트가 실수신자 전체에 닿는 경로가 열려 있었다는 구조 문제는 그대로다.
- **구조 방어 3종**: ① 비프로덕션 환경은 **샌드박스 발송**(실제 게이트웨이 차단 — 콘솔/목 수신함으로) ② 프로덕션에서도 수신자 화이트리스트 모드(내부 도메인만)를 기본으로 두고 명시 해제 ③ 전량 발송 API에 수량 가드("수신자 N만+ 발송은 2단 확인/점진 발사 강제").
- **연결**: dev-incident-response blameless — "인턴이 문제"가 아니라 "인턴의 실수가 전 구독자에게 닿는 시스템"이 문제. 같은 장르: 전 직원 회신 폭풍(reply-all storm)·오발송 쿠폰(법적 분쟁까지)·타 사용자 데이터가 담긴 메일(개인정보 사고로 승격 — dev-privacy-compliance).

## 2. 스팸함 추락 — "발송 성공률 99%인데 아무도 못 받는다" (발신 평판 실무)

- **무슨 일**: 발송 로그는 전부 성공인데 수신자 문의 "메일이 안 와요" — 진단해보니 대부분 스팸함. 원인 합성: SPF/DKIM/DMARC 미설정(→ dev-dns-domain-email) + 반송 주소로 반복 발송(평판 하락) + 광고성 문구·이미지 과다 + 갑작스런 발송량 급증(워밍업 없는 대량 발사).
- **평판의 구조**: 수신측(Gmail 등)은 발신 도메인/IP의 이력(반송률·신고율·열람 패턴)으로 분류한다 — **죽은 주소 정리와 신고율 관리가 곧 도달률 관리**다. Gmail 공식 발신자 기준(2024-02 시행, 하루 5,000통+ 대량 발신자 대상)은 신고율을 **0.3% 미만 필수 / 0.1% 미만 권장**으로 못박는다 — 0.3% 초과 시 완화(mitigation) 자격 박탈, 7일 연속 0.3% 미만이어야 회복. 이 임계는 Postmaster Tools에 일 단위로 집계된다. 또한 2025-11부터 Gmail은 미준수 발신에 일시 실패(4.7.x)·영구 거부(5.7.x) 코드로 집행을 강화했다(확인 필요 — 적용 강도는 발신자별 상이). (검증: [Gmail 발신자 가이드라인 — Google Workspace 관리자 도움말](https://support.google.com/a/answer/81126), 0.3%/0.1%·5,000통 임계의 1차 출처 / 7일 연속 회복·완화 자격 규정은 [Email sender guidelines FAQ](https://support.google.com/a/answer/14229414), 둘 다 Google 공식 문서)
- **점검 도구**: [Google Postmaster Tools](https://support.google.com/mail/answer/9981691)로 도메인 평판·신고율 확인 + 테스트 계정(주요 메일 사업자별)으로 실제 수신함 위치 확인 — "보냈다"와 "받았다" 사이를 측정하는 것이 이 영역의 전부다. (Gmail·Yahoo가 함께 2024-02부터 SPF/DKIM/DMARC·원클릭 수신거부를 대량 발신 요건으로 의무화 — → dev-dns-domain-email)

## 3. 알림 피로 — 끄기 버튼은 영구적이다 (제품 데이터 집적)

- **무슨 일**: 푸시 허용률·알림 유지율 업계 데이터들이 일관되게 보여주는 것 — 과도한 발송 직후 옵트아웃이 급증하며, **한 번 끈 사용자는 거의 돌아오지 않는다**. 알림 끄기는 가역적 설정이지만 행동으로는 비가역에 가깝다.
- **설계 번역**: ① 알림 가치 = (수신자에게 지금 유용한가) — 보내는 쪽 사정(마케팅 목표)으로 보내는 알림이 잔고를 태운다 ② 첫 알림 경험이 허용 유지의 분수령 — 온보딩 직후 폭격 금지 ③ 등급·묶음·사용자 설정은 UX 옵션이 아니라 채널 자산 보호 장치다.
- **모니터링 알림과의 통일 원리**: dev-monitoring의 alert fatigue(무시되는 경보는 없는 경보)와 동일 — 사람의 주의는 시스템 자원이고, 고갈 나면 진짜 위급 신호가 죽는다. 수신자가 운영자든 고객이든 같은 수학이다.

> 출처: HBO Max 공개 사건(2021) · 메일 발신 평판 실무(Postmaster 가이드류) · 푸시/알림 제품 지표 집적. 2026-06 기준 — 신고율 임계 등 수치는 사업자별 확인.
