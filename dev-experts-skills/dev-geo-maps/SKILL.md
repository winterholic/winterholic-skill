# dev-geo-maps — 지도·위치 전문가

> 기준: 카카오맵/네이버지도 API + Google Maps + PostGIS (2026-06, API 세부 확인 필요) · 부패 등급: 중간(반기)

## 정체성

지리정보 실무 전통(여행가챠 tour-data 직결). **"위치 버그의 태반은 알고리즘이 아니라 규약이다 — 좌표 순서, 좌표계, 그리고 '거리'라는 단어의 동상이몽(직선? 도로? 도보?)"**. 지도는 보이는 기능이라 데모는 쉽고, 규약 사고는 데이터가 쌓인 뒤 터진다.

핵심 신조: 좌표는 항상 (lat, lng) 명명으로 다룬다(암묵 배열 금지) · 좌표계는 데이터의 단위다(섞으면 무의미) · "거리"는 정의부터 · API 요금은 설계 변수다.

비유 — 좌표 순서 혼동은 **성과 이름이 뒤집힌 명부**다: 김철수와 철수김 — 대부분 어색해서 들키지만, 둘 다 그럴듯한 경우(위도 37, 경도 127 ↔ 둘 다 한국 근처 값)가 가장 위험하다. 한국 데이터는 (37, 127)대라 뒤집히면 **인도양 어딘가**로 가서 오히려 빨리 들킨다 — 진짜 함정은 전 세계 데이터다.

## 안티패턴 카탈로그 (❌/✅ — 이 스킬의 본체)

### 1. 좌표 순서 암묵 배열
❌ `[127.02, 37.49]`와 `[37.49, 127.02]`가 코드에 혼재 — GeoJSON은 (lng,lat), 대부분 지도 SDK는 (lat,lng)
✅ 내부 표현은 **명명 필드 단일 표준**(`{lat, lng}`) — 배열은 외부 규격 경계(GeoJSON 입출력)에서만 변환 + 그 변환 함수 한 곳에 집약
**왜**: 두 관례가 생태계에 공존한다(GeoJSON/WKT는 x=lng 먼저, Google·카카오 SDK는 lat 먼저). 암묵 배열은 어느 관례인지 코드만 봐선 모르고, 뒤집힌 좌표는 "지도에 점이 안 찍혀요"(바다)나 미묘한 오프셋으로 나타난다.

### 2. 좌표계(CRS) 무인지 혼합
❌ 공공데이터의 TM 좌표(미터 단위 6자리)를 WGS84(도 단위)로 그대로 사용 — 점이 엉뚱한 대륙에
✅ 데이터 수신 시 **좌표계 확인을 스키마의 일부로**(한국 공공데이터: WGS84(EPSG:4326)·GRS80 TM(EPSG:5186 등)·옛 KATEC 혼재) — 변환은 pyproj 등 검증 라이브러리로, 저장은 WGS84 단일 통일
**왜**: 좌표는 좌표계라는 단위가 붙은 수다 — 단위 없이 섞으면 cm와 inch를 더한 것. 관광·상권 공공데이터(tour-data류)는 제공처마다 좌표계가 달라, 통일 없이 적재하면 일부 데이터만 어긋나는 형태로 늦게 발견된다.

### 3. "거리" 정의 생략
❌ 하버사인 직선거리로 "도보 5분 거리" 표기 — 강 건너편 직선 300m가 도보 30분
✅ 정의 분기: 정렬·후보 압축은 직선거리(하버사인 — 공짜·빠름) / **사용자에게 보여주는 시간·거리는 경로 API**(도보·차량 구분) — 2단계 설계(직선으로 상위 N 추림 → 경로 API는 N건만)
**왜**: 직선거리는 지형·도로·다리를 모른다 — 여행·이동 서비스에서 체감 신뢰를 깎는 1순위. 거꾸로 전 건 경로 API 호출은 요금·지연 폭탄이라, 두 도구의 직무 분리가 설계의 핵심이다.

### 4. 마커 1만 개 직접 렌더
❌ 전 POI를 마커로 — 지도 이동마다 브라우저 정지
✅ ① 클러스터러(SDK 내장) ② 뷰포트 내만 로드(bounds 질의 — 서버가 거른다) ③ 대량이면 타일/히트맵 — 3단 사다리
**왜**: 마커는 각각 DOM/캔버스 객체다 — 수천 개부터 모바일이 먼저 죽는다. "지도에 다 보여주기"는 요구가 아니라 미설계다 — 사용자가 한 화면에서 인지하는 POI는 수십 개뿐.

### 5. API 키 노출·쿼터 무관리
❌ 프론트 번들에 무제한 키 — 타인이 내 키로 호출(요금 내 것) / 무료 쿼터 소진 시 지도 전체 백지
✅ 키 분리(프론트 키는 도메인/앱 제한 걸고 노출 전제, 서버 키는 비공개) + 쿼터 알림 + 호출 캐싱(지오코딩 결과는 저장 — 같은 주소 재호출 금지)
**왜**: 지도 API는 호출당 과금이다(Google 2018 가격 개편이 생태계 교훈 — evidence). 지오코딩은 결과가 거의 불변이라 캐시 적중률이 극히 높다 — 캐싱 없는 지오코딩은 같은 답을 돈 주고 반복 구매하는 것.

### 6. 근접 검색을 전 행 거리 계산으로
❌ `ORDER BY haversine(lat,lng,:lat,:lng)` 전 행 — 풀스캔 + 함수 계산, 데이터와 함께 선형 악화
✅ ① 1차: 경계 상자(bounding box — lat/lng BETWEEN, 일반 인덱스 사용 가능)로 후보 압축 ② 2차: 후보만 정밀 거리 ③ 본격 규모는 PostGIS(`ST_DWithin` + GiST 인덱스)
**왜**: 거리 함수는 인덱스를 못 탄다(dev-sql 안티패턴 1과 동일 원리 — 컬럼이 함수에 싸임). 경계 상자는 거리 계산을 인덱스 가능한 범위 술어로 바꾸는 표준 기교이고, PostGIS는 그걸 공간 인덱스로 정식화한 것.

## 워크플로우 (위치 기능 1건)

1. **규약 표 작성** — 데이터 소스별 [좌표계 / 좌표 순서 / 정밀도]를 표로 — 코드 작성 전에.
2. **작성** — 좌표 타입·변환 함수는 단일 모듈(`geo/` 등)에 집약, 프로젝트 디자인 시스템·기존 구조 우선. 기존 파일 덮어쓰기 대신 Edit.
3. **검증 (copy-paste)**:
   ```
   python -c "from geo import to_wgs84; print(to_wgs84(958114, 1943670, 'EPSG:5186'))"   # 변환 1건 눈 확인
   # 적재 검증: 범위 이탈 좌표 검출
   python -c "import json; d=json.load(open('pois.json')); print([p for p in d if not (33<p['lat']<39 and 124<p['lng']<132)][:5])"
   ```
4. **눈 검증 의무** — 표본 5~10개를 실제 지도에 찍어 실세계 위치와 대조(좌표 사고는 눈이 가장 빨리 잡는다). 알려진 장소 1개(자기 동네 등)를 항상 포함.

### 판단 불가 시 — `[확인 필요]` 4요소

좌표 사고는 추측으로 변환하면 전 데이터가 조용히 어긋나므로, 좌표계·순서·정밀도가 불확실하면 멈춰 묻는다(누가/언제/어떻게/기대값):

- **좌표계(CRS) 불명**: "이 데이터가 WGS84인지·TM계인지를 / 변환·적재 전에 / 값의 자릿수(도 단위 소수 vs 미터 6자리)와 제공처 메타데이터로 / 33~39·124~132 범위면 WGS84, 수십만 단위면 TM(EPSG 확인 필요)" — CRS 미확정 변환 금지(엉뚱한 대륙 행).
- **좌표 순서 (lat,lng) vs (lng,lat)**: "이 배열이 lat 먼저인지를 / 외부 소스 파싱 시 / 알려진 장소 1개를 실제 지도에 찍어보는 눈 검증으로 / 자기 동네에 찍히면 정상, 인도양/바다면 뒤집힘" — 추측으로 swap 적용 금지, 표본 확인 후 변환.
- **정밀도가 용도에 충분한지**: "소수 4자리(~11m)가 도보 안내에 충분한지를 / 기능 설계 시 / 요구 정밀도(매장 입구 vs 동네 단위)와 데이터 정밀도 대조로 / 충분하면 진행, 부족하면 더 정밀한 소스 필요" — 기대값 못 얻으면 `[확인 필요: 좌표계/정밀도 — 표본 눈 검증 필요]`로 남기고 ledger 기록.

## 실전 케이스 — Null Island와 Google Maps 요금 개편 (2018): 규약과 비용의 양대 교훈

(0,0) 좌표 — 기니만 바다의 "Null Island" — 는 지오코딩 실패·빈 값이 0으로 적재된 데이터가 모이는 가상의 섬으로, GIS 업계의 공인된 농담이자 실재하는 데이터 품질 문제다(전 세계 데이터셋에서 (0,0) 군집은 거의 항상 결측 처리 버그). 같은 해 Google Maps 요금 대개편(2018-06-11 발표·07-16 발효, API 키+결제계정 필수화·월 $200 크레딧 전환)은 무료에 기대 설계된 수많은 서비스에 월 수백~수천 달러 청구서를 안기며 "지도 API는 설계 변수"임을 생태계에 각인 — 국내 카카오·네이버 API 의존 설계도 쿼터·약관 변경 리스크는 동일하다. 교훈: ① 실패 좌표는 0이 아니라 NULL로(검증 게이트) ② API 비용 구조는 아키텍처 결정(캐싱·2단 설계)의 입력 ③ 단일 지도 SDK 결합도를 낮춰두면(좌표 모듈 집약) 제공자 변경이 가능해진다. 상세: `references/evidence.md`
