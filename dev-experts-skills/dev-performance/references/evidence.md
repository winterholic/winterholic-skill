# dev-performance evidence — 실증 사례

## 1. GTA V 온라인 로딩 (2021) — "프로파일 한 번이면 보였다" (t0st 공개 분석)

- **무슨 일**: GTA Online 로딩 ~6분이 7년간 악명. 익명 개발자 t0st가 바이너리만 들고 스택 샘플링 → 두 함수가 시간 대부분 점유 확인:
  1. 10MB JSON(인게임 상점 카탈로그)을 sscanf 루프로 파싱 — sscanf 구현이 호출마다 strlen → O(n²)
  2. 파싱 항목 중복 검사를 배열 선형 탐색 — O(n²) 2호
- **결과**: 캐싱(strlen 회피) + 해시셋(중복 검사) PoC로 6분 → 약 1분 50초 (70%). Rockstar 공식 반영 + 포상.
- **교훈 체계화**: ① 병목의 위치는 직감 밖(렌더링·네트워크가 아니라 JSON 파싱) ② O(n²)는 n이 작을 때 무죄로 보인다 — 데이터 성장이 곧 시한장치 ③ 소스 없이도 측정은 가능하다 — "프로파일링이 어려워서"는 거의 항상 핑계 쪽이다.

## 2. The Tail at Scale (Dean & Barroso, 2013) — 평균이 거짓말하는 구조

- **무슨 일**: Google 논문이 정식화한 테일 레이턴시 원리 — 서버 1대의 p99가 1초일 때, 요청이 서버 100대를 부채꼴 호출(fan-out)하면 **전체 요청의 63%가 1초+** (1-0.99¹⁰⁰). 평균이 좋아도 테일이 사용자 체감을 지배하는 수학적 구조.
- **실무 번역**: 마이크로서비스·DB 샤딩·외부 API 조합 호출이 많을수록 개별 서비스의 p99 관리가 전체 p50을 결정한다. 처방(논문 제시): 헤지 요청·타임아웃+재시도·느린 복제본 회피 — 단 재시도는 부하 증폭 주의(→ dev-api-integration 백오프).
- **이 스킬과의 연결**: 안티패턴 2. "평균 80ms인데 느리다는 제보가 와요"는 모순이 아니라 분포를 안 본 것.

## 3. 마이크로벤치 무효 측정 — "0ns의 함수" (컴파일러 최적화 실증)

- **무슨 일**: 결과를 사용하지 않는 벤치 루프를 컴파일러가 통째로 제거(dead code elimination)해 "수백만 호출이 0ns"로 측정되는 고전 함정 — JMH(Java)·criterion(Rust) 문서가 첫 페이지에서 경고하는 내용.
- **체크리스트**: ① 결과를 blackhole/사용 처리 ② 워밍업 구간 분리(JIT 언어) ③ 입력을 컴파일 타임 상수로 두지 않기(상수 접기 방지) ④ 통계 처리(반복·분산) — 이 4종을 직접 구현하지 말고 하네스를 쓰는 게 결론.
- **이 스킬과의 연결**: 안티패턴 3. 그리고 마이크로 결과는 항상 시스템 프로파일의 비중과 곱해 해석 — "이 함수 2배 개선"이 전체 0.2%면 우선순위 미달.

> 출처: t0st 공개 블로그 + Rockstar 공식 인정(2021) · Dean & Barroso "The Tail at Scale"(CACM 2013) · JMH/criterion 공식 문서. 2026-06 기준.
