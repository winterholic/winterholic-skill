# evidence + 출고 전 체크리스트

## 실증·출처

- **Martin, *Clean Architecture* (2017)** — 의존성 규칙·"층수는 네 개가 아니어도 된다"(원전 명시)의 출처.
- **Cockburn, "Hexagonal Architecture" (2005, alistair.cockburn.us)** — 포트·어댑터 원전. "앱이 UI·DB 없이 테스트로 구동 가능해야"가 원래 동기 — 테스트 가능성이 목적이라는 본 스킬 신조의 뿌리.
- **Cockburn & Garrido de Paz, *Hexagonal Architecture Explained* (2024, ISBN 9781737519782)** — 원저자가 19년 만에 직접 쓴 단행본. 2005년 웹문서의 모호함(육각형 그림이 처방으로 오독)을 본인이 교정하고 포트·어댑터 의미를 재정의 — 본 스킬의 헥사고날 어휘 채택의 최신 1차 출처.
- **SQLite, "How SQLite Is Tested" (sqlite.org 공식 문서)** — VFS 포트 기반 장애 주입·100% 분기 커버리지. SKILL.md 실전 케이스.
- **비판 출처**: Dan North·커뮤니티의 클린 아키텍처 비용 비판(다수 공개 강연·글, 2010년대 후반) — 비판 표의 재료. 특정 글 1개가 아니라 흐름으로 인용(개별 인용 확인 필요).
- 오픈소스 차용 표기: 클린 아키텍처 보일러플레이트 레포 다수(색인 인지) — **역흡수**: 대부분 4층 직역 템플릿 — 층수 회계·포트 도입 판정표·의존 방향 기계 검사·비판 동비중이 본 스킬 차별점.

## 출고 전 체크리스트 (구조 출고 시)

- [ ] domain/이 표준 라이브러리만 import (`dependency_direction.py` 0건)
- [ ] domain 테스트가 프레임워크 미설치 환경에서 green (구조의 산 증거)
- [ ] 경계 표 작성 — 각 포트에 실명 교체 시나리오 (없으면 정직 결합)
- [ ] 구현체 1개+더블 0개인 인터페이스 없음
- [ ] 포트 시그니처에 외부 타입·예외 누수 없음
- [ ] 시계·랜덤이 주입 가능
- [ ] 조립이 한 곳(main/lifespan)
- [ ] DTO 변환 요청당 2회 이내 (초과 시 층 회계 재검)
