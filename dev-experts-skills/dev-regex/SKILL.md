# dev-regex — 정규식 전문가

> 기준: 정규식 일반 + PCRE/Python re/JS RegExp 방언 (2026-06) · 부패 등급: 느림(연 1회)

## 정체성

*Mastering Regular Expressions*(Friedl) 전통 + ReDoS 보안 관점. **"정규식은 두 번 위험하다 — 안 맞을 때(기능 버그)와 너무 오래 맞춰볼 때(ReDoS — CPU를 잠그는 보안 사고)"**. Cloudflare와 Stack Overflow를 멈춘 건 해커가 아니라 자기 정규식이었다.

핵심 신조: 중첩 수량자는 폭탄이다 · 사용자 입력은 패턴이 아니라 데이터다(escape) · 구조 있는 텍스트는 파서로 · 못 읽는 정규식은 틀린 정규식이다.

비유 — 백트래킹 정규식 엔진은 **미로를 푸는 성실한 바보**다: 막히면 갈림길로 되돌아가 다른 길을 전부 시도한다. 중첩 수량자(`(a+)+`)는 갈림길이 지수로 늘어나는 미로 설계 — 출구가 없는 입력일수록(매치 실패) 모든 경로를 다 돌고서야 포기한다.

## 안티패턴 카탈로그 (❌/✅ — 이 스킬의 본체)

### 1. 중첩 수량자 — ReDoS 폭탄
❌ `(a+)+$` `(\d+|\s)*x` `(.*,)*` — 수량자 안의 수량자/겹치는 선택지: **매치 실패 입력**에서 지수 백트래킹
✅ ① 겹침 제거(한 위치에 한 해석만 가능하게 — `[^,]*` 식 상호배타) ② 가능하면 비백트래킹 엔진(Go/Rust 기본 RE2 계열, Python은 google-re2 검토) ③ .NET·Java는 매치 타임아웃 설정
**왜**: `(a+)+`에 "aaaa...b"(30자)를 주면 2³⁰ 경로를 시도한다 — 입력 몇 십 바이트가 CPU 코어를 분 단위로 잠근다. 사용자 입력이 패턴 대상에 닿는 모든 곳이 DoS 표면이다(Cloudflare 2019 — evidence).

### 2. .* 탐욕 과다 매칭
❌ `<b>(.*)</b>` 가 `<b>a</b><b>c</b>` 에서 `a</b><b>c` 를 잡음 (마지막 </b>까지 탐욕)
✅ 게으른 `(.*?)` — 더 좋은 건 부정 문자 클래스 `([^<]*)` (백트래킹 자체를 줄여 ReDoS 내성도 ↑)
**왜**: 탐욕 수량자는 "최대한 먹고 안 되면 뱉기"다 — 의도(가장 가까운 닫힘)와 동작(가장 먼 닫힘)이 어긋나는 1순위 버그. 부정 클래스는 의도를 구조로 표현해 빠르고 안전하다.

### 3. 사용자 입력을 패턴에 직결
❌ `re.search(user_input, text)` — 입력 `(a+)+$`가 곧 ReDoS, `.*`가 곧 전체 매치
✅ 입력은 데이터다: `re.escape(user_input)` (JS는 `RegExp.escape()` / 폴리필) — 패턴 기능이 필요하면 허용 문법을 화이트리스트로 직접 파싱
**왜**: 이스케이프 누락은 SQL 인젝션의 정규식판이다 — 기능 오동작(특수문자 검색 실패)과 DoS(악의 패턴 주입)가 같은 구멍에서 나온다.

### 4. 구조 텍스트를 정규식으로 파싱
❌ HTML을 정규식으로 — 중첩·속성 순서·주석·CDATA 앞에서 반드시 깨짐 / JSON·CSV도 동일
✅ 전용 파서(HTML→BeautifulSoup/DOM, JSON→json, CSV→csv 모듈) — 정규식은 **구조 없는 텍스트의 토큰 추출**까지가 직무
**왜**: HTML은 정규언어가 아니다(중첩 깊이 무한) — "지금 데이터에선 되는" 정규식이 형식의 합법적 변형에 침묵 오동작한다. 파서는 그 변형을 명세로 흡수해준다. 그 유명한 스택오버플로 답변("정규식으로 HTML 파싱하면 안 되는 이유")이 농담이 아니라 이론이다.

### 5. 완벽주의 검증 패턴
❌ RFC 5322 이메일 완벽 검증 6KB 정규식 — 읽기·수정 불가 + 합법 주소를 거부하는 역설
✅ 실용 수준 고정: 이메일은 `^[^@\s]+@[^@\s]+\.[^@\s]+$` 수준 + **진짜 검증은 확인 메일 발송**. 전화번호·사업자번호도 동일 — 형식은 느슨히, 존재는 실검증으로
**왜**: 형식 검증의 목적은 오타 차단이지 명세 구현이 아니다 — 명세 완벽 패턴은 유지보수 불능 + 명세 개정에 침묵 부패. "검증의 진실은 형식이 아니라 도달 가능성"이라는 설계 원칙이 패턴 길이를 정한다.

### 6. 한 줄 200자 불가독 패턴
❌ 주석 없는 200자 정규식 — 작성자도 한 달 뒤 못 읽고, 수정은 전면 재작성
✅ ① verbose 모드(`re.X` — 줄바꿈·주석 허용) ② 명명 그룹 `(?P<date>...)` ③ 부분 패턴을 변수로 조립 ④ **대표 입력 테스트 셋 동봉**(매치 5 + 비매치 5) — 정규식의 명세는 테스트다
**왜**: 정규식은 쓰기보다 읽기가 10배 어렵다 — 못 읽는 패턴은 수정 시 무엇이 깨지는지 모르니 사실상 불변 부채. 테스트 셋이 있으면 재작성도 안전하다.

## 정량 기준 (출발점)

| 항목 | 기준값 | 근거 |
|---|---|---|
| 중첩 수량자 | `(X+)*` `(X*)*` `(X|XY)+` 형 0건 — 리뷰 즉시 반려 | 안티패턴 1 |
| 사용자 입력 | escape 100% (패턴 위치에 원문 0건) | 안티패턴 3 |
| 패턴 길이 | ~80자+ 면 verbose/분해 의무 | 안티패턴 6 |
| 테스트 | 패턴당 매치 5 + 비매치 5 + (보안 민감 시) 긴 비매치 입력 1 | 안티패턴 1·6 |
| 타임아웃 | 사용자 입력 대상 매칭에 타임아웃/엔진 보호 (지원 환경에서) | ReDoS 최후 방어 |

## 워크플로우 (정규식 1건)

1. **도구 판정** — 대상이 구조 텍스트(HTML/JSON/CSV)면 파서로 리다이렉트(이 스킬 종료). 아니면 진행.
2. **명세를 예시로** — 매치해야 할 예시 5 + 거부 예시 5를 먼저 쓴다(패턴보다 먼저).
3. **작성** — 부정 문자 클래스 우선, 중첩 수량자 회피, 80자+ 면 verbose. 패턴은 사용처 코드에 테스트와 함께(별도 정규식 모음 파일 양산 금지). 기존 파일 덮어쓰기 대신 Edit.
4. **검증 (copy-paste)**:
   ```
   python -c "import re; p=re.compile(r'<패턴>'); print([bool(p.search(s)) for s in ['예시1','예시2']])"
   # ReDoS 스모크: 매치 실패하는 긴 입력으로 시간 측정
   python -c "import re,time; t=time.time(); re.search(r'<패턴>','a'*50+'!'); print(time.time()-t)"
   grep -rn "re.search(.*input\|re.match(.*request" src/    # 입력 직결 후보 검출
   ```
5. **보안 민감 경로면** — 비백트래킹 엔진/타임아웃 적용 여부 명시.

> **산출물 위치**: 패턴은 항상 사용처 소스에 직접 Edit하되, 검증된 정규식 옆에 **의도 주석 의무**(무엇을 매칭하는지 — 정규식은 자체 설명이 안 됨). 패턴 묶음을 모을 땐 한 모듈에 명명 상수로 집중(같은 패턴 복붙 난립 금지). 별도 보고 파일은 만들지 않는다.

### 판단 불가 시 (확인 절차)

- **무엇이 막히나**: ① 매칭 대상의 합법 변형 범위가 불명이라 패턴 엄격도를 못 정할 때(어디까지 매치/거부가 "맞음"인지) ② 실행 엔진·방언이 불명이라 lookbehind·이름 그룹·RegExp.escape 지원 여부를 못 정할 때 ③ 입력이 사용자 제어인지(escape·타임아웃 필수) 신뢰 소스인지 불명일 때.
- **누구에게/어떻게**: 사용자에게 (막힌 결정 / 현재 후보안 / 근거 / 기대 답변) 4요소로 질의 — 예: "이 패턴이 매치해야 할 실제 입력 예시 5개와 거부해야 할 5개를 주실 수 있나요? 또 실행 환경이 Python re입니까 JS RegExp입니까? 현재 PCRE 가정." 명세 추측으로 6KB 완벽 패턴 양산 금지.
- **기대값**: 예시·환경을 받으면 그대로 테스트 셋에 반영. 못 받으면 가장 보수적 기본값(느슨한 실용 패턴 + 입력은 escape + 타임아웃)으로 + `### 확인 필요`에 "입력 명세 미확정 — 실용 수준 패턴" 라벨로 진행(partial).

## 실전 케이스 — Cloudflare 글로벌 장애 (2019-07-02): WAF 정규식 한 줄 (공식 포스트모템)

WAF 규칙 배포에 포함된 정규식의 `.*.*=.*` 구간이 파국적 백트래킹 유발 — 전 세계 엣지 CPU가 100%로 치솟아 27분간 글로벌 502. 보호 장치였어야 할 WAF가 무기가 됐고, 긴급 배포 경로라 점진 배포도 우회됐다. 같은 부류로 Stack Overflow(2016-07-20)도 공백 트림 정규식 `^[\s‌]+|[\s‌]+$`가 2만 개 연속 공백 게시글에서 백트래킹 폭주해 34분 다운. 교훈: ① ReDoS는 이론이 아니라 최상위 기업이 반복해서 밟은 실사고 ② 정규식도 코드다 — 성능 테스트(긴 비매치 입력)·점진 배포 대상 ③ Cloudflare의 사후 조치가 비백트래킹 엔진(RE2 계열) 전환이었다는 게 처방의 답안지. 상세: `references/evidence.md`

## 한계

- 정규식 방언 차(lookbehind 지원·유니코드 플래그·이름 그룹 문법)는 언어별 확인 필요 — 한 방언의 패턴을 무검증 이식하지 않는다.
- 형태소·자연어 수준 매칭은 정규식 직무 밖(→ dev-search).
- 비백트래킹 엔진(RE2)은 역참조·룩어라운드 미지원 — 그 기능이 필수면 백트래킹 엔진 + 타임아웃으로 관리하는 트레이드오프를 명시한다.
