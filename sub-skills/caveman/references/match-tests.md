# caveman 매칭 회귀 시나리오

새 트리거·SKIP 키워드 추가 시 이 표를 검증 anchor로 사용한다. 입력 메시지 → 기대 결과 매핑.

각 행은 SKILL.md의 "자동 트리거 판정 규칙"의 5개 카테고리 / SKIP 우선 규칙 / 강도 자동 선택 / SKIP 회색지대 처리를 검증한다.

## 1) 명시적 호출 (단계 ①)

| # | 입력 | 기대 동작 | 검증 항목 |
|---|------|----------|----------|
| 1.1 | `/caveman` | full 강도로 활성 | 명시 호출 기본값 |
| 1.2 | `/caveman ultra` | ultra 강도로 활성 | 명시 호출 + 강도 지정 |
| 1.3 | "talk like caveman" | full 강도로 활성 | 영문 명시 호출 |
| 1.4 | "케이브맨 모드" | full 강도로 활성 | 한국어 명시 호출 |
| 1.5 | "stop caveman" | 비활성 | 명시 해제 |
| 1.6 | "원래대로" | 비활성 | 한국어 해제 |

## 2) 자동 트리거 5개 카테고리 (단계 ③)

| # | 입력 | 기대 카테고리 | 기대 강도 |
|---|------|-------------|----------|
| 2.1 | "이거 짧게 설명해줘" | (1) 명시 짧음 | full |
| 2.2 | "TL;DR로 부탁" | (1) 명시 짧음 | full |
| 2.3 | "ㄱㄱ 다음 단계 진행" | (2) 캐주얼 | lite |
| 2.4 | "빨리 좀 봐줘 급해" | (2) 캐주얼 | lite |
| 2.5 | "왜 안 돼 이거" | (3) 디버깅 | full |
| 2.6 | "이 에러 봐줘" | (3) 디버깅 | full |
| 2.7 | "이거 맞아?" | (4) 확인성 | ultra |
| 2.8 | "옵션 이름이 뭐였더라" | (4) 확인성 | ultra |
| 2.9 | "이거 해도 돼?" | (5) 의사결정 | lite |
| 2.10 | "괜찮지 이렇게?" | (5) 의사결정 | lite |

## 3) SKIP 우선 (단계 ②가 ③보다 우선)

| # | 입력 | 기대 동작 | 이유 |
|---|------|----------|------|
| 3.1 | "에러 왜 그런지 자세히 설명해줘" | 비활성 (일반 응답) | 디버깅(③) + "자세히/설명해줘/왜 그런지"(SKIP) → SKIP 승 |
| 3.2 | "이거 맞아? 근거도 알려줘" | 비활성 | 확인성(③) + "근거"(SKIP) → SKIP 승 |
| 3.3 | "ㄱㄱ 다만 트레이드오프는 자세히" | 비활성 | 캐주얼(③) + "트레이드오프/자세히"(SKIP) → SKIP 승 |
| 3.4 | "버그인데 회고 작성해줘" | 비활성 | 디버깅(③) + "회고"(SKIP) → SKIP 승 |

## 4) 카테고리 동시 매칭 (강도 더 낮은 쪽 선택)

| # | 입력 | 매칭 카테고리 | 기대 강도 |
|---|------|--------------|----------|
| 4.1 | "맞아? 어때 이거" | (4) ultra + (5) lite | **lite** (더 낮은 쪽) |
| 4.2 | "ㄱㄱ 짧게" | (1) full + (2) lite | **lite** |
| 4.3 | "왜 안 돼 빨리 봐줘" | (2) lite + (3) full | **lite** |
| 4.4 | "TL;DR 이거 맞나" | (1) full + (4) ultra | **full** (더 낮은 쪽) |

## 5) 정밀도 보호 (false positive 방지)

| # | 입력 | 기대 동작 | 보호 규칙 |
|---|------|----------|----------|
| 5.1 | `print("짧게")` 코드 안에서 | 비활성 유지 | 인용 안 키워드 무시 |
| 5.2 | "짧게 말고 자세히 설명해줘" | 비활성 | 부정형 → SKIP 처리 |
| 5.3 | "'자세히'라는 단어가 SKIP 키워드야?" | 비활성 (메타 응답) | 메타 질문은 일반 응답 |
| 5.4 | "지금 caveman 모드 뭐야?" | 일반 응답으로 상태 보고, 모드 유지 | 상태 조회 |

## 6) SKIP 회색지대 처리 (1회 재확인)

| # | 입력 | 기대 동작 |
|---|------|----------|
| 6.1 | "이거 자세히는 모르겠는데 짧게 답해줘" | 트리거 활성(짧게 명시 + "자세히"는 부정 맥락) |
| 6.2 | "자세히는 됐고 결론만" | 트리거 활성(반어법, "결론만" 우세) |
| 6.3 | (모호한 경우) "자세히 짧게" | 1회 질의: "짧게 답할까요, 자세히 답할까요?" |

## 7) 사용자 피드백 시 강도 조정 (자동 트리거 판정 § 6)

활성 중인 상태에서 사용자가 다음과 같이 응답:

| # | 현재 강도 | 사용자 피드백 | 기대 동작 |
|---|----------|--------------|----------|
| 7.1 | lite | "더 짧게" | full로 상향 |
| 7.2 | full | "더 압축" | ultra로 상향 |
| 7.3 | ultra | "더 줄여" | "wenyan-full 시도할까요?" 1줄 제안 |
| 7.4 | ultra | "너무 짧아" | full로 하향 |
| 7.5 | lite | "이해 안 됨" | 일반 모드로 전환, "caveman 해제됨" 보고 |
| 7.6 | full | "어색해" | "lite/full/ultra 중 어느 쪽?" 1회 질의 |

## 8) Auto-Clarity (단계 4 자동 일반 모드)

| # | 입력 / 상황 | 기대 동작 |
|---|-----------|----------|
| 8.1 | `DROP TABLE users` 같은 destructive op | 경고 박스(일반 문체)로 표시 후 캐브맨 재개 |
| 8.2 | "무슨 말?" / "다시" / "이해 안 됨" | 일반 문체 재서술 + "(caveman 재개)" 표기 |
| 8.3 | wenyan-* 활성 중 사용자가 "한자 안 보여" / "□□로 표시됨" | 즉시 동일 의미를 full로 재출력, wenyan-* 자동 트리거 잠금 |
| 8.4 | 다단계 절차(1·2·3 순서) 응답 작성 중 순서 모호 위험 | 일반 문체로 잠시 풀고 끝나면 재개 |

## 9) 다른 스킬과의 호출 순서 (Boundaries)

| # | 상황 | 기대 동작 |
|---|------|----------|
| 9.1 | caveman 활성 중 `/pr-review` 호출 | 보고서 HTML/MD은 일반 문체, 채팅 응답만 caveman |
| 9.2 | caveman 활성 중 `/git-workflow`로 커밋 메시지 작성 | 커밋 메시지는 일반 문체, 채팅 안내만 caveman |
| 9.3 | caveman 활성 중 Edit 도구로 코드 수정 | 코드 자체는 원본, 변경 설명만 caveman |
| 9.4 | caveman + 도구 실행 결과 보고 | 실행 결과·에러는 원문, 그 위 해석만 caveman |

---

## 사용법

새 키워드 추가·변경 시:
1. 변경 후 위 시나리오를 메시지 단위로 실제 입력해보며 기대 동작과 일치하는지 확인
2. 새 키워드가 5번(정밀도 보호) 또는 6번(회색지대)에 걸리지 않는지 검토
3. 다른 카테고리와 동시 매칭 시 4번 규칙 충돌 없는지 확인
4. 회귀 발견 시 이 파일에 새 시나리오 행 추가
