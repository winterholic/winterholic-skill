# life-science — 과학 연구 라우터

Scientific Agent Skills 원본 166종을 한꺼번에 읽지 않고, 요청에 맞는 스킬 1개와 필요할 때만 보조 1개를 고른다. 원본은 자동 등록되지 않는 `imported-sub-skills`에 두므로 상시 컨텍스트 비용은 생기지 않는다.

> 용어: **lazy load(지연 로드)** = 카탈로그에서 후보를 고른 뒤 선택된 `SKILL.md`와 필요한 번들만 읽는 방식. **원본 팩** = K-Dense 저장소를 변경하지 않고 로컬에 보관한 체크아웃.

## 경계부터 판정

| 요청 | 처리 |
|---|---|
| 공개 논문·공개 데이터·실험·모델·과학 패키지를 이용한 연구 | 이 라우터 |
| 개인의 증상·검사 결과·투약·치료 결정 | `life-medical-navigation`으로 보낸다. 연구 스킬로 환자별 결론을 내리지 않는다 |
| 일반 앱·백엔드·인프라 구현 | `dev-experts`로 보낸다 |
| 과학 패키지의 분석 워크플로우를 코드로 구현 | 이 라우터를 주로, `dev-experts`를 구현 보조로 쓴다 |
| 현재 유행 병원체·최신 논문·변경 가능한 API/규정 | 원본 스킬만 믿지 말고 최신 1차 출처를 웹에서 확인한다 |

## 라우팅 절차

1. 요청을 `대상 도메인 + 하려는 동작 + 명시 도구/데이터 형식`으로 3등분한다.
2. `references/routing-index.md`에서 1차 영역과 대표 후보를 고른다. 도구명이나 파일 형식이 명시되면 넓은 방법론보다 그 전용 스킬을 우선한다.
3. 후보가 불명확하면 원본 카탈로그를 **검색만** 한다. 전체 파일을 읽지 않는다.

   ```powershell
   rg -n -i "<도구|데이터형식|연구동작>" "~/.claude\imported-sub-skills\scientific-agent-skills\docs\skills.md"
   ```

4. 주 스킬 1개를 정하고, 서로 다른 단계가 실제로 필요할 때만 보조 1개를 더 고른다. 선택한 파일만 읽는다.

   ```text
   ~/.claude\imported-sub-skills\scientific-agent-skills\skills\<skill-name>\SKILL.md
   ```

5. 선택한 스킬의 `license`, `compatibility`, 데이터 반출, API 키, 외부 서비스 요구를 먼저 확인한다. 번들 스크립트는 읽어서 네트워크·파일 쓰기·서브프로세스 범위를 확인하기 전 실행하지 않는다.
6. `SKILL.md`가 특정 `references/`나 `scripts/`를 지목할 때만 그 파일을 추가로 연다. 원본 저장소의 다른 스킬을 재귀적으로 훑지 않는다.
7. 결과에 사용한 스킬 이름과 원본 commit을 남긴다. 논문·보고서에 실질적으로 기여했다면 원본 저장소와 해당 도구/데이터의 인용 지침도 따른다.

## 선택 우선순위

1. **정확한 도구명/형식**: `scanpy`, `RDKit`, `PDB`, `FASTQ`, `DICOM`처럼 사용자가 지정한 것
2. **완결된 워크플로우**: `bulk-rnaseq`, `literature-review`, `experimental-design`처럼 시작부터 산출물까지 잇는 것
3. **좁은 전문 패키지**: 같은 단계의 구현체가 여러 개일 때 데이터 규모·환경·재현성 조건으로 선택
4. **범용 방법론**: 도구가 정해지지 않았을 때만 사용

❌ `biology`가 들어갔다는 이유로 관련 스킬 20개를 모두 읽는다.

✅ `h5ad 단일세포 QC·클러스터링`을 `도메인=유전체 / 동작=분석 / 형식=h5ad`로 나눠 `scanpy`를 주 스킬, 파일 구조 문제가 있을 때만 `anndata`를 보조로 읽는다.

## 안전·저작권 게이트

- 로컬 원본은 `references/upstream-and-licenses.md`에 기록된 commit 기준이다. 원본 파일의 라이선스·저작권 고지를 지우거나 winterholic 저작물인 것처럼 바꾸지 않는다.
- 저장소 루트는 MIT지만 **개별 스킬의 `license` 필드가 우선**한다. `Unknown`, `Proprietary`, 비상업(NC), GPL 계열은 특히 재배포·상업 사용 가능성을 별도로 판정한다.
- 원본 `SKILL.md`, 스크립트, 에셋은 `winterholic-skill` 공개 미러에 복사하지 않는다. 공개판에는 이 독자 작성 라우터와 출처 안내만 둔다.
- 사용자가 원본 스킬 자체의 배포를 요청하면 해당 스킬의 실제 라이선스 전문과 고지 파일을 먼저 확인한다. 불명확하면 링크로 안내하고 복사하지 않는다.
- 환자·피험자·미공개 연구 데이터와 API 키를 외부 서비스로 보내지 않는다. 필요한 경우 데이터 분류와 사용자 승인을 먼저 받는다.

## 실패·불가 시

| 상황 | 다음 수단 |
|---|---|
| 원본 팩 경로가 없음 | 일반 지식으로 진행하지 말고 K-Dense 원본 URL과 필요한 스킬 이름을 제시한다 |
| 후보가 2개 이상 동률 | 입력 형식·데이터 규모·실행 환경을 확인해 1개로 좁힌다 |
| 패키지·계정·API 키가 없음 | 설치나 키 읽기를 임의로 하지 않고, 재현 가능한 수동 절차 또는 공개 대체재를 제시한다 |
| 라이선스가 Unknown/Proprietary | 로컬 참고까지만 하고 원문·코드·에셋 재배포는 중단한다 |
| 환자별 판단으로 넘어감 | 즉시 `life-medical-navigation`으로 전환하고 의료 전문가 검토를 권한다 |

## 판단이 안 설 때

- **누가**: 사용자에게 묻는다.
- **언제**: 카탈로그 검색과 `compatibility` 비교 후에도 후보가 둘 이상이고, 선택에 따라 입력 변환이나 유료 서비스 사용이 갈릴 때.
- **어떻게**: “입력 형식과 로컬 실행/외부 API 중 어느 쪽을 원하는지” 한 문장으로 묻는다.
- **기대값**: 형식·환경 중 하나를 받으면 주 스킬 1개로 좁힌다. 답이 없으면 네트워크와 비용이 없는 로컬·읽기 전용 경로를 택하고 가정을 밝힌다.

## 산출 형식

```markdown
## 과학 라우팅
- 영역: <도메인 / 동작 / 형식>
- 주 스킬: <skill-name>
- 보조 스킬: <필요할 때만>
- 환경·데이터 경계: <의존성 / 외부 전송 여부>
- 출처: K-Dense scientific-agent-skills @ <commit>
```

## Gotchas

- 저장소 전체 MIT 표기만 보고 개별 스킬까지 MIT라고 단정하면 안 된다. 현재 체크아웃에는 Unknown·Proprietary·NC·GPL 등 서로 다른 표기가 섞여 있다.
- `docs/skills.md`는 후보를 고르는 색인이다. 색인 설명만으로 실행하지 말고 선택된 스킬의 `compatibility`와 제한을 읽는다.
