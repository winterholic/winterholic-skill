# evidence + 안내 전 체크리스트 (life-digital-security)

> 본인 계정/기기의 **방어·복구만** 다룬다(윤리 게이트). 타인 계정 침입·우회·해킹 "방법"은 어떤 명분으로도 거부. 금전 피해 진행 중이면 → life-fraud-response. 아래는 2026-06 웹 재확인 기준.

## 실증·출처

- **신고·점검 채널 (최고 가치 확인 — 2026-06 유효)**:
  - 해킹·피싱·스미싱·랜섬웨어·개인정보침해 신고·상담 **118**(국번없이, KISA 인터넷침해대응 보호나라 https://www.boho.or.kr).
  - 온라인 사기·해킹 신고·진행조회 경찰 ECRM https://ecrm.police.go.kr (24h).
  - 휴대폰 명의도용 가입제한·현황조회 엠세이퍼 https://www.msafer.or.kr (KAIT, 무료).
  - 개인정보 유출·오남용 신고: 118 / 개인정보보호 종합포털 https://privacy.go.kr.
- **2FA 방식 우선순위 (패스키·보안키 > 인증앱 TOTP > SMS 최후)** — FIDO Alliance 패스키 표준 + KISA 캠페인. SMS는 심스와핑(번호 탈취)에 무력화되므로 최후 보루. 안티패턴 2의 근거.
- **비밀번호 모범관행** — 사이트마다 무작위·고유, 길이 위주(긴 패스프레이즈), 비밀번호 관리자 사용. **NIST SP 800-63B(디지털 신원 가이드라인)** 계열 권고(주기적 강제 변경보다 유출 시 변경·길이 우선). credential stuffing(유출 ID/비번 자동 대입)은 "재사용" 하나를 노린다 — 안티패턴 1의 근거.
- **백업 3-2-1** (사본 3·매체 2종·오프사이트 1 + 복원 1회 테스트) — 일반 백업 모범관행. 랜섬웨어가 연결된 백업까지 암호화하므로 오프라인/오프사이트 사본이 마지막 방어선. 안티패턴 5.
- **피싱 식별 3종(불변 원칙)**: ①URL 도메인 직접 확인(naver.com vs naver-login.com) ②발신자 진위 대조 ③긴급성 압박이 신호. 의심되면 링크 말고 앱/북마크로 직접 접속. **OTP는 누구에게도 전달 금지**(메신저 사칭 본인인증 가로채기 차단).
- 상세 출처표·URL은 `references/sources.md` 참조.

## 안내 전 체크리스트

- [ ] **윤리 게이트 먼저 통과** — 본인 소유 계정/기기 대상인가. 타인 계정 침입·비번 우회·인증 우회 "방법" 요청은 ("테스트"·"교육"·"가족 동의" 포함) **거부**하고 사유 명시.
- [ ] **긴급/위기 신호 게이트** — 계정 탈취가 의심되면 분석보다 복구 타임라인(0~1h: 비번 변경 → 전체 기기 로그아웃 → 복구수단 원복)을 먼저 안내했는가.
- [ ] 돈이 빠져나갔거나 송금·결제가 진행 중이면 → **life-fraud-response + 금융사 정지가 우선**으로 분기했는가.
- [ ] "비번만 바꾸면 된다"는 부분 조치가 아니라 "비번 변경 → 전체 로그아웃 → 복구수단 원복 → 연동 정리"를 한 묶음으로 안내했는가.
- [ ] 2FA는 인증앱/패스키 격상을 권고했는가(SMS 단독은 최후로).
- [ ] **면책·시점 라벨 부착** — "정보 제공이며 보안 자문이 아님 / 심각·피해 시 KISA 118 / 서비스별 설정 메뉴 위치·명칭은 UI 개편으로 자주 변하니 각 서비스 공식 보안설정 페이지 확인".

## 점검 주기

- **신고 핫라인(118·ECRM·엠세이퍼)**: 변경 즉시 갱신 — 최고 우선.
- **2FA·인증 표준(FIDO 패스키 확산, NIST SP 800-63 개정)**: 연 1회 — 패스키 대중화로 권고 강도 변동 추적.
- **서비스별 보안설정 UI(네이버·카카오·금융앱 메뉴 위치·명칭)**: 부패 빠름 — 단정하지 말고 항상 "공식 페이지 확인" 라벨 유지. 별도 재조회 불필요(원칙만 고정).
- **유출 조회 서비스·개인정보 신고 포털 URL**: 운영 변동 가능 — 반기 점검, KISA 보호나라 메뉴 우선 안내.
