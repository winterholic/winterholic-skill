# evidence — 디지털 보안(방어·복구) 근거·체크리스트

> 코어스펙 1겹. 본 문서는 **방어·복구 관점만** 담는다 — 공격·침입·우회 기법은 포함하지 않는다.
> 수치·UI는 변동 — 정확한 값/메뉴는 공식 출처 및 각 서비스 보안설정 페이지에서 **확인 필요**.

## 목차
1. 2FA(이중인증) 방식 비교
2. 피싱 식별 체크리스트 (URL·발신자·긴급성)
3. 계정 탈취 복구 단계별
4. 백업 3-2-1 규칙
5. 비밀번호 위생 요약
6. 한국 신고·점검 채널

---

## 1. 2FA(이중인증) 방식 비교

방어력 높은 순. SKILL 안티패턴 2와 연계.

| 방식 | 방어력 | 강점 | 약점 | 권장 |
|---|---|---|---|---|
| 패스키 / 보안키(FIDO2) | 최상 | 피싱에 원천적으로 강함(도메인 바인딩), 기기에 묶임 | 지원 서비스 아직 제한적 | 지원되면 1순위 |
| 인증앱 TOTP (OTP 생성앱) | 상 | 오프라인 동작, 번호 탈취와 무관 | 기기 분실 대비 백업코드 필요 | 보편적 권장 |
| 푸시 승인 | 중상 | 편리 | "승인 피로" 공격(연타 승인 유도) 주의 | 번호 표시 매칭형이면 양호 |
| 이메일 코드 | 중 | 추가 채널 | 이메일이 뚫리면 같이 뚫림 | 보조용 |
| SMS 문자 코드 | 하 | 진입장벽 낮음 | 심스와핑·문자 가로채기 | 최후 보루(없는 것보단 나음) |

핵심: "2FA를 켰다"보다 **"어떤 2FA냐"**가 방어력을 가른다. 백업 코드는 인증앱 분실 대비 필수 — 비밀번호 관리자나 오프라인 안전 보관.

## 2. 피싱 식별 체크리스트 (URL·발신자·긴급성)

SKILL 안티패턴 3·워크플로우 B와 연계. 하나라도 걸리면 멈추고 공식 경로로 직접 확인.

### URL (도메인)
- [ ] 도메인 철자 위장? (naver.com ↔ navor.com / naver-login.com / naver.co.kr-xxx.com)
- [ ] 하위도메인·경로로 진짜처럼 위장? (security.naver.com-login.xxx.com 의 실제 도메인은 xxx.com)
- [ ] 링크 텍스트와 실제 연결 주소가 다름? (눌러서 가는 곳을 미리 확인)
- [ ] 의심되면 **링크 말고 앱/즐겨찾기로 직접 접속** — 이게 유일하게 확실한 방법

### 발신자
- [ ] 공식 발신번호/메일과 대조했는가 (사칭은 발신자명만 흉내)
- [ ] 메신저로 온 "본인인증·인증번호 요청"? → 다른 채널로 본인 확인(사칭 다발)
- [ ] **인증번호·복구코드는 누구에게도 전달하지 않는다**(공식 기관도 요구하지 않음)

### 긴급성·압박
- [ ] "지금 안 하면 계정 정지/벌금/택배 반송/요금 부과" 류 시간 압박? → 피싱 공통 신호
- [ ] 평소와 다른 결제·송금·인증을 재촉하는가
- [ ] 압박당하는 느낌 자체가 신호 — 멈추고 공식 번호/앱으로 직접 확인

이미 입력했다면 → 섹션 3(복구) 즉시 착수.

## 3. 계정 탈취 복구 단계별

SKILL "복구 타임라인"의 상세. **돈이 얽혔으면 금융사 정지 + life-fraud-response 병행이 우선.**

### 즉시 (0~1h)
1. 안전한 다른 기기에서 **비밀번호 변경**.
2. **"전체 기기에서 로그아웃"**(모든 세션 강제 종료) — 비번만 바꾸면 살아있는 세션으로 재침입됨.
3. **2FA·복구수단 점검**: 공격자가 추가한 인증수단/바뀐 복구이메일·전화가 있는지 확인하고 내 것으로 원복. (복구수단을 못 되돌리면 재탈취 반복)

### 24시간 내
4. **연동 앱·OAuth 목록 점검** — 모르는 연동 해제(비번 바꿔도 살아있을 수 있음).
5. **연결된 결제수단 점검** — 카드·페이·포인트 이상 결제 확인, 있으면 해당사 정지·문의.
6. **지인 통지** — 내 계정/메신저로 사칭 메시지(본인인증·송금 요청)가 갔을 수 있음을 알려 2차 피해 차단.

### 이후 (재발 방지)
7. 같은 비번 쓰던 **다른 계정 전부 비번 변경**(근본 원인이 재사용이면 다 위험).
8. 2FA를 **인증앱/패스키로 격상**.
9. **유출 조회** + **KISA 118 상담/신고**.
10. **백업·복구수단 재정비** — 같은 사고를 두 번 겪지 않도록 위생 완성.

## 4. 백업 3-2-1 규칙

SKILL 안티패턴 5와 연계.

- **3** 사본: 원본 + 백업 2개.
- **2** 매체: 서로 다른 종류(예: PC 디스크 + 외장하드/클라우드) — 한 종류 사고에 동시 전손 방지.
- **1** 오프사이트: 그중 하나는 물리적으로 다른 장소 또는 클라우드.

추가 원칙:
- **복원 테스트 1회** — "백업 있다"가 아니라 "복원된다"가 증명돼야 함.
- **오프라인/분리 사본** — 랜섬웨어는 연결된 백업까지 암호화하므로, 상시 연결되지 않은 사본이 마지막 방어선.
- 자동화 — 수동 백업은 결국 안 함.

## 5. 비밀번호 위생 요약

SKILL 안티패턴 1과 연계.

- **사이트마다 고유·무작위** — 재사용이 credential stuffing의 유일한 먹잇감.
- **길이 우선(긴 패스프레이즈)** — 복잡한 짧은 비번보다 긴 비번이 강함(NIST 계열 권고, 확인 필요).
- **비밀번호 관리자** — 인간 기억력보다 강한 유일한 지점. 마스터 비번 하나만 외우고 강하게 보호 + 그 계정에 2FA.
- **주기적 강제 변경은 비효율** — 유출 정황·재사용이 있을 때 바꾸는 게 핵심(맹목적 90일 교체는 약한 변형을 부른다는 게 최근 권고 방향, 확인 필요).

## 6. 한국 신고·점검 채널

| 상황 | 채널 | 비고 |
|---|---|---|
| 해킹·피싱·악성코드 의심·상담 | KISA 인터넷침해대응 **118** (국번 없이) | 24시간, 무료 (확인 필요) |
| 내 PC·계정 보안 점검 자료 | KISA **보호나라**(boho.or.kr) | 점검 도구·가이드 |
| **금전 피해·송금·보이스피싱**(진행 중) | **경찰 112** / 해당 금융사 고객센터 지급정지 | → life-fraud-response 영역 |
| 개인정보 유출 신고·상담 | 개인정보침해 신고센터 **118**(KISA 통합) | 확인 필요 |
| 명의도용·계정 유출 여부 | 이메일/비번 유출 조회 서비스 + 통신/금융 명의도용 확인 | 서비스별 상이, 확인 필요 |

> 전화번호·운영시간·소관 기관은 변동 가능 — 신고 직전 공식 사이트에서 확인 필요. 금전이 빠져나가는 상황은 본 스킬이 아니라 life-fraud-response + 금융사 정지가 우선.
