## 1. Deep Work 핵심 원리

- **정의**: 인지적으로 부담이 큰 작업에 *방해 없이* 집중하는 상태. 새 가치를 만들고, 능력을 키우며, 복제하기 어려운 결과를 낸다. 반대는 shallow work(얕은 작업 — 잡무·알림 응답류, 부가가치 낮고 누구나 가능).
- **주의 잔류(attention residue)**: 작업을 전환하면 이전 작업의 잔상이 뇌에 남아 다음 작업의 집중을 갉아먹는다(Leroy 2009, Newport 인용 — 출처는 evidence-checklist.md). → 멀티태스킹이 비효율인 메커니즘. 짧은 알림 하나의 실제 비용은 그 알림 처리 시간이 아니라 *집중 회복까지의 시간*이다 — Gloria Mark(UC Irvine)의 자주 인용되는 추정으로 평균 약 23분(측정 방식에 따라 약 9~23분 편차, 절대 수치 아님 — 확인 필요).
- **집중은 훈련된다(인지적 운동)**: 산만함에 길든 뇌는 깊은 집중을 못 한다. 매일 끊김 없는 블록을 반복해야 집중 지속 시간이 늘어난다. 점진적 과부하 — 처음부터 4시간은 무리.
- **딥워크 총량 상한**: 숙련자도 하루 약 4시간 내외가 지속 가능한 깊은 집중의 상한(개인차). 그 이상은 질이 급락.
- **의식(ritual)·일정화**: 언제·어디서·어떻게 딥워크를 할지 고정 규칙으로 만들면 "할까 말까"의 의지력 협상을 없앤다.
- **고립과 즉시성 거부**: 끊임없는 연결(상시 알림·즉답 기대)은 얕은 작업 모드에 뇌를 고정시킨다. 즉시성 기대치를 낮추는 것이 딥워크의 전제.

## 2. GTD 핵심 원리 (5단계)

핵심 전제: **머리는 아이디어를 *떠올리는* 곳이지 *붙잡아 두는* 곳이 아니다.** 모든 미결 과제를 신뢰할 수 있는 외부 시스템에 내려놓아야 머리가 비워지고 현재에 집중할 수 있다(Zeigarnik 효과 — 미완 과제는 계속 주의를 끈다 = open loop).

| 단계 | 무엇을 | 핵심 |
|---|---|---|
| 1. 수집(Capture) | 머릿속 모든 미결·아이디어를 수집함에 | 빠짐없이, 신뢰할 수 있는 *단일* 지점 |
| 2. 명료화(Clarify) | 각 항목: "뭔가? 행동 필요한가?" | **다음 행동을 동사로** / 2분 규칙 / 프로젝트 분리 |
| 3. 정리(Organize) | 다음행동·프로젝트·대기·캘린더·언젠가로 분류 | 제자리에 두기 |
| 4. 검토(Reflect) | 다음행동 수시 + **주간 리뷰 주 1회** | 시스템 신뢰를 만드는 단계 (생명선) |
| 5. 실행(Engage) | 맥락·시간·에너지에 맞는 행동 실행 | 고민 없이 집어 실행 |

- **2분 규칙**: 명료화 중 2분 안에 끝나는 일은 미루지 말고 즉시 처리(목록에 넣고 관리하는 비용 > 그냥 하는 비용).
- **다음 행동(next action)**: "보고서" ❌ → "보고서 첫 문단 초안 쓰기" ✅. 모호한 항목은 실행이 안 됨 — 반드시 물리적·구체적 동사로.
- **inbox zero의 원의미**: 메일함을 텅 비우는 게 아니라, 수집함의 모든 항목을 *처리(=다음 행동으로 변환)* 했다는 뜻.

## 3. 우선순위 — 긴급 vs 중요 (아이젠하워 매트릭스)

|  | 긴급 | 안 긴급 |
|---|---|---|
| **중요** | 1사분면: 위기·마감 (불가피) | **2사분면: 딥워크·기획·학습 (여기를 지켜라)** |
| **안 중요** | 3사분면: 대부분의 알림·잡무 (묶어서/위임) | 4사분면: 시간낭비 (제거) |

- 핵심: **중요-비긴급(2사분면)을 미리 시간 블록으로 선점**. 안 그러면 1사분면(긴급-중요)으로 폭발하거나 3사분면(시끄러운 잡무)에 시간을 다 뺏긴다.
- 긴급한 일은 *시끄럽고* 중요한 일은 *조용하다* — 순서대로 처리하면 늘 시끄러운 것만 한다.

## 4. 도구 수집벽 진단 체크리스트

해당 항목이 많을수록 도구가 회피 수단이 된 상태:

- [ ] 최근 3개월 내 생산성 앱·도구를 2개 이상 갈아탔다.
- [ ] 새 도구 세팅·템플릿 만들기에 쓴 시간 ≥ 그 도구로 실제 처리한 일.
- [ ] "이 앱만 제대로 세팅하면 일이 굴러갈 것"이라 자주 느낀다.
- [ ] 정작 핵심 과제는 진척이 없는데 도구 정리는 잘 돼 있다.
- [ ] 유튜브·블로그에서 "생산성 셋업" 영상을 자주 본다.
- [ ] 한 도구를 1개월 이상 꾸준히 써본 적이 드물다.

→ 처방: **현 도구(또는 종이) 하나로 오늘 시작. 새 도구 도입은 1개월 사용 후, 현 도구가 구체적으로 막는 게 있을 때만.**

## 5. 주간 리뷰 템플릿 (주 1회, 요일·시간 고정)

```
## 주간 리뷰 — YYYY-MM-DD
### 1. 수집함 비우기
- [ ] 모든 수집함(메모·메일·종이) 항목을 명료화 → 다음 행동/프로젝트/언젠가/폐기로 변환. 수집함 0으로.
### 2. 진행 점검
- [ ] 진행 중 프로젝트마다 "다음 행동"이 하나씩 정의돼 있나?
- [ ] 대기 중(위임·답장 기다림) 목록 점검 — 재촉할 것?
- [ ] 캘린더 지난주 복기 + 다음 주 미리보기.
### 3. 다음 주 설계
- [ ] 중요-비긴급(2사분면) 작업의 딥워크 블록을 캘린더에 선점했나?
- [ ] 다음 주 1순위 1~3개 선언.
### 4. 막힌 것
- [ ] 미루고 있는 일 — 다음 행동이 너무 큰가? 더 잘게 쪼갠다.
```

> 리뷰는 캘린더에 "남과의 약속"처럼 고정한다. 떠다니면 반드시 건너뛴다.

## 6. 흔한 함정 모음

| 함정 | 증상 | 해독 |
|---|---|---|
| 도구 수집벽 | 앱만 갈아치움, 일은 정체 | 도구 하나로 오늘 시작, 교체는 1개월 후 |
| 멀티태스킹 | 여러 탭·즉답, 산출물 질 저하 | 단일 과제 + 커뮤니케이션 batching |
| 머릿속 보관 | 회의 중에도 딴 할 일이 떠오름 | 즉시 수집함에 내려놓기 |
| 순서대로 처리 | 바빴는데 핵심은 못 함 | 2사분면 시간 블록 선점 |
| 항상 연결됨 | 30분 집중 경험이 없음 | 딥워크 블록 알림 전면 차단 |
| 검토 누락 | 수집함이 죄책감 목록이 됨 | 주간 리뷰 캘린더 고정 (GTD 실패 1위) |
| 의지력 의존 | "더 독하게"로 해결 시도 | 환경·루틴·시작 의식으로 결정 수 줄이기 |
| 모호한 할 일 | "보고서" 같은 항목이 안 굴러감 | 다음 행동을 물리적 동사로 |

## 7. 한 줄 요약

생산성 문제는 대부분 **의지의 문제로 위장한 설계의 문제**다 — 방해받지 않는 *환경*(Deep Work)과 믿을 수 있는 *외부 시스템*(GTD), 그리고 *주기적 검토*가 핵심이다. 도구의 화려함이 아니라 매일 같은 곳을 보는 습관이 일을 한다.
