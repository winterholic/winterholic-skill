# Lite-Research — 경량 조사·검증 하네스

deep-research(대규모 fan-out 리포트 공장)와 메인 즉답 사이의 빈 자리를 메운다: **이질역할 2~4 에이전트, 딱 1라운드**로 "30분짜리 질문"을 수 분에 처리하는 정찰대. /spar(게이팅·이질역할·1라운드 하드캡·인라인 1회·메인 종합)와 /senior-review(배치 검증·모드 스케일·fail-loud)의 검증된 원리를 조사 도메인에 이식했다.

## 왜 이 형태인가 (원리 — spar·senior-review에서 실측 검증됨)

- **동질 fan-out은 역효과, 이질역할 소수는 이득** (arXiv 2509.05396, deep-research 종합): 같은 검색을 N번 시키는 게 아니라 **각도가 다른** 수집자(공식 문서 vs 현장 반례)를 소수만.
- **검증은 배치로** (senior-review 실측): 주장마다 검증자를 붙이면 비용이 폭발한다(무거운 리서치 하네스가 비싸지는 주범). 검증자 1명이 전체 주장을 한 패스에 판정.
- **1라운드 하드캡은 구조로 강제**: workflow.js에 루프가 없다. 부족하면 라운드 추가가 아니라 deep-research로 **전환**.
- **컨텍스트·질문은 메인이 1회 인라인 전달**: 에이전트별 재탐색 금지 + 에이전트당 도구 호출 예산 명시(검색 ~5회·fetch ~3회).
- **출처 없는 주장은 사실 행세 금지**: 모든 claim에 source + sourceType(official/community/code/inference) + confidence 강제. "근거 못 찾음"과 "없다는 근거"를 구분.

## 절대 규칙 (토큰·품질 가드)

1. **게이팅 우선.** 메인이 즉답하거나 WebSearch 1~2회로 풀리면 **에이전트 0** (solo). 하네스는 독립 수집·교차 검증이 진짜 필요할 때만.
2. **최대 4 에이전트·1라운드.** 그 이상 필요해 보이면 이 스킬의 일이 아니다 — deep-research로 전환 제안.
3. **종합은 메인 의무.** 보고서 중계 ❌. sourceType·검증 결과로 가중치를 매겨 **답 하나**로 수렴. inference 주장은 할인, refuted 주장은 정정과 함께 폐기.
4. **불확실성 정직 표기.** gaps(예산 내 미확인)와 conflicts(보고서 간 상충)를 숨기지 않는다. 상충이 핵심 답을 가르면 그게 에스컬레이션 신호다.

## 모드 선택 (게이팅 테이블)

| 상황 | 모드 | 에이전트 |
|------|------|---------|
| 메인이 알거나 검색 1~2회로 끝 | **solo** | 0 (하네스 미호출) |
| 외부 사실·기술 조사, 출처 다양성 필요 | **external lite** | 2 (공식 + 현장) |
| 위 + 주장 검증까지 필요(버전 민감·의사결정 입력) | **external std** | 3 (+배치 검증자) |
| 코드베이스 정찰, 한 각도면 충분 | **codebase lite** | 1 (Explore) |
| 정의·구조 + 사용처·흐름 둘 다 | **codebase std** | 2 (Explore×2) |
| 두 옵션 비교·선택 | **compare** | 2 (옵션별 옹호자, 판정은 메인) |

판단 기준 한 줄: **"답이 틀리면 비싼가?"** — 비싸면 std(검증 포함), 아니면 lite. compare에서 사용자와 *왕복 토론*이 필요해지면 이 스킬이 아니라 /spar.

## 실행 — 번들 오케스트레이터 호출

```
Workflow({
  scriptPath: "~/.claude\skills\lite-research\workflow.js",  // 절대경로 필수 — scriptPath는 ~ 확장 안 됨 (spar 실측)
  args: {
    question: "한두 문장의 질문 하나",
    kind: "external" | "codebase" | "compare",
    depth: "lite" | "std",
    context: "메인이 이미 아는 것 전부: 제약·스택·지금까지의 발견·사용자 상황",
    options: ["A", "B"],            // compare만
    projectRoot: "/abs/path"        // codebase만
  }
})
```

- `context`를 빈약하게 넘기면 에이전트가 이미 아는 걸 재조사한다 — 메인이 아는 건 다 넣는다.
- 수집자들은 **병렬·상호 비노출**(독립 보고). 검증자만 전체 주장을 본다.
- **실전 사례**: `references/example-run.md` — 실제 스모크 런의 claim 밀도·sourceType 사용·gaps 표기·검증 판정 실물. 첫 호출 전에 한 번 보면 종합 품질의 anchor가 된다.

**판단 불가 시 [확인 요청] 형식** — 조사로 안 풀리는 결정 변수(사용자 환경·내부 정책 등)가 나오면 4요소로:

> **[확인 요청]** 누가: 사용자 / 무엇을: X 값·설정·환경 / 어떻게: 구체 확인 방법 1개 / 기대: A면 결론 P, B면 결론 Q로 분기.
> 확인 불가하면: 양쪽 분기를 다 답하되 "가정: ~" 명시 — 조사 결과를 가정 위에 얹었음을 종합에 표기.

## 종합 (메인 의무) — 출력 템플릿

```markdown
**조사 결과** (lite-research {kind}/{depth}, 에이전트 N개)
**답**: {한 문단 — 질문에 대한 직접 답}
- 근거: {핵심 claim 1~3개 — source 표기, official 우선}
- 반례·주의: {현장 보고서에서 산 것 — 없으면 "현장 반례 없음 확인"}
- 미확인: {gaps — 있으면 정직하게}
{conflicts 있으면: ⚠ 상충: {내용} → deep-research로 파볼까?}
```

> ✅ **좋은 종합**: "답: Node 22는 2024-10-29부터 LTS(코드명 Jod), EOL 2027-04. 근거: nodejs.org 릴리스 일정(official). 주의: 일부 네이티브 모듈이 22 초기에 빌드 실패 보고(GH 이슈, 2024-11) — 현재는 해소. 미확인: Alpine 기반 이미지의 V8 플래그 이슈는 예산 내 확인 못 함."
> ❌ **나쁜 종합**: 보고서 2개를 순서대로 요약해 나열하고 끝 — 가중치 판단 없음, 답 없음, gaps 숨김. 중계는 종합이 아니다.

## 거부·실패 처리

- 사용자가 하네스 제안을 **거부** → solo로 즉답(아는 만큼 + 불확실 명시). 같은 질문 재제안 금지.
- `failed:true` 반환(수집자 전멸) → solo 폴백 + 실패 사실 한 줄 보고. 재실행은 사용자 요청 시만.
- **일부 수집자만 생존** → 결과는 쓰되 "한 각도만 반영됨" 명시.
- 검증자 사망(std) → 주장을 "미검증" 라벨로 종합. 검증된 척 금지.

## 에스컬레이션 (단방향)

- 검증자의 `conflicts`가 **핵심 답을 가르는 상충**이면 → "deep-research로 정밀 검증할까?" 한 줄 제안. 동의 시 전환 — lite-research 라운드 추가 ❌.
- 조사가 끝나고 **결정 토론**이 필요해지면 → /spar (조사 결과를 spar의 context로 넘김).
- 코드베이스 정찰 결과 **리뷰 수준 판단**이 필요하면 → /senior-review.

## 결과 기록

- **재사용 가치 판단**: 다시 찾게 될 외부 조사(라이브러리 비교·마이그레이션 함정·버전 정책)면 vault에 보관, 일회성 답이면 대화로 종결.
- **보관 위치·파일명**: `~/.claude/artifacts/vault/wiki/` 아래 주제 디렉토리에 `{주제-슬러그}-{YYYY-MM-DD}.md` 신규 생성(같은 주제 재조사는 기존 파일에 **append** + 날짜 구분 — 덮어쓰기 금지). 보관 전 `vault/claude/CLAUDE.md` 선행 확인(글로벌 규칙), 없으면 보관 진행 후 work-history에 부재 명시.
- 세션 기록은 work-history 글로벌 규칙을 따른다 (별도 규칙 없음).

## 트리거 / 안 트리거

- **트리거**: "가볍게 조사/알아봐/찾아봐", "이 라이브러리 어때", "A vs B 뭐가 나아", "우리 코드에서 X 어떻게 쓰고 있어", 버전·지원 일정·deprecated 확인.
- **안 트리거**: 즉답 가능한 단순 사실(solo), 대규모 검증 리포트(deep-research), 토론·왕복(/spar), 코드 리뷰(/senior-review), 단일 페이지 추출(/web-browse), 도메인 규정 조회(stock-domain — 규정은 조사 아닌 조회).

## 비용

- **external std(3 에이전트) 실측** (2026-06-10 스모크, FastAPI on_event 조사): **123,926 서브에이전트 토큰 / ~5분 / 도구 호출 31회**. 검증 결과 19 claims → 17 confirmed·2 unverifiable·0 refuted. 웹 도구 호출 때문에 spar Council(86k)보다 에이전트당 비싸다 — lite(2 에이전트, 검증 생략)는 ~2/3 수준 추정. deep-research 대비 수~수십 분의 일.
