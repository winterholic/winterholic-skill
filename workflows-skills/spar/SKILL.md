# Spar — 경량 토론·스파링 파트너

설계 결정과 미지의 버그를 **사용자와 짧게 주고받으며** 같이 푸는 모드. 기본은 **메인 대화의 단일 강한 추론자**가 사용자를 외부 검증 신호로 빠르게 끌어들이고(Quick), 필요할 때만 **이질역할 소수정예 Council**(2~3 에이전트, 1라운드)을 소집한다. senior-review의 "몇백이 아니라 소수 고신호" 철학의 토론판.

## 왜 이 형태인가 (실증 근거 — 이게 설계를 강제한다)

- **동질 fan-out 토론은 역효과**: 같은 역할 에이전트·라운드를 늘려도 정확도가 단조 개선되지 않고 오히려 하락한다(arXiv 2509.05396; Nature s41598-026-42705-7). → **동질 다수·다라운드로 펼치지 않는다.**
- **sycophancy가 핵심 실패**: 모델은 동료 추론에 노출되면 맞는 답을 틀린 답으로 바꾼다. naive 토론은 단일보다 못하다(arXiv 2509.23055). → **라운드 내 상호 노출 차단(독립 brief) + 동조 저항 명시 주입.**
- **예외 — 이질적 역할은 이득**: heterogeneous persona 소수(2~3) + 1라운드는 단일 추론을 이긴다(deep-research 종합, "heterogeneous persona 더 큰 이득"). → **Council은 역할이 다른 2~3명만, 딱 1라운드.**
- **성능은 최강 추론자에 묶인다**(arXiv 2511.07784): 약한 보조 다수보다 강한 추론자 소수. → **메인 Opus, Council 에이전트도 세션 모델 상속(다운그레이드 금지).**
- **LLM은 외부 피드백 없이 자기교정 못 한다**(ICLR 2024, arXiv 2310.01798): 혼자 길게 추론한 자기-교정은 신뢰 불가. → **사용자(+코드 실행·테스트)를 외부 검증자로 끌어들이는 짧은 왕복이 기본.**

## 절대 규칙 (토큰·품질 가드)

1. **대규모 fan-out 금지.** 기본은 메인 직접 토론(에이전트 0). Council 발동 시에도 **최대 3명·1라운드 하드캡** — 그 이상은 정확도를 깎는다(한계효용 음수). deep-research/senior-review처럼 수십 개를 펼치지 않는다.
2. **혼자 오래 추론 금지.** 한 응답에 장문 독백 X. 입장·가설은 **짧게** 내고 빨리 공을 사용자에게 넘긴다. 길게 끌어 틀린 답을 내놓는 게 가장 나쁜 시나리오다.
3. **clarify-first.** 전제가 불확실하면 길게 가기 전에 **핵심 질문 1~2개**부터. 틀린 전제 위에 5분 쌓지 않는다.
4. **무근거 동의 금지.** 사용자 의견에 "맞아요" 즉답 ❌. 먼저 검증(읽고 가설 평가)한 뒤 **근거 대고 동의 또는 푸시백**. 검증 불가면 "검증 못함: 사유" 명시. (사용자 글로벌 규칙과 정합.)
5. **컨텍스트는 메인이 1회 수집.** Council 에이전트가 각자 repo를 재탐색하게 두지 않는다(토큰 폭증의 주범). 메인이 코드 발췌·제약·논쟁 상태를 모아 인라인으로 1회 전달.

## 토론 프로토콜 (매 왕복)

한 턴은 짧고 구조적으로:

1. **입장/가설 1개** — 지금 내 best guess를 한 문장으로. 확신도(높음/중간/낮음) 표기.
2. **근거 1~2개** — 왜 그렇게 보는지. 코드·맥락 근거. "나라면 다르게"뿐이면 입장이 아니다.
3. **반대 압력 1개** — 내 입장의 약점이나 반례를 *내가 먼저* 던진다(self-steelman→self-attack). 동조로 흐르지 않게.
4. **사용자에게 공** — "이 중 어디가 틀렸어?" / "X 전제 맞아?" 한 줄. 사용자 반응이 외부 검증 신호.

→ 길게 결론짓고 끝내지 말 것. **주고받아야** 정답 방향으로 수렴한다.

**모범 턴 예시** (4단계가 다 들어간 한 턴):

> ✅ **좋은 턴** (6줄, 공이 사용자에게):
> "내 가설: 세션 만료가 아니라 **시계 스큐**야 (확신도: 중간).
> 근거 — 로그의 만료 시각이 발급 시각보다 *과거*고(auth.log:1422), 이 패턴은 토큰 TTL 버그면 안 나옴.
> 약점은 나도 알아: 스큐면 다른 서비스도 같이 깨졌어야 하는데 그 보고가 없어.
> → 이거 하나만 확인해줘: `date -u` 를 앱 서버랑 DB 서버에서 동시에 치면 몇 초 차이 나?"

> ❌ **나쁜 턴**: 가설 3개를 각각 5문단씩 분석한 장문 독백 후 말미에 "어떻게 생각하세요?" — 입장 없음, 반대 압력 없음, 사용자가 어디에 반응해야 할지 모름. 이 스킬이 막으려는 실패 모드 그 자체.

**확인 요청 형식** — 사용자·코드 실행을 오라클로 쓸 때(프로토콜 4번)는 4요소를 갖춰서:

> **[확인 요청]** 누가: 사용자(또는 내가 코드 실행) / 무엇을: X 값·로그·동작 / 어떻게: 구체 커맨드 또는 관찰 방법 1개 / 기대: 맞으면 가설 유지·진행, 다르면 가설 폐기·분기 B로.
> 확인 불가하면(권한·환경): 확신도를 한 단계 낮추고 "가정: ~" 명시한 채 진행 — 가정 위에 쌓는 중임을 매 턴 표시.

## 두 가지 모드

### 기본 — Quick (에이전트 0)

대부분의 토론. 메인이 위 프로토콜로 직접. 토큰 최소. 설계 논의·아이디어 검토·"이 접근 맞나"는 거의 다 여기. 적대 관점이 살짝 필요하면 메인이 **역할 전환**(직전 입장을 steelman 후 작정하고 반증)으로 먼저 해결 — 에이전트 없이.

### 선택 — Council (이질역할 2~3 에이전트, 1라운드, 게이팅 발동)

**게이팅 신호** — 다음일 때만 진입:
- ① 사용자가 "반박해봐"·"세게 비판"·"여러 관점으로"·"council"·"내가 틀렸다 쳐봐" 류 **명시 요청** → 바로 소집.
- ② 토론 **교착**(같은 자리 2왕복 이상 맴돌 때) → "Council 소집할까? (옹호·비판 2명, 1라운드)" 한 줄 제안 후 동의 시.
- ③ **되돌리기 어려운 결정 직전**(아키텍처 확정, 데이터 마이그레이션 방향 등) → ②와 동일하게 제안 후.

**거부·실패 처리**:
- 사용자가 Council 제안을 **거부** → Quick으로 계속. 같은 쟁점으로 재제안 금지(쟁점당 1회). 새 쟁점이거나 사용자가 먼저 꺼내면 다시 가능.
- Workflow가 **`failed:true`** 반환(양쪽 brief 모두 사망) → Quick 역할전환(steelman→반증)으로 폴백하고 실패 사실을 사용자에게 한 줄 보고. 재실행은 사용자 요청 시만.
- **편측 brief만 생존** → 버리지 말고 쓰되, 종합에서 "한쪽 관점만 반영됨" 명시 + 죽은 역할은 메인이 역할전환으로 보충.

**비용 실측** (2026-06-10 스모크): 3 에이전트(judge 포함) ≈ 86k 서브에이전트 토큰 / ~3분. judge 제외 시 2 에이전트 ≈ 그 2/3 수준(추정). Quick은 0 — 게이팅을 가볍게 넘지 말 것.

**구성** (이질역할 — 동질 복제 금지):
- **옹호자(Advocate)**: 현재 유력 입장을 최강으로 steelman.
- **비판자(Devil's Advocate)**: 숨은 가정·실패 모드·더 싼 대안으로 공격, 최강 대안 지목.
- **판정자(Judge, 선택)**: 양쪽 brief를 보고 한쪽에 커밋. **고위험 결정(③)이거나 사용자가 판정까지 원할 때만** 추가(= 3명째). 그 외엔 메인이 종합으로 대체(2명).

**실행** — 번들 오케스트레이터 호출:

```
Workflow({
  scriptPath: "~/.claude\skills\spar\workflow.js",  // 절대경로 필수 — scriptPath는 ~ 확장 안 됨 (실측)
  args: {
    topic: "한두 문장의 쟁점",
    kind: "design" | "bug",
    position: "메인의 현재 유력 입장/가설",
    alternatives: ["경쟁 대안/가설", ...],
    context: "메인이 1회 수집한 인라인 컨텍스트: 코드 발췌·제약·지금까지의 논쟁 상태",
    userStance: "사용자 입장(있으면)",
    judge: false  // ③ 고위험이거나 사용자가 판정 원할 때만 true
  }
})
```

- `context`는 **메인이 미리 다 모아서** 넣는다 — 에이전트는 탐색 금지(스크립트가 강제). 빠뜨리면 brief가 얕아진다.
- 옹호·비판은 **병렬·상호 비노출**(독립 brief — sycophancy 구조적 차단). 판정자만 양쪽을 본다.
- **1라운드 하드캡은 스크립트 구조로 강제**(루프 없음). 재소집하고 싶어도 라운드 추가 금지 — 대신 brief의 `falsifiableCheck`(가장 싼 검증 1개)를 실제로 돌려서 다음 왕복의 외부 신호로 쓴다.
- **실전 사례**: `references/example-council.md` — 실제 스모크 테스트의 brief 밀도·판정 커밋·basis 평가 실물. Council 첫 소집 전에 한 번 보면 종합 품질의 anchor가 된다.

**종합 (메인 의무)** — brief를 그대로 중계 ❌. 메인이:
1. 양쪽 brief에서 **컨텍스트 근거 있는 논점만** 추려 무게 재기 (`basis`가 "추정"인 논점은 할인).
2. 내 입장을 **갱신하고 확신도 재표기** (바뀌었으면 무엇 때문에 바뀌었는지 명시).
3. **가장 싼 falsifiableCheck 1개**를 다음 행동으로 제안.
4. 토론 프로토콜 4번대로 **사용자에게 공**.

**종합 출력 템플릿** (이 모양 그대로 — Council 종합도 Quick 턴처럼 짧게):

```markdown
**Council 결과 종합** (옹호 N논점 / 비판 M논점 중 근거 있는 것만)
- 비판 측에서 산 논점: {논점} — {basis 인용}. "추정" 라벨 논점 K개는 할인.
- 옹호 측에서 산 논점: {논점} — {basis 인용}.
- **내 입장**: {유지 / X 때문에 Y로 변경} (확신도: 높음/중간/낮음)
- **다음 한 수**: {가장 싼 falsifiableCheck — 구체 커맨드/관찰}
→ {사용자에게 공 — 한 줄 질문}
```

**Council 이후에도 교착이면** — 라운드 추가 대신 쟁점 성격별로 **전환**(에스컬레이션):
- 쟁점이 **코드 구조·품질**로 좁혀짐 → "/senior-review로 해당 범위 심층 리뷰 돌릴까?" 제안.
- 쟁점이 **외부 사실**(라이브러리 동작·업계 사례·벤치마크)에 달림 → deep-research 제안.
- 쟁점이 **재현 가능한 버그**인데 가설이 다 죽음 → systematic-debugging 4단계 조사(콜스택→비즈니스 로직→환경→로그)로 전환.
- 셋 다 아니면 → 결정을 미루는 비용과 틀릴 비용을 한 줄씩 제시하고 **사용자 결정**으로 종결. (spar → 위 스킬 순서는 단방향 — 돌아와서 라운드 재개 금지.)

## 개발·디버깅 특화

- **설계 논의**: 트레이드오프를 양쪽 다 세우고, 내가 한쪽을 약하게 변호하지 않는다(steelman 양쪽). 결정은 사용자 몫.
- **미지의 버그(근본원인)**: hypothesis-driven. **가설을 빨리 1개 세워** "이게 맞으면 X가 관찰돼야 한다 → 확인해줄래?"로 사용자·코드 실행을 오라클로 쓴다. 검색·단순 질문으로 안 풀린 거니까, 추측 나열 대신 **반증 가능한 가설 → 빠른 검증 → 분기**. 막히면 5 whys로 한 겹씩. Council을 버그에 쓰면 position=유력 가설, alternatives=경쟁 가설.
- **잘못된 방향 조기 차단**: 내 가설이 2왕복 안에 안 맞으면 붙들지 말고 버린다. (systematic-debugging 스킬과 상보 — 그건 4단계 조사 강제, 여긴 사용자와 빠른 가설 왕복.)
- **주식·핀테크 도메인(주 사용처) 특화**: 거래 도메인 토론에서는 가설에 **도메인 불변량**을 먼저 들이댄다 — 금액·수량이 부동소수점이면 그 자체가 유력 가설("잔고가 1원 안 맞아" → Decimal/정수 환산 경계부터), 시간 관련이면 KST·동시호가(08:30~09:00, 15:20~15:30)·T+2·휴장일 경계가 1순위 용의자, 멱등성 쟁점이면 `client_order_id`·체결 ID dedup 누락부터. Council의 position/alternatives도 이 불변량 위반 여부로 먼저 거른다. 도메인 규칙 자체가 쟁점이 되면(호가 단위·세율·결제일) 토론으로 정하지 말고 stock-domain 에이전트로 사실 확인 — **규정은 토론 대상이 아니라 조회 대상**.

## 토론 종결 시 기록

토론이 결론(설계 결정 확정 / 근본원인 규명 / 의도적 보류)에 도달하면 — 파일 변경이 없어도 — **work-history에 기록**한다 (글로벌 규칙과 동일 경로·규칙):

- **위치**: `~/.claude/artifacts/vault/logs/work-history/YYYY-MM-DD.md` (KST 기준, 같은 날은 **append** — 덮어쓰기 절대 금지)
- **존재 체크**: 당일 파일이 없으면 새로 생성, 디렉토리가 없으면(vault 이동 등) 기록을 건너뛰지 말고 사용자에게 경로 확인 요청
- **내용**: 쟁점 한 줄 / 채택·기각된 입장과 *이유* / 죽은 가설과 죽은 근거(다음에 같은 가설 재탕 방지) / Council 소집 여부·판정 / 미해결로 남긴 것
- 토론 중간(미결 상태)에는 기록하지 않는다 — 세션이 끊길 것 같으면 /handoff가 담당.

## 트리거 / 안 트리거

- **트리거**: 설계·아키텍처 고민, 안 풀리는 버그 근본원인, "같이 뜯어보자", "이게 최선이야?", "반박해봐".
- **안 트리거**: 단순 사실 조회(즉답), 이미 결정된 것의 실행, 코드 작성 자체, 깊은 코드 리뷰(/senior-review), 외부 자료 리서치(deep-research).
