## 0. 이 문서의 규칙

**수록 기준**: 측정 가능한 규칙으로 환원되거나, 에이전트/하네스의 동작을 바꾸는 실증 데이터만.
취향 담론과, 사실이지만 스킬 동작을 아무것도 바꾸지 않는 배경지식은 제외한다.

**표기**: `[확인됨]` 1차 출처를 직접 열어 확인 · `[미검증]` 출처는 실재하나 본문 대조 못 함 ·
`[확인 필요]` 값이 흔들릴 수 있음

**개정 이력**: v3 — 적대적 검수로 사실 오류 6건 정정, 설계 결함 3건(퇴화 최적점·주수익 기각·앙상블
역근거) 반영, §10 미결 신설. v2 이전 판의 오류는 §11에 남겨 재발을 막는다.

## 1. LLM 은 UI 평가를 얼마나 하는가

근거: Zhong, McDonald, Hsieh, *Synthetic Heuristic Evaluation*, arXiv:2507.02306 (2025).
모바일 앱 2종, Nielsen 10 휴리스틱, GPT-4 / Gemini-1.5-pro / Claude 3.5 Sonnet,
전문 UX 평가자 5명 + 훈련된 연구보조 5명으로 master set 구축. **[확인됨 — PDF 직접 열람]**

### 1.1 커버리지

| 평가 주체 | 렌탈 앱 | 어학 앱 |
|---|---|---|
| 개인 전문가 평균 | 18% (24/133) | 17% (19.4/113) |
| 전문가 5명 집계 | 57% (76/133) | 63% (71/113) |
| GPT-4 | **73% (97/133)** | **77% (87/113)** |
| Gemini-1.5-pro / Claude 3.5 Sonnet | 59% / 57% | 59% / 58% |

- 사람은 과제 반복 시 **31.6% 저하**(OR −0.316, p<0.05), LLM 은 평평 → **루프 구조가 AI 에 유리.**

### 1.2 ★★ 모델을 늘려도 신호가 늘지 않는다 — 앙상블 금지 근거

**[확인됨 — 논문 §5.3.2]** 같은 master set 에 Gemini-1.5-pro 와 Claude 3.5 Sonnet 을 추가 투입한 결과:

> **severity ≠ 0 인 신규 이슈를 단 하나도 찾지 못했다. master set 은 그대로였다.**
> 대신 **severity 0(문제 아님) 만 43건 추가**했다 — 렌탈 Gemini 9 · Claude 12,
> 어학 Gemini 13 · Claude 9.

★ **모델 수 증설 = 신호 0, 잡음 +43.**

⚠️ **선행 연구의 "평가자 3~5명 집계 시 55~90% 커버"는 사람 평가자 문헌(Nielsen 계열)이고
LLM 앙상블에 이식되지 않는다.** 이 논문이 직접 반증했다.

→ **병렬화는 「축 분할」로만 한다. 같은 축에 모델·에이전트를 여러 대 붙이지 않는다.**
축 분할의 근거는 커버리지가 아니라 **출력 토큰 한도**다(§1.6).

### 1.3 강한 축 = 사용자의 최대 고통 지점

**Aesthetic and minimalist design**(여백·밀도·시각 위계): 렌탈 **86%(18/21)** vs 전문가 38%,
어학 **74%(14/19)** vs 42%. 논문 §4.3.2 가 *"작은 레이아웃 차이 검출에서 더 나았다"* 를 별도로 다룬다.

실제 LLM 지적 예시:
- *"'Tour requested' 텍스트 위아래 여백이 일관되지 않고 너무 커서 과하게 패딩된 느낌"*
- *"'Tour' 와 'Tour requested' 의 폰트 크기 차이가 작아 시각 위계가 불명확"*

→ **사용자가 "패딩·배치가 제일 많다"고 한 축이 LLM 최강 구간이다.** 이 스킬의 기대 수익 근거이자,
**§5.1 점수 설계가 반드시 보호해야 하는 구간**이다.

### 1.4 약한 축 = 자동수정 금지 구간

| 축 | GPT-4 | 전문가 5명 |
|---|---|---|
| Consistency and standards (렌탈/어학) | 46% / 40% | 54% / 60% |
| 화면 간(across-screen) 위반 | 43%(3/7) / 50%(3/6) | 86%(6/7) / 83%(5/6) |

논문 §4.3.4: **LLM 이 놓친 화면 간 위반은 전부 Consistency 위반**이었다.
원인은 하나 — **스크린샷을 각각 독립 아티팩트로 보고 화면을 가로질러 종합하지 못한다.**

### 1.5 중복 보고 — 루프 비수렴의 직접 원인

LLM 중복 지적 렌탈 8건·어학 9건, **사람 0건.** 같은 컴포넌트 문제를 화면마다 새 문제로 재보고한다
(셋업 5화면 각각에 "진행 표시 불명확"을 5번). → **dedup 없으면 매 라운드 부활해 수렴하지 않는다.**

### 1.6 오탐률 — 중재자 계층의 정량 근거

**두 수치를 혼동하면 안 된다:**

- **GPT-4 지적 중 severity 0 비율 = 오탐률**: 렌탈 **43/140 = 31%**, 어학 **52/139 = 37%**.
  (분모 = 유효 지적 97 + 오탐 43 / 87 + 52)
- **전문가 5명 집계 오탐률**: 렌탈 6/82 ≈ **7%**, 어학 3/74 ≈ **4%**.
- (참고) severity-0 **풀 전체**에서 LLM 3종이 차지하는 지분은 138/147 ≈ 94% 이지만,
  이 숫자는 오탐률이 아니다 — 분모가 "LLM 지적"이 아니라 "오탐 집합"이다.

★ **결론: LLM 은 사람보다 4~5배 높은 오탐률로, 3배 넘는 유효 지적을 낸다.**
많이 찾고 많이 틀리므로 **뒤에서 거르는 계층이 필수**다.

**오탐 원인이 2종으로 정량화되어 있다 — 중재자 체크리스트가 여기서 나온다:**

1. **UI 컴포넌트 오인식** — 렌탈 42%(18/43), 어학 27%(14/52)
   - OS 상태바 Wi-Fi·배터리를 앱 UI 로 착각 / 팝업 배너를 버튼으로 오인
2. **관례 무지** — 렌탈 42%(18/43), 어학 38%(20/52)
   - 의도적 강조색 버튼 → *"주의를 너무 끈다"* / 모바일 표준 solid vs link 위계 → *"디자인이 다르다"*

⚠️ **[중요] 1번은 우리 맥락에 그대로 이식되지 않는다.** 원 실험은 iOS 스크린샷이라 OS 상태바가
찍혔다. **Playwright 뷰포트 캡처(`fullPage:false`, headless)에는 브라우저 크롬이 애초에 안 들어온다.**
우리 쪽 등가물로 교체한다 → **스크롤바 · 개발 오버레이(HMR 배지·devtools) · 토스트/모달 잔상 ·
스켈레톤 로딩 상태 · 포커스 링**. 이건 판단이 아니라 **캡처 규약(§10-4)으로 제거하는 것이 옳다.**

⚠️ 2번(관례 무지)은 우리 맥락에서 **금융 도메인 관례**(숫자 밀도, 조밀한 테이블, 등락 색상)다.
이것도 순수 판단으로 두지 말고 **프로젝트가 선언한 예외 허용 목록 파일**로 환원해야 중재자가
측정 가능하게 판정한다(§10-5).

### 1.7 프롬프트 — 논문이 시행착오로 확정한 것 (Table 1)

⚠️ **[확인됨 — 원문 재확인] 개수 하한은 레버가 아니다.**
**실패한 1행 프롬프트에 이미 `For each heuristic, identify at least 2 problems.` 가 있었다.**
그런데도 LLM 은 위반을 못 찾고 *"직관적이다·이해하기 쉽다"* 고 확인만 해줬다.

| 시도 | 결과 |
|---|---|
| "휴리스틱 평가 수행 + **휴리스틱당 최소 2개**" | **위반을 못 찾고 "직관적입니다"로 확인만 해줌** |
| ★ + "**근거**를 대라 · **severity(0~4)** 를 매겨라 · **그 severity 인 이유**를 써라 · **휴리스틱이 어디서 깨지는지 최대한 구체적으로**" | 실제 위반이 나오기 시작 (chain-of-thought) |
| + "스크린샷은 **등장 순서대로** 주어졌으니 화면 간 상호작용을 고려하라" | 화면 간 지적 일부 확보 |
| + "10개를 **5개씩 두 번에** 나눠 처리" | 출력 토큰 한도 잘림 해소 → **축 분할의 유일한 근거** |

→ **실제 레버: 지적마다 ①근거 ②severity ③severity 의 근거 ④위치 구체성을 강제한다.**
개수 하한은 효과가 없었을 뿐 아니라, 깨끗한 화면에 걸면 **오탐을 인위적으로 제조**해
중재자 부하를 스스로 키운다. **채택하지 않는다.**

**severity 척도(0~4)**: 0 문제 아님 / 1 화장품 수준 / 2 사소 / 3 중대 / 4 재앙. 빈도 × 영향.
**용도는 보류함 정렬 하나뿐이다.** 라운드 점수에는 쓰지 않는다(§5.1).

## 2. 반복 수정 루프는 왜 무너지는가 — 이 스킬의 최대 리스크

### 2.1 ReLook — 우리와 비슷한 구조에서 궤적이 퇴화했다

근거: *ReLook: Vision-Grounded RL with a Multimodal LLM Critic for Agentic Web Coding*,
arXiv:2510.11498 (2025-10).

- **[확인됨 — 초록]** **Forced Optimization** — *"a strict acceptance rule that admits only
  improving revisions"*. **직전 최고를 엄격히 초과할 때만 채택, 아니면 기각.**
- **[확인됨 — 초록]** **무효 렌더 제로 게이팅** — *"a strict zero-reward rule for invalid renders
  anchors renderability"*. 렌더 실패·타임아웃 캡처면 결과를 통째로 폐기.
- **[미검증 — 본문]** 궤적 퇴화(behavioral collapse)의 구체 양상, 음의 보상 가드가 유발한
  reward hacking, 라운드 실측(추론 상한 3·평균 2·재샘플 10회), 유효 렌더율 40%→80%.

⚠️ **[확인 필요 — 이식 리스크] Forced Optimization 은 RL 학습 시 궤적 채택 규칙이고,
ReLook 의 추론 시 구성은 "critic 을 떼어낸 경량 self-edit 사이클"이다.**
즉 **우리가 하려는 critic-in-the-loop 는 ReLook 이 추론에서 버린 구성이다.**
학습 시 규칙을 추론 루프로 이식하는 것이므로, **라운드 상한 3 은 검증된 값이 아니라
[미검증] 기본값**으로 취급한다.

### 2.2 Contextual Drag — 실패한 시도를 컨텍스트에 남기면 안 된다

근거: *Contextual Drag: How Errors in the Context Affect LLM Reasoning*, arXiv:2602.04288. **[확인됨]**

- 컨텍스트에 남은 **실패한 시도가 이후 생성을 구조적으로 유사한 오류 쪽으로 편향**시킨다.
- **11개 모델 · 8개 추론 과제에서 10~20% 성능 하락.**
- ★ **"외부 피드백도, 성공적인 자기검증도 이 효과를 제거하지 못한다."**

> **매 라운드 수정자는 깨끗한 컨텍스트에서 시작한다** — 현재 스크린샷 + 현재 finding 만.

⚠️ **[검수 지적 — 라이브락] 깨끗한 컨텍스트 + 기각 이력 비노출 + 롤백을 동시에 걸면,
수정자가 방금 기각된 편집을 그대로 재생성해 무한 기각된다.**
ReLook 은 이걸 **라운드 내부 재샘플**로 풀었지 깨끗한 라운드로 푼 게 아니다.

**해소책 — 두 종류의 지문을 하네스가 코드로 관리한다(에이전트에겐 둘 다 비노출):**
1. **finding 지문** — 중복 지적 폐기 (§1.5)
2. **편집 지문** — 기각된 diff 를 차단 목록에 넣어 동일 편집 자동 폐기
3. **재샘플은 라운드 내부에서** 돌린다. 라운드를 넘기지 않는다.

### 2.3 자기수정 일반론 — 그리고 사용자 가설의 근거

- **[확인됨]** Huang et al., *LLMs Cannot Self-Correct Reasoning Yet*, arXiv:2310.01798
  (ICLR 2024): **외부 피드백 없는 내재적 자기수정은 성능을 개선하지 못하고 때로 떨어뜨린다.**
- **[확인됨]** Xu et al., *Pride and Prejudice: LLM Amplifies Self-Bias in Self-Refinement*,
  arXiv:2402.11436: self-bias = **자기 생성물 선호**. GPT-4·GPT-3.5·Gemini·LLaMA2·Mixtral·DeepSeek
  **6개 모델 전부**, 여러 언어·과제에 존재. ★ **자기정제 파이프라인이 self-bias 를 증폭시킨다.**
  확인된 완화책 — **① 더 큰 모델 ② 정확한 평가 신호를 주는 외부 피드백.**

→ **설계 정당화**: 생성자/평가자 분리 · 비평가에 저작 맥락 비노출 ·
**§3 결정론적 검사기가 "정확한 평가 신호를 주는 외부 피드백"** 역할.

## 3. 결정론적 검사 계층

### 3.1 axe-core 의 설계 교훈 — 단, 커버리지 수치는 이식 금지

- ⚠️ **[확인됨 — 정정]** Deque 리포트의 **57.38%** 는 *"Deque 자체 자동 테스트(axe 룰셋)가
  자사 감사 표본에서 잡은 이슈 비율"* 이다. **"WCAG 이슈의 57%가 자동 검출 가능"이라는
  일반 명제가 아니고, §3.3 의 자체 구현 검사기 커버리지 근거로는 쓸 수 없다.**
- ★ **이식할 것은 수치가 아니라 설계 원칙이다: "false positive 제로", 판정 불가 시
  violation 이 아니라 `incomplete`(사람 확인 필요).**

### 3.2 ★ 1층을 두 겹으로 쪼갠다 (검수 지적 반영)

axe 의 zero-FP 는 **axe 룰셋의 속성이지 우리 자체 구현의 속성이 아니다.**
특히 「스케일 이탈」은 §4 의 **빈도 군집화 추정치**에서 나오므로 원리적으로 오탐이 있다
(어떤 값이 의도된 일회성인지 실수인지 CSSOM 에 정보가 없다 — §4 가 스스로 인정).

| 층 | 내용 | 중재 |
|---|---|---|
| **1a** | axe-core 룰 위반 (대비·타겟 크기 등 axe 가 `violation` 으로 확정한 것) | **불필요 — 자동수정** |
| **1b** | 자체 구현 측정 (스케일 이탈·정렬 편차·오버플로·겹침·CLS) | **필요 — 중재자 경유** |

⚠️ 이걸 안 쪼개면 **스킬이 의도된 디자인을 자동으로 뭉갠다.**

### 3.3 레이아웃 안정성 — CLS / Layout Instability API

**[확인됨 — 원문 대조]**

- `PerformanceObserver` entryType **`'layout-shift'`** → `page.evaluate` 에서 결정론적 수집.
- score = **impact fraction × distance fraction**
  (distance fraction = 요소가 이동한 최대 수평·수직 거리 ÷ 뷰포트 최대 변).
- 세션 윈도우: shift 간 1초 미만 묶음, 최대 5초, **그중 최대 버스트 합계**가 CLS.
- 입력 후 500ms 내 shift 는 **`hadRecentInput`** 으로 제외.
  ⚠️ **스크롤·핀치 같은 연속 제스처에는 이 예외가 적용되지 않는다.**
- 판정선: **좋음 ≤0.1 / 개선 필요 0.1~0.25 / 나쁨 >0.25** (75퍼센타일 기준).

⚠️ **`layout-shift` 는 Chromium 전용.** WebKit/Firefox 에서 엔트리가 조용히 0건으로 나오는데
**"shift 없음"으로 읽으면 안 된다.**

### 3.4 정렬·간격·겹침 — 직접 구현할 수밖에 없다

- **[확인됨]** 레이아웃 선언 단언 도구 **Galen Framework 는 2.4.4(2019-03-15) 이후 방치.**
  유지보수되는 후계자를 **찾지 못했다**(부재의 증거는 아님).
- 1층 1b 는 **`getBoundingClientRect` 기반 자체 구현**: 겹침은 top/right/bottom/left 비교,
  오버플로는 `scrollWidth > clientWidth`, 가시성은 `Element.checkVisibility()`,
  겹침 후보는 `document.elementsFromPoint`.
- ⚠️ **비용은 호출 수가 아니라 read/write 인터리빙**이다. `getBoundingClientRect` 는 동기 레이아웃
  플러시를 강제하므로 **DOM 변경과 번갈아 호출하면 레이아웃 스래싱**. **단일 `page.evaluate`
  안에서 DOM 변경 없이 전량 수집**하면 수천 건도 싸다.
- ⚠️ **[확인 필요]** `Element.checkVisibility()` 는 최신 API(Safari 17.4 무렵). WebKit 실행
  가능성이 있으면 feature-detect 후 `getComputedStyle` + rect 폴백.

### 3.5 수치 기준 **[확인됨 — WCAG 2.2 원문 대조]**

| 항목 | 기준 | 레벨 |
|---|---|---|
| 본문 텍스트 대비 (1.4.3) | **4.5:1** | AA |
| 큰 텍스트 대비 (1.4.3) — 18pt+ 또는 14pt+ 볼드 | **3:1** | AA |
| 비텍스트(아이콘·컴포넌트 경계) 대비 (1.4.11) | **3:1** | AA |
| 타겟 크기 (2.5.8) | **24×24 CSS px** | **AA** |
| 타겟 크기 (2.5.5) | 44×44 CSS px | AAA |

⚠️ **24×24 가 AA. 44×44 는 AAA(2.5.5)·Apple HIG 값**이라 섞으면 자동수정이 과잉 개입한다.
2.5.8 예외 5종(간격 24px 확보 / 동등 대체 컨트롤 / 문장 내 인라인 / UA 결정 / 본질적 표현)
판정은 중재자 몫.

⚠️ **[치명적 공백 — §10-5] 대비 검사의 배경색 결정 규칙이 없다.** 반투명·그라디언트·이미지 위
텍스트·겹친 레이어에서 배경을 어떻게 잡을지 정하지 않으면 **자동 대비 검사 오탐 1위 경로**가
그대로 열린다. axe 는 정확히 이 케이스를 `incomplete` 로 돌린다 — 우리도 같은 규칙이 필요하다.

**간격 — 4px 베이스라인 / 8pt 그리드** (Material Design 3: 4dp 베이스라인, 컴포넌트 8dp 배수)

- 자동수정 규칙: **스케일 밖 값(13px, 18px, 22px…)을 가장 가까운 스케일 값으로 스냅.**
- 라운드 0 에서 **프로젝트의 실제 스케일을 먼저 추출**해야 한다(§4).
- ⚠️ **[검수 지적 — 규칙 충돌] 스냅이 위계를 파괴할 수 있다.**
  12px 과 14px 이 둘 다 12 로 붕괴하면 **그룹 경계가 사라진다** — 아래 위계 규칙이 정의한
  위반을 스냅이 스스로 만들어낸다. **스냅만 최적화하면 점수는 오르고 화면은 나빠지는 정확한 경로.**
  → **스냅은 조건부**: *인접 스케일 값이 이웃 간격과 같아지면 금지.* **위계 지표가 스냅보다 상위.**

**위계 — 측정 가능하게 환원되는 것**

- **간격이 관계를 정의한다** → **그룹 내 간격 ≥ 그룹 간 간격이면 위계가 뒤집힌 것.**
- (검사 가능한 제약) 한 화면에서 **폰트 굵기 2종 · 색 3종 상한.**

**한글**

- `word-break: keep-all` 은 CJK 가독성에 유리하나 **좁은 화면에서 긴 URL·긴 단어가 넘친다**
  → `overflow-wrap: break-word` 병용.
- → **상태 커버리지에 「긴 한글 텍스트」 필수.** lorem ipsum 으로는 재현되지 않는다.

## 4. 스페이싱 스케일 추출 (0층)

- ⚠️ **computed style 은 "해결된 결과값"이지 저자의 의도가 아니다.** 어떤 값이 의도된 일회성인지
  실수인지 CSSOM 에 라벨이 없다. **→ 1b 가 원리적으로 오탐을 갖는 이유(§3.2).**
- ★ **CSS 사용자 정의 속성(`--*`)을 우선 읽는다.** `:root`/`:host` 에서 `getComputedStyle` 로
  뽑으면 **저자가 붙인 이름이 남아 있는 유일한 경로.**
- 폴백 = **빈도 군집화**: 반복되는 값 = 의도, 일회성 = 노이즈. 상위 빈도값 집합이 스케일.
- **선행 구현 [확인됨]**: [dembrandt](https://github.com/dembrandt/dembrandt) — **2.6k stars, MIT.**
  Playwright 렌더 → computed style + CSS 변수 → **신뢰도 점수와 함께** 색·타이포·간격 토큰 반환.
  WCAG 대비 분석·DTCG 내보내기·MCP 연동 포함. 최근 활동일 **[확인 필요]**.
- **출력 포맷 [확인됨]**: DTCG *Design Tokens Format Module* — `dimension` 타입은
  `{"value": 0.5, "unit": "rem"}` 객체(MUST), 단위 px|rem 한정.
  ⚠️ 문서 자체가 *"Do not attempt to implement this version"* 을 명시한 드래프트.
  → **내부 축약형을 정본으로, DTCG 는 내보내기 전용.**

## 5. 회귀 검출과 수렴 판정

### 5.1 ★★ 라운드 점수 — 재설계 (검수로 3중 결함 발견)

§2.1 Forced Optimization 은 **라운드 간 비교 가능한 스칼라**를 전제한다. v2 는 "1층 위반 가중합"
이라고만 적어 세 가지가 동시에 깨져 있었다:

**결함 ① 통약 불가.** 스케일 이탈 **건수** · 정렬 편차 **px 총량** · 오버플로 **건수** ·
CLS **무차원 0~1** 은 가중치 없이 더할 수 없다.

**결함 ② 퇴화 최적점 — 빈 화면이 만점이다.** 요소를 지우면 겹침·오버플로·대비 미달·타겟 미달·
CLS 가 **전부 동시에 0** 이 된다. 콘텐츠 보존 불변식이 없으면 롤백 규칙이 **파괴적 편집을 채택**한다.

**결함 ③ 주 수익 구간이 매 라운드 기각된다.** LLM finding 을 점수에서 뺐으므로
*"폰트 크기 차이를 벌려 위계를 만든다"* 같은 **§1.3 형 수정(= 이 스킬의 존재 이유)은 1층 점수를
바꾸지 않아 동점**이고, "엄격히 초과"에서 동점은 기각이다.
**그대로 구현하면 스킬이 아무것도 고치지 않는다.**

**→ 재설계 (셋 다 처리)**

1. **하드 불변식 게이트를 점수보다 앞에 둔다.** 위반 시 점수와 무관하게 **무조건 기각**:
   - DOM 노드 수 감소 금지 (허용 오차 0)
   - 텍스트 콘텐츠 해시 불변
   - 픽셀 diff 상한 초과 금지 (한 라운드가 화면을 통째로 갈아엎지 못하게)
2. **점수는 가중합 대신 사전식(lexicographic) 우선순위**로 비교한다. 가중치를 지어낼 근거가 없다:
   **오버플로 > 대비 미달 > 타겟 미달 > 겹침 > 위계 역전 > 스케일 이탈 > 정렬 편차 > CLS**
   (앞 항이 같을 때만 다음 항 비교)
3. **채택 규칙을 "엄격히 초과"에서 "1층 비퇴보 + 타이브레이커"로 완화한다.**
   - 1층이 나빠지면 → 기각
   - 1층이 같으면 → **해소된 LLM finding 수(중재자 통과분)로 타이브레이크** → 채택
   - 1층이 좋아지면 → 채택

   ⚠️ 이 타이브레이커는 LLM finding 을 **점수에 넣는 게 아니라 동점 판정에만** 쓴다.
   오탐이 섞여도 순위를 뒤집지 못한다.

### 5.2 픽셀 diff — 벤더 표준이 없다

**Playwright `toHaveScreenshot()` [확인됨 — 원문 대조]**: `threshold` **0.2**,
`maxDiffPixels`/`maxDiffPixelRatio` **미설정**(임계 초과 픽셀 1개라도 있으면 실패),
`animations` `"disabled"`, `caret` `"hide"`, `scale` `"css"`, `maskColor` `#FF00FF`,
`fullPage` `false`, `stylePath` 제공.

⚠️ **[확인됨] 색공간 모순 — 양쪽 다 1차 출처 확인.** Playwright 문서는 threshold 를 **YIQ**
지각 색차로 설명하는데, 실제 엔진 pixelmatch 는 **OKLab + HyAB** 로 기술한다.
**threshold=0.2 를 "지각 색차 몇 %"로 해석하는 추론은 성립하지 않는다.**

⚠️ **[확인됨] 기본값 2배 모순**: pixelmatch 자체 기본은 **0.1**, Playwright 는 **0.2** 를 넘긴다.
pixelmatch 문서로 민감도를 추론하면 실제 동작과 2배 어긋난다.

⚠️ **[확인됨] 벤더 튜닝 가이드가 존재하지 않는다.** `maxDiffPixels: 100` /
`maxDiffPixelRatio: 0.01` 같은 숫자는 **벤더 권고가 아니다.**

★ **채택 규칙 — 자기 잡음 캘리브레이션:**
> **같은 페이지를 아무것도 바꾸지 않고 두 번 찍어 관측된 자기 잡음보다 위에 임계를 잡는다.**
> **화면별로 따로.** 전역 단일값을 찾지 않는다.

**기타**
- `includeAA=false` 가 pixelmatch 기본 → **안티앨리어싱 차이는 이미 걸러진다.** 별도 옵션 불필요.
- ⚠️ **`_comparator: 'ssim-cie94'` 는 공개 문서화된 API 가 아니다**(선행 언더스코어 = 비공개).
  회귀 게이트를 얹지 말 것.
- ⚠️ **"스냅샷 1~2px 블러" 금지.** 이 스킬이 잡으려는 **서브픽셀 정렬·간격 신호를 정확히 파괴**한다.
- **[미검증]** 렌더 결정론화: `--force-device-scale-factor=1`, `--disable-gpu`.
  임계값 상향은 반창고이며 진짜 회귀도 같이 숨긴다는 것이 현장 합의.
- **처방**: 최신 Playwright 고정 + **"N픽셀 다른 이미지가 `maxDiffPixels:N+1` 에서 통과하는지"
  1회 자가 테스트**. (과거 #30112 버그가 있었으나 v1.42.1 기준 closed — 전제로 삼지 않는다.)

### 5.3 무효 렌더 게이트

**렌더 실패·타임아웃·빈 스크린샷이면 그 라운드의 LLM 비평을 통째로 폐기한다.** (§2.1 확인됨)

### 5.4 종료 조건

- **1차**: §5.1 채택 규칙으로 **3라운드 연속 채택 0** → 종료. (라운드 상한 3 은 **[미검증] 기본값**)
- **2차(보조)**: dedup 통과 신규 finding 0 이 2라운드 연속.
  ⚠️ dedup 이 하네스에서 도므로 "신규 finding"은 **dedup 통과분**을 뜻한다. 비평가는 매 라운드
  같은 지적을 계속 내고 하네스가 조용히 버리므로 **이 카운터는 "비평가가 만족했다"를 의미하지 않는다.**

## 6. 정보 밀도·시각적 복잡도 정량화

근거: Rosenholtz, Li, Nakano, *Measuring visual clutter*, Journal of Vision (2007).

⚠️ **[확인됨 — 원문 대조로 v2 설명 정정]** 논문은 **3종**을 제시한다:

| 측정치 | 색 변동성 반영 | 채택 |
|---|---|---|
| **Feature Congestion** — 색·방향·크기 등 특징의 변동성을 명시적으로 포착 | **○** | **채택** |
| **Subband Entropy** — 웨이블릿 서브밴드 엔트로피. 근거는 "더 조직화(그룹화)될수록 부호화 엔트로피가 낮다" | **✕** | 미채택 |
| **Edge Density** | **✕** | 미채택 |

원문: *"color variability, accounted for by Feature Congestion but **not** the Edge Density measure
or the Subband Entropy measure, does matter for visual clutter."*

★ **등락색·강조색이 신호의 핵심인 금융 UI 에서는 색을 반영하는 Feature Congestion 만 유효하다.**
(v2 는 Subband Entropy 가 색을 암묵 반영한다고 적었으나 **정반대였다.**)

**용도 — 파이프라인에서의 소비처를 명시한다:**
- 절대 판정선은 **[확인 필요]** → **절대 임계 자동수정 금지.**
- **§5.1 사전식 순위에는 넣지 않는다**(가중치 근거 없음).
- **소비처는 하나: 하드 불변식 게이트의 보조 신호.** 한 라운드에서 Feature Congestion 이
  급락하면 = 요소가 사라졌을 가능성 → **결함 ② 퇴화 편집의 조기 탐지기**로 쓴다.
  이 용도라면 절대 판정선 없이 **전후 델타만으로** 성립한다.

## 8. 조사했으나 채택하지 않은 것 (재조사 방지)

- **토스 디자인 시스템(TDS) 공개 자료** — "일관성 보장·생산성 향상" 수준의 조직 논리라
  측정 가능한 규칙이 나오지 않는다. 사용자가 직접 지목한 소스라 결과를 명시해 둔다.
- **Nielsen 10 휴리스틱 목록 자체** — §1 논문의 실험 프레임이지만 이 스킬의 축은 별도 정의(§10-1).
  severity 척도(§1.7)만 채택.
- **UICrit / Visual Prompting 의 좌표축 오버레이·바운딩 박스 IoU 정밀화**(UIST '24 / arXiv:2412.16829)
  — IoU 0.267→0.357 개선은 사실이나, **사용자 실경험상 "이 화면 패딩들이 어색해" 수준의 영역
  지목으로 이미 수정이 성립**하므로 과투자. 좌표 눈금은 위치 서술 보조로만.
  ★ 단 같은 논문의 **"LLM 이 LLM 지적을 검증하는 단계가 유효 지적을 되레 제거한다"** 는 실패 모드는
  채택 — **§7-1 중재자 설계의 유일한 반례 근거**이므로 삭제 금지. 중재자는 **측정치·예외 목록**으로
  판정하고 LLM 직관 재확인을 하지 않는다.
- **Galen Framework** — 방치되어 사용 불가(§3.4). 대안 탐색은 1회 검색 기준이라 재조사 여지 있음.
- **Deque 57.38% 를 자체 검사기 커버리지 근거로 쓰는 것** — 정의가 다르다(§3.1).

## 10. ★ 미결 — SKILL.md 작성 전 반드시 정해야 하는 것

검수가 "이게 없으면 SKILL.md 작성이 여기서 멈춘다"고 판정한 항목들이다.

1. **축 목록이 정의돼 있지 않다.** §7-8/9 가 "한 에이전트 한 축"인데 축이 뭔지 없다.
   최소한 **여백·리듬 / 시각 위계 / 정렬·그리드 / 색·대비 / 정보 밀도** 수준의 목록과
   축당 검사 항목이 필요하다.
2. **DOM → 소스 매핑이 없다.** 1층은 렌더된 DOM 에서 측정하고 비평은 스크린샷에서 나오는데,
   **수정은 소스(CSS / Tailwind 클래스 / CSS-in-JS / 컴포넌트 props / 토큰 파일)** 에 들어간다.
   **이 스킬에서 공학적으로 가장 어려운 지점인데 한 줄도 없다.**
   무엇을 편집 대상으로 삼을지(토큰만? 클래스명?)와 역매핑 수단(data 속성 주입 / 소스맵 / grep)이
   정해지지 않으면 루프가 돌지 않는다.
3. **롤백의 단위와 메커니즘이 없다.** 라운드 단위면 좋은 편집까지 버리고, finding 단위면
   편집마다 재렌더·재측정이라 라운드당 N회 캡처 비용이 든다. git worktree/stash 를 쓸지,
   비-git 프로젝트는 어떻게 할지 미정.
4. **캡처 규약이 없다.** 뷰포트/브레이크포인트 집합, 테마(라이트·다크), `deviceScaleFactor`,
   headed/headless 고정, 안정화 조건(폰트 로드·network idle·애니메이션 종료), 앱 상태 도달
   방법(로그인·라우트·픽스처). **§5.2 자기 잡음 캘리브레이션 · §5.3 무효 렌더 게이트 ·
   §3.3 CLS 수집이 전부 이 규약에 의존**하므로 없으면 세 규칙이 동시에 무의미해진다.
   §3.5 의 "긴 한글 텍스트 상태" 도 상태 목록이 없어 실행 불가.
5. **대비 검사의 배경색 결정 규칙 / 도메인 예외 허용 목록 파일 형식** (§3.5, §1.6).
6. **종료 시 산출물과 사람 개입 지점.** 3라운드가 개선 없이 끝나면 무엇을 남기는지
   (라운드 0 복구? 최고 점수본?), 보류함을 누가 언제 보는지, 최종 출력이 diff·커밋·리포트 중 무엇인지.

## 11. 이 문서가 과거에 틀렸던 것 (재발 방지)

v1·v2 에서 실제로 잘못 적었고 적대적 검수로 잡힌 것들. 같은 실수를 반복하지 않기 위해 남긴다.

| 오류 | 실제 | 영향 |
|---|---|---|
| "개수 하한 강제가 프롬프트 레버" | **실패한 프롬프트에 이미 있었다.** 레버는 근거·severity·이유·위치 | 설계 결정 하나가 통째로 잘못 섰음 |
| "severity 0 의 65%가 LLM 산 = 오탐률" | 147 은 Gemini·Claude 몫 포함 **오탐 집합**. 실제 오탐률 31~37% | 중재자 게이트 강도 2배 오설정 |
| "3~5대 병렬" | 근거는 **사람 평가자** 문헌. 같은 논문이 LLM 앙상블에서 **신규 유효 0·오탐 +43** 실측 | 정반대 결정 |
| "Subband Entropy 가 색을 암묵 반영" | **반영하지 않는다.** 색을 반영하는 건 Feature Congestion 뿐 | 색 밀도 지표로 오용할 뻔 |
| "WCAG 이슈의 57%가 자동 검출 가능" | **axe 룰셋이 Deque 자사 표본에서 잡은 비율.** 일반 명제 아님 | 자체 검사기 커버리지 근거로 오용 |
| ReLook 궤적 퇴화에 `[확인됨]` | 초록엔 없다. **본문 미검증** | 라운드 상한 3 이 검증값처럼 하드코딩될 뻔 |
| 오탐 원인 "브라우저 크롬 오인" | 원 실험은 **iOS 스크린샷**. Playwright 뷰포트엔 크롬이 안 들어옴 | 존재하지 않는 실패를 검사할 뻔 |
