# 루프 본체 — 2~5층 (T2 전용)

`SKILL.md` 에서 분리한 것이다(본문이 권고 상한 20,000자를 넘겨 2026-09-07 분리).
**T0 단발·TS 스윕에는 이 문서가 필요 없다.** 사용자가 반복 개선(T2)을 명시적으로 요구했을 때만 연다.

- 2층 비평가(축별 병렬) · 3층 중재 · 3.5층 원인 진단 · 4층 수정 · 5층 채택 판정
- 이 문서의 규칙은 `SKILL.md` 의 「절대 규칙」과 「규율 게이트」를 전제로 한다. 그 둘을 먼저 읽는다.

## 2층 — 비평가 (축별 병렬)

축마다 **에이전트 1대**. 같은 축에 여러 대를 붙이지 않는다(절대 규칙 3).

**축 7종**: 여백·리듬 / 시각 위계 / 정렬·그리드 / 색·대비 / 정보 밀도 /
**폼·테이블** / **오버레이·스크롤·반응형**
**+ 화면 간 일관성**(별도, 자동수정 금지)

뒤 두 축은 금융 대시보드·목록·상세의 본체이고, 특히 **브레이크포인트 전환은 실무 패딩 사고의
최대 발원지**다. 축을 늘리는 것은 유일하게 허용된 병렬화 방향이다(모델 증설 ✕, 축 분할 ○).

### ★ 요소 번호 오버레이 — 없으면 스킬이 아무것도 못 고친다

3층은 "1b 가 같은 지점을 측정했는가"로 판정하는데, 비평가는 자연어로 위치를 쓰고 1b 는 DOM
셀렉터를 낸다. **잇는 수단이 없으면 모든 finding 이 보류함으로 떨어져 4층에 입력이 없다.**
반대로 비평가에게 셀렉터를 주면 절대 규칙 1 에 걸린다.

**해소**: 캡처 시 요소마다 번호 배지를 굽고, 비평가가 `#12` 로 지목한다.
번호는 코드도 저작 의도도 아니라 규칙 1 을 어기지 않는다. 하네스가
`번호 → 셀렉터 + rect + computed style` 매핑을 보관하므로 3층·4층이 즉시 조회한다.
상세 규약은 `references/checklists.md` 의 "요소 번호 오버레이 규약".

### `references/checklists.md` 를 반드시 로드한다

**이 스킬의 실질은 그 문서다.** 축별 관찰 패턴 목록과 **비평가 프롬프트 실제 텍스트**가 거기 있다.

- 프롬프트를 **매번 새로 작문하지 않는다.** 그대로 쓰고 `{...}` 만 치환한다.
  프롬프트가 흔들리면 라운드마다 결과가 달라져 채택 판정(5층)이 무의미해진다.
- 체크리스트는 **"판단해라"가 아니라 "이 패턴이 있는지 봐라"** 로 쓰여 있다. 이 형태를 유지한다 —
  판단을 요구하면 취향 지적이 나오고, 그건 논문이 실패한 프롬프트와 같은 종류다.
- 각 항목의 **◆/○ 표기가 자동수정 가능 여부**다. ◆ 는 1b 가 측정하므로 중재자가 검증 가능,
  ○ 는 대부분 보류함행.

### 화면 간 일관성

여러 화면을 한 에이전트에 **등장 순서를 명시해서** 함께 준다. LLM 은 스크린샷을 독립 아티팩트로
보기 때문에 화면 간 위반을 43~50% 밖에 못 잡고, 이 축은 **유일하게 사람에게 지는 축**이다.
→ **결과는 전부 보류함으로.** 자동수정하지 않는다.

### finding 봉투와 severity 0

지적 **내용**은 자유 텍스트다(디자인마다 다르므로 분류 체계를 만들지 않는다).
필드는 `screen` · `seen_in` · `axis` · `target`(요소 번호) · `item` · `severity` · `intent_flag`.

**지문 = `screen + target + item`**
⚠️ **`axis` 를 지문에서 뺐다.** 축이 다르면 지문이 달라져 **축 간 중복이 dedup 을 통과**한다.
`item` 을 넣은 것은 같은 요소에 대한 다른 종류의 지적을 구분하기 위해서다.

severity 0은 폐기하되, 실측상 거의 발화하지 않으므로 오탐 방어선으로 간주하지 않는다.

축이 달라도 타깃 집합이 완전히 같으면 `dedup.mjs filter`가 중복으로 묶고 `also_reported_by`를 붙인다. 부분 겹침은 정상일 수 있어 버리지 않는다.

## 3층 — 중재자

중재자는 **맥락을 가진 채로** 판정하되, **LLM 직관으로 재검증하지 않는다**(절대 규칙 5).
판정 근거는 둘뿐이다:

1. **측정치** — 1b 가 같은 지점을 실제로 측정했는가
2. **프로젝트 예외 허용 목록** — `.ui-refine.json` 에 선언된 의도적 예외

### 매칭은 `scripts/dedup.mjs match` 가 한다

⚠️ **1b 가 재는 요소와 비평가가 가리키는 요소는 층이 다르다.** 가로 넘침을 1b 는 넘치는
**컨테이너**에 붙이는데 비평가는 **잘려 보이는 셀**을 가리킨다(실측). 그래서 매칭은 지목한 번호의
**조상 사슬**까지 본다(자손 방향은 보지 않는다 — 컨테이너 지목이 자식 전체를 근거로 삼으면 헐거워진다).

`no-measure-for-item`은 실패가 아니라 정직한 답이다. 측정 수단이 없는 항목은 매핑을 꾸며내지 않고 보류함으로 보낸다.

```
node scripts/dedup.mjs match findings.json --measure .ui-refine/r0/measure/<id>.json
```

⚠️ **번호가 하나라도 겹치면 매칭으로 치면 안 된다.** 실측에서 "제목↔카드 간격"(1-3) 지적이
무관한 `pad-asym`(카드 내부 상하 여백)에 붙었다 — 여러 번호를 나열한 finding 은 우연히 겹친
측정치와도 매칭된다. **번호 교집합 + 항목↔판정 종류 대응**을 둘 다 봐야 한다.
대응표는 `dedup.mjs` 의 `itemKindMap()`. **`collect.js` 에 판정을 추가하면 이 표도 함께 갱신한다.**

판정 결과 3종: `supported`(→4층) · `unsupported`(→보류함) · `no-measure-for-item`(→보류함).

### 예외 허용 목록 형식

```json
{
  "intentionalDensity": ["/portfolio", "/orders"],
  "semanticColors": { "up": "#d32f2f", "down": "#1976d2" },
  "ignoreSelectors": [".sr-only", "[data-testid]"],
  "spacingScale": [4, 8, 12, 16, 24, 32, 48]
}
```

파일이 없으면 만들라고 제안하되, 없어도 진행한다(그 경우 도메인 관례 지적은 전부 보류함행).

### 캡처 아티팩트는 판단이 아니라 규약으로 제거한다

원 연구의 오탐 1위는 "OS 상태바를 앱 UI 로 오인"이었으나 그건 iOS 스크린샷 사정이고
**Playwright 뷰포트 캡처에는 브라우저 크롬이 안 들어온다.** 우리 쪽 등가물은 다음이며,
중재자가 판단할 게 아니라 **0-4 캡처 규약에서 미리 제거**한다:
스크롤바 · HMR/devtools 배지 · 토스트/모달 잔상 · 스켈레톤 로딩 잔여 · 포커스 링.

### 판정 결과

| 판정 | 처리 |
|---|---|
| 측정치가 뒷받침함 | 4층으로 |
| 예외 목록에 해당 | 폐기 (근거 기록) |
| 측정 불가 + 예외 아님 | **보류함** — 사람이 본다 |

### 3.5층 — 증상에서 원인으로

중재를 통과한 관찰도 곧바로 CSS 처방으로 바꾸지 않는다. 사용자 원문과 관찰마다 경쟁 가설 2~4개를 세우고 DOM·computed style·geometry·interaction으로 하나씩 반증한다.

예: `패딩이 두꺼워 보임 → padding / 고정 width·height / aspect-ratio / grid stretch / 글리프 자체 여백`. 살아남은 원인과 반증 증거만 수정자에게 준다. `padding`처럼 사용자 발화에 나온 속성을 먼저 고르는 것은 금지한다.

- 로컬 속성 하나로 끝나고 footprint·다른 화면이 유지되면 surface 수정
- 같은 증상이 여러 화면, 토큰, 컨테이너, breakpoint에서 반복되면 구조 수정 후보
- IA·콘텐츠 역할·브랜드 판단이 필요하면 자동 수정하지 않고 biz-experts의 해당 렌즈로 넘김
- 스크롤·뒤집기·오버레이처럼 발견 가능성이 핵심이면 정적 샷 대신 1~3단계 task-path probe를 수행하고 전·중·후 상태를 기록

## 4층 — 수정자

**깨끗한 컨텍스트**에서 시작한다. 현재 스크린샷 + 지원된 finding + 원인 진단 + 의도 계약만 준다.
이전 라운드의 기각 이력·실패한 수정은 주지 않는다(절대 규칙 4).

### 토큰이냐 로컬이냐는 자동 판정된다

CDP `CSS.getMatchedStylesForNode` 로 해당 속성을 **최종 결정한 규칙**을 역추적한다.

| 값의 출처 | 수정 대상 |
|---|---|
| `var(--space-3)` 등 **CSS 변수 경유** | **토큰 파일** |
| 유틸리티 클래스(`p-3`) | 클래스명을 소스에서 grep → **해당 화면** |
| 인라인 스타일 / 일회성 리터럴 | **해당 화면** |

⚠️ **토큰을 수정하면 폭발 반경이 전역**이다. 그 라운드의 점수는 반드시 캡처 세트 전체에서 잰다.

⚠️ CDP 세부 시그니처와 React fiber `_debugSource` 가용 여부는 **확인 필요** — 버전별로 갈린다.
역추적이 실패하면 값 grep 으로 폴백하고, 그마저 애매하면 **보류함행**(추측으로 고치지 않는다).

## 5층 — 채택 판정

### 5-1. 하드 불변식 (점수보다 먼저)

하나라도 위반하면 **점수와 무관하게 기각**한다. 이게 없으면 빈 화면이 만점이 된다.

- DOM 노드 수 감소 금지
- 텍스트 콘텐츠 해시 불변
- 캡처 세트·라우트·상태·뷰포트 동일
- summary 스키마와 필수 필드 완전성

픽셀 diff와 Feature Congestion은 현재 번들이 생성하지 않으므로 하드 불변식이라고 부르지 않는다. 구현·검증되기 전까지 화면 교체 방지는 `allowed_change_scope`, DOM·텍스트 보존, 총 판정 건수 비증가, fresh 시각 비교로 맡는다. 없는 지표를 조용히 건너뛰지 않는다.

### 5-2. 점수는 사전식 우선순위로 비교한다

가중치를 지어낼 근거가 없고, 항들의 단위가 통약 불가하다(건수 vs px 총량 vs 무차원 CLS).
**앞 항이 같을 때만 다음 항을 본다:**

```
`scripts/score.mjs`의 `ORDER`가 단일 원본이다. 문서에 축약 목록을 복제하지 않는다.
```

**카운트 정의** — 없으면 비교 함수를 쓸 수 없다:
- 앞의 다섯은 전부 **건수**(px 총량 아님). 정렬 편차도 "1px 초과인 형제 쌍의 수".
- **집계 축은 캡처 세트 전체 합.** 화면별 벡터로 두면 A 가 좋아지고 B 가 나빠질 때
  비교가 성립하지 않는다. 토큰 수정이 전역에 퍼지므로 세트 합이어야 한다.
- CLS 는 **세트 내 최댓값**(합은 화면 수에 비례해 의미가 없다).
- **대비·타겟 미달은 순위에 넣지 않는다** — 1a 라 매 라운드 자동수정돼 항상 0 인 죽은 항이다.

### 5-2.5. verdict 는 「무엇을 못 봤는가」를 포함한다

점수가 좋아져도 **그 점수가 대표하는 범위**가 좁으면 `accept` 라고 말하지 않는다.
`score.mjs` 가 자동으로 낮춘다(둘 다 exit 0 — 작업을 막지 않고 **보고를 바꾼다**):

| verdict | 조건 | 보고 의무 |
|---|---|---|
| `accept` | 게이트 없음 | 그대로 |
| `accept-partial` | `summary.coverage.min` 이 낮음 | **본 범위를 숫자로 함께 말한다.** "나머지는 지적 없음"이라고 쓰지 않는다 |
| `accept-pending-owner` | `narrow-column` 등 구조 신호가 남음 | 자동수정하지 않고 **다열 시안을 먼저 보이고 승인**을 받는다 |

⚠️ 커버리지는 판정이 아니라 **자기 신고**다. 내부 스크롤 셸에서는 `fullPage` 가 아무 일도 하지
않으므로(실측 19%) `.ui-refine.json` 의 `injectCss` 로 높이 잠금을 풀고 **다시 재는 것**이 정답이지,
낮은 커버리지를 그대로 두고 보고만 붙이는 게 정답이 아니다.

### 5-3. 채택 규칙

| 1층 점수 | 처리 |
|---|---|
| 나빠짐 | **기각 + 롤백** |
| 같음 | **해소된 LLM finding 수(중재자 통과분)로 타이브레이크** → 늘었으면 채택 |
| 좋아짐 | 채택 |

시각 위계 수정은 1층 점수가 동점일 수 있으므로 해소 finding은 동점 판정에만 쓰고 순위를 뒤집지 못하게 한다.

시각 위계·균형·밀도처럼 결정론 점수가 동점인 미감 수정은 원본/수정본의 동일 crop을 A/B로 섞어 fresh evaluator에게 한 축만 묻는다. 수정본·코드·이전 점수는 숨긴다. 차이가 근소하거나 ease-of-use·편안함처럼 모델 신뢰가 낮은 축은 자동 채택하지 않고 보류함으로 보낸다.

### 5-4. 롤백은 라운드 단위

수정 하나씩 롤백하면 편집마다 재렌더·재측정이라 캡처가 N배로 든다. 라운드 단위로 되돌린다.
git 리포면 stash/worktree, 아니면 0층에서 뜬 스냅샷으로 복원한다.

### 5-5. dedup 과 라이브락 방지 — 전부 하네스가 코드로

기각 이력을 에이전트에게 보여주지 않고 하네스가 지문으로 재생성을 막는다:

1. **finding 지문** — 중복 지적 폐기. LLM 은 같은 문제를 화면마다 재보고한다(사람은 0건).
2. **편집 지문** — 기각된 diff 를 차단 목록에 넣어 동일 편집 자동 폐기.
3. **재샘플은 라운드 내부에서** 돌린다. 라운드를 넘기지 않는다.

### 5-6. 종료

- **라운드 상한 3.** 이 값은 검증된 수치가 아니라 **[미검증] 기본값**이다
  (근거가 된 연구는 RL 학습 시 규칙이고, 그 연구의 추론 구성은 critic 을 떼어낸 형태다).
- **조기 종료: 한 라운드에서 채택이 0 이면 즉시 종료.**
  ⚠️ 이전 판의 "3라운드 연속 채택 0"은 상한과 같아 **절대 발화하지 않는 죽은 조건**이었다.
- 보조 조건: dedup 통과 신규 finding 0.
  ⚠️ 이 카운터는 "비평가가 만족했다"를 뜻하지 않는다 — 비평가는 계속 지적하고 하네스가 버린다.
- **라운드 내부 재샘플 상한 3회.** 상한이 없으면 라이브락에서 종료가 보장되지 않는다.

### 5-7. 산출물

1. **최고 점수본을 유지**한다(마지막 라운드본이 아니다).
2. **보류함 리포트** — 사람이 판단해야 하는 것들. 축·severity 순으로 정렬하고 각 항목에
   crop·요소 번호·사용자 원문과의 연결·근거·왜 자동수정하지 않았는지를 붙인다.
3. 라운드별 점수 추이 한 줄 요약.
4. 검증 환경(`local/preview/live`)과 보지 못한 라우트·상태·뷰포트·blind spot. 로컬만 봤으면 라이브에서 확인됐다고 말하지 않는다.
