### 0-2. 스페이싱 스케일 추출

**CSS 사용자 정의 속성(`--*`)을 우선 읽는다.** 스타일시트 규칙에 남은 이름이
**저자가 붙인 의도가 남아 있는 유일한 경로**다. computed style 은 해결된 결과값이라 의도가 소실된다.

⚠️ **라이브러리 비의존이 이 단계의 핵심 요구다.** 10개 스택 실측에서 아래를 하나씩
놓칠 때마다 **정상 여백이 통째로 「스케일 이탈」로 지적됐다.** 전부 실측으로 확인된 함정이다:

1. **네임스페이스 접두** — 실무 라이브러리는 변수를 전부 접두한다(`--bs-card-spacer-x`,
   `--mantine-spacing-md`, `--pico-*`). 이름 매칭은 **접두 구간을 허용하되 키워드는 완전 일치**로
   본다. (부분일치로 풀면 `--font-size-sm:13px` 이 스페이싱으로 들어오는 옛 버그가 재발한다.)
2. **중첩 규칙** — `@layer`·`@media`·`@supports` 내부까지 **재귀로** 훑되,
   **지금 적용되는 조건만** 본다. Tailwind v4 는 전부를 `@layer` 안에 넣어 최상위만 보면
   변수가 하나도 안 보이고, Pico 는 브레이크포인트마다 같은 토큰을 다시 정의하므로
   조건을 안 보면 **지금 뷰포트가 아닌 값까지 스케일에 섞인다.**
3. **선행 0 생략** — minified CSS 는 `.25rem` 으로 쓴다. `0.25rem` 만 받으면 놓친다.
4. **★ rem 은 루트 폰트 크기 기준** — 16 으로 하드코딩하면 안 된다.
   Pico 는 뷰포트에 따라 루트를 100%→125% 로 키우므로 1440 에서 `1rem` 은 **20px** 이다.
5. **★ 스케일은 뷰포트마다 다시 뽑는다** — 4번 때문에 라운드당 1회 캐시가 성립하지 않는다.
   360 에서 뽑은 스케일을 1440 에 쓰면 전부 어긋난다.
6. **calc 파생 토큰** — 라이브러리는 토큰을 calc 로 만들고(`calc(var(--x) * 1.25)`),
   그 배수를 **토큰 정의가 아니라 사용처**에 두기도 한다. ①프로브 요소에 `width: var(--x)` 를
   넣어 실제 해석값을 재고 ②선언된 **(변수 × 배수) 쌍**을 모아 스케일을 확장한다.
   둘 다 **스케일 값을 지어내지 않고 읽어내는** 방식이다.
   ⚠️ 프로브는 `:root` 상속만 받으므로 컴포넌트 스코프 변수(Bootstrap 의 `.card{--bs-…}`)는
   못 읽는다. 규칙 직접 파싱을 **대체하지 말고 합집합**으로 쓴다.

세 가지 스케일 모드를 `summary.json`의 `scale.source`로 보고한다:

| source | 조건 | 판정 방식 |
|---|---|---|
| `css-vars` | 이름에 스페이싱 키워드가 든 변수 3개 이상 | 값 집합에 속하는가 |
| **`var-family`** | **이름 끝의 숫자만 다른 변수 가족**(`--s-1 … --s-9`) 3개 이상 | 같음 |
| `base-unit` | 기준 단위 변수 1개(`--spacing` 등) | 선언된 배수로 만든 값 집합 (없으면 정수배) |
| `frequency` | 위 셋 다 없음 | 빈도 군집화 폴백 |

**후보가 여럿이면 이름이 아니라 「이 화면의 여백을 얼마나 설명하는가」(coverage)로 고른다.**
⚠️ **하나만 고르면 안 된다.** 디자인 시스템은 스케일을 여러 벌 두는 게 정상이다 — 본 스페이싱
(4·8·12…)과 별도로 알약형·헤어라인용 **마이크로 스케일**(1·2·3·5·6px)을 두는 식이다.
하나만 고르면 나머지 벌의 정품 토큰이 전부 「이탈」로 지적된다(실측 8문서).
→ **커버리지에 실제로 기여하는 가족을 전부 합친다.** 기여가 0 인 가족(라디우스 등)은 자연히 빠진다.
`summary.json` 의 `scale.families` 가 어떤 가족들이 합쳐졌는지 보여준다.
7. **★ 약어 토큰 이름** — 수제 디자인시스템은 `--s-1 … --s-9` 처럼 줄여 쓴다. 키워드 매칭으로는
   절대 안 잡히므로 **숫자 접미 가족**을 구조로 탐지한다. 이름을 추측하지 않으므로 라디우스
   가족(`--r-1…`)도 후보로 올라오지만, 여백을 설명하지 못해 coverage 에서 자연히 진다.
   실측: 이 경로가 없어서 9단계 토큰을 갖춘 문서가 `frequency` 로 떨어졌고 지적 대부분이 오탐이었다.
8. **★ 스케일은 라우트마다도 다시 뽑는다** — 문서·화면마다 토큰 스케일이 다를 수 있다.
   실측: 첫 문서의 `--s-*` 가 나머지 3개에 적용돼 지적이 **60 → 103 건으로 부풀었다.**

폴백은 전체 요소의 padding/margin/gap 을 수집해 **반복되는 값 = 의도, 일회성 = 노이즈**로
분류한다. ⚠️ **표본으로 담는 속성과 판정에서 보는 속성이 같아야 한다** — 표본에 `marginTop` 만
넣고 판정에서 `marginBottom` 도 보면, `marginBottom` 으로만 쓰인 정품 토큰이 이탈로 지적된다.

폴백 스케일은 추정치이므로 스케일 이탈은 1b 중재를 거친다.
