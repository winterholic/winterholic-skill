# UI 개선 루프

## 이 스킬이 존재하는 이유

사용자가 공급하던 핵심은 해법이 아니라 **문제 존재의 단언과 화면·영역 수준의 위치**였다. 이 스킬은 그 신호를 대신 만들고, 관찰을 원인으로 성급히 바꾸지 않게 한다.

모든 설계 결정의 근거·수치·반례는 `references/research.md` 에 있다. **판정 임계값이나 규칙을
지어내지 말고 그 문서를 열어 확인한다.**

## 번들 (직접 짜지 말고 이걸 쓴다)

측정 구현이 라운드마다 달라지면 5층 점수 비교가 무의미해진다 — 프롬프트가 흔들리는 것과 같은 실패다.

| 파일 | 역할 |
|---|---|
| `scripts/capture.mjs` | 캡처 드라이버. 원본/배지본 두 벌 + 1b 측정 + CLS + 스케일 추출 → `summary.json` |
| `scripts/collect.js` | 브라우저에서 도는 1b 측정 본체(`collectPage`) · 배지(`paintBadges`) · 스케일 추출(`extractScale`) |
| `scripts/score.mjs` | 5층 판정. 불변식 → 사전식 → 타이브레이크. **exit 0 채택 / 1 기각 / 2 불변식 위반** |
| `scripts/dedup.mjs` | 비평가 출력 파싱 · finding 지문 dedup · 편집 지문 차단 |
| `assets/ui-refine.example.json` | 예외 목록 템플릿. 프로젝트 루트에 `.ui-refine.json` 으로 복사 |

```
node scripts/capture.mjs --url http://localhost:3000 --routes /orders \
  --out .ui-refine/r0 --config .ui-refine.json --calibrate
node scripts/dedup.mjs parse critic-out.txt --screen /orders --axis spacing > f.json
node scripts/dedup.mjs filter f.json --seen .ui-refine/seen.json
node scripts/score.mjs --prev .ui-refine/r0 --next .ui-refine/r1 --resolved 3
```

## 절대 규칙 (어기면 스킬이 역효과를 낸다)

1. **비평가에게 코드·diff·설계 의도·저작 사실을 주지 않는다.** LLM 은 6개 모델 전부에서 자기
   생성물을 선호하는 self-bias 를 갖고, 자기정제 파이프라인이 그걸 증폭시킨다. 비평가는
   **스크린샷만 받은 "처음 이 서비스를 켠 사용자"** 다.
2. **지적 개수 하한을 걸지 않는다.** 개수 하한은 실패한 프롬프트에 이미 들어 있었고 효과가 없었다.
   깨끗한 화면에 걸면 **오탐을 인위적으로 제조**한다. 대신 지적마다 **근거·severity·severity 의 근거·
   위치**를 강제한다.
3. **모델·에이전트 수를 늘리지 않는다.** 같은 과제에 모델을 추가 투입하면 **신규 유효 이슈 0건,
   오탐만 +43건**이 실측됐다. 병렬화는 **축 분할로만** 한다.
4. **매 라운드 수정자는 깨끗한 컨텍스트에서 시작한다.** 실패한 시도가 컨텍스트에 남으면 이후
   생성이 구조적으로 유사한 오류로 편향되고, **외부 피드백으로도 제거되지 않는다.**
5. **LLM 이 LLM 의 지적을 직관으로 재검증하지 않는다.** 그 방식은 유효한 지적을 되레 죽인다.
   중재자는 **측정치와 프로젝트 예외 목록**으로만 판정한다.
6. **하드 불변식을 통과하지 못한 수정은 점수와 무관하게 기각한다.** 요소를 지우면 모든 결정론적
   지표가 동시에 개선되므로, 불변식이 없으면 **빈 화면이 만점**이 된다.

## 0층 — 준비

**시작 전 URL과 소스 경로를 현재 작업 맥락에서 먼저 찾는다.** 발견할 수 없을 때만 요구한다.
URL은 캡처, 소스 경로는 스타일 감지·원인 역추적·롤백에 필요하다.

### 0-0. 사용자 신호와 의도 계약

사용자의 `"패딩이 이상해"`를 `padding을 바꿔라`로 번역하지 않는다. 원문을 그대로 보존하고 다음 네 필드를 화면·기존 코드·프로젝트 규칙에서 우선 채운다.

- `goal`: 사용자가 더 좋아졌다고 느낄 축
- `must_keep`: 자산·기능·문구·크기·브랜드·이미 승인된 구조
- `allowed_change_scope`: 표면 조정 / 컴포넌트 구조 / IA·콘텐츠 중 허용 범위
- `acceptance_signal`: 어떤 화면·뷰포트·행동에서 확인할지

명백하면 질문하지 않는다. 미감 방향이나 구조 변경 허용 여부가 결과를 뒤집는데 근거가 없을 때만 한 번 묻는다. 기본값은 **기능·콘텐츠·주요 자산·요소 footprint 보존**이다.

첫 캡처 뒤 각 증상을 `위치 / 관찰 / 가능 계층(surface·component·layout·IA·content·interaction) / confidence`로 적는다. 같은 증상이 두 화면 이상이거나 컨테이너·폭 체계·IA·콘텐츠 밀도에 걸치면 로컬 CSS 수정 전에 구조 문제로 승격한다. 제품·브랜드 판단은 biz-experts, 구현은 dev-experts가 보강하되 이 루프가 관찰과 회귀 확인을 계속 소유한다.

### 0-1. 스타일링 방식 감지

`package.json` 과 설정 파일로 판정한다. 스택을 하드코딩하지 않는다.

| 감지 | 수정 진입점 |
|---|---|
| `tailwindcss` | `tailwind.config.*` 의 스케일 + JSX 클래스 문자열 |
| `*.module.css` | CSS 모듈 파일 |
| `styled-components` / `@emotion` | 컴포넌트 내 템플릿 리터럴 |
| 순수 CSS/SCSS | 스타일시트 |

### 0-2. 스페이싱 스케일 추출

**CSS 사용자 정의 속성(`--*`)을 우선 읽는다.** 스타일시트 규칙에 남은 이름이
**저자가 붙인 의도가 남아 있는 유일한 경로**다. computed style 은 해결된 결과값이라 의도가 소실된다.

⚠️ **라이브러리 비의존이 이 단계의 핵심 요구다.** 10개 스택 실측에서 아래를 하나씩
놓칠 때마다 **정상 여백이 통째로 「스케일 이탈」로 지적됐다.** 전부 실측으로 확인된 함정이다:

1. **네임스페이스 접두** — 실무 라이브러리는 변수를 전부 접두한다(`--bs-card-spacer-x`,
   `--mantine-spacing-md`, `--pico-*`). 이름 매칭은 **접두 구간을 허용하되 키워드는 완전 일치**로
   본다. (부분일치로 풀면 `--font-size-sm:13px` 이 스페이싱으로 들어오는 옛 버그가 재발한다.)
2. **중첩 규칙** — `@layer`·`@media`·`@supports` 내부까지 **재귀로** 훑되,
   **지금 적용되는 조건만** 본다. Tailwind v4 는 전부를 `@layer` 안에 넣어 최상위만 보면
   변수가 하나도 안 보이고, Pico 는 브레이크포인트마다 같은 토큰을 다시 정의하므로
   조건을 안 보면 **지금 뷰포트가 아닌 값까지 스케일에 섞인다.**
3. **선행 0 생략** — minified CSS 는 `.25rem` 으로 쓴다. `0.25rem` 만 받으면 놓친다.
4. **★ rem 은 루트 폰트 크기 기준** — 16 으로 하드코딩하면 안 된다.
   Pico 는 뷰포트에 따라 루트를 100%→125% 로 키우므로 1440 에서 `1rem` 은 **20px** 이다.
5. **★ 스케일은 뷰포트마다 다시 뽑는다** — 4번 때문에 라운드당 1회 캐시가 성립하지 않는다.
   360 에서 뽑은 스케일을 1440 에 쓰면 전부 어긋난다.
6. **calc 파생 토큰** — 라이브러리는 토큰을 calc 로 만들고(`calc(var(--x) * 1.25)`),
   그 배수를 **토큰 정의가 아니라 사용처**에 두기도 한다. ①프로브 요소에 `width: var(--x)` 를
   넣어 실제 해석값을 재고 ②선언된 **(변수 × 배수) 쌍**을 모아 스케일을 확장한다.
   둘 다 **스케일 값을 지어내지 않고 읽어내는** 방식이다.
   ⚠️ 프로브는 `:root` 상속만 받으므로 컴포넌트 스코프 변수(Bootstrap 의 `.card{--bs-…}`)는
   못 읽는다. 규칙 직접 파싱을 **대체하지 말고 합집합**으로 쓴다.

세 가지 스케일 모드를 `summary.json`의 `scale.source`로 보고한다:

| source | 조건 | 판정 방식 |
|---|---|---|
| `css-vars` | 이름에 스페이싱 키워드가 든 변수 3개 이상 | 값 집합에 속하는가 |
| **`var-family`** | **이름 끝의 숫자만 다른 변수 가족**(`--s-1 … --s-9`) 3개 이상 | 같음 |
| `base-unit` | 기준 단위 변수 1개(`--spacing` 등) | 선언된 배수로 만든 값 집합 (없으면 정수배) |
| `frequency` | 위 셋 다 없음 | 빈도 군집화 폴백 |

**후보가 여럿이면 이름이 아니라 「이 화면의 여백을 얼마나 설명하는가」(coverage)로 고른다.**
⚠️ **하나만 고르면 안 된다.** 디자인 시스템은 스케일을 여러 벌 두는 게 정상이다 — 본 스페이싱
(4·8·12…)과 별도로 알약형·헤어라인용 **마이크로 스케일**(1·2·3·5·6px)을 두는 식이다.
하나만 고르면 나머지 벌의 정품 토큰이 전부 「이탈」로 지적된다(실측 8문서).
→ **커버리지에 실제로 기여하는 가족을 전부 합친다.** 기여가 0 인 가족(라디우스 등)은 자연히 빠진다.
`summary.json` 의 `scale.families` 가 어떤 가족들이 합쳐졌는지 보여준다.
7. **★ 약어 토큰 이름** — 수제 디자인시스템은 `--s-1 … --s-9` 처럼 줄여 쓴다. 키워드 매칭으로는
   절대 안 잡히므로 **숫자 접미 가족**을 구조로 탐지한다. 이름을 추측하지 않으므로 라디우스
   가족(`--r-1…`)도 후보로 올라오지만, 여백을 설명하지 못해 coverage 에서 자연히 진다.
   실측: 이 경로가 없어서 9단계 토큰을 갖춘 문서가 `frequency` 로 떨어졌고 지적 대부분이 오탐이었다.
8. **★ 스케일은 라우트마다도 다시 뽑는다** — 문서·화면마다 토큰 스케일이 다를 수 있다.
   실측: 첫 문서의 `--s-*` 가 나머지 3개에 적용돼 지적이 **60 → 103 건으로 부풀었다.**

폴백은 전체 요소의 padding/margin/gap 을 수집해 **반복되는 값 = 의도, 일회성 = 노이즈**로
분류한다. ⚠️ **표본으로 담는 속성과 판정에서 보는 속성이 같아야 한다** — 표본에 `marginTop` 만
넣고 판정에서 `marginBottom` 도 보면, `marginBottom` 으로만 쓰인 정품 토큰이 이탈로 지적된다.

폴백 스케일은 추정치이므로 스케일 이탈은 1b 중재를 거친다.

### 0-2.5. 측정 범위 — 기본은 첫 뷰포트, 긴 문서는 `fullPage`

기본값은 **첫 뷰포트만** 측정한다. 비평가가 보는 스크린샷과 범위를 맞추기 위해서다.

긴 문서는 `.ui-refine.json`의 `"fullPage": true`로 측정과 캡처를 함께 전체 페이지로 바꾼다.

측정 범위와 캡처 범위는 반드시 같이 움직인다.

전체 페이지의 반복 판정은 규칙 단위(`addGrouped`)로 집계한다.

**측정 경계 — 문서는 하나가 아니다.** 1b 는 최상위 document 뿐 아니라 **shadow root** 와
**같은 출처 iframe 문서**까지 들어간다(iframe 안 좌표는 부모 좌표계로 밀어 정렬·겹침 판정을
같은 평면에서 한다). 경계를 안 넘으면 웹컴포넌트·임베드 위젯 화면이 **지적 0건 = 깨끗함**으로
둔갑한다 — 실측: iframe 픽스처가 요소 6개로 잡혀 안에 심어 둔 미정의 변수·토큰 밖 값이 통째로
빠졌다(경계를 넘은 뒤 12개, 두 결함 모두 검출).

⚠️ **교차 출처 iframe 은 원리적으로 읽을 수 없다.** 이건 고칠 수 있는 구멍이 아니라 사각지대라,
`summary.json` 의 `blindSpots` 와 stderr 경고로 남는다. **그 경고가 있으면 사용자에게 그대로
전달한다** — "그 영역은 감사하지 못했다"이지 "문제가 없다"가 아니다.

### 0-3. 캡처 세트 확정 — 곱셈을 경계한다

세트 크기는 축의 곱으로 폭발하므로 한 호출에 많은 이미지를 붙이지 않는다.

**기본값 (사용자가 명시적으로 넓히기 전까지 이걸 쓴다):**

| 항목 | 기본값 | 이유 |
|---|---|---|
| 라우트 | **사용자가 지목한 화면 1개 + 직접 연결된 화면 최대 2개** | 전 라우트 스윕은 명시 요청 시에만 |
| 뷰포트 | **360×800 / 1440×900 + 위험 경계 최소 세트** | breakpoint·짧은 높이·fixed/sticky·`vh/dvh`가 있으면 경계 전후나 360×640/375×667 중 필요한 것만 추가 |
| 테마 | **라이트만 비평가에 첨부.** 다크는 1b 대비 측정만 | 다크 관련 항목(4-5·4-10)이 전부 ◆라 첨부 불필요 |
| 미디어 | 기본 `screen`·light. **다크·인쇄는 `.ui-refine.json` 으로 명시할 때만** | 아래 ⚠️ 참조 |
| 상태 | **정상 + 긴 한글 텍스트** | 빈·로딩·에러는 재현 수단 확보 시에만 추가 |
| 비평가 첨부 | **호출당 4장 이하** | 나머지 조합은 1b 결정론 측정만 |

기본값이면 세트 = 1 × 2 × 1 × 2 = 4장이다. 추가 뷰포트는 전 곱집합이 아니라 위험 신호가 있는 상태에만 붙인다.

다크·인쇄는 해당 조건으로 렌더해야만 감사된다. 지원 프로젝트라면 `"colorSchemes": ["light","dark"]` 또는 `"media": "print"`를 주고, 켜지 않은 모드는 "문제 없음"이 아니라 "미감사"로 보고한다.

**긴 한글 텍스트는 필수다** — `word-break: keep-all` 부작용은 lorem ipsum으로 재현되지 않는다.
상태를 만드는 수단(`page.route` 인터셉트 / 픽스처 / MSW)을 확보하지 못하면 그 상태를 세트에서
빼고 **사용자에게 뺐다고 보고한다.** 조용히 건너뛰지 않는다.

**로그인**이 필요하면 자격증명이나 픽스처 경로를 요구한다.

### 0-4. 캡처 규약 고정

`animations: "disabled"`, `caret: "hide"`, `scale: "css"`, headless 고정,
`--force-device-scale-factor=1`. 폰트 로드 완료 + network idle 후 촬영.
**수정 후 재캡처 전에는 HMR 리빌드 완료를 기다린다** — 안 그러면 옛 화면을 보고 "안 고쳐졌다"고 오판한다.

**목적이 다른 캡처를 섞지 않는다.**

- `regression`: 애니메이션·캐럿·변동 요소를 통제한 원본. 계측·회귀 비교용.
- `experience`: 실제 스크롤바·포커스·hover/open/error 등 사용 단서를 보존. 비평용.
- `badged`: 안정화된 regression 상태에 번호를 입힌 위치 연결용. affordance 판단은 번호 없는 experience와 짝지어 본다.

전역 CSS 주입은 레이아웃을 바꿀 수 있다. 캡처용 스타일은 변동 요소를 숨기는 좁은 selector만 쓰고, `injectCss`로 스크롤 셸을 푸는 진단 패스는 원래 레이아웃 패스와 분리한다. 주입 패스의 sticky·fixed·정렬 판정은 채택 근거로 쓰지 않는다.

**아티팩트 제거** (3층이 이 항목을 참조한다 — 여기가 비면 중재자가 판단으로 떠안는다):
스크롤바는 캡처용 CSS 로 숨기고, HMR·devtools·프레임워크 배지는 셀렉터로 가리고,
토스트·모달 잔상은 애니메이션 종료 대기로 없애고, 스켈레톤은 콘텐츠 렌더 완료 대기로 넘긴다.
포커스 링은 캡처 전 `document.activeElement.blur()`. 제거하지 못한 것은
**비평가 프롬프트의 "지적하지 않을 것" 목록이 2차 방어선**이다.

### 0-5. 캡처 진실성·자기 잡음 캘리브레이션

**같은 화면을 아무것도 바꾸지 않고 두 번 찍어 diff 를 측정하고, 그 위로 픽셀 임계를 잡는다.
화면별로 따로.** 벤더가 제시하는 임계값 표준은 존재하지 않으므로 전역 단일값을 찾지 않는다.

`fullPage` 결과 높이가 뷰포트와 같고 내부 scroll container가 있으면 전체 캡처로 간주하지 않는다. 지연 이미지 decode, 프레임워크 portal/HMR artifact, 현재 환경(`local/preview/live`, URL, viewport)을 summary에 남긴다. 캡처용 CSS 전후 geometry가 달라지면 그 패스는 `diagnostic-only`다.

### 1b 측정 규칙

단일 `page.evaluate` 안에서 **DOM 변경 없이 전량 수집**한다. `getBoundingClientRect` 는 동기 레이아웃
플러시를 강제하므로 DOM 변경과 번갈아 호출하면 레이아웃 스래싱이 난다. 배치 수집이면 수천 건도 싸다.

**정의를 확정하지 않으면 판정 함수를 쓸 수 없다.** 아래를 그대로 쓴다.

| 항목 | 판정 | 배제 |
|---|---|---|
| 오버플로 | 상자를 넘치면서 **①자기가 잘라내거나 ②조상이 잘라내거나 ③화면 밖으로 나갈 때**만 결함. `overflow:visible` 로 상자 밖에 그려질 뿐이면 글자는 안 잘린다 | `overflow` 가 `auto`·`scroll`, `intentionalHScroll` 예외. 세로는 `overflow-y:hidden` 일 때만 |
| **미정의 CSS 변수** | `gap`·`padding`·`margin` 이 **선언되지 않은 `var()`** 를 참조 — 속성이 통째로 무효가 돼 **0 으로 무너지고 글자가 붙는다** | 폴백이 있는 참조(`var(--x, 8px)`), 스페이싱 외 속성(`text-align:var(--x)` 처럼 "미설정=기본값"은 널리 쓰이는 관용구다) |
| 겹침 | 두 rect 의 교집합 면적 > 0 | 부모-자식·조상-후손 관계, `position` 이 `fixed`·`sticky`·`absolute` 인 쪽, `z-index` 가 명시된 쪽, `pointer-events:none`, **인라인 요소**(여러 줄로 접히면 rect 가 줄을 합친 상자라 나란한 것끼리 겹쳐 보인다), **SVG 내부**(Mermaid 는 rect 위에 g 를 겹쳐 그리는 게 정상) |
| 정렬 편차 | **같은 부모의 형제**를 **마진 박스** 기준으로 비교. 세로 스택은 `left`, 가로 배치는 **줄로 나눈 뒤** 줄 안에서 `top`. 차이가 **1px 초과**면 위반 | `display:none`·`visibility:hidden`, 인라인 요소, `position:absolute`·`fixed`. **중앙정렬 컨테이너**(auto 마진·좌우 대칭). **교차축 정렬이 start 계열이 아닌 경우 전부**(center·baseline·end·stretch 는 높이가 다르면 좌표가 달라야 정상). **자식마다 `align-self` 가 다른 경우** |
| **위계 역전** | **그룹 내 최대 간격 ≥ 그룹 간 최소 간격** | 사이에 구분선·배경색 변화가 있으면 제외 |
| **죽은 세로 띠** | 같은 부모 아래 **폭·좌측이 일치하는 블록 자식 2개 이상**이 부모 콘텐츠 폭보다 좁아 한쪽에만 큰 여백이 남음 (띠 ≥ 콘텐츠 폭의 1/4, 반대쪽의 2배 이상) | 좌우 대칭(중앙정렬), 자식 1개, absolute·fixed |
| **무너진 요소** | 테두리·배경이 있거나 내용이 든 상자가 **한 변만** 8px 미만 — 데이터 미도착·flex 계산 실수로 접힌 것. **가장 바깥만** 보고한다 | 두 변이 다 작은 장식·구분선 |
| 스케일 이탈 | `padding`·`margin`·`gap` 의 0 아닌 px 값이 0-2 스케일 밖. **값 단위로 묶는다** — 하나의 결정(6px)이 prop 별로 쪼개지면 사전식 비교에서 과대대표된다 | `auto`·`%`·`0`, 소수 px, 예외 셀렉터 |
| 행 높이 편차 | **줄 수가 같은 행끼리만** 비교. 줄 수가 다르면 높이가 다른 게 정상이다(한글 표는 행마다 줄 수가 다르다) | 1px 이하 차이 |
| CLS | `PerformanceObserver` entryType `'layout-shift'`, `hadRecentInput` 제외 | — |

**그룹 정의**: 같은 부모 아래 연속한 형제들 중 **간격이 같은 것끼리 한 묶음**.
간격이 바뀌는 지점이 그룹 경계다. 이 정의는 스케일 추출(0-2)에 의존하지 않는다 —
상대 비교만 하므로 순환하지 않는다.

**위 7종 외에 `collect.js` 가 재는 것 18종 더** — 반복 요소 패딩 불일치 · 이중 들여쓰기 ·
행/열 간격 비대칭 · 상하 패딩 비대칭 · 컨트롤 패딩 비율 · 폰트 굵기 종류 · 링크 어포던스 ·
focus 스타일 부재 · 셀 패딩 · 행 높이 편차 · 표 헤더 sticky · 소수 자릿수 혼재 ·
숫자 정렬 혼재 · 등폭 숫자 · 빈 셀 · 입력 폭 균일 · placeholder 라벨 대용 · 필수 표시 혼재.
전체 목록과 체크리스트 항목 대응은 `references/checklists.md` 상단 표.

⚠️ **판정 종류를 늘릴 때는 `collect.js` · `capture.mjs` 집계 · `score.mjs` 의 `ORDER`
세 곳을 함께 고친다.** 한 곳만 고치면 새 지표가 점수에 안 들어가 조용히 무시된다.
(`dedup.mjs` 의 `itemKindMap()` 도 함께 — 3층 매칭이 그 표를 쓴다.)

### 판정을 고칠 때의 원칙 — 배제 규칙을 덧붙이지 않는다

오탐이 나오면 **그 화면을 보고 배제 규칙을 거꾸로 넣고 싶어진다. 그게 과적합이다.**
10개 스택 실측에서 오탐 건수의 대부분이 **소수의 근본 원인**으로 모였고, 개별 배제가 아니라
원인을 고쳐야 사라졌다. 오탐을 만나면 순서는 이렇다:

1. **건수를 세지 말고 원인으로 귀속시킨다.** (정렬 오탐 73건 → 원인 4종에 93% 가 모였다)
2. 원인이 「엔진·라이브러리가 보장하는 것을 우리가 다시 재고 있다」면 **재지 않는다.**
3. 임계값을 지어내지 말고 **선언된 것을 읽어낸다**(CSS 에 적힌 배수·토큰·정렬값).
4. 그래도 남으면 그때 예외 목록(`.ui-refine.json`)으로 — **코드가 아니라 프로젝트 설정으로.**

**같은 판정을 여러 요소가 공유하면 규칙 단위로 집계한다.** CSS 규칙 1개가 600행 표에서
36건으로 세면 그 한 규칙이 사전식 비교 전체를 지배해 다른 축이 의미를 잃는다.

⚠️ `layout-shift` 는 **Chromium 전용**이다. WebKit/Firefox 에서 0건이 나오는 것을 "shift 없음"으로
읽으면 안 된다.

⚠️ **대비 검사의 배경색이 판정 불가일 때(반투명·그라디언트·이미지 위 텍스트·겹친 레이어)는
`incomplete` 로 돌린다.** 이건 자동 대비 검사 오탐 1위 경로다. 색을 덮어쓰지 않는다.

### 스냅은 조건부다

스케일 이탈을 고칠 때 **인접 스케일 값이 이웃 간격과 같아지면 스냅을 금지**한다.
12px 과 14px 이 둘 다 12 로 붕괴하면 그룹 경계가 사라져 **위계 역전을 스스로 만들어낸다.**
**위계 지표가 스냅보다 상위다.**

### ★ 요소 번호 오버레이 — 없으면 스킬이 아무것도 못 고친다

3층은 "1b 가 같은 지점을 측정했는가"로 판정하는데, 비평가는 자연어로 위치를 쓰고 1b 는 DOM
셀렉터를 낸다. **잇는 수단이 없으면 모든 finding 이 보류함으로 떨어져 4층에 입력이 없다.**
반대로 비평가에게 셀렉터를 주면 절대 규칙 1 에 걸린다.

**해소**: 캡처 시 요소마다 번호 배지를 굽고, 비평가가 `#12` 로 지목한다.
번호는 코드도 저작 의도도 아니라 규칙 1 을 어기지 않는다. 하네스가
`번호 → 셀렉터 + rect + computed style` 매핑을 보관하므로 3층·4층이 즉시 조회한다.
상세 규약은 `references/checklists.md` 의 "요소 번호 오버레이 규약".

### `references/checklists.md` 를 반드시 로드한다

**이 스킬의 실질은 그 문서다.** 축별 관찰 패턴 목록과 **비평가 프롬프트 실제 텍스트**가 거기 있다.

- 프롬프트를 **매번 새로 작문하지 않는다.** 그대로 쓰고 `{...}` 만 치환한다.
  프롬프트가 흔들리면 라운드마다 결과가 달라져 채택 판정(5층)이 무의미해진다.
- 체크리스트는 **"판단해라"가 아니라 "이 패턴이 있는지 봐라"** 로 쓰여 있다. 이 형태를 유지한다 —
  판단을 요구하면 취향 지적이 나오고, 그건 논문이 실패한 프롬프트와 같은 종류다.
- 각 항목의 **◆/○ 표기가 자동수정 가능 여부**다. ◆ 는 1b 가 측정하므로 중재자가 검증 가능,
  ○ 는 대부분 보류함행.

### 화면 간 일관성

여러 화면을 한 에이전트에 **등장 순서를 명시해서** 함께 준다. LLM 은 스크린샷을 독립 아티팩트로
보기 때문에 화면 간 위반을 43~50% 밖에 못 잡고, 이 축은 **유일하게 사람에게 지는 축**이다.
→ **결과는 전부 보류함으로.** 자동수정하지 않는다.

### finding 봉투와 severity 0

지적 **내용**은 자유 텍스트다(디자인마다 다르므로 분류 체계를 만들지 않는다).
필드는 `screen` · `seen_in` · `axis` · `target`(요소 번호) · `item` · `severity` · `intent_flag`.

**지문 = `screen + target + item`**
⚠️ **`axis` 를 지문에서 뺐다.** 축이 다르면 지문이 달라져 **축 간 중복이 dedup 을 통과**한다.
`item` 을 넣은 것은 같은 요소에 대한 다른 종류의 지적을 구분하기 위해서다.

severity 0은 폐기하되, 실측상 거의 발화하지 않으므로 오탐 방어선으로 간주하지 않는다.

축이 달라도 타깃 집합이 완전히 같으면 `dedup.mjs filter`가 중복으로 묶고 `also_reported_by`를 붙인다. 부분 겹침은 정상일 수 있어 버리지 않는다.

## 3층 — 중재자

중재자는 **맥락을 가진 채로** 판정하되, **LLM 직관으로 재검증하지 않는다**(절대 규칙 5).
판정 근거는 둘뿐이다:

1. **측정치** — 1b 가 같은 지점을 실제로 측정했는가
2. **프로젝트 예외 허용 목록** — `.ui-refine.json` 에 선언된 의도적 예외

### 매칭은 `scripts/dedup.mjs match` 가 한다

⚠️ **1b 가 재는 요소와 비평가가 가리키는 요소는 층이 다르다.** 가로 넘침을 1b 는 넘치는
**컨테이너**에 붙이는데 비평가는 **잘려 보이는 셀**을 가리킨다(실측). 그래서 매칭은 지목한 번호의
**조상 사슬**까지 본다(자손 방향은 보지 않는다 — 컨테이너 지목이 자식 전체를 근거로 삼으면 헐거워진다).

`no-measure-for-item`은 실패가 아니라 정직한 답이다. 측정 수단이 없는 항목은 매핑을 꾸며내지 않고 보류함으로 보낸다.

```
node scripts/dedup.mjs match findings.json --measure .ui-refine/r0/measure/<id>.json
```

⚠️ **번호가 하나라도 겹치면 매칭으로 치면 안 된다.** 실측에서 "제목↔카드 간격"(1-3) 지적이
무관한 `pad-asym`(카드 내부 상하 여백)에 붙었다 — 여러 번호를 나열한 finding 은 우연히 겹친
측정치와도 매칭된다. **번호 교집합 + 항목↔판정 종류 대응**을 둘 다 봐야 한다.
대응표는 `dedup.mjs` 의 `itemKindMap()`. **`collect.js` 에 판정을 추가하면 이 표도 함께 갱신한다.**

판정 결과 3종: `supported`(→4층) · `unsupported`(→보류함) · `no-measure-for-item`(→보류함).

### 예외 허용 목록 형식

```json
{
  "intentionalDensity": ["/portfolio", "/orders"],
  "semanticColors": { "up": "#d32f2f", "down": "#1976d2" },
  "ignoreSelectors": [".sr-only", "[data-testid]"],
  "spacingScale": [4, 8, 12, 16, 24, 32, 48]
}
```

파일이 없으면 만들라고 제안하되, 없어도 진행한다(그 경우 도메인 관례 지적은 전부 보류함행).

### 캡처 아티팩트는 판단이 아니라 규약으로 제거한다

원 연구의 오탐 1위는 "OS 상태바를 앱 UI 로 오인"이었으나 그건 iOS 스크린샷 사정이고
**Playwright 뷰포트 캡처에는 브라우저 크롬이 안 들어온다.** 우리 쪽 등가물은 다음이며,
중재자가 판단할 게 아니라 **0-4 캡처 규약에서 미리 제거**한다:
스크롤바 · HMR/devtools 배지 · 토스트/모달 잔상 · 스켈레톤 로딩 잔여 · 포커스 링.

### 판정 결과

| 판정 | 처리 |
|---|---|
| 측정치가 뒷받침함 | 4층으로 |
| 예외 목록에 해당 | 폐기 (근거 기록) |
| 측정 불가 + 예외 아님 | **보류함** — 사람이 본다 |

### 3.5층 — 증상에서 원인으로

중재를 통과한 관찰도 곧바로 CSS 처방으로 바꾸지 않는다. 사용자 원문과 관찰마다 경쟁 가설 2~4개를 세우고 DOM·computed style·geometry·interaction으로 하나씩 반증한다.

예: `패딩이 두꺼워 보임 → padding / 고정 width·height / aspect-ratio / grid stretch / 글리프 자체 여백`. 살아남은 원인과 반증 증거만 수정자에게 준다. `padding`처럼 사용자 발화에 나온 속성을 먼저 고르는 것은 금지한다.

- 로컬 속성 하나로 끝나고 footprint·다른 화면이 유지되면 surface 수정
- 같은 증상이 여러 화면, 토큰, 컨테이너, breakpoint에서 반복되면 구조 수정 후보
- IA·콘텐츠 역할·브랜드 판단이 필요하면 자동 수정하지 않고 biz-experts의 해당 렌즈로 넘김
- 스크롤·뒤집기·오버레이처럼 발견 가능성이 핵심이면 정적 샷 대신 1~3단계 task-path probe를 수행하고 전·중·후 상태를 기록

## 4층 — 수정자

**깨끗한 컨텍스트**에서 시작한다. 현재 스크린샷 + 지원된 finding + 원인 진단 + 의도 계약만 준다.
이전 라운드의 기각 이력·실패한 수정은 주지 않는다(절대 규칙 4).

### 토큰이냐 로컬이냐는 자동 판정된다

CDP `CSS.getMatchedStylesForNode` 로 해당 속성을 **최종 결정한 규칙**을 역추적한다.

| 값의 출처 | 수정 대상 |
|---|---|
| `var(--space-3)` 등 **CSS 변수 경유** | **토큰 파일** |
| 유틸리티 클래스(`p-3`) | 클래스명을 소스에서 grep → **해당 화면** |
| 인라인 스타일 / 일회성 리터럴 | **해당 화면** |

⚠️ **토큰을 수정하면 폭발 반경이 전역**이다. 그 라운드의 점수는 반드시 캡처 세트 전체에서 잰다.

⚠️ CDP 세부 시그니처와 React fiber `_debugSource` 가용 여부는 **확인 필요** — 버전별로 갈린다.
역추적이 실패하면 값 grep 으로 폴백하고, 그마저 애매하면 **보류함행**(추측으로 고치지 않는다).

## 5층 — 채택 판정

### 5-1. 하드 불변식 (점수보다 먼저)

하나라도 위반하면 **점수와 무관하게 기각**한다. 이게 없으면 빈 화면이 만점이 된다.

- DOM 노드 수 감소 금지
- 텍스트 콘텐츠 해시 불변
- 캡처 세트·라우트·상태·뷰포트 동일
- summary 스키마와 필수 필드 완전성

픽셀 diff와 Feature Congestion은 현재 번들이 생성하지 않으므로 하드 불변식이라고 부르지 않는다. 구현·검증되기 전까지 화면 교체 방지는 `allowed_change_scope`, DOM·텍스트 보존, 총 판정 건수 비증가, fresh 시각 비교로 맡는다. 없는 지표를 조용히 건너뛰지 않는다.

### 5-2. 점수는 사전식 우선순위로 비교한다

가중치를 지어낼 근거가 없고, 항들의 단위가 통약 불가하다(건수 vs px 총량 vs 무차원 CLS).
**앞 항이 같을 때만 다음 항을 본다:**

```
`scripts/score.mjs`의 `ORDER`가 단일 원본이다. 문서에 축약 목록을 복제하지 않는다.
```

**카운트 정의** — 없으면 비교 함수를 쓸 수 없다:
- 앞의 다섯은 전부 **건수**(px 총량 아님). 정렬 편차도 "1px 초과인 형제 쌍의 수".
- **집계 축은 캡처 세트 전체 합.** 화면별 벡터로 두면 A 가 좋아지고 B 가 나빠질 때
  비교가 성립하지 않는다. 토큰 수정이 전역에 퍼지므로 세트 합이어야 한다.
- CLS 는 **세트 내 최댓값**(합은 화면 수에 비례해 의미가 없다).
- **대비·타겟 미달은 순위에 넣지 않는다** — 1a 라 매 라운드 자동수정돼 항상 0 인 죽은 항이다.

### 5-3. 채택 규칙

| 1층 점수 | 처리 |
|---|---|
| 나빠짐 | **기각 + 롤백** |
| 같음 | **해소된 LLM finding 수(중재자 통과분)로 타이브레이크** → 늘었으면 채택 |
| 좋아짐 | 채택 |

시각 위계 수정은 1층 점수가 동점일 수 있으므로 해소 finding은 동점 판정에만 쓰고 순위를 뒤집지 못하게 한다.

시각 위계·균형·밀도처럼 결정론 점수가 동점인 미감 수정은 원본/수정본의 동일 crop을 A/B로 섞어 fresh evaluator에게 한 축만 묻는다. 수정본·코드·이전 점수는 숨긴다. 차이가 근소하거나 ease-of-use·편안함처럼 모델 신뢰가 낮은 축은 자동 채택하지 않고 보류함으로 보낸다.

### 5-4. 롤백은 라운드 단위

수정 하나씩 롤백하면 편집마다 재렌더·재측정이라 캡처가 N배로 든다. 라운드 단위로 되돌린다.
git 리포면 stash/worktree, 아니면 0층에서 뜬 스냅샷으로 복원한다.

### 5-5. dedup 과 라이브락 방지 — 전부 하네스가 코드로

기각 이력을 에이전트에게 보여주지 않고 하네스가 지문으로 재생성을 막는다:

1. **finding 지문** — 중복 지적 폐기. LLM 은 같은 문제를 화면마다 재보고한다(사람은 0건).
2. **편집 지문** — 기각된 diff 를 차단 목록에 넣어 동일 편집 자동 폐기.
3. **재샘플은 라운드 내부에서** 돌린다. 라운드를 넘기지 않는다.

### 5-6. 종료

- **라운드 상한 3.** 이 값은 검증된 수치가 아니라 **[미검증] 기본값**이다
  (근거가 된 연구는 RL 학습 시 규칙이고, 그 연구의 추론 구성은 critic 을 떼어낸 형태다).
- **조기 종료: 한 라운드에서 채택이 0 이면 즉시 종료.**
  ⚠️ 이전 판의 "3라운드 연속 채택 0"은 상한과 같아 **절대 발화하지 않는 죽은 조건**이었다.
- 보조 조건: dedup 통과 신규 finding 0.
  ⚠️ 이 카운터는 "비평가가 만족했다"를 뜻하지 않는다 — 비평가는 계속 지적하고 하네스가 버린다.
- **라운드 내부 재샘플 상한 3회.** 상한이 없으면 라이브락에서 종료가 보장되지 않는다.

### 5-7. 산출물

1. **최고 점수본을 유지**한다(마지막 라운드본이 아니다).
2. **보류함 리포트** — 사람이 판단해야 하는 것들. 축·severity 순으로 정렬하고 각 항목에
   crop·요소 번호·사용자 원문과의 연결·근거·왜 자동수정하지 않았는지를 붙인다.
3. 라운드별 점수 추이 한 줄 요약.
4. 검증 환경(`local/preview/live`)과 보지 못한 라우트·상태·뷰포트·blind spot. 로컬만 봤으면 라이브에서 확인됐다고 말하지 않는다.
