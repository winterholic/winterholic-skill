# UI 개선 루프

## 이 스킬이 존재하는 이유

사용자가 공급하던 핵심은 해법이 아니라 **문제 존재의 단언과 화면·영역 수준의 위치**였다. 이 스킬은 그 신호를 대신 만들고, 관찰을 원인으로 성급히 바꾸지 않게 한다.

모든 설계 결정의 근거·수치·반례는 `references/research.md` 에 있다. **판정 임계값이나 규칙을
지어내지 말고 그 문서를 열어 확인한다.**

## 이 스킬이 실패한 방식 (설계 근거 요약)

세 가지가 지금 설계를 만들었다. 전문·인용은 **`references/failure-log.md`**.

1. **호출 0회** — UI 세션 94건 동안 한 번도 안 불렸다. 도구가 없어서가 아니라 **진입 비용**이 요청
   크기와 안 맞아서다. → **T0 단발**을 기본으로.
2. **실제로 돌린 두 번 다 오너 반려** — 점수는 `accept` 였는데 오너는 화면을 통째로 물렸다.
   **반려하는 축이 점수 안에 없었다.** → `narrow-column` 신설 + verdict 강등 게이트.
3. **넓은 지시에서 눈으로 훑고 "괜찮아 보인다"로 닫았다** — 11개 화면 전수 감사에서 품질 축 0건.
   → **TS 스윕 + 실행 영수증.**

**한 줄로: 이 스킬의 산출물은 "고쳤다"가 아니라 「무엇을 어디까지 보고 무엇을 못 봤는가」다.**

## 티어 — 어디까지 켤지 먼저 고른다

**기본은 T0 다.** 사용자가 루프를 요구하지 않았는데 T2 를 켜지 않는다.

| 티어 | 언제 | 무엇을 한다 | 비용 | 산출 |
|---|---|---|---|---|
| **T0 단발** | **기본값.** 한 화면·한 요소의 불만, "이거 이상해", 고친 뒤 확인 | `quick.mjs` 1회. 라운드·비평가 없음 | 30초, 파일 0개 | 커버리지 + 판정 목록 + 구조 신호 |
| **TS 스윕** | **넓은 지시**("방금 작업한 거 전반적으로 점검해줘", "알아서 다 봐줘") | `sweep.mjs` — 대상 전수 열거 + 화면마다 계측 + 커버리지 표 | 화면당 수 초 | 표 + 미감사 축 목록 |
| **T1 한 바퀴** | 스윕에서 나온 판정이 여러 화면·토큰·breakpoint 에 걸칠 때 | 캡처 세트 + 1층 + 비평가 1~2축 + 수정 1라운드 | 수 분 | 위 + 보류함 + 점수 1회 비교 |
| **T2 루프** | 사용자가 **명시적으로** 반복 개선을 요구할 때만 | 아래 5층 파이프라인 전체, 최대 3라운드 | 수십 분 | 위 + 라운드별 점수 추이 |

```bash
# T0 — 이게 이 스킬의 기본 진입점이다
node scripts/quick.mjs --url http://localhost:3000/orders
node scripts/quick.mjs --url http://localhost:3000/orders --viewport 360x800
node scripts/quick.mjs --url ... --full          # 첫 화면 아래까지 잰다

# TS — 넓은 지시는 이걸로 받는다. 대상을 안 주면 일부러 실패한다
node scripts/sweep.mjs --url http://localhost:3000 --routes /,/orders,/orders/1
```

playwright 는 이 스킬의 의존성이 아니라 **대상 프로젝트에서 빌려 쓴다.** 프로젝트 루트에서
실행하거나 `PLAYWRIGHT_PATH=<프로젝트>/node_modules/playwright` 를 준다. 없으면 스크립트가
`확인 못함:` 을 찍고 exit 3 으로 끝난다 — **침묵하지 않는다.**

**승격 조건은 관찰이지 취향이 아니다.** T0 결과가 아래 중 하나면 T1 로 올린다 — 같은 판정이
두 화면 이상 / 토큰·컨테이너·breakpoint 에 걸침 / 커버리지가 낮아 T0 로는 답을 못 냄.
**T0 에서 끝나는 게 정상이고 흔한 경우다.**

## 넓은 지시를 받았을 때 (TS 스윕)

**"방금 작업한 거 전반적으로 UI/UX 점검해줘"가 이 스킬이 가장 크게 실패하는 지점이다.**
좁은 지적("이 카드 헐거워")은 잘 되는데 넓은 지시가 안 되는 **비대칭 자체가 단서**였다.

실패 장면(2026-07-04, memoir): 넓은 위임을 받아 11개 화면을 전수 스크린샷까지 찍고
**발견 2건**, 그것도 둘 다 기능·구조 결함이고 **패딩·글씨·공간활용 같은 품질 축은 0건**.
결론은 *"대부분 이미 잘 잡혀 있어 추가 손 안 댐"* 이었다. 그런데 그 뒤로도 오너 지적은 계속됐다 —
**그 "깨끗하다"가 틀렸다.**

원인 넷, 그리고 각각의 대응:

| 왜 무너지나 | 대응 |
|---|---|
| **판정 기준이 사라진다.** 구체적 지적이 오면 그 발화가 곧 기준인데, 넓은 지시에서는 기준을 스스로 세워야 한다. 안 세우고 "눈으로 보니 괜찮다"로 닫는다 | 눈이 아니라 `sweep.mjs` 계측으로 판정한다. **"문제 없음"은 계측 근거가 있을 때만 쓴다** |
| **0건이 안전한 답으로 보상된다.** 넓은 지시에서 "문제 없음"은 리스크가 없다 | **0건은 결론이 아니라 신호다.** 넓은 지시에서 전 화면 0건이면 대개 화면이 깨끗한 게 아니라 **측정 축이 모자란 것**이다 |
| **대상 집합을 못 박지 않는다.** 감으로 몇 개만 보고 무엇을 뺐는지 안 남는다 | `sweep.mjs` 는 `--routes` 가 없으면 **일부러 실패한다.** 대상을 먼저 열거해 사용자에게 보이고, 뺀 것은 이유와 함께 보고한다 |
| **§0-3 기본값이 범위를 되레 좁힌다**("지목한 화면 1개 + 연결 2개") | 아래 지시 폭 분기를 따른다 |

**지시 폭에 따른 대상 기본값**

| 지시 | 라우트 기본값 |
|---|---|
| 좁은 지적("이 화면 여기가") | 지목한 화면 1개 + 직접 연결 최대 2개 (§0-3 그대로) |
| **넓은 지시("전반적으로", "방금 작업한 거", "알아서")** | **이번 작업이 닿은 화면 전부 + 그 화면에서 한 번에 갈 수 있는 화면.** 목록을 먼저 보이고 시작한다 |

**보고에 반드시 들어가는 것**: 대상 목록(뺀 것과 이유 포함) · 화면별 판정 수 · 화면별 커버리지 ·
**계측이 못 보는 축**(발견가능성·카피·브랜드·상호작용·미포함 모드). 마지막 항목이 빠지면
그 보고는 "지적 없음"과 "감사 못함"을 섞은 것이다.

### ★ 실행 영수증 — 「쟀다」를 말이 아니라 산출물로 증명한다

`quick.mjs`·`sweep.mjs` 는 끝에 **실행 영수증**을 찍는다(도구·시각·실측 목록·커버리지·못 본 축·지문).
**그 블록을 보고에 그대로 옮긴다.**

- 외부 평가(2026-09-07)가 이 스킬의 가장 깊은 구멍을 짚었다 — *"「대상을 안 정하고 넘어가는」 우회는
  코드로 막혔지만, 「정한 대상에 대해 실제로 계측했다」는 정직성은 여전히 자율에 의존한다."*
  영수증은 그 자율을 산출물로 바꾼다. **안 돌리고 쓴 보고서는 영수증을 만들 수 없다.**
- 지문은 **측정 결과**에서 나온다 — 대상만 같고 결과가 다르면 지문도 달라진다(`sweep.mjs --self-test` 가 확인).
- 영수증은 **못 본 축을 항상 싣는다.** 그래서 영수증을 인용하면 위 「반드시 들어가는 것」의 마지막
  항목이 자동으로 따라온다.
- ⚠️ 위조 방지 장치가 아니다. 막는 것은 **「돌린 셈 치고 넘어가기」** 라는 훨씬 흔한 실패다.
- **영수증이 없는 보고는 계측하지 않은 것으로 간주한다.** 못 돌렸으면 `미실행: <사유>` 를 한 줄 남긴다.

## 규율 게이트 — 손대기 전에 여는 문서

이 루프는 **관찰과 검증**을 소유하고, **기존 화면을 고칠 때의 규율**은 소유하지 않는다.
규율 정본은 `~\.claude\biz-experts-skills\existing-screen-edit.md`(규율 12종)다.
여기에 복제하지 않는다 — 두 벌이 되면 반드시 어긋난다.

| 이 루프가 지금 하려는 것 | 먼저 읽을 규율 |
|---|---|
| 사용자 불만을 계약으로 옮길 때 | 1 범위 · 2 요구 크기 · 7 승인 경계 |
| 레이아웃 구조를 바꾸려 할 때 (`narrow-column` 포함) | **7 승인 경계**(성역·시안 선확인) · 9 기존 결 |
| 원인을 지목할 때 | 8 진단 순서(배치→상자→크기) · 4 원인 단일 확정 금지 |
| 세로 공간이 모자랄 때 | 3 공간 예산 |
| "고쳤다"를 말하기 직전 | 5 계측으로 닫기 · 11 계측이 거짓말하는 법 · 12 완료 기준 |
| 한 곳을 고친 뒤 | 10 전파 점검 |

**규율 7 이 이 스킬에 특히 중요한 이유**: 이 루프는 자동으로 고칠 수 있어서 승인 경계를 넘기 쉽다.
스타일 조정은 자율이고, **요소 신설·레이아웃 구조 변경·이미 만족을 표명한 영역은 승인 사항**이다.

## 번들 (직접 짜지 말고 이걸 쓴다)

측정 구현이 라운드마다 달라지면 5층 점수 비교가 무의미해진다 — 프롬프트가 흔들리는 것과 같은 실패다.

| 파일 | 역할 |

| `scripts/sweep.mjs` | **TS 스윕.** 넓은 지시를 커버리지 표로 닫는다. 대상 미확정이면 실패한다 |
| `scripts/capture.mjs` | 캡처 드라이버. 원본/배지본 두 벌 + 1b 측정 + CLS + 스케일 추출 → `summary.json` |

| `references/loop-pipeline.md` | 2~5층 전문 (T2 에서만) |
| `references/failure-log.md` | 설계 근거 전문 — 왜 이 모양인지 따질 때 |
| `references/scale-extraction.md` | 스페이싱 스케일 추출 함정 8종 (`frequency` 폴백·이탈 무더기일 때만) |

node scripts/dedup.mjs filter f.json --seen .ui-refine/seen.json
node scripts/score.mjs --prev .ui-refine/r0 --next .ui-refine/r1 --resolved 3

## 절대 규칙 (어기면 스킬이 역효과를 낸다)

1. **비평가에게 코드·diff·설계 의도·저작 사실을 주지 않는다.** LLM 은 6개 모델 전부에서 자기
   생성물을 선호하는 self-bias 를 갖고, 자기정제 파이프라인이 그걸 증폭시킨다. 비평가는
   **스크린샷만 받은 "처음 이 서비스를 켠 사용자"** 다.
2. **지적 개수 하한을 걸지 않는다.** 개수 하한은 실패한 프롬프트에 이미 들어 있었고 효과가 없었다.
   깨끗한 화면에 걸면 **오탐을 인위적으로 제조**한다. 대신 지적마다 **근거·severity·severity 의 근거·
   위치**를 강제한다.
3. **모델·에이전트 수를 늘리지 않는다.** 같은 과제에 모델을 추가 투입하면 **신규 유효 이슈 0건,
   오탐만 +43건**이 실측됐다. 병렬화는 **축 분할로만** 한다.
4. **매 라운드 수정자는 깨끗한 컨텍스트에서 시작한다.** 실패한 시도가 컨텍스트에 남으면 이후
   생성이 구조적으로 유사한 오류로 편향되고, **외부 피드백으로도 제거되지 않는다.**
5. **LLM 이 LLM 의 지적을 직관으로 재검증하지 않는다.** 그 방식은 유효한 지적을 되레 죽인다.
   중재자는 **측정치와 프로젝트 예외 목록**으로만 판정한다.
6. **하드 불변식을 통과하지 못한 수정은 점수와 무관하게 기각한다.** 요소를 지우면 모든 결정론적
   지표가 동시에 개선되므로, 불변식이 없으면 **빈 화면이 만점**이 된다.

## 0층 — 준비

**시작 전 URL과 소스 경로를 현재 작업 맥락에서 먼저 찾는다.** 발견할 수 없을 때만 요구한다.
URL은 캡처, 소스 경로는 스타일 감지·원인 역추적·롤백에 필요하다.

### 0-0. 사용자 신호와 의도 계약

사용자의 `"패딩이 이상해"`를 `padding을 바꿔라`로 번역하지 않는다. 원문을 그대로 보존하고 다음 네 필드를 화면·기존 코드·프로젝트 규칙에서 우선 채운다.

- `goal`: 사용자가 더 좋아졌다고 느낄 축
- `must_keep`: 자산·기능·문구·크기·브랜드·이미 승인된 구조
- `allowed_change_scope`: 표면 조정 / 컴포넌트 구조 / IA·콘텐츠 중 허용 범위
- `acceptance_signal`: 어떤 화면·뷰포트·행동에서 확인할지
- **`sanctuary`**: 사용자가 **만족을 표명한 영역.** 지적도 수정도 하지 않는다. 반려 원인 1위가
  이 경계를 넘은 것이었다(*"2,4,6,8,9,10은 훌륭해"* 뒤에 그걸 건드리는 식).
- **`needs_approval`**: 요소 신설 · 레이아웃 구조 변경 · 인상이 크게 바뀌는 변경.
  `narrow-column` 처방(다열 배치)이 여기 들어간다. **"개선해봐"는 구조 변경 승인이 아니다.**
  인상이 바뀌는 변경은 **시안 1개를 먼저 보이고 승인**을 받는다.

명백하면 질문하지 않는다. 미감 방향이나 구조 변경 허용 여부가 결과를 뒤집는데 근거가 없을 때만 한 번 묻는다. 기본값은 **기능·콘텐츠·주요 자산·요소 footprint 보존**이다.

첫 캡처 뒤 각 증상을 `위치 / 관찰 / 가능 계층(surface·component·layout·IA·content·interaction) / confidence`로 적는다. 같은 증상이 두 화면 이상이거나 컨테이너·폭 체계·IA·콘텐츠 밀도에 걸치면 로컬 CSS 수정 전에 구조 문제로 승격한다. 제품·브랜드 판단은 biz-experts, 구현은 dev-experts가 보강하되 이 루프가 관찰과 회귀 확인을 계속 소유한다.

### 0-1. 스타일링 방식 감지

`package.json` 과 설정 파일로 판정한다. 스택을 하드코딩하지 않는다.

| 감지 | 수정 진입점 |
|---|---|
| `tailwindcss` | `tailwind.config.*` 의 스케일 + JSX 클래스 문자열 |
| `*.module.css` | CSS 모듈 파일 |
| `styled-components` / `@emotion` | 컴포넌트 내 템플릿 리터럴 |
| 순수 CSS/SCSS | 스타일시트 |

### 0-2. 스페이싱 스케일 추출

`extractScale()` 이 한다. **직접 짜지 않는다.** 판정에 필요한 것은 「어느 모드로 나왔는가」뿐이고,
그건 `quick.mjs` 출력과 `summary.json` 의 `scale.source` 에 찍힌다.

| source | 뜻 | 지적을 얼마나 믿나 |
|---|---|---|
| `css-vars` · `var-family` · `base-unit` | 저자가 선언한 토큰을 읽어냈다 | 스케일 이탈을 그대로 믿는다 |
| `frequency` | 토큰을 못 찾아 빈도로 **추정**했다 | **추정치다.** 스케일 이탈은 중재를 거치고, 보고에 추정이라고 밝힌다 |

**스케일은 뷰포트마다·라우트마다 다시 뽑는다**(rem 기준이 뷰포트에 따라 바뀌고, 문서마다 토큰이 다르다).
여러 벌의 스케일이 공존하는 것이 정상이라 커버리지에 기여하는 가족을 **전부 합친다** — 하나만 고르면
나머지 벌의 정품 토큰이 전부 「이탈」로 지적된다.

실측 함정 8종(네임스페이스 접두·중첩 규칙·선행 0 생략·rem 루트·calc 파생 등)과 그 근거는
**`references/scale-extraction.md`**. 위 두 상황에서만 연다.

### 0-2.5. 측정 범위 — 기본은 첫 뷰포트, 긴 문서는 `fullPage`

기본값은 **첫 뷰포트만** 측정한다. 비평가가 보는 스크린샷과 범위를 맞추기 위해서다.

긴 문서는 `.ui-refine.json`의 `"fullPage": true`로 측정과 캡처를 함께 전체 페이지로 바꾼다.

측정 범위와 캡처 범위는 반드시 같이 움직인다.

전체 페이지의 반복 판정은 규칙 단위(`addGrouped`)로 집계한다.

**측정 경계 — 문서는 하나가 아니다.** 1b 는 최상위 document 뿐 아니라 **shadow root** 와
**같은 출처 iframe 문서**까지 들어간다(iframe 안 좌표는 부모 좌표계로 밀어 정렬·겹침 판정을
같은 평면에서 한다). 경계를 안 넘으면 웹컴포넌트·임베드 위젯 화면이 **지적 0건 = 깨끗함**으로
둔갑한다 — 실측: iframe 픽스처가 요소 6개로 잡혀 안에 심어 둔 미정의 변수·토큰 밖 값이 통째로
빠졌다(경계를 넘은 뒤 12개, 두 결함 모두 검출).

⚠️ **교차 출처 iframe 은 원리적으로 읽을 수 없다.** 이건 고칠 수 있는 구멍이 아니라 사각지대라,
`summary.json` 의 `blindSpots` 와 stderr 경고로 남는다. **그 경고가 있으면 사용자에게 그대로
전달한다** — "그 영역은 감사하지 못했다"이지 "문제가 없다"가 아니다.

### 0-3. 캡처 세트 확정 — 곱셈을 경계한다

세트 크기는 축의 곱으로 폭발하므로 한 호출에 많은 이미지를 붙이지 않는다.

**기본값 (사용자가 명시적으로 넓히기 전까지 이걸 쓴다):**

| 항목 | 기본값 | 이유 |
|---|---|---|
| 라우트 | **좁은 지적이면** 지목한 화면 1개 + 직접 연결 최대 2개. **넓은 지시면 「넓은 지시를 받았을 때」 절을 따른다** | 이 기본값을 넓은 지시에 그대로 쓰면 범위가 되레 좁아진다(실측 2026-07-04) |
| 뷰포트 | **360×800 / 1440×900 + 위험 경계 최소 세트** | breakpoint·짧은 높이·fixed/sticky·`vh/dvh`가 있으면 경계 전후나 360×640/375×667 중 필요한 것만 추가 |
| 테마 | **라이트만 비평가에 첨부.** 다크는 1b 대비 측정만 | 다크 관련 항목(4-5·4-10)이 전부 ◆라 첨부 불필요 |
| 미디어 | 기본 `screen`·light. **다크·인쇄는 `.ui-refine.json` 으로 명시할 때만** | 아래 ⚠️ 참조 |
| 상태 | **정상 + 긴 한글 텍스트** | 빈·로딩·에러는 재현 수단 확보 시에만 추가 |
| 비평가 첨부 | **호출당 4장 이하** | 나머지 조합은 1b 결정론 측정만 |

기본값이면 세트 = 1 × 2 × 1 × 2 = 4장이다. 추가 뷰포트는 전 곱집합이 아니라 위험 신호가 있는 상태에만 붙인다.

다크·인쇄는 해당 조건으로 렌더해야만 감사된다. 지원 프로젝트라면 `"colorSchemes": ["light","dark"]` 또는 `"media": "print"`를 주고, 켜지 않은 모드는 "문제 없음"이 아니라 "미감사"로 보고한다.

**긴 한글 텍스트는 필수다** — `word-break: keep-all` 부작용은 lorem ipsum으로 재현되지 않는다.
상태를 만드는 수단(`page.route` 인터셉트 / 픽스처 / MSW)을 확보하지 못하면 그 상태를 세트에서
빼고 **사용자에게 뺐다고 보고한다.** 조용히 건너뛰지 않는다.

**로그인**이 필요하면 자격증명이나 픽스처 경로를 요구한다.

### 0-4. 캡처 규약 고정

`animations: "disabled"`, `caret: "hide"`, `scale: "css"`, headless 고정,
`--force-device-scale-factor=1`. 폰트 로드 완료 + network idle 후 촬영.
**수정 후 재캡처 전에는 HMR 리빌드 완료를 기다린다** — 안 그러면 옛 화면을 보고 "안 고쳐졌다"고 오판한다.

**목적이 다른 캡처를 섞지 않는다.**

- `regression`: 애니메이션·캐럿·변동 요소를 통제한 원본. 계측·회귀 비교용.
- `experience`: 실제 스크롤바·포커스·hover/open/error 등 사용 단서를 보존. 비평용.
- `badged`: 안정화된 regression 상태에 번호를 입힌 위치 연결용. affordance 판단은 번호 없는 experience와 짝지어 본다.

전역 CSS 주입은 레이아웃을 바꿀 수 있다. 캡처용 스타일은 변동 요소를 숨기는 좁은 selector만 쓰고, `injectCss`로 스크롤 셸을 푸는 진단 패스는 원래 레이아웃 패스와 분리한다. 주입 패스의 sticky·fixed·정렬 판정은 채택 근거로 쓰지 않는다.

**아티팩트 제거** (3층이 이 항목을 참조한다 — 여기가 비면 중재자가 판단으로 떠안는다):
스크롤바는 캡처용 CSS 로 숨기고, HMR·devtools·프레임워크 배지는 셀렉터로 가리고,
토스트·모달 잔상은 애니메이션 종료 대기로 없애고, 스켈레톤은 콘텐츠 렌더 완료 대기로 넘긴다.
포커스 링은 캡처 전 `document.activeElement.blur()`. 제거하지 못한 것은
**비평가 프롬프트의 "지적하지 않을 것" 목록이 2차 방어선**이다.

### 0-5. 캡처 진실성·자기 잡음 캘리브레이션

**같은 화면을 아무것도 바꾸지 않고 두 번 찍어 diff 를 측정하고, 그 위로 픽셀 임계를 잡는다.
화면별로 따로.** 벤더가 제시하는 임계값 표준은 존재하지 않으므로 전역 단일값을 찾지 않는다.

`fullPage` 결과 높이가 뷰포트와 같고 내부 scroll container가 있으면 전체 캡처로 간주하지 않는다. 지연 이미지 decode, 프레임워크 portal/HMR artifact, 현재 환경(`local/preview/live`, URL, viewport)을 summary에 남긴다. 캡처용 CSS 전후 geometry가 달라지면 그 패스는 `diagnostic-only`다.

## 1층 — 결정론적 검사 (두 겹으로 나눈다)

**1a 와 1b 를 섞으면 스킬이 의도된 디자인을 자동으로 뭉갠다.** 그러나 자동 도구 하나만으로 접근성 적합성을 판정할 수도 없다. axe 결과는 확정 실패와 사람 검토 항목을 분리하되, 수정은 의도 계약과 회귀 검사를 통과해야 한다.

| 층 | 내용 | 처리 |
|---|---|---|
| **1a** | axe-core 가 `violation` 으로 확정한 것 | 원인 위치는 확정하되 수정안은 의도 계약·불변식 경유 |
| **1b** | 자체 측정: 스케일 이탈 · 정렬 편차 · 오버플로 · 겹침 · 위계 역전 · CLS | **중재자 경유** |
| — | axe 가 `incomplete` 로 돌린 것 | **보류함행** (판정 불가를 판정하지 않는다) |

### 1b 측정 규칙

단일 `page.evaluate` 안에서 **DOM 변경 없이 전량 수집**한다. `getBoundingClientRect` 는 동기 레이아웃
플러시를 강제하므로 DOM 변경과 번갈아 호출하면 레이아웃 스래싱이 난다. 배치 수집이면 수천 건도 싸다.

**정의를 확정하지 않으면 판정 함수를 쓸 수 없다.** 아래를 그대로 쓴다.

**판정 이름을 사용자에게 옮길 때** — 이름 그대로 말하면 안 통한다. 뜻으로 바꿔 전한다.

| 판정 | 사용자에게는 이렇게 |
|---|---|
| `hierarchy` (위계 역전) | "묶여 보여야 할 것끼리 오히려 더 떨어져 있어서, 제목이 아래 내용이 아니라 위 덩어리에 붙어 보입니다" |
| `narrow-column` (좁은 기둥) | "넓은 화면에서 글이 가운데 좁은 기둥에만 있고 좌우가 통째로 비어 있습니다" |
| `dead-row` (죽은 가로 띠) | "화면 높이만큼 자리를 잡아뒀는데 내용이 위쪽에만 있어 아래가 빕니다" |
| `coverage` (감사 커버리지) | "이번에 실제로 본 범위입니다. 나머지는 문제가 없는 게 아니라 **못 본 것**입니다" |

| 항목 | 판정 | 배제 |
|---|---|---|
| 오버플로 | 상자를 넘치면서 **①자기가 잘라내거나 ②조상이 잘라내거나 ③화면 밖으로 나갈 때**만 결함. `overflow:visible` 로 상자 밖에 그려질 뿐이면 글자는 안 잘린다 | `overflow` 가 `auto`·`scroll`, `intentionalHScroll` 예외. 세로는 `overflow-y:hidden` 일 때만 |
| **미정의 CSS 변수** | `gap`·`padding`·`margin` 이 **선언되지 않은 `var()`** 를 참조 — 속성이 통째로 무효가 돼 **0 으로 무너지고 글자가 붙는다** | 폴백이 있는 참조(`var(--x, 8px)`), 스페이싱 외 속성(`text-align:var(--x)` 처럼 "미설정=기본값"은 널리 쓰이는 관용구다) |
| 겹침 | 두 rect 의 교집합 면적 > 0 | 부모-자식·조상-후손 관계, `position` 이 `fixed`·`sticky`·`absolute` 인 쪽, `z-index` 가 명시된 쪽, `pointer-events:none`, **인라인 요소**(여러 줄로 접히면 rect 가 줄을 합친 상자라 나란한 것끼리 겹쳐 보인다), **SVG 내부**(Mermaid 는 rect 위에 g 를 겹쳐 그리는 게 정상) |
| 정렬 편차 | **같은 부모의 형제**를 **마진 박스** 기준으로 비교. 세로 스택은 `left`, 가로 배치는 **줄로 나눈 뒤** 줄 안에서 `top`. 차이가 **1px 초과**면 위반 | `display:none`·`visibility:hidden`, 인라인 요소, `position:absolute`·`fixed`. **중앙정렬 컨테이너**(auto 마진·좌우 대칭). **교차축 정렬이 start 계열이 아닌 경우 전부**(center·baseline·end·stretch 는 높이가 다르면 좌표가 달라야 정상). **자식마다 `align-self` 가 다른 경우** |
| **위계 역전** | **그룹 내 최대 간격 ≥ 그룹 간 최소 간격** | 사이에 구분선·배경색 변화가 있으면 제외 |
| **죽은 세로 띠** | 같은 부모 아래 **폭·좌측이 일치하는 블록 자식 2개 이상**이 부모 콘텐츠 폭보다 좁아 한쪽에만 큰 여백이 남음 (띠 ≥ 콘텐츠 폭의 1/4, 반대쪽의 2배 이상) | 좌우 대칭(중앙정렬), 자식 1개, absolute·fixed |
| **죽은 가로 띠** `dead-row` | 화면 높이급으로 잡힌 상자인데 콘텐츠가 위쪽에만 몰려 아래가 비어 있음. 「화면이 너무 빈다」의 세로판 | **html·body**(높이가 저자 선언이 아니라 뷰포트에서 온다 — 빼지 않으면 짧은 페이지가 전부 결함), 스크롤하는 상자(그건 커버리지 소관), `justify-content`·`align-content` 가 center·end 계열 |
| **글자 하한** `font-too-small` | 자체 텍스트를 가진 요소의 `font-size` 가 **11px 미만**. 근거는 `korean-typesetting.md` §6 (실측: 선언 515개 중 13px 이하 71%) | SVG 내부, 예외 셀렉터 |
| **한글 행간** `ko-line-height` | 한글이 든 요소의 `line-height / font-size` 가 **1.0 미만** — 받침이 윗줄과 겹친다 | `line-height: normal`, 한글이 없는 텍스트 |
| **제목 위계·행간** `heading-size` `heading-lineheight` | 제목이 같은 영역 본문보다 크지 않음 / 제목이 본문 행간(≥1.5)을 상속해 줄상자만 커짐(이중 여백) | 형제에 본문급 요소가 없을 때는 판정하지 않는다 |
| **좁은 기둥** `narrow-column` | 폭 ≥1024 뷰포트에서 콘텐츠 기둥이 뷰포트의 55% 미만이고 **좌우 띠가 둘 다 비어 있음**. 위 「죽은 세로 띠」가 대칭이라는 이유로 빼는 케이스를 잡는다 — **오너가 실제로 반려한 축** | 띠에 무엇이든 있음(사이드바·레일·다열), 한쪽만 남음(죽은 세로 띠 소관), 좁은 뷰포트. **자동수정 금지** — 승인 경계 |
| **무너진 요소** | 테두리·배경이 있거나 내용이 든 상자가 **한 변만** 8px 미만 — 데이터 미도착·flex 계산 실수로 접힌 것. **가장 바깥만** 보고한다 | 두 변이 다 작은 장식·구분선 |
| 스케일 이탈 | `padding`·`margin`·`gap` 의 0 아닌 px 값이 0-2 스케일 밖. **값 단위로 묶는다** — 하나의 결정(6px)이 prop 별로 쪼개지면 사전식 비교에서 과대대표된다 | `auto`·`%`·`0`, 소수 px, 예외 셀렉터 |
| 행 높이 편차 | **줄 수가 같은 행끼리만** 비교. 줄 수가 다르면 높이가 다른 게 정상이다(한글 표는 행마다 줄 수가 다르다) | 1px 이하 차이 |
| CLS | `PerformanceObserver` entryType `'layout-shift'`, `hadRecentInput` 제외 | — |

**그룹 정의**: 같은 부모 아래 연속한 형제들 중 **간격이 같은 것끼리 한 묶음**.
간격이 바뀌는 지점이 그룹 경계다. 이 정의는 스케일 추출(0-2)에 의존하지 않는다 —
상대 비교만 하므로 순환하지 않는다.

**위 7종 외에 `collect.js` 가 재는 것 18종 더** — 반복 요소 패딩 불일치 · 이중 들여쓰기 ·
행/열 간격 비대칭 · 상하 패딩 비대칭 · 컨트롤 패딩 비율 · 폰트 굵기 종류 · 링크 어포던스 ·
focus 스타일 부재 · 셀 패딩 · 행 높이 편차 · 표 헤더 sticky · 소수 자릿수 혼재 ·
숫자 정렬 혼재 · 등폭 숫자 · 빈 셀 · 입력 폭 균일 · placeholder 라벨 대용 · 필수 표시 혼재.
전체 목록과 체크리스트 항목 대응은 `references/checklists.md` 상단 표.

⚠️ **판정 종류를 늘릴 때는 `collect.js` · `capture.mjs` 집계 · `score.mjs` 의 `ORDER`
세 곳을 함께 고친다.** 한 곳만 고치면 새 지표가 점수에 안 들어가 조용히 무시된다.
(`dedup.mjs` 의 `itemKindMap()` 도 함께 — 3층 매칭이 그 표를 쓴다.)

### 판정을 고칠 때의 원칙 — 배제 규칙을 덧붙이지 않는다

오탐이 나오면 **그 화면을 보고 배제 규칙을 거꾸로 넣고 싶어진다. 그게 과적합이다.**
10개 스택 실측에서 오탐 건수의 대부분이 **소수의 근본 원인**으로 모였고, 개별 배제가 아니라
원인을 고쳐야 사라졌다. 오탐을 만나면 순서는 이렇다:

1. **건수를 세지 말고 원인으로 귀속시킨다.** (정렬 오탐 73건 → 원인 4종에 93% 가 모였다)
2. 원인이 「엔진·라이브러리가 보장하는 것을 우리가 다시 재고 있다」면 **재지 않는다.**
3. 임계값을 지어내지 말고 **선언된 것을 읽어낸다**(CSS 에 적힌 배수·토큰·정렬값).
4. 그래도 남으면 그때 예외 목록(`.ui-refine.json`)으로 — **코드가 아니라 프로젝트 설정으로.**

**같은 판정을 여러 요소가 공유하면 규칙 단위로 집계한다.** CSS 규칙 1개가 600행 표에서
36건으로 세면 그 한 규칙이 사전식 비교 전체를 지배해 다른 축이 의미를 잃는다.

⚠️ `layout-shift` 는 **Chromium 전용**이다. WebKit/Firefox 에서 0건이 나오는 것을 "shift 없음"으로
읽으면 안 된다.

⚠️ **대비 검사의 배경색이 판정 불가일 때(반투명·그라디언트·이미지 위 텍스트·겹친 레이어)는
`incomplete` 로 돌린다.** 이건 자동 대비 검사 오탐 1위 경로다. 색을 덮어쓰지 않는다.

### 스냅은 조건부다

스케일 이탈을 고칠 때 **인접 스케일 값이 이웃 간격과 같아지면 스냅을 금지**한다.
12px 과 14px 이 둘 다 12 로 붕괴하면 그룹 경계가 사라져 **위계 역전을 스스로 만들어낸다.**
**위계 지표가 스냅보다 상위다.**

## 2~5층 — 루프 본체 (T2 에서만 연다)

전문은 **`references/loop-pipeline.md`** 다. T0·TS 에는 필요 없어서 본문에서 뺐다(2026-09-07).

| 층 | 하는 일 | 한 줄 원칙 |
|---|---|---|
| 2층 비평가 | 축 7종 + 화면 간 일관성, 축마다 에이전트 1대 | 모델을 늘리지 말고 **축을 나눈다**. 스크린샷만 주고 코드·의도는 주지 않는다 |
| 3층 중재 | `dedup.mjs match` 로 finding ↔ 측정치 대조 | 직관으로 재검증하지 않는다. `no-measure-for-item` 은 실패가 아니라 정직한 답이다 |
| 3.5층 원인 진단 | 관찰마다 경쟁 가설 2~4개를 세워 반증 | 사용자 발화에 나온 속성(`padding`)을 먼저 고르는 것은 금지 |
| 4층 수정 | 깨끗한 컨텍스트에서 시작, 토큰이냐 로컬이냐는 역추적으로 판정 | 역추적 실패 시 **보류함행**(추측으로 고치지 않는다) |
| 5층 채택 | 하드 불변식 → 사전식 비교 → 타이브레이크 | 요소를 지우면 모든 지표가 좋아진다 — 불변식이 점수보다 먼저다 |

**verdict 3종**(`score.mjs` 가 자동으로 낮춘다. 셋 다 exit 0 — 작업을 막지 않고 **보고를 바꾼다**):
`accept` / `accept-partial`(커버리지가 낮다 — 본 범위를 숫자로 함께 말한다) /
`accept-pending-owner`(`narrow-column` 등 구조 신호가 남았다 — 시안 먼저, 승인 먼저).

## 실행 전 확인

⚠️ **이 목록은 T1·T2 용이다.** T0 에 12항목 사전점검을 요구한 것이 이 스킬이 94세션 동안
한 번도 안 불린 이유다. **T0 는 아래 세 줄이 전부다.**

**T0 (기본값)**
- [ ] 렌더되는 URL 이 있는가 (없으면 사용자에게 한 줄로 요청 — dev 서버는 이 스킬이 안 띄운다)
- [ ] 사용자 원문을 **번역하지 않고** 보존했는가 ("패딩이 이상해" ≠ padding 을 바꿔라)
- [ ] 보고할 때 **커버리지를 판정보다 먼저** 말하기로 했는가

**T1·T2 추가분**

- [ ] dev 서버 URL 과 **소스 디렉터리 경로**를 둘 다 받았는가
- [ ] `goal / must_keep / allowed_change_scope / acceptance_signal`을 고정했는가
- [ ] 스타일링 방식을 감지했는가
- [ ] 요소 번호 배지본 / 원본 두 벌 캡처가 되는가
- [ ] 스페이싱 스케일을 추출하고 **어느 모드(`css-vars`/`base-unit`/`frequency`)로 나왔는지** 사용자에게 보고했는가
- [ ] **캡처가 빈 화면이 아닌가** — `capture.mjs` 가 exit 4 를 내면 404·라우팅 실패다. 빈 화면은
      모든 지표가 0 이라 5층 비교에서 **항상 이긴다.** (`--routes` 에 절대경로를 주면
      `--url` 의 경로가 날아간다 — 라우트에 프로젝트 경로를 통째로 넣을 것)
- [ ] 캡처 세트(라우트 × 뷰포트 × 테마 × 상태)를 확정했는가
- [ ] 내부 스크롤·짧은 화면·breakpoint 위험에 필요한 frontier 뷰포트를 넣었는가
- [ ] regression과 experience 캡처 목적을 분리했는가
- [ ] 자기 잡음 캘리브레이션을 돌렸는가
- [ ] 되돌릴 수단(git stash / 스냅샷)을 확보했는가

## 판단이 안 설 때 — 무엇을 묻는가

막히면 그냥 멈추거나 아무 말이나 묻지 않는다. **네 필드를 채워서 한 번에 묻는다.**
(이 스킬은 "판정 불가를 판정하지 않는다"가 원칙이라, 묻는 상황이 정상 경로다.)

| 필드 | 내용 |
|---|---|
| **무엇을** | 어느 화면·요소·판정이 걸렸는가 (셀렉터 또는 요소 번호까지) |
| **왜 못 정하는가** | 측정이 없어서 / 예외인지 의도인지 몰라서 / 승인 경계라서 — 셋 중 무엇인가 |
| **선택지** | 내가 보는 갈래 2~3개와 각각의 결과 |
| **기대 답** | 한 단어로 답할 수 있게. "1번" 또는 "그대로 둬" |

자주 나오는 세 상황의 채워진 예시:

| 상황 | 이렇게 묻는다 |
|---|---|
| `narrow-column`(구조·승인 경계) | *"`/legal` 데스크톱에서 본문이 720px 기둥이고 좌우 360px씩 비어 있습니다(#19). 다열로 나누면 인상이 꽤 바뀝니다 — ①좌측 목차 레일 신설 ②본문 폭만 넓히기 ③그대로. 시안이 필요하면 ①로 한 장 만들어 보여드리겠습니다. 어느 쪽으로 갈까요?"* |
| `no-measure-for-item`(측정 수단 없음) | *"비평가가 '주 액션이 묻힌다'고 지적했는데 1b 에 이걸 잴 수단이 없습니다(보류함행). ①육안으로 판단해 고친다 ②그대로 두고 보류함에 남긴다 — 어느 쪽이 좋을까요?"* |
| 스케일이 `frequency` 폴백 | *"스페이싱 토큰을 못 찾아 빈도 추정으로 잡았습니다 — 「스케일 이탈」은 신뢰도가 낮습니다. ①토큰 파일 위치를 알려주세요 ②이 축은 뺍니다."* |

**묻지 않는 것**: 스타일 조정 범위의 일상 판단(규율 7상 자율), 이미 만족을 표명한 영역(성역 — 묻지도 고치지도 않는다).
**답을 못 받으면**: 진행하되 그 항목을 보류함에 남기고 **무엇을 못 정했는지 보고에 적는다.** 조용히 고르지 않는다.
