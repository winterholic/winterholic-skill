# dev-experts 디스패처

> 이 파일은 연결만 한다. 도메인 지식과 긴 표는 chief·전문가·README에서 필요할 때만 읽는다.

개발 작업을 받으면:

1. **프로젝트 규칙 우선 확인** — 현재 작업이 프로젝트 폴더 안이고 그 프로젝트에 CLAUDE.md·프로젝트 스킬이 있으면 **그쪽이 우선**. 이 스킬군은 프로젝트 규칙이 침묵하는 영역만 채운다.
2. `~/.claude\dev-experts-skills\README.md`에서 후보 이름을 찾고 **실제 `SKILL.md` 존재를 확인**한다. 이름을 추측해 `dev-<이름>` 경로를 만들지 않는다.
3. 스택·방법이 명확하고 카탈로그의 단일 항목과 정확히 맞으면 그 전문가로 직행한다. 그 외에는 `~/.claude\dev-experts-skills\dev-chief-architect\SKILL.md`를 읽어 무게중심 1명부터 고른다. 보강 전문가는 선행 결과가 필요함을 보일 때만 추가한다.
4. **반복 오류는 직행 예외**다. `또`, `여전히`, `아직도`, `같은 에러`, `근본 원인` 또는 두 번째 수정 시도부터는 `systematic-debugging`으로 재현·실행 경로·환경을 먼저 고정한 뒤 도메인 전문가를 붙인다.
5. 호출 전 다음 route capsule을 만든다: `목표·증상 / 관측 증거 / 현재 가설과 반증 조건 / 범위·비범위 / 불변식 / 완료 조건과 확인 방법`. 불명확해도 조사로 채울 수 있으면 묻지 않는다.
6. 카탈로그에 없거나 파일이 없으면 그 축만 `일반 지식 + 최신 공식 문서`로 폴백하고, 빠진 전문성·대체 근거·재확인 항목을 한 줄로 알린다. 버전 의존 사실은 런타임·설치 버전과 공식 문서를 우선한다.
7. 변경 표면에 맞춰 검증한다: 코드=좁은 테스트, UI=브라우저·스크린샷, DB=정합성·실행계획, 배포=실제 대상 환경의 health와 수정 동작. 명령 통과만으로 다른 표면까지 검증됐다고 말하지 않는다.

## 라우팅 ❌/✅ 예시

- ❌ "삼성전자 살까?" → dev 전문가 호출 (경계 밖 — 투자 판단은 stock-experts)
- ✅ "주식 시세 수집기 짜줘" → 이 디스패처 (주식 소재라도 **코드 작업**이면 dev)
- ✅ "FastAPI 422 에러" → 카탈로그 확인 후 dev-fastapi 직행
- ✅ "FastAPI 422가 여전히 나" → systematic-debugging으로 재현·환경 확인 → dev-fastapi
- ❌ "UI가 이상해, 화면 좀 봐줘" → dev-react 직행 (이미 렌더된 화면 평가는 ui-refine-loop가 먼저)
- ❌ sample-service 폴더 작업에서 프로젝트 CLAUDE.md 무시하고 전문가 일반론 적용
- ✅ 프로젝트 규칙 먼저, 전문가는 빈 곳만 (절차 1)

## 사용자가 라우팅을 거부하면

- **"스킬 찾지 말고 그냥 해줘"** → 디스패처 생략하고 직접 진행. 단 보안·인증·결제 관련이면 리스크 한 줄은 남긴다(품질 축은 무언 통과 금지).
- **"그 전문가 말고"** → 이유를 1회만 묻고 사용자 지정대로 진행. 같은 오라우팅 거부가 반복되면 라우터의 라우팅 표 수정을 제안.
- **권고 자체를 거부** ("그냥 빨리") → 거부된 권고와 그 리스크를 방침에 1줄 기록하고 진행(partial — 전체를 보류하지 않는다).

## 라우팅 출력

인라인으로 `주도 전문가와 이유 / route capsule / 보강 조건 / 검증 표면 / 확인 필요`만 남긴다. 내부 카탈로그 설명은 사용자 응답에 노출하지 않는다.

## 처음 쓰는 세션을 위한 30초 워크스루

"수집기 하나 짜줘" 요청이면 프로젝트 규칙 → README 검색 → chief가 `dev-data-engineering`을 주도로 선택 → route capsule 전달 → 수집 경계 테스트와 실제 적재 정합성까지 확인한다. Postgres나 TDD는 필요가 확인된 시점에만 보강한다.

## 주의

- **비개발 직군 작업은 biz-experts로** — PM·기획·디자인·마케팅·카피·사업전략·CTO 역할·세일즈·HR 등 코드가 본체가 아닌 직무 작업은 `~/.claude/skills/biz-experts/SKILL.md`(또는 `~/.claude\biz-experts-skills\`)로 넘긴다. 코드 구현이 본체면 이 디스패처가 맞다.
- 이미 렌더된 화면의 "어색함·패딩·배치·완성도" 진단은 `ui-refine-loop`가 관찰을 주도하고, 구현 단계에서만 해당 프론트 전문가를 쓴다.
- 일반 작업 중 공용 troubleshooting ledger를 자동 수정하지 않는다. 재현 가능한 근본원인이 확정되면 종료 보고에 `학습 후보` 한 줄을 남기고, 사용자가 하네스 갱신을 요청할 때 work-history의 반복 사례로 승격한다.
- 스킬에 적힌 버전·설정값·임계치는 작성 시점 기준이다 — 버전 라벨이 낡았으면 **공식 문서가 이긴다**.
- 이 스킬군은 일반론 전문가다. 프로젝트 고유 컨벤션·도메인 규칙과 충돌하면 프로젝트가 이기고, 알려진 안티패턴일 때만 한 줄 지적한다.
