# dev-experts 디스패처

> 용어: **디스패처** = 전화 교환원(작업을 받아 맞는 부서로 연결만 한다, 직접 작업 ❌) · **라우터** = 작업을 분해해 전문가 조합을 정하는 수석 아키텍트 · **폴백** = 전문가 스킬이 없을 때 일반 지식 + 공식 문서로 진행하는 대체 경로 · **⬜/✅** = 카탈로그상 미제작/제작됨.

개발 작업을 받으면:

1. **프로젝트 규칙 우선 확인** — 현재 작업이 프로젝트 폴더 안이고 그 프로젝트에 CLAUDE.md·프로젝트 스킬이 있으면 **그쪽이 우선**. 이 스킬군은 프로젝트 규칙이 침묵하는 영역만 채운다.
2. `~/.claude\dev-experts-skills\dev-chief-architect\SKILL.md`를 Read한다(아키텍트 라우터). 라우터가 작업을 [언어 × 프레임워크 × 방법론 × 품질] 축으로 분해해 전문가 1~3명을 정한다.
3. 스택·방법이 이미 특정된 작업(예: "FastAPI 의존성 주입", "pytest fixture", "Dockerfile 줄여줘")은 라우터를 건너뛰고 해당 전문가 `~/.claude\dev-experts-skills\dev-<이름>\SKILL.md`를 직접 Read한다. 전문가 목록·제작 상태(✅/⬜)는 `~/.claude\dev-experts-skills\README.md` 카탈로그 참조.
4. **미제작(⬜) 전문가는 Read 시도하지 않는다** — 폴백으로 진행하고 다음 형식으로 한 줄 알린다:
   `⬜ dev-<이름> 미제작 — 일반 지식 + <공식 문서명>으로 진행. 확인 필요: <스킬이 있었다면 검증했을 항목>`
   (무엇이 빠졌는지 / 무엇으로 메우는지 / 사용자가 뭘 재확인하면 되는지 — 3요소를 채운다. 공식 문서조차 없는 영역이면 그 항목만 "판정 불가"로 분리하고 가용 부분으로 진행.)
5. 읽은 매뉴얼의 워크플로우·안티패턴·검증 명령을 그대로 따른다. 공통 규칙(우선순위 사다리·버전 라벨·"확인 필요" 표기·트러블슈팅 ledger)은 README에 있다.
6. **삽질 30분 초과 해결 시** `~/.claude\dev-experts-skills\troubleshooting\ledger.md`에 1행 추가(append-only, 파일이 없으면 헤더 행과 함께 생성). 새 삽질 전엔 ledger를 먼저 grep:
   ```
   Grep: pattern="<에러 키워드>" path="~/.claude\dev-experts-skills\troubleshooting\ledger.md"
   Grep: pattern="dev-<후보>" path="~/.claude\dev-experts-skills\README.md"   # 제작 상태 확인
   ```

## 라우팅 ❌/✅ 예시

- ❌ "삼성전자 살까?" → dev 전문가 호출 (경계 밖 — 투자 판단은 stock-experts)
- ✅ "주식 시세 수집기 짜줘" → 이 디스패처 (주식 소재라도 **코드 작업**이면 dev)
- ❌ "FastAPI 422 에러" → 라우터 경유 (스택이 특정됐는데 우회로를 태움)
- ✅ "FastAPI 422 에러" → dev-fastapi 직행 (절차 3)
- ❌ sample-service 폴더 작업에서 프로젝트 CLAUDE.md 무시하고 전문가 일반론 적용
- ✅ 프로젝트 규칙 먼저, 전문가는 빈 곳만 (절차 1)

## 사용자가 라우팅을 거부하면

- **"스킬 찾지 말고 그냥 해줘"** → 디스패처 생략하고 직접 진행. 단 보안·인증·결제 관련이면 리스크 한 줄은 남긴다(품질 축은 무언 통과 금지).
- **"그 전문가 말고"** → 이유를 1회만 묻고 사용자 지정대로 진행. 같은 오라우팅 거부가 반복되면 라우터의 라우팅 표 수정을 제안.
- **권고 자체를 거부** ("그냥 빨리") → 거부된 권고와 그 리스크를 방침에 1줄 기록하고 진행(partial — 전체를 보류하지 않는다).

## 처음 쓰는 세션을 위한 30초 워크스루

"수집기 하나 짜줘" 요청이 오면: ① 현재 폴더에 프로젝트 CLAUDE.md 있나 → 있으면 그 규칙 우선 ② 스택 미특정 → 라우터 Read → "data-engineering 무게중심 + postgres + tdd" 조합 결정 ③ README에서 셋 다 ⬜ 확인 → 위 폴백 형식으로 알리고 일반 지식 + 공식 문서로 작업 ④ 도중 30분 삽질 해결 시 ledger 1행.
