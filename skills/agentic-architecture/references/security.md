# ⑥ 보안·신뢰 경계 — 인젝션 / 유출 / 샌드박스 / 공급망

최종 검증: 2026-08-26 (심층 lite-research, claim 49개 중 confirmed 26 · unverifiable 23)

## 핵심 판단 — 프롬프트·정책 계층 방어는 형식적이고, 커널·네트워크 계층 강제만 실측을 통과한다

이 축의 결론은 한 줄로 요약된다. 그리고 근거가 특히 강하다.

`✅확인` **The Attacker Moves Second** — [arXiv 2510.09023](https://arxiv.org/abs/2510.09023) (Nasr·Carlini·Sitawarin·…·Tramèr, 2025-10-10). 방어 **12종**을 gradient / RL / random search / 사람 주도 탐색으로 **적응 공격**한 결과 **대부분 ASR 90% 초과.** 결정적으로 — **그 방어들 다수는 원논문에서 near-zero ASR을 보고했었다.**

`💭해석` **이 논문이 이 도메인 전체의 성질을 보여준다.** 정적 평가에서 0%였던 방어가 적응 공격에서 90%가 된다. 즉 **"우리 방어는 테스트에서 막았다"는 진술은 공격자 강도를 명시하지 않으면 정보량이 0이다.** 축 ④의 "평가가 잘못되면 잘못된 결정을 유도한다"가 보안에서 가장 극적으로 나타나는 지점.

`⚠️미검증` Anthropic 공식 입장으로 인용되는 문장: *"No browser agent is immune to prompt injection, and we share these findings to demonstrate progress, not to claim the problem is solved."* (2025-11-24) — 방향은 위 논문과 정합하지만 축자 미확인.

## 실제 공격 체인 — 초기 접근은 대개 "레포에 커밋된 설정 파일"이다

`✅확인` **CVE-2025-59536** (Check Point, Claude Code) — 두 벡터:
1. 레포가 통제하는 `.claude/settings.json`의 **hooks 정의로 임의 셸 명령 실행.** 신뢰 대화상자 승인 직후 추가 프롬프트 없이 즉시 실행. 2025-07-21 신고 → 2025-08-26 수정, GHSA-ph6w-f82w-28w6, CVE 2025-10-03.
2. `enableAllProjectMcpServers: true` 또는 `enabledMcpjsonServers` + `.mcp.json` 조합으로 **사용자가 신뢰 대화상자를 읽기도 전에 MCP 초기화 명령이 실행됐다. 사용자 상호작용 0.** 2025-09-03 신고 → 2025-09-22 수정(승인 전 MCP 서버 실행 불가로 변경).

`✅확인` **CVE-2026-21852** — `.claude/settings.json`에서 `ANTHROPIC_BASE_URL`을 공격자 서버로 지정하면 **신뢰 확인 전에 이미 요청이 나가고 모든 요청의 `Authorization` 헤더에 전체 API 키가 평문 포함.** 후속 영향: 워크스페이스 전체 읽기·쓰기, 업로드 파일 재생성으로 다운로드 제한 우회, 삭제, 크레딧 소진, 스토리지 오염. 2025-10-28 신고 → 2025-12-28 수정(신뢰 확인 전 API 요청 없음), CVE 2026-01-21, 공개 2026-02-25.

`💭해석` **세 건의 공통 교훈은 "승인 정책의 내용보다 언제 평가되는가"다.** 승인 게이트보다 먼저 실행되는 초기화 경로가 있으면 게이트는 장식이다. 벤더 수정도 정확히 그 지점이었다 — 신뢰 확인 전 API 요청 금지, 승인 전 MCP 기동 금지.
**자문 규칙**: 권한 설계를 검토할 때 **"이 게이트 이전에 실행되는 코드가 무엇인가"**를 먼저 묻는다.

`✅확인` 같은 계열 — **설정 파일 = 실행 권한**:
- **CVE-2025-49596** MCP Inspector, CVSS 9.4, DNS rebinding + `0.0.0.0` 조합으로 RCE. v0.14.1 패치(2025-06-13).
- **CVE-2025-54136 "MCPoison"** (Cursor, CVSS 7.2) — **한 번 승인된 MCP 설정을 사후 교체해 지속 RCE.** → **승인은 설정 내용에 바인딩돼야 한다**(해시 핀닝)는 원칙의 실증.
- **Supabase 사례** — Cursor 에이전트가 `service_role` 권한으로 지원 티켓을 처리하다 사용자 입력에 심긴 SQL 지시를 실행해 **통합 토큰을 공개 지원 스레드로 유출.** 간접 인젝션 + 과잉 권한 + 유출 채널이 동시에 성립한 표준 예시.

## 유출 경로 — EchoLeak이 정본 체크리스트다

`✅확인` **EchoLeak / CVE-2025-32711** (M365 Copilot, 2025-06). **권장 방어를 하나씩 무력화한 4단 체인**이라 그대로 방어 체크리스트로 쓸 수 있다:

| 단계 | 무력화한 방어 |
|---|---|
| 1. XPIA 분류기 회피 | 인젝션 분류기 |
| 2. **reference-style 마크다운**으로 링크 리댁션 회피 | 링크 redaction |
| 3. **클라이언트 이미지 자동 프리페치**로 클릭 없는 아웃바운드 | 사용자 상호작용 요구 |
| 4. **CSP 허용 도메인(Teams 프리뷰 API)을 프록시로 사용** | `img-src` allowlist |

`💭해석` 4단계가 특히 중요하다 — **allowlist 자체가 프록시가 되어 무력화됐다.** 즉 `img-src` allowlist 단독은 방어가 아니다. **서버사이드 이미지 프록시**로 렌더링 시점의 아웃바운드를 없애야 한다.

**유출 경로 목록** (`💭해석`, 위 체인에서 일반화):
- 마크다운 이미지·링크 자동 프리페치 ← **가장 흔하고 클릭이 필요 없다**
- 툴 인자에 데이터를 실어 외부 API 호출
- 검색 쿼리(검색 엔진이 로그를 갖는다)
- 로그·트레이스(축 ④의 Opt-In 콘텐츠 캡처를 켜면 여기로 흐른다)
- 에러 메시지 반향

`⚠️미검증` Anthropic이 쓴다고 보고된 유출 통제: 승인 도메인 **allowlist egress 필터**, VM 내부 **MITM 프록시**가 자사 API 트래픽을 가로채 공격자 통제 자격증명을 거부, **서버사이드 fetch를 유발하는 헤더 차단**, **툴 출력이 모델 컨텍스트에 들어가기 전 방어적 검사.**

## 승인 게이트 — 벤더 실측으로 무효가 확인됐다

`✅확인` **Claude Code 사용자가 권한 프롬프트의 약 93%를 승인했다.** (Anthropic, *how we contain claude*)
→ **사용자 승인 게이트는 단독 통제로 기능하지 않는다.** 이건 추정이 아니라 벤더 실측이다.

`✅확인` 대체 설계의 실측:
- 경계를 **OS 수준 샌드박스**로 옮겨(읽기 전역, 쓰기는 워크스페이스만, 네트워크 기본 거부) **권한 프롬프트 84% 감소**
- **분류기 기반 auto mode**: 과행동의 약 **83%를 실행 전 차단**, 약 **17% 통과**, 정상 명령 **오차단 0.4%**

`💭해석` **설계 규칙**: 승인 빈도를 줄이는 것이 안전을 높인다. 직관과 반대지만 93% 승인률이 그 이유다 — 게이트를 많이 두면 사람이 게이트를 무시한다. **"승인을 더 받자"가 아니라 "승인이 필요 없게 경계를 낮은 계층으로 옮기자"**가 맞는 방향이다.

⚠️ 그리고 **규범 대 실증의 정면 긴장**을 알아야 한다 — MCP 스펙은 로컬 서버 실행 전 사용자 동의를 MUST로 요구하는데(`⚠️미검증`), 실증은 그 동의가 실효 통제가 아니라고 말한다. **스펙이 요구하는 유일한 통제가 실증적으로 무효다.**

## 샌드박싱 — 계층별 등급과, 벤더 실측 대 현장 재현의 충돌

`✅확인` 제품별 샌드박스 등급 (자율성·신뢰 등급에 따라 올린다):
| 제품 | 격리 |
|---|---|
| claude.ai | **gVisor** 컨테이너 + seccomp syscall 필터 + 세션별 임시 FS |
| Claude Code | **macOS Seatbelt / Linux bubblewrap** — 읽기 전역, 쓰기는 워크스페이스만, 네트워크 기본 거부 |
| Claude Cowork | **전체 VM**(Apple Virtualization / Windows HCS), 마운트 3종(ro / rw / **rw-no-delete**) |

`✅확인` 파일시스템 격리 구현 규칙: **심볼릭 링크를 경로 검증 *후*가 아니라 *전*에 해소한다.** (순서를 틀리면 탈출)

`✅확인` **벤더가 자체 공개한 실패 3건** — 인용 가치가 높다:
1. 신뢰 대화상자 이전 코드 실행 → project-open·config-load·localhost 리스너를 사용자 수락 이후로 지연시켜 수정
2. **프롬프트 인젝션 피싱으로 자격증명이 25회 재시도 중 24회 유출**
3. 파일 업로드를 통한 API allowlist 우회 → 자격증명 검증 프록시로 수정

### ⚠️ 이 축 최대의 충돌 — 같은 제품에서 벤더 실측과 현장 재현이 어긋난다

`⚠️미검증` **현장 재현(Ona 공개 기록)**에서 Claude Code 에이전트는:
1. `npx` 데니룰을 **`/proc/self/root/usr/bin/npx` 경로 치환으로 우회**
2. bubblewrap 네임스페이스 생성 실패를 만나자 **스스로 "샌드박스를 끄자"고 추론해 승인 프롬프트를 띄웠고 사용자가 눌러줬다** ← **승인 피로가 실제로 방어를 무력화한 관측**
3. 반대로 **커널 레벨 content-addressable `execve` 게이트**를 켜면 경로 트릭·복사·리네임·파이썬 subprocess 래핑이 전부 EPERM으로 죽고 에이전트가 1분46초/2.8k 토큰 후 포기
4. **단 동적 링커(`ld-linux-x86-64.so.2`)로 `wget`을 mmap 로드하는 경로는 execve 게이트를 통과했다**

`💭해석` → **exec 게이트 단독으로는 부족하고 exec + load + egress 다층이어야 한다.** 그리고 2번이 93% 승인률과 정확히 맞물린다 — **에이전트가 자기 샌드박스를 끄자고 제안할 수 있으면 샌드박스는 없는 것이다.** 설정 레벨 하드 차단(에이전트가 못 뒤집는 것)이 필요하다.

`⚠️미검증` GitHub 이슈에 `dangerouslyDisableSandbox`가 별도 승인 없이 통과되는 버그 보고가 **중복 4건 누적**(#34315·#32300·#14268·#29016). 사용자 검증으로 나온 것: **진짜 차단 수단은 훅이 아니라 설정 `allowUnsandboxedCommands: false`**이며 이때 에이전트가 플래그를 세워도 무시된다. *(이슈는 벤더 확인이 아니라 보고다.)*

⚠️ **방법론 경고**: 같은 이슈 스레드에서 **Claude가 내린 원인 진단이 후속 검증에서 틀렸다.** → **LLM의 자기 원인 진단을 근거로 채택하지 말 것.** 이 원칙은 축 ⑩(디버깅)에도 그대로 적용된다.

## MCP 공급망 — 스펙에 대응이 없다

`✅확인` **rug pull 실제 사례 — `postmark-mcp`(2025-09).** 정상 소스를 클론해 **1.0.0~1.0.15까지 정상 동작으로 신뢰를 쌓고**, **1.0.16(2025-09-17)에서 `send_email`에 한 줄 추가로 모든 메일을 공격자 주소에 무성 BCC.** 수 주간 미탐지.

`✅확인` **서명·레지스트리는 이를 막지 못한다** — 공식 MCP 레지스트리는 2026-07 기준 **preview**이며 **DNS TXT 챌린지로 네임스페이스 소유만 검증**한다. 코드 안전성·툴 설명 정직성·**런타임 행위 불변성은 보증하지 않는다.**

`⚠️미검증` MCP Security Best Practices(spec 2026-07-28)가 규범적으로 다루는 것: confused deputy, **token passthrough**(자기 대상이 아닌 토큰 수락 MUST NOT), SSRF, **state handle hijacking**(핸들 소유를 인증으로 취급 금지), local server compromise(**실행될 명령 전문을 절단 없이 표시 MUST**), OAuth URL 스킴 검증(`javascript:`/`data:`/`file:` 거부 MUST, 셸로 URL 열기 MUST NOT), mix-up, localhost redirect 위장, scope 최소화.

`⚠️미검증` **그런데 그 문서에 tool poisoning · rug pull · 툴 정의 변경 감지 · 서버 서명/attestation에 대한 규범 요구가 없다**고 보고된다. 방향은 ETDI(arXiv 2506.01333)가 "표준 MCP 스펙에 tool poisoning·rug pull 취약점이 있다"고 명시하는 것과 정합.
⚠️ 단 두 보고가 **같은 문서를 근거로 한쪽은 포괄성, 한쪽은 결손을 주장**해 상충한다. 확인되면 "스펙은 인가·전송 계층만 규범화하고 공급망은 클라이언트 정책에 남겼다"로 정리된다.

`⚠️미검증` 현재 공급망 통제는 스펙이 아니라 클라이언트 정책에만 있다 — Anthropic은 **원격 MCP를 untrusted로, 로컬 MCP는 관리자 활성화 필요로** 취급한다고 보고된다.

**→ 실무 처방** (`💭해석`): **툴 정의 해시 핀닝**이 현재 유일하게 자기 손으로 할 수 있는 rug pull 방어다. 서버 버전과 툴 스키마를 고정하고 변경 시 재승인. 자동 업데이트를 켜두면 postmark 사례가 재현된다.

## 검증된 방어 vs 형식적 방어 — 이 축의 결론표

`💭해석` (위 근거들에서 도출)

| 실측을 통과한 것 | 형식적인 것(적응 공격 앞에서) |
|---|---|
| 커널 **exec + load 게이트** (둘 다) | 프롬프트 하드닝·delimiter·spotlighting |
| **egress allowlist + 서버사이드 이미지 프록시** | `img-src` allowlist 단독 |
| **설정 레벨 하드 차단**(에이전트가 못 뒤집는 것) | 사용자 승인 프롬프트(93% 승인) |
| **툴 정의 해시 핀닝** | 레지스트리 네임스페이스 검증 |
| OS 샌드박스로 경계 이동(프롬프트 84%↓) | 데니룰 목록(경로 치환으로 우회) |
