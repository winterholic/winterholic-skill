# ⑧ 비용·레이턴시 엔지니어링 · 모델 교체

최종 검증: 2026-08-26 (심층 lite-research. 공식 출처 수집자 실패 → 현장 각도 + `claude-api` 번들 스킬 인용)

> ⚠️ 이 축도 공식 수집자가 실패했다. 다만 다른 경로로 **Anthropic 공식 문서 기반 번들 스킬**(`claude-api`)이 인용돼 벤더 상수 계열은 신뢰도가 높다.
> 🔴 **가격·한도·기본값은 이 축에서 가장 빨리 낡는다. 답하기 전에 반드시 WebSearch 또는 `claude-api` 스킬로 현재 값을 확인한다.**

## 핵심 판단 — 캐싱은 "켰다"로 끝나지 않는다

`✅확인` **캐시 최소 프리픽스가 세대별로 단조롭지 않다.** 미달 시 **에러 없이 조용히** `cache_creation_input_tokens=0`이 된다.

| 최소 길이 | 모델 |
|---|---|
| **512** | Opus 5 · Fable 5 · Mythos 5 |
| **1024** | Opus 4.8 · Sonnet 5 · Sonnet 4.6 · Sonnet 4.5 · Opus 4.1/4 |
| **2048** | Opus 4.7 · Haiku 3.5 |
| **4096** | Opus 4.6 · Opus 4.5 · **Haiku 4.5** |

→ **3K 프롬프트는 Opus 5에서 캐시되고 Opus 4.6/Haiku 4.5에서는 안 된다.** 모델을 바꿨는데 캐시가 죽었다면 여기부터 본다.

`✅확인` **쓰기 프리미엄과 손익분기**: read ≈ **0.1×**, write = 5분 TTL **1.25×** / 1시간 TTL **2×**.
- 5분 TTL은 **요청 2회에 손익분기** (1.25+0.1=1.35 vs 2)
- 1시간 TTL은 **최소 3회 필요** (2+0.2=2.2 vs 3)

→ **1시간 TTL은 "더 안전한 기본값"이 아니다.** 더 많은 재사용을 요구한다.

`✅확인` **무효화는 3계층**(tools → system → messages)이고 변경 종류에 따라 파급이 다르다:
- **전체 재구축 강제**: 툴 정의 변경, **모델 스위치**
- **tools+system 캐시 보존**: `tool_choice`, 이미지, thinking on/off 토글

**회피책** `✅확인`:
- 시스템 프롬프트 중간 변경 → top-level `system`을 고치지 말고 **`messages[]`에 `role:"system"` 메시지를 append**(Opus 5·4.8·Fable 5·Mythos 5, 베타 헤더 불필요)
- 툴 세트 변경 → **`defer_loading` + `tool_addition`/`tool_removal` 블록**(Opus 5 이후, 베타 `mid-conversation-tool-changes-2026-07-01`)
- **모델 스위치는 회피책 없음**(캐시는 모델 스코프) → **서브에이전트로 분리**

### 에이전트 루프 특유의 조용한 미스 2종
`✅확인`
1. **20블록 lookback** — 각 breakpoint는 최대 20개 content block까지만 역방향 탐색한다. 한 턴이 20블록을 넘으면(tool_use/tool_result 다발) 다음 요청이 이전 캐시를 못 찾고 **조용히 미스**한다. → **긴 턴에 ~15블록마다 중간 breakpoint.**
2. **병렬 팬아웃 전량 풀가격** — 캐시 엔트리는 **첫 응답이 스트리밍을 시작한 후에야** 읽을 수 있다. 동일 프리픽스 N개를 동시 발사하면 **전부 풀가격**. → **1개 보내고 첫 토큰을 기다린 뒤 나머지 N−1을 발사.**

### 실전 사고 — 시스템 프롬프트의 타임스탬프
`⚠️미검증` 캐시가 전혀 히트하지 않는 버그의 대표 원인은 **시스템 프롬프트에 박힌 동적 콘텐츠**(타임스탬프, "Current Date & Time", 메시지 ID, 세션 메타데이터). 매 턴 프리픽스가 바뀌어 `cache_read`가 영구히 0이 된다.
보고된 실측: **매 턴 170,602 토큰이 cache write로 재과금**, 예상 $9 → 실제 $35, 헤비 유저 $50–100/일, **메시지당 $0.05 예상이 $0.50.**

`⚠️미검증` **프레임워크·프록시 레이어가 원인이 되는 3패턴**: (a) 하드코딩된 모델 ID switch로만 breakpoint를 붙여 **신규 모델은 캐싱 0**, (b) Anthropic 모델을 **OpenAI 호환 어댑터로 라우팅하면 cache-write 필드가 유실**(OpenAI usage 스키마에 없음), (c) 멀티스텝 에이전트가 **매 스텝 정적 프리픽스를 풀가격 재전송.**

`💭해석` **진단 순서**: `cache_read_input_tokens`를 로깅해 0으로 떨어지는 지점을 찾는다 → 그 요청의 프리픽스를 이전 요청과 diff한다 → tools 배열·system 앞단·모델 ID를 순서대로 본다. 축 ④의 캐시 토큰 회계 속성이 이걸 위한 것이다. 축 ⑦에 `tools` 배열 변경으로 −274,262 토큰이 날아간 실측이 있다.

## 라우팅·캐스케이드 — 언제 값하지 않나

`⚠️미검증` **가장 위험한 실패는 silent escalation**: 벤더 업데이트로 저가 모델의 출력 포맷이 바뀌어 스키마 검증이 대량 실패하면 라우터가 전부 대형으로 승격시켜 **요청마다 두 번 과금**한다.
→ **감시 지표는 정확도가 아니라 escalation rate의 시계열이다.** 잘 캘리브레이션된 캐스케이드는 월 단위로 안정적이다.

`⚠️미검증` 값하지 않는 조건으로 반복 제시되는 것: (a) 월 LLM 지출이 대략 **$200 미만**이면 라우팅 레이어 구축·유지 시간이 절감을 초과, (b) **escalation rate ~65%인데 가격차가 2배뿐**이면 오버헤드만 추가.
🔴 **이 수치들은 블로그 계열이고 조건(워크로드·모델·시점)이 불명이다. 임계값으로 못 박아 쓰지 말 것.**

`⚠️미검증` 설계서에서 깔끔해 보이는 intent 카테고리가 프로덕션에서 겹친다 — **단순 질의에 암묵적 복잡성이 있고, 엣지케이스가 오히려 자명하게 해결된다.** 체계적 오라우팅을 잡을 모니터링이 필수.

`🔴시효주의` "45~85% 절감, 품질 95% 유지" 류 수치는 **조건 미명시 SEO 계열이다. 인용 금지.**

## 배칭

`⚠️미검증` Batch API **50% 할인**은 **순차 의존이 있는 에이전트 루프에 그대로 적용 불가**다 — 결과 순서 무보장, 최대 24h, `fallbacks` 파라미터 거부, 일부 클라우드 게이트웨이 미지원.
→ **현실적 용도는 루프 밖**: 평가(eval) 실행, 백필, 대량 분류. 축 ④의 회귀 테스트를 여기 태우면 비용이 반이다.
⚠️ "억지로 끼워 넣어 실패한" 실명 후기는 확보하지 못했다.

## 레이턴시 — TTTF가 체감을 지배한다

`⚠️미검증` 체감은 총 처리시간이 아니라 **TTFT**가 지배한다. 추론 모델의 대표 불만: **thinking display가 꺼져 있으면 수십 초 스피너만 보이고 사용자는 "멈춤"으로 읽는다.**

`✅확인` **그 회귀의 API 차원 원인이 실재한다** — `thinking.display` 기본값이 **Opus 4.6/Sonnet 4.6의 `"summarized"`에서 Opus 4.7·4.8·Opus 5·Sonnet 5·Fable 5의 `"omitted"`로 조용히 바뀌었다.** thinking 블록은 계속 오지만 **텍스트가 빈 문자열**이라, `block.thinking`을 렌더링하던 UI는 **에러 없이 빈 화면**이 된다.
→ `thinking={"type":"adaptive","display":"summarized"}`를 **명시**해야 한다. `display`는 가시성만 제어하고 **과금은 동일**하다.

`💭해석` 이건 축 ⑩의 "모델 업그레이드 후 깨짐"의 교과서적 사례다 — **크래시가 아니라 조용한 기본값 변경**이고, 증상은 "느려졌다"로 신고된다.

### 레버의 방향이 반직관적이다
`✅확인`
- **에이전틱 작업에서 높은 effort를 미리 주면 턴 수가 줄어 총 비용·시간이 오히려 감소할 수 있다.** 관계가 단조롭지 않다.
- **Opus 5는 low/medium이 예상보다 강해 그쪽이 주 비용·레이턴시 레버다.**
- `task_budget`은 `max_tokens`와 달리 **모델이 카운트다운을 인지하는 "제안"**이며 최소 20,000 토큰, **강제 상한이 아니다.**
- **Opus 5에서 verbosity는 effort로 줄어들지 않고 프롬프트로만 줄어든다** — 간결성 지시로 응답 길이 ~20% 감소 실측.

`⚠️미검증` 추론 토큰이 가시 출력의 **5~50배**까지 갈 수 있고, 에이전트에서는 **툴 호출마다 추론이 반복**되어 "툴 호출 횟수 × 호출당 추론량"으로 증폭된다. *(원문 미확인.)*

`💭해석` **턴 수를 줄이는 것이 토큰을 줄이는 것보다 레이턴시에 크게 듣는다.** 축 ③의 코드 실행 실측이 이걸 지지한다 — 순차 체인 길이 ≥12에서 PTC가 **벽시계 0.32~0.96배**(단일 추론 턴 vs 링크당 턴). 단 GPT-5는 예외로 2.8배.

## 증류·파인튜닝 — 에이전트에서 실패가 명확하다

`⚠️미검증` **AppWorld에서 교사 시연으로 학습한 오픈웨이트 모델이 학습 손실은 수렴했는데 태스크 성공률 0%였다.**

`💭해석` **현실적 순서: 프론티어 모델에서 프롬프트·구조 최적화 → 레이턴시·비용이 강제할 때만 증류.** 그리고 축 ⑤의 DSPy 3조건(측정 가능 메트릭 + 라벨 세트 + 대량 호출)이 여기에도 적용된다 — 메트릭 없이 증류하면 손실만 수렴하고 태스크는 실패한다. 위 사례가 정확히 그것이다.

## 모델 교체 — 회귀는 "전부가 조금씩 나빠지는" 형태다

`💭해석` 크래시가 아니므로 총평 지표로는 안 보인다. 그래서 탐지가 실패한다.

`✅확인` **절차적 교훈**: **모델과 프롬프트를 같이 바꾸면 원인 분리가 불가능하다. 모델만 먼저 옮기고 측정, 그다음 프롬프트를 별도 변경으로 재튜닝한다.**

`✅확인` **프롬프트 과적합의 구체적 반례 3종** — 일반 베스트프랙티스가 역전된다:
| 낡은 프롬프트 | 신모델에서의 결과 |
|---|---|
| 구모델의 소극성을 극복하려 넣은 `CRITICAL: You MUST` 류 | **툴 과다호출** 유발 |
| `double-check your answer` 류 자기검증 지시 | Opus 5에서 **과검증** 유발 → **삭제가 정답** |
| 코드리뷰 하네스의 `only high-severity` 지시 | 신모델이 **더 충실히 따라** 버그 탐지력은 올랐는데 **측정 recall만 떨어짐**(하네스 효과) |

`💭해석` 세 번째가 특히 중요하다 — **지표가 나빠졌는데 실제로는 좋아진** 경우다. 축 ④ 없이는 이걸 구분할 수 없고, 그냥 "새 모델이 나쁘다"고 결론 내린다.
그리고 축 ①의 자기검증 논점과 연결된다 — 외부 검증 신호 없는 self-critique는 이제 **모델이 알아서 하므로 지시가 오히려 해롭다.**

## 레이트리밋·폴백

`✅확인` **폴백 설계의 반례**: 429 대응으로 **fast mode를 끄는 것은 무해하지 않다** — **speed 변경이 프롬프트 캐시를 무효화**하므로 "한 단계 낮춰 재시도"가 **캐시 리빌드 비용을 동반**한다.

`💭해석` 그래서 폴백 순서는 비용만 보지 말고 **캐시 유효성**을 함께 본다. 같은 모델 내 재시도(백오프) → 캐시 유지되는 파라미터 조정 → 모델 교체(캐시 전량 무효)를 마지막으로.

## 실패 패턴

- **시스템 프롬프트에 타임스탬프** → 캐시 영구 0. 가장 흔하고 가장 비싸다.
- **모델을 올렸는데 캐시 최소 길이가 커졌다** → 조용히 캐싱 중단.
- **동일 프리픽스 N개 동시 발사** → 전부 풀가격.
- **한 턴에 20블록 초과** → 조용한 미스.
- **1시간 TTL을 기본값으로** → 3회 미만 재사용이면 손해.
- **모델·프롬프트 동시 변경** → 원인 분리 불가.
- **낡은 강조 문구를 그대로 이관** → 과다호출·과검증.
- **429에 모델을 낮춤** → 캐시 전량 무효.
- **에이전트 루프에 Batch API** → 순서 무보장으로 깨진다.

## 미확인 (gap)

- **공식 수집자 실패** — 벤더 가격표·배치 API 문서 각도 미확인.
- 라우팅·캐스케이드의 **조건 명시된 실측 절감폭** 없음. 임계값 전부 블로그 계열.
- 스트리밍·낙관적 실행·투기적 실행의 **정량 개선폭** 미확보.
- 증류 성공 사례(품질 유지) 미확보 — 실패 사례만 있다.
- 파인튜닝 **비용 회수 지점**의 구체 수치 없음.
- 배칭을 에이전트에 억지 적용해 실패한 실명 후기 없음.
