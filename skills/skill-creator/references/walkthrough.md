# 한 벌 통과 — §1~§6 을 사례 하나로 꿰어 본다

각 절의 규칙은 `../SKILL.md` 에 있다. 여기는 그 규칙들이 **하나의 요청에서 실제로 어떻게 떨어지는지**를 보여주는 자리다. 규칙만 읽으면 각 판정의 축은 알아도 판정이 어느 쪽으로 기우는지가 안 보인다.

> **사례는 가상이다.** 인용한 규칙·경로·명령은 실재하는 것을 그대로 썼다. 결과물 문장을 여기서 베껴 쓰라는 뜻이 아니라, **어디서 무엇을 결정했고 왜 반대쪽이 아니었는지**를 보라는 뜻이다.

---

## 요청

> "홈서버 점검할 때마다 내가 똑같은 걸 시키고 있어. 이거 스킬로 만들어줘."

## §0 — 이게 스킬이 맞나

| 물음 | 답 | 판정 |
|---|---|---|
| 어떤 턴에서든 발동해야 하나 | 아니다. 홈서버 얘기가 나올 때만이다 | `CLAUDE.md` 아님 |
| 결정론적으로 강제돼야 하나 | 아니다. 점검 항목은 상황따라 바뀐다 | 훅 아님 |
| 사용자·프로젝트에 대한 사실인가 | 서버 스펙은 사실이지만 요청은 **절차**다 | `memory/` 아님 |
| 알아볼 수 있는 순간에 발동하나 | "홈서버 점검해줘"라는 발화가 그 순간이다 | **스킬** |

결정: 스킬. 다만 서버 스펙·IP 같은 **사실**은 스킬에 박지 않고 `C:\homeserver\PROJECT_CONTEXT.md` 를 읽으라고 지시한다. 사실을 스킬에 복사하면 두 곳이 따로 낡는다.

## §1 — 요구사항 수집

대화에서 이미 나온 것은 다시 묻지 않는다. 6개 중 넷은 맥락에서 뽑혔고, **빠진 둘만** 묻는다.

| 항목 | 어디서 나왔나 |
|---|---|
| 해결할 문제 | 요청 문장 그대로 |
| 트리거 발화 | 지난 대화에서 사용자가 실제로 친 말 — "홈서버 상태 어때", "서버 점검", "디스크 얼마 남았어" |
| 산출물 | ❓ 물어본다 — 응답인가 `.claude\reports\` 에 남기는 파일인가 |
| 의존성 | ssh. 없으면 아무것도 못 한다 |
| 경계 | ❓ 물어본다 — `dev-experts` 의 홈서버 전문가와 어떻게 갈리나 |
| 공개 여부 | 서버 IP 가 들어가면 비공개 |

**가장 값어치 있는 재료는 "사용자가 고친 지점"이다.** 지난 대화에서 사용자가 "load 는 코어 수로 나눈 배수로 보여줘"라고 고쳤다면, 그 한 줄이 곧 판정 기준이라 스킬 본문에 그대로 들어간다.

## §2 — 어디에 두고 무엇을 번들할지

- **위치**: "홈서버 점검해줘"가 자동으로 걸려야 한다 → `skills/` 직속. 상시 ~100토큰을 낼 값어치가 있다.
- **폴더명**: `homeserver-checkup`. 명사구다(`check-homeserver` 아님).
- **번들**: 점검 명령이 대여섯 개 고정으로 반복된다 → `references/patterns.md` 의 "3회 이상 유사 패턴 반복 → 번들 대상" 기준에 걸린다. `scripts/collect.sh` 로 뺀다. 스크립트는 **결과만 컨텍스트에 들어오므로** 길이 부담이 없다.

## §3 — 작성

뼈대부터 뜬다.

```bash
cp "~/.claude\skills\skill-creator\assets\SKILL.template.md" "~/.claude\skills\homeserver-checkup\SKILL.md"
```

`name: homeserver-checkup` — 디렉터리명과 한 글자도 다르지 않게. description 은 What + 실제 발화 + 경계 순으로 쓰고, 인접한 `dev-experts` 를 이름으로 지목한다.

## §4 — 게이트

```bash
python "~/.claude\skills\skill-creator\scripts\check-skill.py" "~/.claude\skills\homeserver-checkup"
```

FAIL 이 나오면 여기서 멈춘다. 그다음 §4 ② 의 다섯 자리를 본다. 이 사례에서 실제로 비어 있던 것은 **D2** 였다 — ssh 가 안 붙을 때 무엇을 하는지가 없었다. "사용자에게 알린다"로 적어 두었다가, 그건 fallback 이 아니라는 규칙에 걸려 "직전 점검 결과를 `.claude\reports\` 에서 찾아 시각과 함께 보여주고, 그게 없으면 미확인으로 보고"로 고쳤다.

## §5 — 검증

테스트 발화 3개를 만든다. 하나는 일부러 애매하게 흘린다.

- `"서버 좀 봐줘"` ← 애매한 것
- `"홈서버 디스크 꽉 찬 거 같은데"`
- `"미니PC 상태 점검"` ← 사용자가 실제로 쓰는 다른 이름

사용자에게 보여 확인받고, **fresh 세션**에서 넣어 본다. 이 세션에서 스스로 흉내 내면 안 된다 — 저자의 저주. `"서버 좀 봐줘"` 가 안 걸리면 본문이 아니라 **description** 을 고친다.

## §6 — 등록

- [ ] `skill-list.md` 에 행 추가 + **상단 개수 수정**
- [ ] 트리거가 겹치는 `dev-experts` 의 description 에도 이쪽을 지목 — 한쪽만 고치면 반쪽이다
- [ ] 서버 IP 가 들어갔으므로 공개 금지를 스킬 안과 `skill-list.md` 양쪽에 표기

여기까지 해야 끝이다. 폴더만 만들고 멈추면 아무도 안 읽는다.

## 이 사례에서 실제로 갈렸던 자리

| 자리 | 고른 쪽 | 반대쪽을 안 고른 이유 |
|---|---|---|
| §0 | 스킬 | 스펙 사실만이면 `memory/` 였다. 요청은 절차였다 |
| §2 위치 | `skills/` | `sub-skills/` 면 상시 비용 0 이지만 이름을 알고 불러야 한다. 자동 발동이 요구사항이었다 |
| §2 번들 | 스크립트로 뺌 | 본문에 명령을 늘어놓으면 매 트리거마다 그 길이를 문다 |
| §4 | D2 를 다시 씀 | "알린다"는 다음 수단이 아니다 |
