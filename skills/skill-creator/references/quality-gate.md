## 넘기기 전 게이트 — 다섯 개는 반드시 채운다

### B3. 판단 불가 상황의 4요소

스킬이 막혔을 때 **누가 / 언제 / 어떻게 / 기대값** 을 적는다. 넷 중 하나라도 비면 B3 는 깎인다.

```markdown
## 판단이 안 설 때
- **누가**: 사용자에게 묻는다 (에이전트나 다른 스킬에 넘기지 않는다)
- **언제**: 후보가 둘 이상 남고 파일 내용으로 못 가릴 때. 그 전에 먼저 mtime·주제어 grep 으로 좁힌다
- **어떻게**: 한 줄 질문 + 후보 목록. 선택지를 늘어놓고 설명하지 않는다
- **기대값**: 사용자가 이름 하나를 답한다. 무응답이면 가장 최근 것으로 진행하고 그 사실을 밝힌다
```

### C2. 좋음/나쁨 대비 예시

각 지침에 예시를 붙이되, **대비 쌍**으로 준다. 좋은 예만 있으면 경계가 안 보인다.

```markdown
나쁨: `git add -A`
좋음: `git add <내가 실제로 친 경로>`
이유: -A 는 다른 세션이 만든 파일까지 스테이징한다
```

### C3. 산출물의 파일명·위치·덮어쓰기 규칙

파일을 만드는 스킬이면 셋 다 적는다. 하나라도 비면 세션마다 다른 곳에 떨군다.

```markdown
- 위치: `.claude\reports\`
- 파일명: `YYYY-MM-DD-HHmm-<주제-kebab>.md`
- 같은 이름이 있으면: append 한다. 덮어쓰지 않는다
```

경로는 CLAUDE.md 의 **§ Output Paths** 표를 따른다. **스킬 안에서 새 절대경로를 발명하지 않는다.**

### D2. 거부·불가 시 fallback

사용자가 거절하거나 도구가 없을 때 무엇을 하는지. "안 되면 사용자에게 알린다"는 fallback 이 아니다. **다음 수단을 지목**해야 한다.

```markdown
| 상황 | 다음 수단 |
|---|---|
| web-browse 미연결 | URL 을 사용자에게 주고 본문 복붙 요청 |
| 봇 차단 | 우회 시도하지 않는다. 차단 사유와 URL 을 보고 |
| 사용자가 "그냥 답해" | 라이브러리만으로 답하고 "외부 검증 생략" 한 줄 첨부 |
```

### E1. 도메인 용어 풀이

스킬이 쓰는 약어·전문어를 처음 나오는 자리에서 한 번 푼다. 매번이 아니라 한 번.

```markdown
progressive disclosure(점진적 공개) — metadata → 본문 → 번들 순으로 필요할 때만 여는 3단 로딩
```

## Gotchas 절을 반드시 만든다

Anthropic 내부 운영에서 **가장 값어치 있는 콘텐츠로 지목된 것이 gotchas 절**이다. 실제 실패 지점을 적고, 새 엣지 케이스가 나올 때마다 덧붙인다. 스킬을 정적 문서가 아니라 **실패 로그 누적처**로 운영하라는 뜻이다.

초안에 gotchas 가 비어 있는 것은 정상이다. 다만 **빈 절이라도 만들어 두어야** 다음 세션이 거기에 적는다. 절이 없으면 실패 경험이 휘발된다.

## 과잉 명세 경계 (anti-railroading)

게이트를 채우라는 말이 **모든 것을 지시하라**는 뜻은 아니다. 과잉 명세는 Claude 가 상황에 맞게 방향을 트는 능력을 죽인다. Anthropic 이 안티패턴으로 지목한 railroading 이 이것이다.

| 결정론이 필요한 곳 | 판단을 남길 곳 |
|---|---|
| 파일 경로·명명 규칙 | 어떤 표현으로 쓸지 |
| 실행 순서가 안전에 걸릴 때 | 몇 개 섹션으로 나눌지 |
| 되돌릴 수 없는 작업의 확인 절차 | 어떤 예시를 고를지 |

`ALWAYS`·`NEVER` 를 남발하면 그 스킬은 경직된다. 강제어는 **되돌릴 수 없는 것**에만 쓴다.
