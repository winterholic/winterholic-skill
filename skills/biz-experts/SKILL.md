# biz-experts 디스패처

> 용어: **디스패처** = 전화 교환원(작업을 받아 맞는 부서로 연결만, 직접 작업 ❌) · **라우터** = 작업을 분해해 전문가 조합을 정하는 CPO/CMO · **폴백** = 전문가 스킬이 미제작일 때 거장 원칙 + 공식 자료로 진행하는 대체 경로.

비개발 직군 작업(제품·디자인·마케팅·사업·운영·세일즈·피플)을 받으면:

1. **프로젝트 규칙 우선 확인** — 현재 작업이 프로젝트 폴더 안이고 그 프로젝트에 CLAUDE.md·프로젝트 스킬이 있으면 **그쪽이 우선**. 이 스킬군은 프로젝트 규칙이 침묵하는 영역만 채운다.
2. `~/.claude\biz-experts-skills\biz-chief-strategist\SKILL.md`를 Read한다(라우터). 라우터가 작업을 [기능 × 단계 × 산출물 × 지표] 축으로 분해해 전문가 1~3명을 정한다.
3. 직무가 이미 특정된 작업(예: "랜딩 카피 써줘", "RICE로 우선순위", "피치덱 구조")은 라우터를 건너뛰고 해당 전문가 `~/.claude\biz-experts-skills\biz-<이름>\SKILL.md`를 직접 Read한다. 전문가 목록·제작 상태(✅/⬜)는 `~/.claude\biz-experts-skills\README.md` 카탈로그 참조.
4. **미제작(⬜) 전문가는 Read 시도하지 않는다** — 폴백으로 진행하고 한 줄 알린다:
   `⬜ biz-<이름> 미제작 — 거장 원칙(<원전>) + 공식 자료로 진행. 확인 필요: <스킬이 있었다면 검증했을 항목>`
5. 읽은 매뉴얼의 워크플로우·안티패턴·산출물 템플릿을 그대로 따른다. 공통 규칙(우선순위 사다리·버전 라벨·사후 채점·윤리 게이트)은 README에 있다.
6. **되돌리기 어려운 큰 결정**(가격·리브랜딩·핵심 기능 방향·캠페인 예산)이면 산출물에 가설·성공지표·확인 시점을 명시하고, 선택적으로 `decisions-ledger.md`에 1행 추가.

## 라우팅 ❌/✅ 예시

- ✅ "온보딩 화면 기획해줘" → 이 디스패처 (서비스 기획·UX)
- ✅ "이 기능 PRD 써줘" → biz-prd-writing 직행 (직무 특정)
- ❌ "온보딩 화면 React로 구현해줘" → dev-experts (코드 작성이 본체)
- ❌ "삼성전자 살까?" → stock-experts (투자 판단)
- ❌ "연말정산 어떻게" → life-experts (개인 세무)
- ✅ "마케팅 카피 + 랜딩 구조 같이" → 라우터 경유 (copywriter + ux-writer/product-marketing 조합)

## 사용자가 라우팅을 거부하면

- **"스킬 찾지 말고 그냥 해줘"** → 디스패처 생략하고 직접 진행. 단 윤리 게이트 영역(과장광고·다크패턴·차별·허위표시)이면 리스크 한 줄은 남긴다.
- **"그 전문가 말고"** → 이유를 1회만 묻고 지정대로 진행.
- **권고 자체 거부** → 거부된 권고와 리스크를 1줄 기록하고 진행(partial — 전체 보류 금지).

## 주의

- 스킬에 적힌 벤치마크·전환율·플랫폼 수수료·정책은 작성 시점 기준이다 — 낡았으면 **공식 문서·플랫폼 정책이 이긴다**.
- 이 스킬군은 일반론 전문가다. 프로젝트 고유 브랜드 가이드·도메인 규칙과 충돌하면 프로젝트가 이기고, 알려진 안티패턴일 때만 한 줄 지적한다.
- 코드가 필요한 지점(랜딩 구현·이벤트 트래킹 코드·대시보드 구현)은 dev-experts로 넘긴다 — biz는 **무엇을·왜**까지, **어떻게 코딩**은 dev.
