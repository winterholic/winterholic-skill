# 비즈니스 — FDE 로서 고객사에 쓰는 글

사용자는 FDE(Forward Deployed Engineer)로 새 회사에 합류했고 고객사가 있다.

이 갈래의 글은 **나중에 근거로 다시 읽힌다.** 장애 보고는 사후 회의에서, 일정 메일은 지연이 났을 때 다시 열린다. 그래서 규칙 하나가 나머지를 지배한다. **약속과 추정을 섞지 않는다.**

---

## 원칙

### 결론 먼저
고객사는 배경을 안 읽는다. 첫 두 줄에 결론이 없으면 그 메일은 실패한다.

```
나쁨: 안녕하세요. 지난주 요청 주신 건과 관련하여 내부적으로 검토를 진행하였고,
      여러 방안을 논의한 결과 다음과 같이 안내드립니다.
좋음: 요청하신 기능은 3월 2주차에 배포하겠습니다.
      검토 과정에서 범위가 하나 줄었는데, 아래에 정리했습니다.
```

### 약속과 추정을 문장 단위로 구분한다

| 무게 | 표현 | 언제 |
|---|---|---|
| 약속 | `~하겠습니다`, `~까지 드리겠습니다` | 내가 통제할 수 있고 지킬 수 있을 때만 |
| 계획 | `~할 예정입니다` | 확정됐지만 변수가 남아 있을 때 |
| 추정 | `~로 보입니다`, `현재까지는 ~입니다` | 아직 확인 중일 때 |
| 미확인 | `확인해서 <시점>까지 알려드리겠습니다` | 모를 때. **모른다고 쓰는 것이 정답이다** |

**모르는 것을 추정으로 덮지 않는다.** 대신 언제까지 알아보겠다고 쓴다. 그 시점은 지킨다.

### 사과는 한 줄, 그다음은 다음 행동
사과가 길면 상대는 자기가 뭘 해야 하는지 모른다.

```
나쁨: 이번 일로 불편을 드려 대단히 죄송합니다. 저희 내부적으로도 심각하게
      받아들이고 있으며, 재발 방지를 위해 최선을 다하겠습니다.
좋음: 어제 14시부터 40분간 조회가 실패했습니다. 불편을 드려 죄송합니다.
      원인은 배포 중 설정 누락이었고 이미 복구했습니다.
      재발 방지책은 금요일까지 정리해서 공유드리겠습니다.
```

### 기술 설명은 고객사의 언어로
내부 용어를 그대로 내보내지 않는다. 고객사가 아는 단위(화면·업무·건수)로 바꾼다.

```
나쁨: N+1 쿼리 때문에 레이턴시가 튀었습니다.
좋음: 목록 화면이 느렸습니다. 한 번에 가져와도 될 데이터를 건마다 나눠 조회하고 있었습니다.
```

### 숫자를 쓴다
`빠르게`, `조속히`, `최대한` 은 약속이 아니다. 날짜와 수치로 쓴다.

## 상황별 뼈대

| 상황 | 순서 |
|---|---|
| **장애·이슈 통보** | 언제부터 언제까지 + 무엇이 안 됐는지 + 영향 범위 + 현재 상태 + 다음 조치와 시점 |
| **일정 지연** | 새 날짜 먼저 + 이유 한 줄 + 그때까지 무엇이 되는지 + 대안 |
| **요구사항 확인** | 내가 이해한 것을 **내 말로 다시 적고** + 맞는지 묻는다. 애매한 지점을 지목한다 |
| **에스컬레이션** | 지금 상태 + 내 선에서 못 정하는 이유 + 필요한 결정 + 언제까지 |
| **미팅 노트** | 결정된 것 / 미결 / 액션(담당·기한). 대화 재현이 아니라 **결정 목록**이다 |
| **범위 밖 안내** | 왜 범위 밖인지 + 하려면 무엇이 필요한지 + 지금 할 수 있는 대안 |

**미팅 노트는 회의록이 아니다.** 누가 무슨 말을 했는지가 아니라 무엇이 정해졌는지를 적는다.

## 이 갈래에서 특히 자주 나는 tell

| 나쁨 | 좋음 |
|---|---|
| 요청주신 사항들에 대한 대응 방안을 통해 처리가 진행될 예정입니다 | 요청하신 사항은 아래 방안으로 처리하겠습니다 |
| 현재 총 3벌의 케이스가 확인되어지고 있습니다 | 지금까지 확인된 케이스는 3건입니다 |
| 빠른 시일 내에 회신드리겠습니다 | 목요일까지 회신드리겠습니다 |
| 해당 부분에 대해서는 확인이 필요한 상황입니다 | 이 부분은 확인해서 내일 알려드리겠습니다 |
| 최선을 다하겠습니다 | (뺀다. 아무 정보가 없다) |

## ⚠️ 사용자에게 받아야 할 것

이 절이 비어 있는 동안 이 갈래는 일반론에 머문다. 다음 라운드에 확인한다.

- 고객사와 쓰는 언어 — 한국어 전용인가, 영어 혼용인가
- 메일 말고 다른 채널이 있는가 (고객사 슬랙·지라·전용 포털)
- 회사에 정해진 메일 템플릿·서명·머리말 규칙이 있는가
- **사용자가 단독으로 할 수 있는 약속의 수위** — 일정을 혼자 확정해도 되는지, 어디부터 상급자 확인이 필요한지
- 고객사가 개발 조직인가 현업 조직인가 (기술 용어 수위가 갈린다)

**이걸 모르는 상태에서 약속 문장을 대신 써 주지 않는다.** 초안을 주되 약속의 수위는 사용자가 정하게 한다.
