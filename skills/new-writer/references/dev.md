# 개발자 일상 — 커밋·PR·주석·기술문서·이슈

독자는 대개 **미래의 나**다. 지금 아는 것을 그때는 모른다. 그래서 이 갈래의 핵심은 문장력이 아니라 **무엇을 남기고 무엇을 버리는가**다.

## 공통 원칙

- **무엇을 했는지가 아니라 왜 했는지.** diff 가 what 을 이미 말한다.
- **용어는 음차 유지.** 억지 번역이 오히려 안 읽힌다 (`korean-tells.md` §5).
- **추측과 확인된 사실을 구분해서 적는다.** 추측이면 추측이라고 쓴다.
- **한 문서 안에서 영/한을 섞지 않는다** (§7). 코드 식별자와 굳은 약어(`PR`·`CI`)는 예외다.

---

## 커밋 메시지

이 레포에서 실제로 쓰는 형식은 Conventional Commits 다.

```
feat(auth): JWT 기반 인증 구현
fix(cart): 수량 0 이하 입력 시 에러 처리
docs(readme): 설치 가이드 갱신
```

- **제목은 명령형·현재형.** `구현했음` 이 아니라 `구현`.
- **본문은 why.** 무엇을 바꿨는지는 diff 를 보면 된다. 왜 이 방향을 골랐고 무엇을 버렸는지를 적는다.
- 실패한 접근이 있었으면 그것도 한 줄. 다음 사람이 같은 길을 다시 판다.
- 제목에 마침표를 찍지 않는다.

⚠️ **확인 필요**: 새 회사 레포도 Conventional Commits 를 쓰는지 사용자에게 확인하지 않았다. 다르면 그쪽 규칙이 우선한다.

---

## PR 설명

리뷰어가 알아야 하는 것은 셋이다.

1. **무엇을 왜** — 한두 문장
2. **어떻게 검증했는가** — 돌린 명령과 결과. "테스트했습니다"는 검증이 아니다
3. **어디부터 보면 되는가** — 파일이 많으면 진입점을 지목한다

```
나쁨: 리팩토링 및 버그 수정을 진행하였습니다.
좋음: 주문 조회가 느려서 N+1 을 없앴습니다. 목록 API 응답이 1.4초에서 0.2초가 됐습니다.
      검증: `pytest tests/orders` 42 passed. 먼저 `repository.py` 부터 보시면 됩니다.
```

- 스크린샷이 말보다 빠른 변경(UI)은 스크린샷을 붙인다.
- 범위 밖으로 남긴 것이 있으면 명시한다. 리뷰어가 지적하기 전에.

## 코드 주석

프로젝트 규칙과 정합해야 한다. `CLAUDE.md` 기준은 이렇다.

- **why 만 적는다.** 자명한 주석은 쓰지 않는다.
- 허용되는 셋: ①약어 풀이 (`LTV = Loan-To-Value`) ②자명하지 않은 비즈니스 규칙 ③`TODO`/`FIXME`/`REFACTOR`/`NOTE` 태그
- **최소한으로, 한국어로, 가독성 좋게.** 사용자가 명시한 선호다.

```
나쁨: // 사용자 목록을 가져온다
     users = fetch_users()

좋음: // 탈퇴 후 30일은 복구 가능해서 조회에 포함한다 (정책 2024-03)
     users = fetch_users(include_withdrawn_within_days=30)
```

## 기술 문서·사내 위키

- **결론 먼저, 배경은 뒤로.** 읽는 사람은 답을 찾으러 왔다.
- **분기가 둘 이상이면 표로.** 산문으로 늘어놓으면 안 읽힌다.
- 제목은 메소드명처럼 (`korean-tells.md` §19). 추상 명사 제목은 내용을 못 알려준다.
- 코드 블록은 **복사해서 바로 돌아가는 형태**로. 자리표시자는 `<...>` 로 표시한다.

## 이슈·티켓

세 칸이면 충분하다.

```
재현: 1) 장바구니에 3개 담기 2) 하나 삭제 3) 새로고침
기대: 2개 남음
실제: 3개로 돌아옴 (스크린샷 첨부)
```

- **환경을 적는다.** 브라우저·버전·계정 종류. 재현이 안 되는 이슈의 절반은 여기서 갈린다.
- 심각도를 스스로 부풀리지 않는다. 판단은 받는 쪽이 한다.

## 자주 나는 tell (이 갈래 특화)

| 나쁨 | 좋음 |
|---|---|
| 해당 이슈에 대한 대응을 진행하였습니다 | 이 이슈를 처리했습니다 |
| 3벌의 케이스가 확인되어집니다 | 케이스 3건을 확인했습니다 |
| 성능 개선 작업을 통해 속도가 향상되었습니다 | 쿼리를 고쳐 응답이 1.4초에서 0.2초가 됐습니다 |
| 이 함수는 3개의 파라미터를 가집니다 | 이 함수는 파라미터가 3개입니다 |
| 관련 파일들을 모두 수정하였습니다 | 관련 파일을 모두 고쳤습니다 |

숫자가 있으면 숫자를 쓴다. `향상되었습니다` 보다 `1.4초 → 0.2초` 가 언제나 낫다.
