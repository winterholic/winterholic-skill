# 캐주얼 — 사내 메신저

독자는 같은 팀이고 지금 바쁘다. **완결문 강박을 버리는 것**이 이 갈래의 핵심이다.

이 갈래에서는 `korean-tells.md` 의 tell 중 **구두점 축(1~4)만** 본다. 문법 축(10~16)은 거의 적용하지 않는다. 메신저에서 `~에 대해` 하나 고치자고 문장을 다시 쓰는 것은 과잉이다.

---

## 원칙

### 한 메시지 한 용건
용건이 둘이면 메시지를 둘로 보낸다. 상대가 하나만 답하고 나머지를 잊는다.

### 결론 먼저
배경 설명으로 시작하면 안 읽힌다.

```
나쁨: 어제 배포 관련해서 확인해 봤는데 로그를 보니까 좀 이상한 부분이 있어서요,
      혹시 시간 되실 때 같이 보실 수 있을까요?
좋음: 어제 배포 로그가 좀 이상한데 같이 봐주실 수 있나요? (스레드에 로그 붙여둘게요)
```

### 완결문이 아니어도 된다
```
나쁨: 해당 건은 배포가 완료되었습니다.
좋음: 그거 배포 완료했어요
```

### 답하기 쉬운 형태로 묻는다
열린 질문보다 선택지 두 개.

```
나쁨: 이거 어떻게 할까요?
좋음: 이거 지금 롤백할까요, 아니면 내일 아침에 고칠까요?
```

### 물음표를 아끼지 않는다
실측상 사람은 100발화당 74회 물음표를 쓰고 나는 5회 쓴다. 확인을 건네는 문장이 사람의 기본값이다.

---

## 존대 수위 — 상대에 따라 네 단계

| 상대 | 어투 | 예 |
|---|---|---|
| 같은 팀 동료 | 해요체, 짧게 | `그거 배포했어요` |
| 타 팀 | 해요체 + 맥락 한 줄 | `주문 API 스키마 바뀌어서 공유드려요` |
| 상급자 | 해요체~합쇼체, 결론 먼저 | `배포 끝났습니다. 지표는 내일 확인하겠습니다` |
| 고객사 채널 | 합쇼체 | `business.md` 로 간다 |

**한 채널 안에서 수위를 흔들지 않는다.** 레지스터 흔들림은 메신저에서도 tell 이다.

---

## 상황별 뼈대

| 상황 | 뼈대 |
|---|---|
| **요청** | 무엇을 + 언제까지 + 왜 급한지(있으면). `내일 오전까지 이 PR 리뷰 부탁드려요. 배포가 목요일이라서요` |
| **거절·지연** | 못 한다 + 언제 가능 + 대안. `이번 주는 어려워요. 다음 주 화요일부터 가능한데, 급하시면 A 님이 아실 것 같아요` |
| **도움 요청** | 시도한 것 먼저 + 막힌 지점. `로컬에서 X 해봤는데 Y 에서 막혔어요. 혹시 짚이는 데 있나요?` |
| **진행 공유** | 지금 상태 + 다음 + 막힌 것. 세 줄이면 충분하다 |
| **실수 알리기** | 무슨 일 + 영향 범위 + 지금 뭐 하는 중. **사과는 한 줄.** 길어지면 상대가 상황을 못 읽는다 |

---

## 이모지

톤 조절용이지 장식이 아니다. **거절·지연·실수를 알릴 때 한 개** 정도가 무난하다. 문장마다 붙이면 그 자체가 AI 티다.

---

## 하지 말 것

- 사내 메신저에 보고서 문체 쓰기 (`~하였습니다`, `~에 대하여`)
- 스레드로 갈 내용을 채널 본문에 길게
- 인사말로 한 줄 쓰고 용건을 다음 메시지로 (알림이 두 번 간다)
- 읽는 사람이 스크롤해야 하는 길이. 길면 문서로 만들고 링크를 보낸다
