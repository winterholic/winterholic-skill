# verification-before-completion 매칭 회귀 시나리오

새 트리거·SKIP 키워드 추가 시 이 표를 검증 anchor로 사용한다. 입력/응답 맥락 → 기대 결과 매핑.

## 1) True Positive — 정상 발동 (6개)

| # | 맥락 | 기대 동작 | 검증 항목 |
|---|------|----------|----------|
| 1.1 | 사용자: "테스트 통과했어?" | 발동 → `pytest` 실행 후 출력 인용 | 통과 키워드 |
| 1.2 | Claude 응답 draft에 "함수 추가 완료" 포함 | 발동 → `git diff`·`python -c` evidence 추가 | 완료 키워드 |
| 1.3 | "수정 완료" 응답 | 발동 → diff + 재실행 결과 | 수정 완료 키워드 |
| 1.4 | "빌드 성공" 응답 | 발동 → `npm run build` 출력 인용 | 통과·성공 키워드 |
| 1.5 | "엔드포인트 동작 확인" 응답 | 발동 → `curl` 결과 인용 | 동작 보증 키워드 |
| 1.6 | "버그 해결" 응답 | 발동 → 재현 케이스 재실행 결과 | 수정 완료 키워드 |

## 2) False Positive — 발동하면 안 됨 (2개)

| # | 맥락 | 기대 동작 | 보호 규칙 |
|---|------|----------|----------|
| 2.1 | 코드 블록 안 `print("작업 완료")` 리터럴 | 비활성 | 인용·코드 안 키워드 무시 |
| 2.2 | 인용 문장 "사용자가 '통과'라고 말했을 때" 메타 설명 | 비활성 | 메타·인용 맥락 |

## 3) Conflict — 다른 스킬과 동시 활성 시 우선순위 (2개)

| # | 맥락 | 기대 동작 | 우선순위 |
|---|------|----------|---------|
| 3.1 | caveman ultra 활성 + "테스트 통과" 주장 | evidence 1줄 축약 (`$ pytest tests/ → 5 passed`) | caveman 강도 조정 + verification 룰 유지 |
| 3.2 | 코드 리뷰 받는 중("이 코드 이상해") + 수정 후 "고침" | verification 발동(evidence 필수) + CLAUDE.md 즉답 동의 금지 룰 동시 적용 | 검증 후 동의/푸시백 |

## 4) 갱신 시 점검

- 새 트리거 추가 시 1) True Positive 표에 행 1개 이상 추가
- 새 SKIP 추가 시 2) False Positive 표에 행 1개 이상 추가
- description 키워드 변경 시 1~3 표 전체 재실행 (수동 매칭 검토)
